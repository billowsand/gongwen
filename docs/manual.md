# 使用手册

## 公文词表与输入法

「公文词表」页把长期积累的公文变成输入法词库，让打字和成文用的是同一套名称。

- **累积**：点「扫描」只处理正文变过的稿件（按内容哈希记账），已扫过且没改动的整篇跳过；默认只统计已发布与已归档的稿件，草稿默认不计入。同一篇稿件反复保存也不会把词频算重。
- **合并**：标准词库里的单位全称、对外名称、简称、别名与机关代字，以及校对词表里的「建议写法」，都会并进词表并自动置为已接受；校对词表里的「错误写法」进黑名单，既不入库也不导出——不会把写错过的字固化进输入法。
- **确认**：拒绝过的词永久记住，重扫不再冒头；人工标过读音或短码的词条会锁定，重扫不覆盖。
- **导出**：导出小鹤双拼用户码表（UTF-8 带 BOM，含 `---config@` 码表头），在小鹤输入法的码表管理里导入「主码-用户码表」即可。有重码时同时写出重码报告。

排序与筛选按**省键数**来，而不是按词频。小鹤词组是四码定长：一个 n 字词正常要敲 2n 键，进了用户码表一律 4 键，所以省 `2n-4` 键——二字词省 0 键，默认不导出。排序权重是「省键数 × 出现篇数」，导出默认有条数上限：用户码表与主码表合用同一个编码空间，词收得越多重码越多、翻页越频繁。

导出的码表是明文文件，导入输入法后不再受本应用管控。涉密的项目代号、人名与文号请先在词表页拒绝再导出。

## 使用 Ollama

本应用通过 OpenAI 兼容协议接入本地模型服务，因此同样支持 Ollama：

1. 启动 Ollama 服务（`ollama serve`，默认端口 11434）并拉取所需模型；
2. 在“设置 → 本地模型服务设置”中，把对话、Embedding、Rerank 三个「接口地址」都改为 `http://127.0.0.1:11434/v1`（三个配置相互独立）；
3. 模型名填 Ollama 的模型 tag，例如对话模型 `qwen2.5:7b`、Embedding 模型 `bge-m3` 或 `nomic-embed-text`；
4. 重排方式选「用对话大模型重排」：Ollama 目前不提供 rerank 专用端点，无法使用「专用端点」模式，改用对话模型打分同样可用。

## 源码编辑器的 Markdown 字面

Markdown 源码模式默认整篇用编辑器字体，`#`、`##` 只能靠符号数量分辨层级。不熟悉 Markdown 的人可以在“设置 → 字体 → 源码编辑器的 Markdown 字面”换一套模板：

- **编辑器字体**：六处全用编辑器字体，Markdown 标记最醒目（默认，与以往一致）；
- **标题随公文**：`#` 小标宋、`##` 黑体、`###` 楷体、`####` 及以下仿宋，正文仍用编辑器字体；
- **与公文一致**：正文也换成仿宋，源码看着最接近打印稿。

也可以不挑模板，给文档标题、一级/二级/三级及以下标题、正文与「标记及行内代码」六处分别指定字面，模板一栏会显示「自定义」。这里的公文字面与预览、导出同源——在“编译字体”里把正文换成本机仿宋，编辑器里的仿宋跟着换。本设置只改屏幕上的字面，字号、行距与导出结果都不受影响；`#`、`|`、`**` 这类只在源码里出现的符号默认留在编辑器字体上，仍然一眼可辨。

要连字号、行距一起按公文排，用“视图 → 实时排版”：非活动行按公文版式排版，只有光标所在行显示 Markdown 标记。

## 研究报告的数学公式

研究报告正文支持 LaTeX 数学公式：行内公式用 `$...$` 包起来（如 `质能方程 $E=mc^2$ 表明……`），独立成段的公式用 `$$...$$` 包起来并单独占一段：

```text
$$\int_0^1 x^2\,dx = \frac{1}{3}$$
```

导出的 PDF 用 amsmath/mathtools 排版，支持分数、上下标、求和、积分、矩阵、`cases` 等常见构造；`$` 需要写成字面字符时用 `\$` 转义。公文文种不支持公式，`$` 在公文里始终是普通字符。

预览与导出的差异要知道：预览由应用内置渲染器即时画出，字形是 STIX Two Math；导出 PDF 由内置 Tectonic 用 TeX 的 CM 数学字体排版，两者字形不同属正常现象，版式尺寸以导出为准。预览渲染器不支持的写法（如公式里夹中文的 `\text{中文}`）在预览里显示为带源码的占位框，导出 PDF 不受影响。含行内公式的段落在预览里按左对齐显示，导出 PDF 仍是两端对齐。

## 使用本机字体编译

排版默认使用随应用分发的内置字体：标题方正小标宋、一级标题黑体、二级标题楷体、正文仿宋、页码宋体。要换成本机装的字体，在“设置 → 编译字体”勾选「使用本机字体编译」，再给五个位置分别选字体，保存后下次导出即生效；某一项留作「内置」就继续用内置字体。屏幕上的公文预览同步切换，所见即所得。

内置 Tectonic 编译时按文件加载所选字体，导出的 `.tex` 拿到别的机器上编译时按字体名加载——目标机器上装了同名字体才能得到一致效果。字体文件后来被删除或卸载时会自动退回内置字体，并在导出结果里给出提示。

列表只收录 `.ttf` 与 `.otf`。字体集合（`.ttc`，例如 `simsun.ttc`、`msyh.ttc`）一个文件里装着多个字面，按文件加载必须额外指定字面序号，未在内置 Tectonic 上验证过，因此不可选；这类字体可另找单字面的 `.ttf` 版本。二级标题字体同时充当正文的斜体字面，改它会一并影响正文里的斜体。

## 生僻字与兜底字体

公文正文用的仿宋、楷体是 GB2312 字库，只有 6763 个汉字，人名里的「喆」「赟」「堃」这类字在它们上面没有字形。程序对所有字体位置都挂了一支兜底字体：排不出的字自动换用它，预览、Word 与 PDF 三端一致，不必配置。内置兜底字体是宋体，覆盖 GBK 全部 21791 个汉字，日常人名、地名够用。

要排 GBK 以外的字（如「𠮟」这类 Unicode 扩展区汉字），在“设置 → 编译字体 → 兜底字体”另选一支字库更大的本机字体即可。这一项不受「使用本机字体编译」开关约束——它决定的是一个字排不排得出来，不是版式；所选字体也漏掉的字，仍由内置宋体接着兜。兜底只在缺字时生效，正常的字一律还用当前位置自己那支字体。

## 词库模板与稿件迁移

词库模板可在“标准词库”页点击「下载空白模板」得到 `.xlsx` 空白模板（仅表头 + 数据验证），填好后用「导入 Excel」按编码优先合并；也可「导出 Excel」备份当前词库。示例配置见 `config.example.json`。运行时配置默认保存在用户配置目录的 `LocalTools/GongwenAssistant/config/config.json`，稿件库为同目录的 `manuscripts.db`。

导出稿件 ZIP 时会随附当前完整标准词库（`vocabulary.json`，含单位、人员与联系方式），拿到另一台电脑导入时，预览页会显示包内词库规模并默认勾选「合并包内标准词库到本机」——按层级编码/姓名增量合并，不覆盖目标机器已有的词条；取消勾选则只导入稿件。旧版稿件包不带词库，导入不受影响。

## 界面字体

界面字体不再随应用打包，Windows 默认为微软雅黑、Linux 默认为 Noto Sans SC，也可在设置中选择其他本机字体。
