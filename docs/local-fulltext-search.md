# 本地全文检索交接

## 第一阶段实现

知识库新增独立 SQLite FTS5 表 `knowledge_local_fts`，每篇全文按 jieba 分词建立一行索引，补充连续汉字单字与二元组，避免专名内部及分词边界漏召回。它与 `knowledge_chunks`、向量 BLOB、embedding 模型状态完全分离；向量重建不会覆盖本地索引。删除文档通过 SQLite 触发器清除全文条目。

外部文件和稿件库收录都在后台线程导入并建立本地索引。打开知识库页时会扫描并后台补建旧数据，进度复用知识库任务条；第一次本地搜索也会再次检查缺失项作为兜底。全文检索默认按钮与 Enter 都走本地路径，原 RAG 检索仍以「语义检索（需模型）」显式调用，问答保持原流程。

普通输入先用 jieba 分词与汉字二元组生成候选词项，再逐个加引号以参数绑定查询；空格分隔的组之间同时匹配，汉字组内允许部分词命中并按 BM25 排序，纯英文与编号组要求各词同时命中；用户输入不会被当作 FTS 运算符。双引号包裹的输入作为明确短语，SQL 中按原文连续短语核验后再截取结果数量，避免先 LIMIT 后过滤导致漏搜。BM25 控制相关度和结果顺序，最多返回 50 篇。原文逐篇读取并裁成有限上下文片段，命中范围直接从原文字面匹配计算，不使用 jieba token 偏移；英文按 ASCII 大小写不敏感匹配。无法在原文定位的 token 不会伪造高亮。结果可复制片段、打开只读原文并定位命中，或另开全文版式预览。

查询最长 256 个字符；检索、分词和旧数据补建均在后台。查询输入或文种过滤变化时清除当前结果，过期后台结果按 query + kind 丢弃。

## 编辑快捷键与人工验收

表格回车、编号层级均由用户键盘操作触发，不调用模型，也不改变解析与导出语法。

1. 不启动模型服务，打开知识库，等待旧材料全文索引补建；搜索只在正文出现的词，查看命中、高亮、复制及原文定位。导入新材料后直接搜索，改标题、删材料、重启后复查。语义检索与问答仍是独立的模型入口。
2. 用空格分隔多个关键词，用双引号查连续原文。试查含六角括号的文号、英文及连字符；输入改变或切换文种后，不能出现旧查询的结果。
3. 在表格单元格的文字后按 Enter，应出现 `<br>`，预览仍在同一格换行；Ctrl+Z 一次恢复。Shift+Enter 保留源码换行。用系统中文输入法和应用内输入法确认候选，不应误插换行。
4. 写 `1. 第一项` 后回车生成空 `2. `，按 Tab 成为第一项子项；输入后回车继续同级。空子项 Enter 或 Shift+Tab 提升，顶层空项 Enter 退出；后续同级编号跟着调整。一次 Ctrl+Z 恢复整次动作。
5. 空 `## ` 标题 Tab 成为 `### `，Shift+Tab 提升；主标题不参与，最深到 `##### `。非空正文、段内编号及代码围栏不触发 Tab 层级编辑。

### 已知范围

- 本地搜索范围是已收录的知识库材料，不扫描整个磁盘，也不执行 OCR。
- 普通汉字关键词允许部分词命中，空格分组要求各组均匹配；需要严格连续匹配时使用双引号。
- 搜索最多返回50篇；超出256字符或32组关键词会明确提示。摘要优先显示首处正文命中，标题独有命中仍可打开全文。
- 列表仅沿用现有两级语义，成品子项仍按段内编号接排；不会生成任意多级列表。
- GUI、真实剪贴板/输入法与实际办公材料库仍需真机验收。

### 本机合成性能样例

调试构建，临时磁盘SQLite数据库，每篇约200余字；查询计时仅包括本地搜索API，不包括打开数据库和GUI渲染。连接冷查指重开连接后的首次查询，未清空系统文件缓存。

| 文档数量 | 导入并建全文索引 | 连接冷查 | 热查 |
|---|---|---|---|
| 1000篇 | 5.29秒 | 4.43毫秒 | 1.61毫秒 |
| 10000篇 | 57.96秒 | 12.75毫秒 | 11.56毫秒 |

来源路径索引补齐前曾测得万篇导入约194秒，但两次运行负载不同，不将其作为严格的性能对比。实际机关材料的长度、表格、词项分布及磁盘性能都会影响结果；真实材料库由人工验收时进一步观察。
