## 一、未提示的明文落盘

### 口径

「提示」只对**释放到普通文件或外部系统**的敏感明文成立：

- 加密导出文档（Word/PDF/源码包/随行单据）不提示；关闭加密后每次明文导出提示；
- 普通工作区（未启用应用锁）的文档导出也提示一次风险；
- 稿件包、批量 PDF 集合、全量备份自带独立密码，不弹明文提示；
- 打印、剪贴板（含文件复制）、另存、系统打开等出口各自确认；
- 加密容器（GWA1/GWA2/SQLCipher/资源 BLOB/密封树）、诊断日志、缓存与临时文件不按
  「明文业务文件」算，但必须加密、权限收紧、可清理。

### 逐类结论

- 文档成品（PDF/Word/Typst 包/Markdown 源码包/随行单据/花脸稿/送批材料合并件/PDF 附件另存/
  写作成果）全部先内存生成、再经 `export/protection` 加密后原子写出；加密失败、缺密码、
  失钥一律 fail-closed，不降级明文。
- 打印与预览：花脸稿预览、附件预览、直接打印全部内存驱动；CUPS 走 stdin，Windows 从
  字节解析，不再生成送打缓存；打印、复制/剪切文本/图片/文件在加密工作区逐次确认。
- 稿件包 / PDF 集合 / 全量备份：7z AES-256 且文件头加密，暂存只写密文；恢复只写密文到
  隔离暂存，换入后强制重新解锁。
- Pi：工作文件、技能快照、用户技能、Durable 会话、交付回执、接口缓存、证据全部 GWA2
  或密封树；Node host 除无业务数据的 owner 锁文件外没有直接写盘；随包 host 与
  `pi-host/src` 逐文件一致，manifest 哈希全匹配。
- 进程转交：只写「端口 + 本轮随机令牌」的 endpoint（0600），旧明文 `inbox` 启动即擦除。

**没有发现**加密工作区里把正文写进新明文文件的出口；也没有发现确认前先建目录、先写
临时件或隐藏清单的路径（确认前不执行导出线程）。

### 已修问题

| 级别 | 问题 | 修法 |
|---|---|---|
| P1 | 帮助手册 PDF 明文写进**配置目录** `help/`，之后全量备份的「内部只许密文」检查会把整份备份永久拒绝；渲染失败还留下 `.pdf.part` 明文残件 | 帮助 PDF 改放用户缓存目录 `help/`；写失败删除残件；备份导出排除 `help/` |
| P1 | 份号清单在**明文导出模式**下退回 `fs::write`（0644、非原子），而注释与文档都声称「原子写 + 0600」 | 非捕获模式改走 `storage::atomic_write`（0600、同目录原子替换）；加密模式仍交内存加密 |
| P2 | 诱饵槽写出的公开帮助截图（`alt-images/`）不在备份明文豁免内 → 备份卡死 | 备份按「名称 + 公开字节」判定，真实槽与诱饵槽同等豁免 |
| P2 | 空白词库模板导出未提示，且数据校验列表含配置里的单位代字 | 加 `PII_EXPORT_WARNING` 确认 |
| P2 | 原子写崩溃残留 `.tmpXXXXXX` 可能是明文配置/密钥副本，迁移扫描不认它 | 启动/锁定清掉超过 1 小时的顶层 `.tmp*` 普通文件（不动在途写入与用户自己的 `.tmp` 后缀文件） |

### 仍是产品边界（不算漏网）

- 系统「打开方式」把成品交给外部 Office / 阅读器：其临时/恢复文件、剪贴板历史、打印队列、
  纸件、模型服务端副本都在应用保护范围外；文档已声明。当前加密工作区没有为「系统打开」
  单独加确认，属可改进项。
- 普通工作区（未启用应用锁）本身就是明文模式；首次跳过的风险确认只做一次，文档口径一致。
- 未解锁状态下崩溃只写不含 panic 原文、路径与环境变量的最小诊断，这是「宁可少诊断也不
  明文降级」的有意取舍。

### 已修问题

1. **P0：停用应用锁后只要第二密码系统用过，重启即进入「锁文件丢失」死局。**
   停用只把当前（真实）槽解成明文并删除 `vault.dat`，诱饵槽的 `alt-*` 密文从此没有
   DEK；重启 `Probe::Skipped + encrypted_data_on_disk(Decoy)` 命中 `lock_lost`，而该页
   只有说明文字、没有任何可操作出口。修法三层：
   - 设置页「停用密码保护」先检查诱饵槽，有加密数据就拒绝并提示先「清除第二密码」；
   - 锁屏提交时再拦一次（防止旧标记/旧版本残留标记）；
   - 停用完成前同时检查两个槽，任一有密文就保留 `vault.dat` 并回到锁屏；
   - 锁屏新增「取消停用，保留密码保护」（撤销密封的停用标记，不改数据）；
   - `wipe_slot_files` 目录名单补 `logs`（诱饵崩溃日志也是旧 DEK 密文，漏删会复现死局）；
   - 失败文案明确「部分数据可能已解密为明文」，并说明取消停用后重新解锁会重新加密。
2. **P1：旧版根目录 `apis.json` 永久明文。** v0.8 之前的数据接口配置写在配置目录根，
   只有打开数据接口页才惰性迁移；不在任何名单里，启用应用锁后仍是明文，并让全量备份
   永久失败。已加入 `SEALED_FILE_NAMES` / `SEALED_JSON_NAMES` / 擦除名单，迁移、锁丢失
   探测、停用解密、备份与 0600 权限自动覆盖。
3. **P1：帮助 PDF / 诱饵公开截图卡死全量备份**：见第一节。
4. **P2：`wipe_slot_files`、迁移、停用解密、锁丢失探测四份目录名单字面量不一致**：本次
   至少把 `logs` 补齐；统一常量仍建议后续做（见剩余项）。
5. **P2：旧图片迁移跟随符号链接**：迁移会读链接目标再覆写删除；`overwrite_then_delete`
   也用跟随链接的 `metadata`。现改为 `symlink_metadata` 只处理普通文件，链接不跟进。
6. **P2：导出设置损坏无法恢复**：`.export-password` 解不开时设置页直接 return，所有文档
   导出被挡且只能手工删文件。设置页新增「重置导出设置…」二次确认（只删这份导出密码
   设置，不影响稿件、登录密码与其他配置）。
7. **P2：`.gwx` 导入暂存副本跨锁定/退出残留**：暂存副本内容加密但文件名沿用原件（明文
   元数据）。锁定、启动、工作区初始化时一并清掉，需要导入时会重新复制。

### 剩余缺口（未在本次修，建议排期）

- **停用不是两阶段**：`decrypt_slot_files` 先把数据库转明文，再逐文件解封/删除；任一失败
  不回滚，磁盘会留下部分明文而 UI 仍显示锁定。已加「取消停用」与失败提示，但彻底修法
  是「全部解到临时副本并验证后再切换」。
- **停用不展开 Pi 虚拟树**：`work-files.json`/`skill-files.json` 只会变成明文 JSON 容器，
  明文模式 host 不读容器；再次启用时同名不同内容会硬失败。需要停用时展开或让明文 host
  也支持容器。
- 锁丢失探测名单比迁移名单窄（根目录 `config.json.损坏-*`、`apis.json.bak`、`.迁移-*` 残留）；
  目录名单四份字面量应提为单一常量。
- 备份恢复换入目录时未释放 `instance.lock` 与资源库全局连接；恢复后到重新解锁之间理论上
  可起第二个实例。
- 迁移失败没有「跳过并只读进入」出口（Pi 超大文件、`apis/` 符号链接等会反复卡在锁屏）。
- 7z 格式无 AEAD：完整性依赖加密头 + 条目 CRC32，不是 AEAD（文档已如实写「内容与文件名
  加密」，建议再补一句完整性边界）。
- 读取侧明文降级：已有密钥句柄时，密封名单里的文件若被替换成明文 JSON 会被直接接受
  （本地写权限前置，属同用户攻击面）；GWA1 旧格式无 AAD 绑定，迁移完成后建议拒绝读取。

## 三、最近提交与密码学实现

### 密码学核对结论（未发现 P0）

- 依赖全部标准实现，没有自研密码学：RustCrypto `aes-gcm` / `argon2`、`lopdf` 的
  V5/R6、`ms-offcrypto-writer` 的 ECMA-376 Agile、`sevenz-rust2` 的 AES-256。
- 随机源：`rand::rng()` / `OsRng` / `getrandom`（DEK、盐、IV、nonce、导出密码生成）。
- 根密钥：Argon2id 64 MiB / 3 轮 / 4 并行、16 字节盐；DEK 随机 32 字节；改密只重裹
  DEK、不碰数据；`vault.dat` 真槽与哑槽同形不可区分。
- GWA2：`magic‖nonce12‖AES-256-GCM‖tag16`，AAD 绑定槽位/用途/逻辑路径；跨槽、跨路径
  替换必失败；每次 seal 新随机 nonce；Node 侧逐字节一致并有固定向量测试。
- PDF：AES-256、标准安全处理器 V5/R6、元数据一起加密、owner=user=独立导出密码，
  不用权限位冒充保密。Word：完整 OOXML Agile 包加密（AES-256-CBC / SHA-512 /
  100000 轮 / HMAC）。7z：内容与文件头均加密、显式 `2^19` 轮。
- 加密导出默认开启、未设密码/设置损坏/失钥都拒绝导出，不降级明文；导出密码与登录
  密码双向拒绝；`.export-password` 由槽位 GWA2 密封，停用应用锁时清除。

### 已修问题

| 级别 | 问题 | 修法 |
|---|---|---|
| P1 | 多条目 7z 复用同一套 AES salt/IV：导出源码包/份号清单、稿件包、全量备份的每个条目与加密头部都共用一组参数，CBC 下会泄露条目之间相同前缀的信息，也与「每条目新盐/IV」的承诺不符 | 每条目、以及 finish 前给头部，各自新建 `AesEncoderOptions`（新随机 salt/IV）；稿件包与全量备份同步修 |
| P1 | 旧 ZIP 格式稿件包导入没有条目数上限：ZIP64 包声明海量条目时 `ZipArchive::new` 先解析整个中央目录，可打爆内存/卡死界面 | 先读 EOCD：ZIP64 标记（0xFFFF）直接拒绝，解析后再卡条目上限；补回归用例 |
| P2 | `export_artifacts` 用 `paths[&p]` 直接索引 HashMap，未来若有产物绕过内存捕获会先 panic（且明文可能已落盘） | 改为 `get().ok_or(错误)`，缺失即整批失败 |
| P2 | `Protection::encode` 扩展名大小写敏感（`报告.PDF` 报「格式不支持」） | 扩展名转小写再匹配 |
| P2 | 备份对操作系统元数据零容忍（`.DS_Store`、`Thumbs.db`、`._*` 会让整份备份失败） | 备份导出排除这些条目（不含用户内容、用户也无法「完成加密」） |

### 列为后续的风险

- Node `owner.mjs` 的锁自愈只凭「文件头像 GWA 或 SQLite 报 not a database」就删锁重建；
  需要本地写权限或磁盘损坏前置，理论上可造成双 host 并发。建议自愈前加持有者探测/超时。
- 单实例回环转交：接受线程单线程 + 1 秒读超时，本机任意进程可反复占住转交；token 比较
  非常量时间。只影响可用性。
- 打印内存化后同一 PDF 在链路上被整份克隆多次，200 MiB 上限下峰值可达数百 MB。
- 用户技能容器把 `Vec<u8>` 直接 JSON 序列化（数字数组，体积膨胀 4–6 倍）；每次读取全量重解析。
- 7z 单条目读取回调返回 SkipBlock 时不校验该条目 CRC（需密码持有者构造，完整性弱化）。
- 导出密码可能含 PDF SASLprep 会规范化的字符（NBSP/兼容字符），与 Word/7z 的原始 UTF-16
  口令不一致；建议导出密码限制在 SASLprep 稳定字符集。
- Rust 侧 stderr scrub 只覆盖模型 API key；DEK 当前只经 stdin 传给 host，建议也加进 scrub 名单。

1. 启用应用锁（含第二密码）→ 进一次诱饵系统 → 设置页「停用密码保护」应被拦下并提示
   先清除第二密码；清除后再停用应正常。
2. 加密工作区：使用帮助 → 生成 PDF → 再到数据备份导出 7z 备份，应成功。
3. 关闭「加密导出文档」后导出带份号的公函：份号清单应为 0600 且原子写（`stat -f '%Lp'`）。
4. 旧 ZIP 稿件包导入、新 7z 稿件包导入 / 导出往返；导出源码包与全量备份用 7-Zip 或
   Keka 打开，确认需要密码且文件名不可见。
5. 锁屏取消停用、导出设置损坏后的「重置导出设置」入口。
