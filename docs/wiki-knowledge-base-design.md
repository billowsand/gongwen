# 维基知识库设计方案（资料库 → 知识库）v2

> 2026-11-10 提案 v2，整合用户详细意见后重写。分类框架来源、编写触发、双层并行、单分类归属、导览页、版本全量保留等口径已确认；待确认问题见 §11。基线 commit `1d7499b`。
> 前置调查：① 知识库现状探查（RAG 资料库实锤）；② Pi 智能体扩展点探查（两种能力均有现成范本）；③ docs/ 历史口径（无维基先例、问答为一次性 `pi_chat` 调用，无冲突）。

## 一、背景与问题判断

现有「知识库」是完成度很高的 RAG 资料库（`knowledge_docs`/`knowledge_chunks`/FTS5，双路召回 + RRF + rerank + 证据台账），但它无组织框架、无条目互链、无页面概念、无审核流、无知识沉淀回路——是资料库，不是知识库。

**产品形态**：现有「知识库」改名「资料库」（存储、检索、导入原样保留）；新建基于维基的「知识库」，由两个 Pi 能力支撑——**维基制作智能体**（建框架、整编页面、持续维护，全程人工审核）与**维基运用工具**（写作时语义导航取知识）。

## 二、已拍板口径

1. **分类框架两级**：主题（一级）→ 分类（二级），分类下不再分层。框架来源两条路：**AI 从现有资料归纳** 或 **用户导入已有框架**（见 §3）。
2. **审核**：每新增/变更页面都必须人工审核；**审核时可直接修改页面正文**（纠正口径），修改后采纳同样留痕。
3. **版本历史**：每次采纳（含审核修改）记录一个不可变版本，可查看、对比、回滚。
4. **链接机制**：Obsidian 风格 `[[页面名]]` 双链；页面背后是唯一 ID，**改名整体跟随**（明面标题、暗面 ID）。
5. **页面视图**：正文内链可点击跳转；每个页面显示**被哪些页面引用**（backlinks）。
6. **删除保护**：被其他页面引用的页面**原则上不能删除**（程序拦截，需先解除引用）。
7. **语义导航**：写作取知识时，智能体做**语义综合判断**——进入某主题页后由它判断是否需要下钻到别的页面，**不是把链接的文档一股脑全拉进来**。链接列表只是候选方向，读哪些由模型结合写作任务决定，程序只设预算上限。
8. **触发**：一期手动发起；AI 在用户指导下持续建设（新增资料提示关联，未整编文档可圈选整编）。
9. **运用范围**：一期只接 Pi 写作；资料库检索与维基双层并行（wiki 不命中可回落 `kb_search`）。
10. **页面归属**：单分类（2026-11-10 确认），跨主题内容靠页面间链接解决。
11. **导览页**：每个主题/分类自动生成一篇导览页，内容同样 AI 整编、可审核（2026-11-10 确认）。
12. **版本保留**：全量保留，回滚也产生新版本（2026-11-10 确认）。
13. **维基阅读版式（2026-11-13）**：正文沿用公文助手 Markdown 的基础切块规则，由维基独立排版。采用宋体正文、黑体小节和连续滚动，保留源码标题层级。页面内链以行内链接显示，未建页通往缺口清单，〔En〕以资料依据标记显示，块引用以单独的引文框呈现。阅读器提供版式预览、只读 Markdown 源码和左右对照，审核台使用同一版式实时预览。
14. **配色跟随主题（2026-11-10 确认）**：知识库界面**不建独立配色体系**，全部颜色取应用主题系统（`src/theme/` 的 Sheet 语义槽位：强调色/面板中性色/语义色），随主题切换（含暗色、Omarchy 跟随）自动整体换色。
15. **控件复用（2026-11-10 确认）**：框架建立/调整界面**复用标准词库页**（[src/app/vocabulary.rs](../src/app/vocabulary.rs)）的成熟交互——层级缩进树、行内「＋」菜单（新增下级/同级）、本级内移动、右侧详情编辑，不新造树编辑控件。

## 三、分类框架

### 3.1 结构

两级：`主题（theme）→ 分类（category）`，分类下直接挂页面。页面归属为**单分类**（口径 10）。主题与分类节点本身各有一篇**导览页**（口径 11，自动存在，内容由整编生成）——这样 Obsidian 链接也能指向主题/分类（如 `[[××工作]]`）。

### 3.2 框架建立的两种来源

**A. AI 归纳（冷启动）**

1. 用户在知识库页点「从资料归纳框架」，发起 Pi 作业（技能 `gongwen-wiki-frame`）；
2. 智能体用只读工具（`kb_search`/`kb_read`）遍历资料库，**归纳主题与分类**：产出框架提案 JSON——主题/分类树 + 每个分类挂靠的依据文档 + 归纳理由；
3. 框架审核界面：树形展示提案，用户可增删改名、拖动调整归属；
4. 确认后框架入库生效。

**B. 用户导入（已有框架）**

1. 用户粘贴或导入大纲（Markdown 层级列表格式，见待定问题 P3）；
2. 程序解析成主题/分类树，用户界面调整；
3. 可选：让智能体把现有资料文档**映射**进分类（建议每篇文档归哪个分类、哪些分类下还空着），确认后生效。

两条路殊途同归：都产出「框架 + 资料初步映射」，进入 §4 的页面整编。

## 四、维基制作流程（核心）

整体是一条「**框架 → 整编 → 审核 → 入库 → 标记 → 维护**」的流水线，全程 Pi 只产提案、程序把关、人工审核：

### 阶段 0：框架建立

见 §3。产出：生效的主题/分类树 + 各分类下的资料文档清单。

### 阶段 1：页面整编

1. **发起**：用户在框架树上选一个分类（或主题），点「整编此页」/「整编本分类」。一次发起覆盖该节点下需要生成的全部页面（分类导览页 + 该分类下的条目页），逐页审核。
2. **智能体工作循环**（技能 `gongwen-wiki-write`，交付 JSON）：
   - 读该分类下的资料文档（`kb_read`），判断该分类应拆成几个主题页（一页一主题）；
   - 逐页撰写正文：自然行文综述，行文中用 `[[页面名]]` 链接相关页面；
   - **链接目标规则**：已有页面/导览页可直接链；资料库里存在但维基还没有的概念，写成**待建页链接**（红链，入库后进入「缺口清单」，提示将来整编）；
   - 每页附**依据清单**：本页内容出自哪些资料文档、各自支撑哪些要点（正文内用来源标记，见 §5.3）；
3. **产出**：页面提案集 JSON（标题、正文、所属分类、出链清单、依据清单）→ 回执 → 确定性复核（链接目标存在或是已登记的红链、依据文档存在、所属分类存在）→ 待审收件箱。

### 阶段 2：审核与入库

- 收件箱逐页呈现：**新页**渲染全文审阅，**改页**显示 diff；
- 审核界面支持**直接编辑正文**（改口径、删错句），编辑与采纳一体；
- 「采纳」→ 程序写库：页面入库（或生成新版本），登记解析后的链接边，依据清单落成**资料文档确认标记**；
- 「退回」附意见，可重新发起。

### 阶段 3：版本与回溯

- 每次采纳产生不可变版本（正文快照 + 来源运行 + 是否经人工修改）；
- 页面可查看版本列表、任意两版对比、回滚到旧版（回滚也产生新版本）。

### 阶段 4：持续维护

- **新增资料入库时**：程序按分类/检索比对，提示「可能关联的维基页」，用户可发起「按新资料更新」（一期仅提示，手动发起）；
- **资料库列表**：每篇文档显示「未整编 / 已用于维基」标记（由确认标记派生）；用户可圈选未整编文档反向发起整编；
- **缺口清单**：待建页红链、无页面覆盖的分类，都是维护入口；
- **治理**：断链检测、空分类提示、删除保护（§5.2）。

## 五、页面与链接机制

### 5.1 页面身份

- 页面 = **唯一 ID（UUID）+ 显示标题**。正文链接写 `[[标题]]`（可加 `|显示文字`）；
- 程序按 ID 解析链接，**标题改名全库跟随**；新标题与现有页面重名时提示；
- 页面必须挂在某个分类下；主题/分类导览页与普通页同构，只是归属特殊。

### 5.2 链接边与删除保护

- 入库时程序解析正文链接，维护 `wiki_links` 边表（出链）；backlinks 由边表反向查询，无需额外存储；
- **被引用的页面禁止删除**（程序拦截）；删除前需先处理引用或强制改链；
- 资料文档删除时，引用它的页面列入「需复核」清单（不自动改）。

### 5.3 溯源（依据清单）

- 每页有「本页依据」：资料文档列表 + 各文档支撑的要点；正文关键陈述带来源标记（如 〔E3〕，对应证据编号）；
- 采纳时逐条校验依据文档存在；**这是维基内容可信度的根基**（错误会长期污染写作，溯源 + 人工审核是唯一兜底，不放宽）。

## 六、维基运用（写作时的语义导航）

### 6.1 语义导航原则（已拍板）

写作需要知识时，智能体按语义综合判断取料，不是机械拉取全部链接：

1. **入口**：`wiki_search`（按写作任务语义检索页面，含标题与摘要）或直接读给定页；
2. **阅读**：`wiki_read` 读页面全文或段落；
3. **下钻判断**：模型结合「已读内容 × 写作任务」自行决定是否读下一页；`wiki_links` 只给出链候选（标题 + 一句话摘要），**不是必读清单**；
4. **溯源到原文**：页面信息不够细时，`wiki_doc_read` 按页的依据清单读原始资料文档的对应段落；
5. **兜底**：仍不足时回落 `kb_search`（资料库全文检索）。

### 6.2 预算与护栏

- 维基工具设**独立小额度**（建议 12 次/轮，待定问题 P4），与写作工具额度分开，防遍历挤占写作预算；
- 每次命中自动登记证据台账，交付闸门只认台账；
- 全程只读，写作作业不需要为此开新作业类型。

## 七、技能框架

### 7.1 撰写侧（Pi 作业，不占写作门禁，范本 = 任务助手作业）

| 技能 | 职责 | 交付 | 一期 |
|---|---|---|---|
| `gongwen-wiki-frame` | 从资料归纳框架 / 整理导入框架并映射资料 | 框架树 JSON | ✅ |
| `gongwen-wiki-write` | 页面整编（读料→拆题→成页→链接→依据） | 页面提案集 JSON | ✅（先只新建） |
| `gongwen-wiki-update` | 按新资料更新已有页（diff 提案） | 页面更新 JSON | 二期 |

三个技能共用同一作业链：手动发起 → Pi 作业 → JSON 回执 → 确定性复核 → 待审收件箱 → 人工审核（可编辑）→ 界面线程写库。复用 `kind=task` 回执模式，协议不动。

### 7.2 使用侧（只读领域工具，接进写作作业）

| 工具 | 职责 |
|---|---|
| `wiki_search` | 语义检索页面（标题/摘要/FTS） |
| `wiki_read` | 读页面全文/段落 |
| `wiki_links` | 列出页面的出链候选（标题+摘要），供下钻判断 |
| `wiki_doc_read` | 按页的依据清单读原始资料文档段落 |

登记模式照 `kb_search`/`kb_read`（`src/pi_agent/tools.rs` 三处 + `bridge.mjs DOMAIN_TOOLS`），证据台账自动生效。

### 7.3 接入写作任务

- 写作技能（6 个内置技能）的提示与 references 增加取料路径说明：**先维基（语义导航）→ 再原文（wiki_doc_read）→ 兜底资料库检索**；
- 写作、维基整编与更新、任务助手可使用四个维基只读工具；框架归纳只浏览资料库，风格作业保持独立；
- 写作页 `@` 提及可引用维基页（待定问题 P5）。

## 八、数据模型

挂在 manuscripts.db（SQLCipher 自动覆盖），照 `src/manuscript.rs` 的 DDL 模式（knowledge 系列表同款）：

- `wiki_nodes`：框架节点（id、parent_id 可空、name、kind：theme/category；两级约束由程序保证）；
- `wiki_pages`：id（UUID）、title、node_id（归属分类）、kind（normal/guide）、status、current_version、created/updated_at；
- `wiki_page_versions`：id、page_id、version、body 快照、source_run_id、review_edited（bool）、created_at；
- `wiki_links`：from_page、to_page、to_node（导览页/红链目标）、link_text、resolved（红链未建为 false）；
- `wiki_doc_refs`：page_id、version_id、doc_id、支撑要点——**资料文档「已用于维基」的确认标记**挂在版本上；
- `wiki_category_docs`：已确认的分类与资料映射，供整编取料，和生效页面的依据分开保存。
- 资料库侧：`knowledge_docs` 不加列，「未整编/已用于维基」由 `wiki_doc_refs` 派生。

## 十二、风险与已知坑

- **幻觉积累**：维基错误长期污染写作；靠 §5.3 溯源 + 每页人工审核兜底，不建议放宽；
- **链接腐化**：页面改名靠 ID 解决；资料文档删除触发「需复核」清单；
- **遍历成本**：语义下钻由模型自主，预算上限（§6.2）防失控；
- **审核负担**：每页必审 + 整编一次出多页，审核界面效率是关键（逐页卡片、依据对照、可编辑）；
- **旧数据**：现有 knowledge_docs 全部保留为资料库，无迁移；「未整编」标记从零开始累积。

### 待确认的设计取舍

1. **何时让条目参与自动取证。** 当前以人工审核和原文仍存在为门槛。新资料入库只提示，不自动推翻已审核口径。若业务资料常有失效日期或版本替代，建议明确「生效 / 待复核 / 已替代」的状态和适用时点，再决定问答对冲突口径的处理。
2. **审核台是否跨重启保留。** 当前待审批次和编辑草稿在会话内保留，锁定或退出后不恢复。建议先确定是否需要持久收件箱和退回意见。若需要，草稿与意见应进入加密存储，与生效版本分开。

4. **历史链接语义。** 回滚恢复旧正文和依据。旧正文里的链接按现有链接图重新解析；若目标曾改名且当前页面已移除旧链接，旧关系可能无法自动找回。若要求回滚也恢复原目标身份，需要按版本保存链接目标，并定义目标页面已被删除时的展示方式。
