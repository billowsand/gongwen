# 标准词表身份引用与同名消歧：整体修复方案

> 2026-10-30。状态：整体修复已实现，回归与样张检查见第十节，待用户 GUI 试用。前九节保留设计依据，第十节记录最终实现。
> 目标：单位、人员按身份关联，名称只用于检索与显示；不能确定身份时明确留待核对，绝不猜配。

## 一、现状与根因

已核对下列实际调用链，不能只修词库树或下拉框标签：

| 位置 | 当前行为与风险 |
| --- | --- |
| `models/vocabulary.rs` | 有本机 `u64 id`、单位层级编码、人员所属单位；人员 `code` 只在单位内唯一，并不是全局人员身份 |
| `units.rs::relocate_entry` | 移动单位时改写整个子树编码及人员所属单位；层级编码不能独自承担永久身份 |
| `draft_page/form.rs::unit_pool` | 候选值与上级仍传规范名称，编码只参与检索；同名候选无法区分 |
| `app/widgets.rs::SelectOption` | `value` 按规范名称保存；新增默认名称也按全词库查重，未按父节点区分 |
| `units.rs::UnitDisplay::find` | 先找编码，再取第一个同名单位；旧字符串同时可能是编码和名称 |
| `units.rs`、`draft_page/form.rs` | 人员候选退化为“姓名、电话”，部分收集按姓名去重，丢失人员身份 |
| `element_fields.rs::person_phone_of` | 单位内按姓名找不到后，回落全词库第一个同名人员，可能带错电话 |
| `units.rs::reporting_leaders` | 按所选姓名扫描全部人员，同名者可能一起进入称谓合并 |
| `vocabulary_xlsx.rs::merge` | 人员按“单位＋姓名”合并，而不是人员编码；同单位同名人员可能被覆盖 |
| `element_fields.rs`、`ai_panel/field_card.rs` | 建议值、校验与排序仍依赖名称，单改人工表单无法覆盖 AI 采纳路径 |
| `task_ui/owner.rs` 等 | 任务负责人已有本机词条 ID，但跨机与其他姓名匹配入口仍须一起审计 |

## 二、身份模型与唯一性规则

### 2.1 身份编码和层级编码分开

- 每个单位、每个人员增加永久全局身份编码（UUID），分别用 `UnitId`、`PersonId` 类型封装。
  本机整数 `id` 可继续服务树形界面，不能进入跨机身份判断。
- 单位现有 `code` 保持用户可见的业务／层级编码；人员现有 `code` 可保持单位内编号，
  界面同时提供永久人员身份编码。不能把人员的 `01` 当作全词库唯一编码。
- 改名、排序、调动、改业务编码均不改变永久身份。父单位、所属单位以 `UnitId` 关联；
  现有编码列只作兼容读写与显示，不再靠编码前缀推断已经明确存下来的父子关系。
- 对新格式，显式父身份与编码层级矛盾时报冲突，不静默重挂。旧 Excel 没有父身份时，
  仍按旧规则还原树，再进行完整校验；新导出补充身份编码和父单位身份编码列。
- 删除后新建的同名、同业务编码条目取得新身份，不复用被删除身份。

这样既满足“按编码区别”，也避免单位一移动、人员一调动，已保存稿件便指向别处。

### 2.2 单位名称约束

- 单位唯一键是 **父单位身份＋去首尾空白后的规范名称**。顶层共用虚拟根，同名顶层禁止新增。
- 同父节点禁止重名，不同父节点允许重名，不要求深度相同。祖先与后代同名也允许。
- 规范名不做简繁、内部空格或近似字的自动归并。外部名、简称、别名允许重合，交给消歧，
  它们都不是身份键；别名不能绕过规范名的同级查重。
- 新增、改名、移动、批量导入、词库合并共用同一校验器。移动到目标父节点前查重；
  整批操作校验最终结果，失败不部分写入，也不能由 normalize 自动改名或合并。
- 检查身份重复、单位业务编码重复、人员所属单位内编号重复、父引用缺失、自指、环和深度上限。
  编码大小写沿用现有精确比较规则，检索忽略大小写不能改变身份判断。

### 2.3 人员规则

- 同名人员在不同单位，甚至同一单位，都允许独立存在；只禁止身份重复或同单位人员编号重复。
- 候选、选中、去重、排序、电话、职务、权限、负责人绑定全部按 `PersonId`。
- 相同姓名、电话、职务都不能作为“是同一个人”的证据。相同身份通过多条祖先路径出现才去重。
- 人员调动保留身份，更新所属单位；既有稿件的姓名、职务、电话及归属快照不随之自动改变。

## 三、公文表单与关联查询

### 3.1 单一写入数据源

新增带版本号的结构化要素引用：单位字段用 `UnitRef`，人员字段用 `PersonRef`，
多值用有序数组。引用包含永久身份和选择时的名称／编码／祖先路径等快照。
人员快照另含所属单位、职务、电话；单位快照包含实际输出需要的外部名、简称、代章和代字信息。
引用显式区分“已绑定”“旧值待核对”“人工文字”，不能用一个字符串兼容所有语义。

旧 `TemplateProfile` 文本字段作为旧格式读取与兼容展示内容，不再与新引用各自可写；
新格式以结构化引用为唯一来源，经适配器给旧调用方显示文字。不得先把编码塞进原字段，
再让尚未迁移的预览或导出把编码印到纸上。旧格式缺省时不写出新增空字段。

覆盖发文、联合发文、主发文、主送、抄送、落款、承办、呈报领导，以及联合承办逐行联系人；
会议纪要名单／分送／印发等词库选择入口、电话记录、签收单、模板默认值也逐项清点。
纯手填字段保留文字语义，不能因文字与词库相等就暗中绑定。

### 3.2 单位与人员联动

- 单选／多选候选分别携带身份值、显示标签、检索字段、父身份，检索结果点击后写身份。
- 主送／抄送／发文的既有互斥、联合主单位有效性、份数统计、排序均按单位身份，
  两个同名不同单位不得互相剔除。同一单位在多个合法角色出现仍只是一种身份。
- 承办联系人按所选 `UnitId` 及显式祖先链过滤，保留现有“允许承办上级单位”权限规则；
  呈报领导按落款单位及祖先单位身份收集。单位已定而无合格人员时显示空候选，不回落全词库。
- 选定人员后直接取该 `PersonId` 的电话、职务，不再用姓名二次查找；取消全词库同名兜底。
- 切换承办单位：原联系人仍符合权限则保留，否则清除人员绑定，处理其自动带出的电话并提示。
  手改电话要记录为人工覆盖，不能与自动电话混用；关联变更时明确标记待核对。
- 联合承办以一条结构化记录保存“单位引用、人员引用、电话及覆盖状态”，
  不再以两串名称的下标作为新数据配对依据。旧版按索引配对只存在于兼容迁移。
- 词库变更后，当前稿提示“词条已更名／调动／删除，可核对更新”，不得静默替换。
  更新快照仍走用户操作与 `element_fields::apply_field`，连带修改支持整体撤销。

## 四、名称显示与逐级消歧

### 4.1 两个明确的比较范围

1. **选择界面**：在完整候选池中计算唯一标签。搜索、过滤、勾选不能让同一候选的标签跳变。
   树中可显示本级名称，但收起值、检索结果、已选标签必须有足够上级信息；旁列业务编码。
2. **公文纸面**：一次收集整份稿件实际出现的单位身份，涵盖发文、主送、抄送、落款、承办版记、
   印发、分送和其他实际输出的单位位。先计算一份显示计划，再供预览、Word、PDF、签收单等共用。
   不得每个字段各算各的。只在正文自由文字中出现的名称不自动改写正文。

同一身份多处出现不算同名冲突；不同身份使用规范名、外部名、简称后相同，都算冲突。

### 4.2 算法

1. 按输出用途取基础显示名称（规范名／外部名／简称），按身份去重后比较最终文字。
2. 对冲突项加入最近父单位名称；仍冲突再加入祖父，直到足以区分。
   例如“办公室”→“教育局办公室”→“甲市教育局办公室／乙市教育局办公室”。
3. 每轮同时扩展冲突组，并重新比较**全部结果**，处理“新拼出的名称恰好撞上另一单位原名”。
   浅层节点用尽祖先后保持当前结果，其他冲突项继续扩展；相同输入集合与词库快照得到相同结果。
4. 不把显示前缀写回词库规范名；对已有完整前缀只在整段前缀确实一致时避免重复，
   不以任意子串猜简称边界。拼接仍有歧义时，界面用“上级 › 本级”明确分隔。
5. 到根后仍无法区分（例如外部名路径全部相同），界面再附业务编码／永久身份编码；
   正式纸面提示无法唯一表达，要求核实对外名称，或由用户确认本稿的明确显示文字，
   不能默认把内部 UUID 印进公文，也不能导出两处无法区分的单位名。
6. 现有主送／抄送前缀省略必须服从消歧计划：不得删掉用来区分身份的祖先；
   拼接、省略、简称等全部完成后再验证各身份的可区分性，失败回退更完整名称。

### 4.3 人员显示

同名候选显示“姓名 · 职务 · 已消歧的所属单位”，还不能区分则附人员编号／身份编码。
正式输出通常仍印姓名；同一输出中确有同名人员，则补单位、职务等可理解的限定信息。
同一单位同名同职务无法区分时要求用户核对显示称谓，不能擅自编造。
呈报领导的姓氏＋职务合并只在不损失身份区分时使用；同姓或同名冲突时回退完整姓名，
仍冲突则补单位，不能把两个不同人员压成一个“张主任”。

## 五、AI 与其他调用方

- 词库查询返回带类型的身份编码、业务编码、完整路径、可读名称，名称搜索返回候选数组；
  多项命中不取第一项。人员搜索保留所属单位和人员身份，不能按姓名压平。
- 摘录仍必须来自材料原文；程序把摘录解析为身份：唯一且符合字段范围才能生成建议，
  有歧义则给带单位路径的选择题。模型不能凭空生成编码以绕过摘录与范围检查。
- `FieldSuggestion`、选择题答案、已确认信息、建议卡去重／过期／排序／撤销均保留身份引用；
  同名不同身份必须判为实际变更。词库改动后采纳前再次校验身份、类别、归属权限。
- 保持 AI 三条红线：授权类要素不建议不出题；描述类只在用户采纳时由界面统一写值。
- 旧会话／检查点中的名称建议迁移不唯一时失效并提示重新选择，不能继续按同名取首项。
- 任务负责人等现有本机 ID 使用者迁到同一永久身份契约，避免词库导入重分配本机 ID 后串人。
  词库别名替换工具遇到多身份对应同一别名时，不得自动选定其中一家。

## 六、导入、同步与旧数据

### 6.1 词库合并

- 新格式优先按永久身份匹配；相同身份但类别不同、父属冲突等进入显式冲突处理。
- 无永久身份的旧单位按唯一业务编码匹配；旧人员按“所属单位身份＋人员编号”匹配，
  编号缺失时，姓名仅产生待确认候选，不自动覆盖。改名不能被解释成另一个人，
  同名也不能被解释成同一个人。同编码不同身份要求人工关联，不能覆盖身份。
- 不同机器独立录入的同一现实单位会有不同 UUID，提供明确关联／合并操作及映射记录；
  不能以同名或同码自动宣告等价。业务编码冲突在落库前解决。
- 新导出保留 UUID 和显式父属身份。旧 Excel 导入仍兼容，预检报告列行号、路径、编码和冲突原因。
  合并在暂存数据上校验最终集合，通过后整体替换；词库与稿件跨存储变更用可恢复迁移记录衔接。

### 6.2 旧稿与迁移

1. 备份并扫描配置、模板、活稿、会话、任务负责人及词库交换数据；输出可统计的迁移报告。
2. 对现有有效词条一次性分配并持久化永久身份，重复运行不重新编号。本机整数 ID 只在本机映射。
3. 对旧格式明确区分来源：已知编码字段按编码解析；已知名称字段按名称解析。
   不能通用地“先当编码试，再当名称试”，以免某单位名称恰好等于另一单位编码。
4. 名称唯一，且满足字段范围时可建立迁移候选；人员还需核对所属单位，
   有历史电话等证据冲突时也不能自动绑定。多个候选、无候选、同级重名均保留原值并标待核对。
   只显示路径或电话供人判断，不以推测最高分自动配对。
5. 存量同级重名不自动删除、改名、合并或改挂根节点；提供修复清单。
   结构冲突期间禁止依赖该冲突范围的新绑定，其他无关有效节点仍可使用。
6. 活稿迁移结果通过可恢复流程保存。已提交、同步版本和归档快照保持原始字节及校验值，
   不原地重写旧 `payload_hash`；旧版本仅以兼容视图读取，用户核实后在新版本保存新引用。
7. 新版本携带选定身份和输出所需快照（包括消歧所需的祖先路径）。历史版本导出、送批归档、
   花脸稿对照使用该版本快照，不查当前词库临时补名字或电话。
8. `.gwx`／旧 ZIP 往返即使不合并词库，也能按稿件快照显示；对方词库缺项时保留外来身份，
   不按本机同名条目接管。新包标明能力／格式版本，旧程序不能假装无损读写新引用。

删除词条保留稿件引用快照及失效状态，不级联删除稿件要素。历史版本未包含身份的旧歧义无法
凭程序恢复事实，应明确标出限制；涉及正式导出时要求人工核对，不能给“已自动修复”的假保证。

## 七、实施分期与交付边界

| 期次 | 改动与完成条件 |
| --- | --- |
| 1. 身份与数据契约 | 永久身份、显式父属、统一索引／唯一性校验、迁移报告、导入暂存合并；旧数据可读且不丢条目 |
| 2. 人工填写全链 | 结构化字段、单位／人员候选、联合承办、电话／权限／互斥、模板和任务负责人；同名项能独立选择保存重开 |
| 3. 显示与历史输出 | 整稿消歧计划、全载体统一显示、版本快照、同步／送批／归档兼容；同名样张和两机往返通过 |
| 4. AI 与收尾 | AI 查询、抽取、澄清、建议卡、旧会话处理、帮助与词库格式说明；人工与 AI 采纳得到相同身份结果 |

各期可以单独验证，但新格式写入／重名能力须等所有消费链适配后统一启用，不能中途发布
“表单存了身份、导出还按姓名”的混合状态。必要时用内部能力开关，最后一期再开放。
实现后更新本文交接，并同步要素填写、离线同步、送批材料相关设计说明及帮助。
如涉及正文语法或词库使用的技能说明变化，再同步技能包与其规定检查。

## 八、验收矩阵

- **单位**：同父重名新增／改名／移动／导入均拒绝且无部分修改；异父、异深度重名均成功；
  顶层重名、规范名与编码撞字、任意业务编码、改码／移树后引用不串。
- **人员**：跨单位同名、同单位同名同职务／同电话均能分别选；多路径人员只按身份去重；
  选择乙单位张三只带乙的电话和职务，候选为空不显示其他单位人员，调动与撤销不串。
- **表单**：单独／联合发文、主发文、主抄互斥、多个承办条目、呈报领导、名单、版记、
  份数、人工电话覆盖、切换文种、模板套用、存盘重开、词条删除再新增全覆盖。
- **消歧**：两级／三级祖先重名、不同深度、祖先后代同时选、拼接结果撞已有全称、外部名／
  简称重合；同名分散在发文与抄送、落款与承办版记也必须区分；搜索标签稳定，
  原有前缀省略不得重新制造歧义；同姓领导不能被错误合并。
- **旧数据与交换**：迁移幂等、失败恢复、旧字段名称／编码碰撞、无法消歧不取首项、
  同名不同人员导入不合并、同身份改名不新增人、不同机器本机 ID 相同不串；
  带／不带词库的 `.gwx` 往返、版本分叉与合并、旧 ZIP、旧会话重开。
- **历史稳定性**：词库改名／移树／改码／调人／改电话／删除后，既有提交版和归档输出不变，
  原版本校验值不变；三方合并把身份与其快照作为关联整体，不能拼成甲身份乙电话。
- **AI**：同名材料出澄清题，非法身份不采纳，同名不同身份卡片不去重，
  权限或归属变化后旧建议过期；授权字段维持只读。
- **输出**：预览、DOCX、Typst PDF、签收单、送批合并和花脸稿对照使用同一身份及显示计划。
  排版变动前读 `docs/typst-engine.md`，生成 `typst_samples`，目视检查长前缀的换行、版记与红头。

按实际改动运行 fmt、check、Clippy、相关回归与全量测试；沙箱预期失败单独记录，
不为消除环境失败改业务规则。最终 GUI 验收用一份至少包含两棵同名单位子树、
同单位同名人员和跨单位同名人员的固定词库，从选择、保存、AI 建议一直走到打印样张。

四期功能已经贯通，不分阶段开放半套身份引用。

### 实现与方案的具体调整

- 永久身份为 UUID；本机整数 ID 继续用于树形界面。`VocabularyEntry.identity` 为身份，
  `owner_identity` 为父／所属单位身份。原业务编码继续作为可读编号与旧交换格式的兼容列。
- 为兼容既有表单控件、多值编辑、版本 JSON 与成对承办条目，字段内使用带类别的身份引用
  `@unit:<uuid>` / `@person:<uuid>`，多值仍由统一 split/join 接口维护；没有另外建立可独立
  写入的“名称值＋ID 值”两套状态。`TemplateProfile.vocabulary_snapshot` 持有词条与祖先
  快照，形成引用与显示适配层。没有额外引入 `UnitId` / `PersonId` 新类型或重建所有字段为数组。
- 无法唯一解析的旧值使用保留原文的待核对标记。选择框显示原文和待核对提示，导出不允许
  把失效身份或内部编码印到正式纸面。普通词库外手填文字仍可按现有规则显示。
- 新格式父关系以永久父身份为准，允许业务编码不以父编码开头；旧 Excel 仍由最长编码
  前缀还原树。移动任意编码子树时按真实父关系分配新业务编码，不再要求原编码可切前缀。
- 词库更名、移动、改电话不自动更新稿件快照；用户重新选择时刷新该项及其祖先。
  切换承办单位导致原人员不合格时清空该配对的姓名与电话，保留其他联合承办行。
- 纸面没有增加内部 UUID 后缀。补齐祖先仍不能区分的对外名称，以及同单位同名同职务且
  纸面仍无法区分的人员，提示维护可区分用名后再导出；没有增加“本稿名称覆盖”编辑器。
- 迁移不重写已提交、归档或同步版本的原始快照／哈希。活稿在编辑入口补齐唯一引用；
  首次配置身份补号原子保存并留备份，旧坏关系保留供核对，不因迁移校验失败启动成空配置。
  迁移提示在词库与表单内显示，没有另设独立报告窗口。
- `.gwx` 清单 schema 升至 3（仍读 1、2）；随包词库 schema 升至 2（仍读 1）。
  旧程序拒绝新格式，避免不认识身份字段后无损回写的假象。三方合并继续复用已有
  文种＋整份 profile 的原子合并，因此不会把甲身份与乙电话／祖先快照拼在一起。
- 任务负责人增加永久身份数据库列，启动及数据库恢复时补旧本机绑定，已有身份绝不
  按姓名或被复用的整数 ID 重绑。AI 要素建议、题目动作、词库工具、建议卡已贯通身份；
  正文缺口的文字候选仍保留文字语义。AI 红线与采纳入口保持不变。
