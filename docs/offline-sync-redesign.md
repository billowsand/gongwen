# 离线稿件身份识别与版本合并：方案与交接

> 本文两部分：前半是方案原文（需求结论），后半是实施进度、与方案的出入和已知坑。
> 每完成一段，更新「实施进度」。

## 总结

沿用加密 ZIP 做多台电脑间的往返同步。**稿件身份、版本身份、内容相等是三件不同的事**：
标题和文号只用于提示候选，不能据此自动认定同稿；各电脑的数据库整数 `id` 也不再用于跨库去重。

| 导入结果 | 判定与处理 |
| --- | --- |
| 同一稿件、同一版本 | 稿件 UUID、版本 UUID 和内容校验值均一致；跳过重复导入 |
| 同一稿件、不同版本 | 有共同版本，且一方是另一方的后续版本；预览后确认更新 |
| 同一稿件、发生分叉 | 找到共同祖先，生成三方合并预览；冲突由用户处理 |
| 身份不明 | 仅列出相似候选，由用户确认关联；没有可靠共同祖先时不自动合并 |

## 关键改动

- 给稿件增加持久的全局 UUID；给每个不可变版本增加 UUID、父版本关系和基于行文要素、
  Markdown 正文、备注计算的 SHA-256 校验值。版本号保留作本机显示序号，不作为同步依据。
  同 UUID 却有不同校验值时拒绝导入并报错；内容相同但版本 UUID 不同，标为“内容相同、历史不同”。
- 将现有线性版本历史迁入可记录两个父版本的历史结构。ZIP 新格式携带所选稿件的完整版本祖先、
  当前工作稿和资源；旧格式仍可读取。导出前保存当前打开稿件的最新编辑内容，并建立
  **不显示为提交版本**的同步检查点，让两台电脑随后各自修改时仍能找到共同基线。
- 合并对原始 Markdown 做保留空白和标记的三方比较：不重叠的修改可进入候选结果；
  同一位置的不同修改标为冲突。行文要素按字段比较，相互依赖的字段成组处理
  （文种+方案、日期+自动开关）。花脸稿用于展示结果，不充当合并算法。
  状态变化单独提示；PDF 附件按内容去重、只增不自动删除。图片及历史版本引用的资源随包校验，
  遇到同路径不同内容时不得覆盖本机文件。
- 导入预览逐篇给出判定、共同基线、两侧变化和合并后的全文。**任何更新都须用户确认后写入当前稿件**；
  确认分叉合并时生成一个可见的合并版本，记录两个父版本。用户可明确选择“暂存待处理分支”，
  保持当前正文不变，日后继续处理。已归档稿件保持不可修改；不同内容只能明确另存为具有新身份的稿件。
- 旧 ZIP 或两个独立身份的稿件可由用户人工关联。若找不到内容完全一致的历史快照作为基线，
  只提供人工对照与选择，不推测共同祖先。导入先完整校验包及所选稿件，再提交数据库和资源变更；
  失败不得留下部分合并结果。

## 验收

- 用两套独立数据库验证：相同整数 `id` 的不同稿件不会误合并；同一 ZIP 重复导入幂等；
  A→B→A 往返能识别相同、落后、更新和分叉。
- 覆盖正文独立修改、同一行冲突、仅空白或 Markdown 标记变化、行文要素冲突、工作稿未提交、
  归档稿、旧 ZIP 人工关联，以及同名不同内容的图片与 PDF。
- 合并预览逐项核对后，再运行现有解析、要素校验与文字复核；确认保存、撤销或暂存分支后，
  历史和正文均能重新打开并正确导出。

## 约定

本期处理误判、误覆盖与包损坏，不提供人员或设备签名认证。词库仍按现有独立选项合并，
不参与稿件版本身份。方案依据仓库 `main` 的现有导入和版本结构实施。

### 代码地图

- `src/manuscript/sync.rs`：身份与版本图。`manuscripts.document_uuid`（唯一索引）
  + `sync_revisions`（UUID 主键、parent1/parent2、payload_hash、visible_number
  为空即“不显示的同步检查点”）+ `sync_aliases`（人工关联的别 UUID）+
  `legacy_imports`（旧包内容指纹幂等）+ `pending_sync_heads`（暂存分支）。
  `migrate` 把旧线性 `manuscript_versions` 逐条迁入版本图，工作稿与最新版本
  内容不一致时补一个检查点；schema 升到 user_version 8。
- `src/manuscript/merge.rs`：保守三方合并（纯函数）。Markdown 用 `similar`
  逐行（保留空白）diff 后按「变更是否重叠」聚块：不重叠进候选结果，重叠且两侧结果
  不同标冲突；要素是 JSON 树三方合并，文种+方案、日期+自动开关两组成组；
  `MergeProposal::manual` 用于无共同基线时整份交给用户。
  `resolve(choices)` 按 要素→备注→正文 的顺序取侧，正文可整体手工改写覆盖。
- `src/manuscript_io/sync.rs`：`inspect` 逐篇判定关系
  （New/Same/Equivalent/LocalAhead/IncomingAhead/Diverged/NoBase/Legacy/Archived），
  共同祖先用 LCA（多个 LCA 判 NoBase，不推测）；`import_with_actions` 先重读清单、
  校验清单哈希、图片/PDF 校验值与同名冲突，SAVEPOINT 包裹全部写入，失败回滚并
  清理已落盘的图片；`inspect_pending`/`merge_pending` 是暂存分支的恢复入口。
- `src/manuscript_io.rs`：ZIP schema v2（完整版本祖先 + `assets` 图片清单带
  SHA-256），导出原子写（临时文件 + persist），v1 包仍可读；导出新格式前
  收集活稿与全部历史版本引用的图片，缺图拒绝导出。
- `src/app/manuscript_ui.rs`：导入预览逐篇「查看与处理」——判定、共同基线、
  本机/导入内容哈希、按关系给出动作按钮（跳过/新稿/采用导入版/合并为新版本/
  暂存分支/关联并暂存/另存副本），冲突逐项勾选 + 合并后全文预览 + 手工调整；
  稿件详情页列「待处理导入分支」，可打开合并对话框继续处理；
  `save_open_manuscripts_for_zip` 导出前先把打开标签的脏工作稿写库
  （非草稿则拒绝导出）。导入更新后自动刷新起草页打开的同稿标签。

### 与方案的出入（有意为之）

1. **暂存分支的恢复入口在稿件管理详情页，不是起草页版本时间轴**。
   归档稿不能进起草页，详情页对两种稿件一视同仁；时间轴集成留待后续。
2. 合并冲突的「正文」允许整体手工改写（`markdown_override`），不只逐项取侧——
   用户核对合并后全文时的自然诉求。
3. `src/storage.rs` 增加了 `#[cfg(test)]` 测试接缝 `set_test_config_dir`，
   仅测试用，生产行为不变；图片相关导入测试在临时目录跑，不碰真实配置目录。

### 测试覆盖（`manuscript_io::sync::round_trip_tests` 与 `manuscript::merge::tests`）

两套独立库往返（新→同→落后→更新→分叉→合并）、相同整数 id 不误合并、
同 UUID 不同校验拒绝、本机较新（工作稿未提交）、同内容状态变化单独采用、
归档稿只另存新身份、旧 v1 包幂等 + 人工关联不推测基线、同行文冲突暂存后
恢复为双父可见合并版本、同名不同内容图片拒绝且不部分写入、同内容图片不触碰、
PDF 内容去重只增不删同名改名、仅空白 + 仅标记变化的干净合并（合并结果过
`export::parse_markdown` 并可再导出被对侧识别）、要素独立合并与同字段冲突取侧、
要素成组（文种+方案、日期+自动开关）、备注三方合并。

### 已知坑

- `ImportSummary` / `import_zip` / `collect_image_entries` / `source_ids` 降为
  `#[cfg(test)]`：旧按 `source_id` 去重的导入路径只服务存量测试，正式导入全走
  `sync::import_with_actions`。
- v2 导出要求活稿与全部历史版本引用的 `images/` 图片都在本机存在，缺一张即拒绝导出
  （方案的明确取舍）；旧稿图片已被手动删掉时会卡在导出，需先清理历史版本引用。
- 图片冲突检查在本机文件名层面（`images/<名>` 同路径不同内容拒绝），不做内容寻址重命名。
- `config_dir` 测试接缝是进程级 Mutex，图片测试合并为一个用例内部顺序执行两个场景，
  避免并行测试争抢覆盖；新增依赖 config_dir 的测试时注意这一点。
