# 送批材料：方案与交接

> 本文两部分：前半是方案（需求结论），后半是实施进度、与方案的出入和已知坑。
> 每完成一期，更新「实施进度」。

## 总结

呈批件（白头件、红头呈批件）送领导审批时，后面往往还跟着几份独立的件：要发的函稿、
相关的普通公文、支撑用的研究报告等。「送批材料」就是给呈批件挂上这些随行件，
在一个面板里统一看它们的版本情况，并**一键按顺序合并成一个 PDF** 用于打印装订。
某个件改了不用重新整理，重新导出即可。

**随行件不是附件。** 呈批件正文里 `<!-- [附件] -->` 标记的附件是主件的一部分，
照旧随正文排版；随行件是稿件库里另外的独立稿件，不在呈批件正文里标注、不加
「附件N」标识，版式与它单独导出时完全一致。

| 需求结论 | 取舍 |
| --- | --- |
| 名称 | 「送批材料」，避开「附件」二字，免得与正文附件混淆 |
| 能挂送批材料的主件 | 仅白头件（`WhitePaper`）、红头呈批件（`RedHeadApproval`） |
| 随行件来源 | 仅稿件库内的稿件；外部 PDF（来文扫描件）、Word 本期不做 |
| 引用关系 | 引用而非拥有：同一稿件可同时挂在多个主件下 |
| 嵌套 | 只有一层：挂着随行件的稿件不能被当作随行件，被当作随行件的稿件不能再挂随行件 |
| 导出取哪一版 | 每个件（含主件本身）一律取**最新提交版**；工作稿里未提交的修改不进包，醒目警告 |
| 导出后又有新版本 | 下次导出直接用最新版本，只做提示；导出记录不锁定内容 |
| 归档 | 主件归档时把各随行件**钉在确定的版本**上——这是「一律用最新版」的唯一例外 |
| 版式 | 各件独立页码；每件从奇数页起（自动补空白页），双面打印后可拆开分别装订 |
| 目录页 | 可选，导出时勾选 |
| 面板信息 | 各件最新提交的版本号、提交时间、提交说明；另有「有未提交修改」「上次导出后有新版本」两类提示 |
| 离线同步 | 导出同步 ZIP 时默认连同随行件一起打包 |

## 关键设计

### 1. 数据模型

建表沿用候选区、词表的做法：在 `migrate()` 末尾幂等建表，不单开 `user_version` 档位。

```sql
-- 主件 → 随行件清单。主件用本机 id（随主件删除级联清除）；
-- 随行件用稿件全局 UUID（document_uuid），不用本机整数 id，
-- 这样同步到另一台电脑、或随行件尚未导入时，关联都不会断。
CREATE TABLE IF NOT EXISTS send_package_items (
    owner_id              INTEGER NOT NULL REFERENCES manuscripts(id) ON DELETE CASCADE,
    item_uuid             TEXT    NOT NULL,
    sort_order            INTEGER NOT NULL,
    -- 仅主件归档时写入：钉住的版本（sync_revisions.revision_uuid）；平时为 NULL，表示跟最新提交版
    pinned_revision_uuid  TEXT,
    added_at              TEXT    NOT NULL,
    PRIMARY KEY (owner_id, item_uuid)
);
CREATE INDEX IF NOT EXISTS idx_send_package_items_item ON send_package_items(item_uuid);

-- 导出记录：每导出一次合并 PDF 记一条。只记本机，不进同步包（含本机文件路径）。
CREATE TABLE IF NOT EXISTS send_package_exports (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_id     INTEGER NOT NULL REFERENCES manuscripts(id) ON DELETE CASCADE,
    exported_at  TEXT    NOT NULL,
    output_path  TEXT    NOT NULL,
    with_toc     INTEGER NOT NULL DEFAULT 0,
    total_pages  INTEGER NOT NULL
);
-- 每次导出里每个件（含主件本身，sort_order = 0）的身份与版本。
-- title/kind 冗余保存：稿件以后改名、删除，记录仍能读懂。
CREATE TABLE IF NOT EXISTS send_package_export_items (
    export_id      INTEGER NOT NULL REFERENCES send_package_exports(id) ON DELETE CASCADE,
    sort_order     INTEGER NOT NULL,
    document_uuid  TEXT    NOT NULL,
    revision_uuid  TEXT    NOT NULL,
    payload_hash   TEXT    NOT NULL,
    visible_number INTEGER,
    title          TEXT    NOT NULL,
    kind           TEXT    NOT NULL,
    page_count     INTEGER NOT NULL,
    blank_pages    INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (export_id, sort_order)
);
```

- `item_uuid` 解析为本机稿件时走现有的 `find_document_uuid`（含别名表 `sync_aliases`），
  离线合并过身份的稿件照样能找到。找不到的显示为「本机未找到该稿件」，保留关联，
  不自动删除——对方的同步包导入进来后自然恢复。
- 版本、校验值全部复用离线同步的不可变版本图（`sync_revisions` 的 `revision_uuid`、
  `payload_hash`、`visible_number`），不另起一套。

### 2. 「最新提交版」与「未提交修改」的判定

- **最新提交版**：该稿件当前历史线上最新的可见版本（`visible_number` 非空），
  与版本面板里显示的「最新版」一致。
- **有未提交修改**：活稿行（`manuscripts`）按 `payload_hash` 算出的校验值与最新提交版不同。
- **尚无提交版本**的稿件（新建后从未提交）不能进包：导出前拦下，提示先提交。
- 有待处理的同步分支（`pending_sync_heads`）时额外警告：包里用的是本机这一支。

### 3. 引用规则

- 主件只能是白头件、红头呈批件。主件改成别的文种时清单数据保留、面板隐藏，
  改回呈批件后恢复；改文种前若挂着随行件，提示一句。
- 随行件可以是任意文种，但须满足：不是主件自己；本身没有挂随行件；
  已被当作随行件的稿件不能再挂随行件（选择器里直接不列出或置灰并说明原因）。
- 同一稿件在同一主件下只能出现一次（主键保证）。
- **删除保护**：删除一篇被引用的稿件前，列出引用它的主件并二次确认，确认后连同关联一起删除；
  被**已归档**主件钉住的稿件不允许删除（钉住的版本随稿件级联删除会让归档材料缺件）。

### 4. 界面

- **入口**：起草页打开呈批件时，工具栏增加「送批材料」；稿件库里呈批件的详情同样可进入。
- **面板**：主件排第一行（固定，不可移动），下面是随行件，可拖动排序、移除、在新标签中打开。
  每行显示：文种、标题、最新提交的版本号、提交时间、提交说明。行尾提示：
  - 工作稿有未提交修改 → 标红「有未提交修改，导出将使用 vN」；
  - 上次导出后该件又提交过新版本 → 淡色提示「上次导出用的是 vM」，点开用现有花脸稿
    对比 vM 与当前版本（版本对照视图已具备，只需按 revision_uuid 取两份快照）。
- **添加**：从稿件库选择，可按标题、文号搜索，按文种过滤；不符合引用规则的稿件不可选并说明原因。
- **随行件的反向引用**：任一稿件的详情里显示「被以下呈批件引用」。
- **导出记录**：面板底部列出历次导出（时间、文件、总页数），展开可看当时每个件的版本。

### 5. 合并导出

1. **导出前确认清单**：列出每个件将使用的版本；有未提交修改、尚无提交版本、
   本机未找到、存在待处理分支的件分别醒目标出。存在「尚无提交版本」或「本机未找到」时不能导出。
   可勾选「前面加目录页」。
2. **逐件编译**：每个件按选定版本的快照（`snapshot` + `content_markdown`）编译，
   走与单独导出相同的路径与版式，出非盖章件 PDF。现有 `compile_record_pdf` 只能编译活稿行，
   需抽出一个按快照编译的变体供两处复用。盖章件（`pdf_attachments`）本期不参与合并。
3. **合并**：主件在前，随行件按清单顺序依次接上；每个件（及目录页）的页数为奇数时，
   在其后补一张与末页同尺寸的空白页，保证下一个件从奇数页开始。各件页码保持各自原样，
   不重排。合并需新增依赖 `lopdf`（MIT，与 GPL 兼容）；`hayro` 只负责渲染，不做合并。
4. **目录页**（可选）：用 TeX 单独排一页，字体与正文一致；列出序号、名称、文种、密级、版本号、页数（2026-10-03 加密级列，取各件所用版本的密级）。
5. **原子输出**：任何一个件编译失败，整个导出失败，不生成缺件的半成品。先写临时文件，
   成功后改名到目标路径（沿用 `export_selected_pdfs` 的做法）。
   默认文件名「<主件标题>（送批材料）.pdf」。
6. **记录与打印**：成功后写一条导出记录；完成提示里提供「打印」「系统打开」，
   打印复用 `print_pdf`。

### 6. 归档钉版

主件从草稿或发布转为归档时，给每个随行件写入 `pinned_revision_uuid`：

- 默认钉在**最近一次导出记录**里该件的版本，也就是实际送出去的那一套；
- 从未导出过，或某随行件是导出后才加的，钉在归档时的最新提交版；
- 最近一次导出之后有件提交过新版本时，归档确认框列出差异，由用户选
  「钉在送出时的版本」或「钉在当前最新版本」。

归档后清单只读（不可增删、排序）。之后导出一律用钉住的版本，不再提示「有新版本」。

### 7. 离线同步

- **导出**：同步 ZIP 选中的稿件里有主件时，导出对话框默认勾选「连同送批材料一起导出」，
  把随行件作为普通稿件（含完整版本祖先）一并打包。清单写进 manifest：
  `owner_uuid`、`item_uuid`、`sort_order`、`pinned_revision_uuid`。导出记录不进包。
- **导入**：清单随主件的判定一起处理——主件被跳过（同版本）则清单不动；
  主件确认更新时，清单一并采用包内的；主件分叉合并时，两边清单若不同，
  在导入预览里整体二选一（本机 / 包内），不做逐项合并。
  归档主件的钉版随包带来，所钉版本须在包内或本机存在，否则按包损坏处理。
- 旧 ZIP 没有清单字段，按空清单读取。

## 验收

- 引用规则：主件文种限制、不能引用自己、嵌套被拦、同一主件下不重复；一稿多引时反向引用正确。
- 导出：三个件、页数分别为奇 / 偶 / 奇时，补白页位置正确，每件首页都落在奇数页；
  勾选目录页时目录页同样补齐。任一件编译失败时不生成输出文件、不覆盖已有同名文件。
- 版本：随行件工作稿有未提交修改时，导出内容等于其最新提交版而非工作稿；
  从未提交的稿件拦下；导出记录里的 `payload_hash` 与所用版本一致。
- 导出后随行件提交新版本：面板出现提示，花脸稿对比的两端正确；再次导出使用新版本。
- 归档：默认钉在最近一次导出的版本；有差异时的选择生效；归档后清单只读、导出用钉住的版本；
  被钉住的稿件不能删除。
- 同步：带清单导出 → 另一套数据库导入，关联完整、顺序一致；随行件缺失时显示「本机未找到」，
  补导入后恢复；旧 ZIP 可读；主件分叉时清单二选一生效。

## 约定

- 本期不做：外部 PDF / Word 作为随行件、盖章件参与合并、逐件加「代拟稿」等标注、
  随行件在包内改版式、跨件连续页码。
- 送批材料只是组织和输出，不碰任何件的正文与行文要素，不涉及 AI，不影响三条红线。

### 第一期：数据层

代码在 `src/manuscript/send_package.rs`（`ManuscriptStore` 的子模块，与候选区同样做法）。

- 三张表在 `migrate()` 末尾幂等建表；导出记录两张表本期只建表，读写在第三期。
- 接口：`send_package_items` / `has_send_package_items` / `send_package_referrers` /
  `send_package_add_block`（返回 `AddBlock`，带 `reason()` 供界面置灰说明）/
  `add_send_package_item` / `remove_send_package_item` / `reorder_send_package` /
  `latest_committed_revision` / `send_package_item_state`（最新提交版、有无未提交修改、
  有无待处理分支）。
- 删除保护接在 `delete` / `delete_many` 的事务里（`detach_before_delete`）：
  `delete` 原先不走事务，现在改为事务内先摘关联再删行。
- 测试 10 个，覆盖顺序、排列校验、引用规则（含嵌套两个方向）、一稿多引、归档只读、
  删除摘关联与拒删（含批量整批回滚）、主件删除级联、别名解析与本机未找到、版本状态。

**与方案的出入**

- 删除保护比方案更严：方案写「被已归档主件**钉住**的稿件不能删」，实现为「被**已归档**
  主件引用就不能删」，不看是否钉版。钉版要到第四期才有，这之前归档的主件没有钉版记录，
  按原写法随行件照样能删，归档材料就会缺件。
- 「最新提交版」取 `sync_revisions` 里 `visible_number` 最大的一行；它与
  `manuscript_versions` 的最新版本号一一对应（提交与导入落地时两边同时写）。

**已知坑**

- 依赖要求 rustc 1.95；Linux 沙箱没装 GTK 开发库时，用
  `--no-default-features --features linux-portal-dialogs` 编译测试。

### 第二期：面板界面

面板在 `src/app/send_package_ui.rs`（`manuscript_ui.rs` 已超 3000 行，不往里加）。
第一期模块顶部的 `allow(dead_code)` 已删。数据层补了 `manuscript_brief`：只读
标题、文种、状态三列，不像 `get()` 那样连 PDF 附件的 BLOB 一起读。

- **入口**：起草页「开始」页签第一组（保存、提交版本旁）的「送批材料」，只在白头件、
  红头呈批件下出现，没存库时置灰（`DraftAction::OpenSendPackage`）；稿件库详情卡
  「送批材料（N）→ 管理…」。
- **面板**：主件固定首行；随行件每行显示文种、标题、最新提交版（版本号、名称、时间、
  说明）与状态，行尾打开 / 上移 / 下移 / 移出清单。提示三种：有未提交修改（含起草页里
  还没存库的改动）→「导出将使用 vN」；从未提交 →「不能进包」；有待处理同步分支。
  本机找不到的随行件照常列出，只能移出。已归档主件整份只读。
- **状态刷新**：面板每 3 秒自动重读一次（查询都很轻），也可手动刷新；清单变动后
  顺带刷新稿件库详情卡。
- **添加**：候选区按关键词、文种筛选，最多列 200 条；不合引用规则的置灰，悬停显示
  `AddBlock::reason()`。条件或清单变化才重查。
- **详情卡**：呈批件显示送批材料清单与「管理…」；被引用的稿件显示「用作以下呈批件的
  送批材料」，点标题打开那件呈批件的面板。
- **删除确认**：单篇删除气泡列出引用它的呈批件（说明删除后会从中移除）；被已归档
  呈批件引用的，气泡说明原因且不给确认键。批量删除把这类稿件像归档稿一样跳过并计数。
- **改文种**：挂着随行件的呈批件改成别的文种时，状态栏提示清单暂不显示、改回即恢复
  （只在切换那一刻查一次库）。

**与方案的出入**

- 最初排序只用上移 / 下移按钮；2026-10-03 补上 `egui_dnd` 拖动手柄与边缘自动滚动，随后取消了上下移按钮，只留拖动；行内打开 / 移出按钮改为鼠标悬停该行才显示。
  主件不参与拖放，归档清单只读；松手后复用 `reorder_send_package` 事务保存，拖动期间暂停
  定时刷新。`Esc` 或列表外松手取消；排序后重新生成已打开的导出确认计划，防止沿用旧顺序。
  使用与 egui 0.35 匹配的 `egui_dnd` 0.16，0.17 发布包已依赖 egui 0.36，不能直接升级。
  拖动或按钮排序后可撤销上一次排序；按 UUID 核对当前清单，增删或外部排序后失效，
  不覆盖后来的清单变化，撤销也会更新导出确认计划。
  自动化验证：5 项真实 egui 指针事件 / 内存库测试通过，覆盖双向拖动、取消、归档只读、
  顺序落盘、导出版本保持与撤销冲突保护；fmt 与 clippy 全目标检查通过。
- 「上次导出后有新版本」的提示和花脸稿对比要依赖导出记录，挪到第三期与导出一起做。

### 第三期：合并导出

- **数据层**（`src/manuscript/send_package.rs`）：`send_package_plan` 生成导出计划——
  主件在前、随行件按清单顺序，每件取钉住的版本（第四期写入）或最新提交版的完整快照，
  取不到的记 `PlanBlocker`（从未提交 / 本机未找到 / 钉住的版本缺失）。导出记录读写
  `record_send_package_export` / `send_package_exports`。
- **导出编排与合并**（`src/manuscript_io/send_package.rs`）：`export_send_package`
  逐件编译（编译函数由调用方注入，正式走 `manuscript_io::compile_snapshot_pdf`，
  即从 `compile_record_pdf` 抽出的按快照编译）→ 可选目录页 → `merge_pdfs` 合并 →
  临时文件改名落盘。任一件失败整体失败，不留半成品、不动已有同名文件。
- **合并细节**：页面挂到新页面树前先把从上层节点继承的 `Resources` / `MediaBox` /
  `CropBox` / `Rotate` 落到页面上（XeLaTeX 常把它们放在页面树节点上，不落就丢尺寸和
  字体）；奇数页的部分后补一张与其末页同尺寸的空白页，**最后一部分不补**；原文件的
  书签、命名目标等文档级结构不保留。
- **目录页**：当成一篇普通公文走现有管线（`plaindocument` 只有密级、标题、正文），
  正文是「序号 / 名称 / 文种 / 版本 / 页数」管道表加一句合计；密级沿用主件，免得涉密
  材料的标题印在不标密级的纸上。先编各件拿到页数，最后编目录页、放在最前面。
- **界面**（`src/app/send_package_ui.rs`）：面板底部「导出合并 PDF…」→ 生成计划、
  显示确认清单（每件版本、未提交修改含起草页未存库改动、待处理分支、不能进包的原因，
  可勾目录页，可「重新检查」）→「选择位置并导出」弹保存框 → 后台线程编译合并，面板
  底部显示进度（`WorkerResult::SendPackage`，导出中算 `any_busy`，界面按时刷新）→
  成功后写导出记录、在应用内 PDF 标签打开成品（打印、系统打开、定位都在那里）；失败
  原因完整显示在面板里。计划在主线程生成、快照随计划交给线程，确认之后再提交的版本不会混进来。
  同一时间只跑一个导出；导出中关掉面板照常跑完、照常记账。
- **上次导出后有新版本**：面板每件对比最近一次导出记录里的版本号，不同就提示并给
  「对照 vM → vN」按钮，打开现有的版本对照窗（花脸稿）。
- **导出记录**：面板底部折叠区列出历次导出（时间、页数、是否含目录、文件），展开看当时
  每件的版本与页数，文件还在就能直接打开。
- 面板开着时每 3 秒叫醒一次界面（`request_repaint_after`），否则界面空闲不重绘，自动刷新
  形同虚设（第二期漏了这点）。

**与方案的出入**

- 完成后没有另做「打印 / 系统打开」提示，直接在应用内 PDF 标签打开成品，那里本来就有
  打印（Windows 走原生对话框、Unix 走 `lp`）、系统打开、定位。
- 最后一部分后面不补空白页：没有下一件需要从奇数页开始，补了只会多印一张白纸。
- `lopdf` 原本就在依赖树里（间接依赖），这次只是直接声明，`Cargo.lock` 没有新增包。

**验证与已知坑**

- 测试：合并（顺序、补白位置、继承属性下沉、横向页后的空白页同为横向）、编排（编译顺序、
  目录内容与页数、记录字段）、整体失败不动已有文件、目录页 TeX 走普通公文且表格被解析、
  计划取提交版而非活稿行、钉版与缺件、记录往返。
- 用 LibreOffice 与 ReportLab 产出的真实 PDF 合并后，经 hayro 逐页渲染核对过字体与图形完好。
- **沙箱里没有 TeX 运行时，真实的公文编译 → 合并整条链还没在真机上跑过。**接手第四期前
  先在装有运行时的机器上导出一份「白头件 + 函稿 + 研究报告（+ 目录页）」核对：各件版式与
  单独导出一致、补白位置、目录页表格与密级。
- 研究报告自带的目录超链接、PDF 书签在合并后失效（文档级结构不保留），打印不受影响。

### 第四期：归档钉版与同步携带

**归档钉版**

- 新表 `send_package_owner_pins`：主件自己也要钉（清单表里没有主件这一行）。导出计划
  的主件同样先读钉版。
- `archive_pin_preview` 列出主件与各随行件「送出时的版本」（最近一次导出记录）和
  「当前最新提交版」；`archive_with_send_package(id, PinChoice)` 在一个 SAVEPOINT 里写
  钉版并归档。默认 `PinChoice::Exported`：钉送出时的版本，没导出过的件（含导出后才加的）
  钉最新提交版；`Latest` 反之。有件两者都没有（从未提交、本机找不到且没导出过）就整体拒绝。
- 稿件库的「确认归档」一律走 `archive_with_send_package`，没挂送批材料时就是普通归档。
  归档确认框列出每件将钉的版本，送出后有件改过时给两种钉法单选；有钉不住的件不给确认。
- 面板：已归档主件的各行显示「钉住 vN」，不再提示未提交修改与新版本；说明文字改为
  「导出时每件取归档时钉住的版本」。

**同步携带**

- `ManifestRecord.send_package: Option<SendPackageSnapshot>`：呈批件（以及改过文种但仍挂着
  随行件的）一律带上，空清单也带——对方据此知道这边清空了；为空时不写出，旧包兼容。
- ZIP 密码框加「连同呈批件的送批材料一起导出」（默认勾）：所选主件的随行件并入导出范围
  （`with_send_package_items`），导出前一并保存它们在起草页里开着的工作稿。不勾时只带清单。
- 导入：新建 → 原样带清单（归档主件连同钉版）；另存副本 → 带清单不带钉版；采用导入版 /
  合并 → 按 `take_package`；跳过、暂存分支、本机已归档 → 不动清单。清单在整包稿件落库后
  统一 `replace_send_package`（同一导入事务）。只有连状态一起采用且导入侧是归档时才带钉版。
- 导入预览：两边清单不同时，「采用导入版 / 生成合并版本」下多一个勾选「送批材料清单也采用
  导入版（本机 N 件 → 导入 M 件）」；动作是跳过或暂存时给一行说明。
- 测试（`send_package_sync_tests`）：带随行件往返（顺序、钉版、归档状态）、只带清单时显示
  本机未找到并在随行件导入后恢复、内容相同清单不同时默认不覆盖且勾选后替换、钉版只随归档
  状态走、无清单记录的序列化与旧版一致。

**与方案的出入**

- 删除保护维持第一期的「被已归档主件引用就不能删」，不看是否钉版（钉版只是版本，引用关系
  才决定归档材料缺不缺件）。
- 方案写「所钉版本须在包内或本机存在，否则按包损坏处理」，实现为**照常导入、钉版保留**：
  不勾「连同送批材料」时随行件本来就不在包里，按损坏拒收会让这种正常用法没法走。钉住的
  版本找不到时，导出计划报「归档时钉住的版本在本机找不到」，补导入随行件后自然恢复。
- 同步导入不按本机引用规则拒收清单（只剔掉指向主件自己的项与重复项）：数据在对方机器上
  已经过规则检查，拒收会丢数据。两台机器分别改清单，理论上可能导入出「嵌套」的清单，
  目前不处理。
- 清单增删不产生版本，所以「谁新」只能靠人判断，见上面 `take_package` 的默认值。
