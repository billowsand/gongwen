# 内置审校规则适用性审核（2026-10-08）

本次审核覆盖校对词表、硬编码文档规则、要素/结构校验、审校界面、采纳自检和智能体检查入口，并对照公文处理条例与标点符号标准。只新增审核记录，未修改运行代码。

## 一、结论

目前确实存在未在管理界面列出的内置规则，也存在能够直接从代码推导的误报。根因有四个：

1. `TemplateKind` 混合了版式和文类：白头件、红头呈批件、普通公文不是具体法定文种。代码却把前两者统一当作请示，后者统一当作非请示。
2. 多数检查扫描全文字符串，没有识别正文、转述、直接引文、附件各自的语义边界。
3. 将语料风格偏好表述成普遍规范，例如破折号至多一次、强制词至多五次、冒号不能用于列举。这些不宜作为默认审校条件。
4. 管理页只管理词表，硬编码规则另外运行，同名分组的关闭操作不能覆盖它们。

应按「模板能力 × 实际文种/材料类型 × 行文方向 × 文本区域 × 稿件状态」确定适用性。只按当前八个模板分组仍会误报。

## 二、哪些规则没有显示

- `proofread-lexicon.tsv` 当前有 **155 条**种子词条，管理页通过 `Lexicon::resolved` 展示、编辑和启停。这部分是可见的。
- `src/proofread_rules.rs` 有 **21 个 `RULE-*` 编号**，另有一个导出时成文日期提醒。管理页没有它们的规则目录、适用范围、触发条件或启停入口。
- `src/validator.rs` 的要素、结构、会议议程、日期、研究报告检查也未以规则目录展示；它们直接返回提示字符串。
- `src/draft_page/form.rs:696` 注释明确说明文档规则不进词表；`src/app/proofread_ui.rs:111` 的管理数据源仅为词表。

结果抽屉可以看到已经命中的文档规则，并可以逐条忽略；这不等于规则在管理页可见。永久忽略按「规则来源编号＋命中原文」保存，也不是按文类停用整条规则。AI 的 `check.proofread` 直接运行检查，不读取修订面板的忽略名单；采纳后必错自检同样直接运行规则。需要明确区分「不再展示某次命中」和「规则不适用」。

帮助文档 `assets/help/09-proofread.md` 和对应 `docs/help/09-proofread.md` 仍称有25条文档规则，与本次统计口径不一致；管理代码文件头仍称141条词条。建议后续从规则目录生成数量，减少文档漂移。

## 五、可见词表也存在适用性问题

词表 `Lexicon::check(&str)` 没有 `DraftInput` 或文类参数，因此所有启用词条对所有文类统一运行。管理页能看到，不代表条件足够精确。

- `FML-003` 对“特此请示”总是提示；`FML-004` 对“请阅示”总是提示。宜作为可选单位习惯或结语建议，不能暗示其他写法一律不规范。
- `FML-007/008` 针对“我觉得/我认为”；`FML-014` 针对“综上所述”。电话记录原话、讲话稿、研究结论和报告总结应有不同适用条件。
- `TYP-010 曾强`、`TYP-070 其它`、`TYP-056 起动` 等按裸子串认必错，存在人名、专业术语、异形词偏好与上下文边界风险。例如“曾强同志”会命中“曾强→增强”。不能把全部词条的“必错”视为零歧义。
- `TYP-066 惟一→唯一` 的“现行规范词形”说明需重新核验。教育部历史答复明确指出《第一批异形词整理表》未整理这组；不能据此表宣称必错。此处建议标记来源待核验，不直接作当前规范结论。
- `GRM-011 免费赠送` 等语义冗余判断需要语境；与确定错字分开，避免被批量必错采纳。

建议先逐条核验必错词条的证据和命中边界，再补文类范围。分文类不能解决人名裸子串误替换。

## 六、建议的文类分工和界面

保留现有版式模板，另外提供明确的「正文类型」，由人选择或确认：函、请示、报告、通知、纪要、制度/办法、讲话/经验材料等；电话记录、会议议程、研究报告保留专门检查集合。无法确定的旧稿默认类型未知，只运行确实通用的检查，不从版式强推请示/报告。

| 类型 | 默认检查重点 | 默认不套用的规则 |
|---|---|---|
| 函 | 函的要素、商洽/询问/审批语义、附件引用、标题与实际文种 | 非请示文种一律禁止请求、通用词频配额 |
| 请示 | 请求事项与结语、本稿行文对象、事实来源；一文一事需语义核验 | 按结语次数认多事、要求唯一固定结语 |
| 报告 | 报告事项、是否夹带本稿审批请求 | 强制增加请示结语 |
| 通知/制度/办法 | 执行对象、职责、时限、条款结构 | 强制词配额、统一限制冒号列举 |
| 电话记录 | 来电要素、通话时间、原话与拟办意见边界 | 公文标题“关于”、原话行文方向、按今天转换原话日期 |
| 会议议程 | 时间地点、参与人、议程事项顺序；明确标示所选模板限制 | 公文结语、一般行文风格检查 |
| 研究报告 | 报告结构、公式、图表、交叉引用、文献 | 法定公文标题限制、请示结语、事务材料风格配额 |
| 讲话/经验材料 | 明确错字、事实核对、所选风格提示 | 第一人称禁用、普遍禁止总结句 |

管理页增加「文档规则」和「要素/模板规则」目录。每条显示编号、名称、依据、适用文类/方向/区域、级别、触发例子、排除例子，以及当前稿件是否适用和原因。可以只读展示强制规则；无需为了可见性让用户关闭真正的事实和授权要素闸门。

风格提示允许按文类启停，停用必须同时作用于编辑复扫、AI `check.proofread`、合并预审和采纳自检的数据源。强制规则与风格提示应分清；修改的是不正确的适用判定，不是迁就模型放宽闸门。

还需同步 `src/prompt.rs:177` 起的 `style_guide`：当前提示词限制“必须/应当/不得/严禁”合计2处，而审校只数“必须/严禁”并允许5处，两边标准已冲突；呈批模板的起草提示也强制请示结语。否则只修审校，模型仍按错误的通用偏好起草。涉及语法/文种规则时同步 `skills/gongwen-markdown/`。

## 七、验证与实施顺序

已运行 `cargo test --locked proofread_rules::tests -- --nocapture`，**34项通过**。这证明现有预期仍成立，不能证明适用性正确：当前测试主要检查能否命中和单篇函件样例，缺少跨文类排除案例。本次未运行全量测试、未修改代码、未完成 GUI 真机验收。

建议实施顺序：

1. 修正呈批报告被当请示、公函审批请求、研究/记录标题、敬称误命中和附件数量语义，补正反例。
2. 引入实际正文类型与区域上下文，统一各检查入口；对类型未知的旧稿保持保守。
3. 建立规则目录，展示不可编辑规则的依据与范围；风格提示按文类选用。
4. 清理必错词条边界、提示词冲突和帮助文档，再做 GUI 验收。

回归至少覆盖：同一文本在函/报告/请示/电话记录/研究报告下的不同预期；主文与附件独立编号；引用内容含请求结语；“贵阳市财政局”；一个附件印3份；“附件10万元预算表”；长制度出现多次“必须”；报告“综上所述”；签发旧稿重导。每类都需要应报和不应报的对照。

## 八、规范依据

- [《党政机关公文处理工作条例》（工信部转载）](https://www.miit.gov.cn/xwdt/szyw/art/2020/art_6afb8ee6d07540dcacccbeb47dbc0fd4.html)：第八条区分报告、请示与函，函可请求批准；第九条标题构成及成文日期；第十四、十五条行文关系、一文一事和报告不得夹带请示。
- [GB/T 15834—2011《标点符号用法》（上海交通大学医学院转载标准全文）](https://www.shsmu.edu.cn/yywz/info/1026/1526.htm)：4.7规定冒号的提示/总结用途；4.10规定破折号的多种用途，不能推出程序的篇级数量配额。

## 九、本次实施进度（2026-10-08）

按第七节顺序，第 1 步与若干可独立落地的第 2、4 步项已完成，全部改动带正反例测试。

### 已落地

- **文种由标题认，不从版式推。** `proofread_rules` 与 `validator` 都新增「标题末尾自称的
  法定文种」判定：呈批件、白头件、普通公文不再被当成请示。`validator` 的「妥否，请指示」
  只在标题自称「请示」时要求，自称报告或文种不明时不再强加（文种不明只给一条「请确认」提示）。
- **RULE-KIND-REQUEST 收紧。** 只在正文自报为报告、通知、通报、公告、通告、纪要、决定等
  非请示性文种、且结语确属本稿时才报；函的审批请求、电话记录转述、引文里的结语均排除。
- **标题规则按文类分流。** 研究报告题名、电话记录单标题、会议名称不再套公文标题规范；
  书名号、引号内部的标点豁免。文种一致检查只对「模板＝法定文种」的公函、电话通知生效。
  删去通用「关于」检查（RULE-TITLE-GUANYU）。
- **RULE-HONOR-ATTACHED 收紧并降级。** 正则改为带捕获组、限定中间 1–5 字，排除跨短语
  匹配（「贵单位负责联系市财政局」）；词库确认完整机构名之前只给「疑似」，不再以必错提示。
  敬称与自称规则改在正文区运行，附件表单与直接引文不判。
- **附件语义拆分。** 「份」是印制份数，不再与内嵌附件种类数比较；RULE-ATTACH-COUNT 只认
  「附件 N 项／件」与完整编号清单。RULE-ATTACH-REF 要求引用动词，并在金额、数量单位前止步
  （「附件10万元预算表」不再是附件 10）。
- **数字与序号。** 汉字年份、请求结语只扫正文区并跳过引文；层级序号在小数点后接数字时
  不认第三层（「1.5亿元」），并在新标题、附件标记处重置，跨区段不延续。
- **撤销冒号揭晓规则（RULE-PUNCT-COLON）**：GB/T 15834 允许用冒号提示下文，通用禁用判据
  不成立。
- **开篇空表态只报本机关。** 「党中央高度重视」这类历史陈述不再当空表态。
- **要素校验口径。** 方括号年份只查「某办函[2026]012号」形态的文号，不再扫任意 `[2026]`；
  电话记录、研究报告不查相对日期（原话与引用语境不改）；会议议程的提示语改为「当前模板
  要求」，删去另加一条「未完全符合骨架」的重复判定。
- **起草提示词与审校对齐。** `style_guide` 的强制词配额由「四词合计≤2」改为与审校一致

  结语，改为按行文方向区分。

## 十、对上述修订的复审与续修（2026-10-08）

复审结论：第一轮修订解决了部分模板误判，但不能视为审核事项全部完成。特别是结语仍只认
“妥否，请指示”、附件说明被解析成零项、块引文未排除、风格配额仍默认运行，以及起草提示词
和外部技能仍禁止正确冒号等，存在实际缺口。本次在原修订之上继续修改，未提交或发布。

### 本次补齐

- 新增 `proofread_rules/context.rs`，要素校验与文档规则共用主标题识别和正文掩码。
  主标题不取自附件或块引文；保护附件、表格、块引文和直接引语，支持附件后 `[正文]`
  切回，掩码保持原文字节长度，建议仍能准确定位。未知标题不从呈批版式推断请示。
- 呈批请示兼容“妥否，请批示”“当否，请指示”“特此请示”“请予批准”等请求性结语。
  引文或附件中的结语不能替主文满足检查。夹带请求只查本稿独立结语，研究与电话记录排除；
  多个结语只提示重复，不再根据次数推断一文多事。
- 附件说明“附件：情况表”“附件：3份”和空标签不再宣称有零项。只有从1起连续编号才认
  项目清单；金额和印制份数不是项目序号。数量或引用与内嵌内容冲突改为疑似，因为检查器
  没有完整的另行随附清单，不能把“未内嵌”断言成“没有”。
- 敬称检查排除贵阳、贵港、贵溪、贵定地名；语气检查只对句起直接要求给疑似，避免
  “上级要求你局”“督导组要求市政府”等第三方叙述误报。称谓混用只提醒核对对象，
  不再以相同机关后缀断言同一对象。词库中其他专名和复杂转述仍需更精细的上下文支持。
- 自动日期仅对正式公函、白头件、红头呈批件导出提醒；手定日期、预览版和无该日期槽的
  类型不提示。成文日期不叫“过期”，也不建议把历史材料日期按导出当天重算。
- 新增 `proofread_rules/catalog.rs`：管理页展开「文档规则与要素校验」可查看
  **19条正文规则＋1条导出日期核对**的编号、级别、范围、条件和依据。要素校验暂按六类
  展示说明，尚不是逐条结构化目录。目录一致性测试检查所有正文规则编号，避免遗漏。
- 破折号、强制词、进一步和开篇表态四类风格提示默认关闭，按模板明确选用，存入
  `ProofreadConfig.document_styles`，旧配置回落为空。编辑复扫、AI `check.proofread`
  和合并预审共用配置入口；采纳自检仍只检查必错，风格提示始终不能成为拒绝采纳的依据。
- 起草提示词取消标点和用词绝对配额，明确报告不加请示结语；同步外部技能的检查清单、
  文种说明、行文规范及 Python 自检脚本，防止内部修正后外部起草继续套旧规则。
- 修正五条种子词条的默认风险级别：TYP-010“曾强”改为疑似且默认关闭；TYP-066“惟一”
  改为默认关闭的词形偏好提示、依据待核验；TYP-056“起动”、TYP-070“其它”、
  GRM-011“免费赠送”改为疑似，不提供自动替换。用户原有显式覆盖按已有契约保留。
