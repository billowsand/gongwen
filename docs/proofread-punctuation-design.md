# 标点处理现状与改造建议（2026-11-22）

> 目的：把「标点」这一类的现状、缺口、自动与提示的分界、以及要动的代码拆清楚。
> 范围：起草页 Markdown、版式预览、实时 PDF、导出、保存、导入/粘贴、清洗。
> 与 [审校自动更正与人工确认清单](proofread-autofix-inventory.md) 配套；那篇讲词条与
> 文档规则，这篇专讲标点。

## 一、结论

1. **现在已经有两条「显示/导出先规范、源码后写回」的成熟先例**：
   - 引号：预览与导出在行内排版时统一成中文引号（`export/text.rs`），源码不动；
   - 有序列表末尾标点：解析时统一成 `；`/`。`（`export/parse.rs`），源码不动，
     保存时再把源码改成同样的写法。
2. **真正缺的不是「自动更正」，而是半角标点、空格、重复标点、省略号这几类
   根本没有进入预览/导出/保存链路**。它们只在导入、粘贴、手动「清洗」里做，
   所以手打的半角标点会一直留在源码里，预览和 PDF 也照原样排。
3. **`1。`→`1.` 不是要修的毛病，是要保留的输入法补偿**：中文全角输入法敲 `1.`
   常出 `1。`，不转就认不成 Markdown 列表。这条继续留在输入层，不并入保存修复。
   真正要改的是**失焦、自动保存、切换标签、新稿第一次输入、点「复制全文」时也去
   规整整篇列表**：这些不是用户按保存，源码不该变，而且多数绕过了撤销栈。
4. **特殊标点要的是「保存时整体匹配」**：发文字号的六角括号 `〔〕` 不好打，用户
   随手打 `[2026]`、`【2026】`、`（2026）`、`〈2026〉`，保存时应统一成 `〔2026〕`；
   公文引用外层括号也应统一成全角 `（）`。这类修复现在只在审校抽屉里给「采纳」，
   没有在保存时自动落地。
5. **列表末尾句号/分号是整篇判断**：现有 `normalize_ordered_list_punctuation`
   已经按列表组整体判断，问题是它在失焦/自动保存时也跑；应只留在显式保存，
   一次看完整篇再定。
6. **标题标点规则本身有误**：`RULE-TITLE-PUNCT` 把标题里的顿号 `、` 也当必错，
   而「关于做好元旦、春节期间有关工作的通知」是常见规范写法。规则不改，不能拿它
   做自动更正。
7. 建议分两层：
   - **字符级 1:1 标点**（半角→全角、引号、列表标记 `1。`→`1.`）：预览、导出、保存
     都可以直接做，源码映射不变；
   - **结构级 N:M 标点**（空格、重复标点、省略号、标题末尾句号）：导出与保存先做；
     预览要显示，就得给预览加一张源码偏移映射表，作为第二期。
8. 源码只在**显式保存**时写回标点更正；预览和导出只改显示/输出，不改源文。
   自动保存、切换标签、失焦、复制全文都不再改源码。

## 二、现状：标点在这几条路上分别怎么走

| 环节 | 触发 | 现在做什么 | 代码 |
| --- | --- | --- | --- |
| 输入 | 在行首 `1`–`9` 位数字后敲 `。`/`．` | 把输入事件里的标点改成 ASCII `.`。**这是必要的输入法补偿，保留** | `src/draft_page/list_period.rs`，在 `editor.rs:881` 调用 |
| 编辑框失焦 | 点到表单/侧栏/别的控件 | 整篇有序列表末尾标点统一成 `；`/`。` | `src/draft_page/editor.rs:1228` |

| 手动保存 | `Ctrl+S`、标题栏保存、保存并关闭 | 同上，先改源码再检查稿件状态 | `src/app/manuscript_ui/detail.rs:993` |
| 复制全文 | 功能区「复制全文」 | 先把源码规整一遍，再复制 | `src/draft_page/ribbon.rs:405` |

| 导入/粘贴 | 打开文档、粘贴 | 半角标点转全角、空格归一、引号不转、列表结构还原 | `doc_import/clean.rs`、`rich_paste/pipeline.rs` |

### 2.1 已经做对的部分

- **引号**：`normalize_chinese_quotes` 在 `inline_atoms` 里按字符一对一替换，源码范围
  不变，所以预览、Word、PDF 都能用同一份排版结果，源码不动。这是「显示先规范」
  的正确样板。
- **列表末尾标点**：解析器在 `parse_markdown` 里对列表项做 `normalize_ordered_item_punctuation`，
  预览/Word/PDF 看到的是已统一的写法；保存时再把源码改成同样写法。方向是对的，但
  **时机不对**：解析器每帧都判，用户边改列表，预览里的句号/分号就可能跟着变；
  失焦/自动保存也会判。应把判断集中到显式保存，预览/导出只显示已保存的结果。
- **段末缺句号**：定为「疑似」，给一键改法但不自动。这符合「拿不准的进提示」。

### 2.2 缺失的部分

- `doc_import::clean::normalize_punctuation` 只服务导入/粘贴/手动清洗，**预览、PDF、
  导出、保存都不调用**。所以手打的 `工作,通知;时间:上午` 会原样留在源码，也原样排进 PDF。
- `normalize_spaces` 同样只在导入/粘贴/手动清洗时跑，预览/导出/保存不跑。
- 重复标点（`，，`、`。。`、`、、`、`；；`、`！！`、`？？`）、省略号（`...`、
  `。。。`）、破折号写法（`--`）没有任何检测或修复。
- 发文字号六角括号、公文引用外层括号虽然有规则和一键改法（`RULE-NUMBER-BRACKET`、
  `RULE-CITATION-NUMBER`），但**保存时不会自动应用**，要用户逐条点采纳。
- 列表末尾句号/分号虽然保存时会整体判断，但失焦/自动保存也跑，时机不对。
- 标题标点只报第一个、无改法，且把顿号 `、` 当错。
- 没有「中文语境半角标点」的审校提示；它是静默缺失，不是提示太多。

## 三、问题清单

### P0：会直接造成「字自己变」或误报

1. **失焦/自动保存/首次输入改源码**：`editor_lost_focus`、`autosave_all`、
   `auto_create_touched_doc` 都会走 `normalize_ordered_list_punctuation`。用户没有按保存，
   源码已经变了；切标签也会触发。列表末尾到底用句号还是分号，应该等整篇保存时判断，
   不应该在失焦或自动保存时判。
2. **保存失败也改源码**：`try_save_to_manuscript_library` 先规整源码，再去检查
   归档/发布状态和稿件库。检查失败时，正文已经被改，且没有写库。
3. **复制全文改源码**：点「复制全文」不是编辑动作，却把源码规整了一遍。
4. **这些改动绕过撤销栈**：`editor_lost_focus` 和 `try_save` 都是直接 `*text = normalized`，
   `TextEdit` 的撤销记录里没有这一步，`Ctrl+Z` 撤不回来。
5. **特殊标点没有保存时自动匹配**：`RULE-NUMBER-BRACKET` 与
   `RULE-CITATION-NUMBER` 已经能检测并给出规范写法，但只停在审校抽屉里，用户要逐条
   点「采纳」。保存时应整篇扫一遍、一次改好。
6. **列表末尾判断在预览里也每帧跑**：`parse_markdown` 每次解析都按组重判，用户边改
   列表，预览的句号/分号可能跟着变。这不是源码改动，但同样是「边改边判断」。应改为
   保存时一次判，预览/导出只显示保存后的源文。

### P1：规则本身不对，或在保护上有洞

7. **标题顿号误报**：`TITLE_ALLOWED_PUNCT` 只有书名号和引号；`first_stray_punctuation`
   把 `、` 判成违规。常见标题「关于做好元旦、春节期间有关工作的通知」会报「必错」。
8. **标题括号不参与嵌套判断**：只跟踪书名号和引号深度，`（……，……）` 里的逗号会被报。
9. **标题只报第一个标点**：标题里同时有 `、` 和 `。` 时，先报 `、`，把真正该改的句号挡住。
10. **`normalize_punctuation` 保护不全**：
   - 裸域名 `www.例子.中国`、邮箱 `a@例子.中国` 会被改成 `www.例子。中国`；
   - 中文扩展名的文件名/路径 `文件.文档`、`C:\目录\文件.文档` 会被改；
   - 行首手写编号 `一.总体要求` 会变成 `一。总体要求`。
11. **`normalize_spaces` 不认代码围栏/行内代码**：直接把一行里的连续空格压成一个，
    代码里的 `let x = "a  b";` 会被改。
12. **`normalize_chinese_quotes` 会进代码**：`inline_atoms` 只跳过反引号本身，代码内容
    仍是 atom，代码里的 `"` 会被改成中文引号；URL 里的 `'` 也可能被当成英文撇号。
13. **列表末尾标点会吃掉省略号/破折号**：`terminal_punctuation` 包含 `…` 和 `—`，
    `normalize_ordered_item_punctuation` 会把「1. 详见……」改成「1. 详见。」。
14. **段末标点只查 `Paragraph`**：列表项由解析器/保存 pass 统一末尾标点，不经过这条规则。

### P2：可以补，但不该自动

15. 破折号/连接号：`--`、`-`、`—` 在范围、转折、停顿里都可能，程序分不清，应提示。
16. 引号不配对：可能是直接引语没写完，自动配对会改原意，应提示。
17. 标题内部标点：`、` 合法，`，`/`；`/`：` 要结合标题语义，建议提示删除而不是自动。

## 四、标点分类与处置建议

### 4.1 自动更正（确定错，且程序能给出唯一写法）

| 类别 | 例子 | 处理 | 预览 | 导出/PDF | 保存 |
| --- | --- | --- | --- | --- | --- |
| 发文字号年份括号 | `某函[2026]12号`、`某函【2026】12号`、`某函（2026）12号` | 年份括号统一成 `〔2026〕`；全角数字转半角 | 可后做 | 是 | 是（整篇扫） |
| 公文引用整体 | `《XX》(某函[2026]12号)` | 外层全角括号 + 内层六角括号 + 序号不编虚位 | 可后做 | 是 | 是（整篇扫） |
| 中文语境半角标点 | `工作,通知;时间:上午(附件)!` | 转全角 `，；：（ ）！` | 第一期（1:1） | 是 | 是 |
| 直引号/方向错/混杂引号 | `"第一句"`、`“第二句“` | 配对为 `“”`/`‘’` | 已有 | 已有 | 新增 |
| 列表标记误写 | 行首 `1。`、`1．` | 改 `1.`（输入层已处理全角输入法；保存再兜底粘贴/导入） | 不靠预览改结构 | 保存后随源文 | 是 |
| 有序列表末尾标点 | 一组里 `；`/`。` 混用、缺末尾标点 | **只在显式保存时整篇扫一遍、按每个列表组判断**：有分号风格就其余分号、末项句号；否则全句号；`？`/`！`/`……`/`——` 结尾不动 | 保存前不重判，显示源文；保存后随源文一致 | 保存后随源文；未保存不重判 | 是（整篇扫） |
| 中文与标点之间空格 | `正文 ，下一句` | 删空格 | 第二期 | 是 | 是 |
| 汉字与数字之间空格 | `2026 年 5 人` | 删空格 | 第二期 | 是 | 是 |
| 重复同类标点 | `，，`、`、、`、`；；`、`！！`、`？？` | 收成一个 | 第二期 | 是 | 是 |
| 省略号写法 | `...`、`。。。`、单个 `…` | 改 `……` | 第二期 | 是 | 是 |

> 若选 5.4 的 B 方案：第一期 = 在 `inline_atoms` 里做「一进一出」的字符替换，源码范围
> 不变，预览/Word/PDF 自动生效；第二期 = 改动字符数，给预览加源码映射。
> 若选 A 方案：预览从第一期就用 `Corrected` 全量 + 映射，不再分这两步。
> 导出与保存不受这个限制，可以先做。

### 4.2 进提示，不自动改

| 类别 | 例子 | 建议级别 | 为什么 |
| --- | --- | --- | --- |
| 段末缺句号 | 正文段落末尾没有 `。` | 疑似 | 可能是落款、附件名、引文；已有规则与一键改法 |
| 标题内部标点 | `关于甲，乙的通知`、`关于甲；乙的通知` | 疑似 | 标题可能用顿号、括号；先修规则，再给「删除这个标点」的改法 |
| 标题末尾句号 | `关于……的通知。` | 疑似（可一键删） | 确定不该有，但标题边界要先判对；第一期先提示 |
| 破折号/连接号 | `2026--2027`、`甲-乙` | 疑似 | 范围号、连接号、破折号都可能，程序不猜 |
| 引号不配对 | 只有一个 `“` | 疑似 | 可能是引文没写完，自动补会改原意 |
| 路径/文件名里的点 | `文件.文档`、`C:\目录\文件.文档` | 不报或提示 | 首先不能自动改；能确认是路径就跳过 |

### 4.3 永不自动改

- 代码围栏、行内代码、公式 `$...$`、HTML 注释、Markdown 链接/图片地址；
- 公文引用（名称与文号）、文号里的括号与序号（由专门规则处理）；
- 直接引语里的标点（是原文事实，改了就是改引文）；
- 网址、邮箱、裸域名、文件路径、文件名扩展名；
- 行首/行尾避头尾：那是排版问题，由预览与 Typst 的断行规则处理，不改源码。

### 4.4 保存时整篇修复清单（按优先级）

这一轮最该补的，不是把 `1。` 改掉（输入层已经做了），而是下面这些「保存时一次
看整篇」的修复。表单里的发文字号早就会走 `normalize_number`；缺的是**正文与引用里**
的保存时自动匹配：

| 优先级 | 修复 | 例子 | 说明 |
| --- | --- | --- | --- |
| P0 | 发文字号年份括号 | `某函[2026]12号`、`某函【2026】12号`、`某函（2026）12号`、`某函〈2026〉12号` | 任何非 `〔〕` 括号都匹配成 `〔2026〕`；全角数字转半角 |
| P0 | 公文引用外层括号 | `《XX》(某函[2026]12号)` | 外层转全角 `（）`，内层年份转 `〔〕`，序号不编虚位 |

| P1 | 中文引号配对 | `"第一句"`、`“第二句“`、`「第三句」` | 直引号、方向错、混杂风格统一成 `“”`/`‘’` |
| P1 | 省略号 | `...`、`。。。`、单个 `…` | 统一成 `……`；代码/URL 内不动 |
| P1 | 重复标点 | `，，`、`、、`、`；；`、`！！`、`？？` | 收成一个；`……`、`——` 不拆 |
| P1 | 中文语境半角标点 | `工作,通知;时间:上午(附件)!` | 转全角；数字、时刻、版本、URL、路径不动 |
| P1 | 中文/数字之间的空格 | `2026 年 5 人`、`正文 ，下一句` | 删多余空格；西文单词之间保留 |
| P2 | 列表标记兜底 | 粘贴/导入带来的 `1。`、`1．` | 输入层已处理手打；保存再兜底非键入来源 |

## 五、目标结构

### 5.1 一个纯函数，三种消费

```text
punctuation::correct(markdown, Options) -> Corrected {
    text: String,
    edits: Vec<Edit { source: Range<usize>, corrected: Range<usize> }>,
}
```

- 不碰 egui、不读配置、不写盘，能单测；
- `Options` 分开关：`character`（1:1 宽度/引号/列表标记）、`whitespace`、`repeats`、
  `ellipsis`、`document_numbers`（六角括号）、`citations`（引用外层括号）、
  `list_tail`（整篇列表末尾判断）、`title_tail`；
- 所有开关组合都幂等：同一份文本跑两遍，第二遍零改动；
- `Corrected` 提供 `to_source(range)` / `to_corrected(range)`，预览需要时用。

### 5.2 三种消费

| 消费者 | 用什么 | 写不写源码 | 备注 |
| --- | --- | --- | --- |
| 版式预览 | A 方案：`Corrected` 全量 + 偏移映射；B 方案：先用 `inline_atoms` 的 1:1，第二期再接映射 | 不写 | 点击、选区、光标、锚点都要映射回源码 |
| 实时 PDF / 导出 | `Corrected.text` 的局部标点（括号、引号、半角、重复、省略号）；**列表末尾整篇判断不含** | 不写 | PDF/Word/Markdown/Typst 用同一份；列表末尾等保存后再统一 |
| 显式保存 | `Corrected.text` 全量（含列表末尾整篇判断） | 写 | 保存成功后写回编辑器，一次撤销；自动保存不写 |

### 5.3 保存时序（建议）

1. 检查只读、归档/发布状态、稿件库可用；
2. 对当前源码跑 `punctuation::correct`。它内部依次做：
   - 公文引用与发文字号（`document_reference::detect_numbered` / `detect_loose_numbers`）；
   - 列表末尾标点：整篇扫一遍，按每个列表组判断（`normalize_ordered_list_punctuation`）；
   - 引号、半角/全角、空格、重复标点、省略号、标题末尾；
   所有替换按源码位置排序后一次落盘，避免前一处改完、后一处 span 偏了。
3. 有变化时，用一次可撤销的编辑写回编辑器（有 `egui::Context` 时走
   `replace_with_undo`；没有上下文时至少留一条「保存时标点规范」记录）；
4. `revalidate()`；
5. 用规整后的正文保存；
6. 状态栏报「已保存；规范标点 N 处」；保存失败则源码不动。

自动保存、切换标签、新稿首次输入、复制全文：只保存/复制当前源码，不跑标点规整。

### 5.4 预览先做到哪一步

预览要显示更正后的文字，就必须把「更正后的坐标」映射回「源码坐标」，否则点击、
选区、光标、导航空格都会偏。有两种推进方式：

| 方式 | 预览能看到什么 | 代价 | 适合 |
| --- | --- | --- | --- |
| **A. 一步到位** | 全部自动更正（词条 A1/A3/A4 + 标点 1:1/N:M） | 要改 `preview/render.rs` 的入口与所有 `clicked`/锚点/选区/光标映射；工作量大但一次成型 | 想彻底做到「所见即所得」 |
| **B. 先做等长替换** | 等长词条（布署→部署）+ 半角→全角 + 引号 + `1。`→`1.` | 不改偏移，`inline_atoms` 里就能做；变长替换（涉及到→涉及）要等映射 | 想先小步上线 |

> 词条 A1 里有不少「多字 → 少字」的替换（`涉及到`→`涉及`、`凯旋归来`→`凯旋`、
> `的的`→`的`）。如果第一期不做映射，这些在预览里只能先保持原样，等保存/导出再改；
> 用户会在预览里看到一部分错别字没被处理。这个取舍要先定。

建议：**如果要把「预览自动更正」作为卖点，直接做 A**；只做 B 的话，预览会显得
「有的改了、有的没改」，反而需要额外解释。导出与保存不受这个限制，可以先上。

## 七、哪些标点要进「提示」

建议新增/调整这些文档规则（都在 `proofread_rules` 里，进审校抽屉）：

1. `RULE-TITLE-PUNCT`（改）：只报标题内 0 深度的 `。`、`，`、`；`、`：`；`、`、`·`、
   书名号、引号、括号内容豁免；给「删除这个标点」的改法，级别改「疑似」。
2. `RULE-SENTENCE-END`（保留）：段末缺句号，疑似 + 一键补。
3. `RULE-PUNCT-DASH`（改）：不再只数破折号次数，改为「疑似破折号/连接号写法」，
   给「改为——」或「改为至」的候选，但由人点。
4. `RULE-PUNCT-QUOTE`（新，可选）：引号数量不成对，提示核对。
5. 路径/文件名里的点不单独立规则：能确认就跳过；确认不了也不自动改。
6. `RULE-NUMBER-BRACKET`、`RULE-CITATION-NUMBER` 不再作为「待采纳」提示：
   保存/导出时自动应用；只有认不出代字或序号时才提示人工核对。
7. 列表末尾标点不再单列提示：它是整篇保存时的体例判断，不逐条出题。

> 这些提示的 `replacement` 必须是确定文本；给不出就只提示，不猜。

## 九、需要拍板

1. **列表末尾标点的判断范围**：明确放在显式保存时整篇判断，这点已经确定；
   剩下的是「按每个列表组分别判」还是「全篇统一一种风格」。现在按组判，
   如果全篇统一，要先定以哪一组为准。
2. **预览范围**：选 A「一步到位做全量映射」（推荐，预览不会有的改了有的没改），
   还是选 B「第一期只做 1:1，第二期再补映射」？前者改动大、体验完整；后者上线快。
3. **直接引语**：引号里的半角标点改不改？我建议不改，最多提示；改了就是改引文。
4. **标题内部标点**：`、` 允许；`，`/`；`/`：` 是只提示删除，还是直接自动删？
   我建议先提示，等标题规则在真实稿上跑一轮再定。
5. **路径/文件名保护**：是否把 `文件.文档`、`C:\目录\文件.文档`、裸域名统一纳入
   保护区？这会牺牲少量正常句号的自动转换，但能避免改坏路径。
6. **特殊括号接受范围**：发文字号除了 `[]`、`【】`、`（）`、`{}`、`〈〉`，要不要
   连 `「」`、`『』`、`《》` 也认？认得多，误伤书名号的几率也高；我倾向认前五类，
   `《》` 不碰。
