# 版本变更与浏览界面改造方案（Zed 式 diff + 花脸稿预览）

> 状态：第 ① 期已完成；第 ② 期除「公文要素就地标注」外已完成，均已合入 `main`；其余各期待实施。本文记录需求讨论的结论、设计要点、技术路线与分期计划；
> 实施进度、与方案的出入和下一步见 `docs/version-diff-handoff.md`。

## 一、核心思路：两层 diff

| | 代码层（Markdown diff） | 视觉层（花脸稿） |
|---|---|---|
| 比什么 | Markdown 源码原文 | 「印在纸上的字」：编号已生成、Markdown 标记已剥离、按段落排好的纯文本 |
| 要求 | 严谨：任何字节级改动都记录，含标记、空行、格式 | 好读：只标真实文字的增删，像人工红笔改稿，不像 Word 审阅 |
| 呈现 | 左侧，Zed 式统一 diff，可编辑 | 右侧实时预览；PDF、Word 导出与之一致 |
| 数据来源 | 现有 `diff.rs` 的 `body_diff` | 新建视觉 diff 引擎（见第四节） |

两层**各算各的**，只通过「源码字节范围」互相定位（点击互跳、悬停高亮、统一导航）。视觉层不再从
源码 diff 推导，这就绕开了现在 `redline.rs` 的根本问题：哨兵插进 Markdown 原文后，`**`、标题
层级、空行这类格式改动也被当成文字改动，甚至把哨兵插进语法中间。

## 二、需求结论（选择题收敛结果）

### 代码层（左侧）
1. **统一视图**（不分栏）：删除行红底叠在新增行绿底上方，行号槽有增删色条，未改动区折叠。
2. **可编辑 + 逐块还原**：diff 视图就是编辑器本身，直接改字、实时反映；每个变更块（hunk）旁有
   「还原」按钮，一键退回基准版那一块。
3. **公文要素变化**在代码区顶部以「要素变化」卡片列出（字段级，沿用 `draft_changes`）。
4. **AI 修订建议并入**：以虚线框「待采纳块」叠入代码 diff，每块「采纳 / 拒绝」；未采纳前不进正文、
   不进花脸稿。`ai_guard` / `validator` / `proofread` 闸门不变——三条红线不动。

### 视觉层（右侧预览与导出）
5. **粒度**：词级（jieba 分词）+ 自动归并——同一分句内改动过密就整句「删旧句、插新句」。
6. **编号顺移不标注**：标题、列表、序号表、附件编号都是程序生成的，不算修改；只标真正新增 / 删除的
   那一项，其余编号直接显示新值。
7. **纯格式变化不标注**：加粗、标题层级、列表样式、表格对齐、段落拆分 / 合并、空格、全半角等，
   一律按新版排，不画任何记号。
8. **段落移动识别为移动**：新位置正常排出，段首加小注「（本段由原第 X 段移来）」，原位置不再整段
   画删除线；移动同时改了字的，新位置再按段内增删标注。代码层仍是删 + 增。
9. **公文要素就地标注**：版头、版记里的主送、抄送、成文日期、签发人、文号等改动，在版面原位画
   删除线 + 方框。
10. **标记样式**（预览 / PDF / Word 三处一致）：**删除 = 红色直删除线；新增 = 蓝色方框**。
11. **Word 用普通字符格式**实现（删除线 + 字符边框 + 颜色），不用 Word 原生修订。
12. **不要说明页**：一切就地标注。表格列数变了就整表「删旧表、插新表」；图片替换就旧图打叉、新图
    加框；标题现在也就地标注。
13. **研究报告也覆盖**：文字同样词级标注；公式不拆，改了就整个公式旧的删除线、新的加框。
14. **预览始终显示全文**（折叠只在左侧做），保证预览就是导出的纸。

### 版本与浏览
15. **只比两版，基准可选**：永远是「基准版 → 目标」的累计改动；基准默认最新提交版。
16. **浏览界面合并为一套**：左边栏是版本时间轴（最上面是「当前未提交」），点任一版本即在同一个
    「代码 diff + 花脸稿」视图里看它相对上一版 / 基准的变化。历史版本只读，只有「当前未提交」可编辑。
    稿件管理的对照窗改为以只读方式打开这套视图，不再单独维护 `diff_view` 的分栏布局。
17. **花脸稿自动留档**：导出的 PDF 存进稿件附件（`PdfAttachment`），文件名带「v3→当前」与日期；
    时间轴上标出「在此处出过花脸稿」。

### 联动
18. **点击互跳 + 悬停高亮**：点预览里的某处标记，左侧定位到对应变更块；悬停任一侧，另一侧同一处
    淡色高亮。
19. **统一变更导航**：顶部一组「上一处 / 下一处」（F7 / Shift+F7），两侧同时跳。
20. **预览保真**：默认 egui 实时预览，标记样式、字体、增删位置与导出一致，换行和分页不保证逐行相同；
    另设「打印预览」按钮，后台编译 PDF，用内置 hayro 查看器看真实纸面。

## 三、界面布局

```
┌ 工具栏：基准 [v3 · 送审稿 ▾] → 当前未提交 │ 共 12 处 ↑↓ │ 打印预览 │ 导出花脸稿 ▾ ┐
├──────────┬──────────────────────────────┬──────────────────────────┤
│ 版本时间轴 │ 要素变化（2 项）▸               │        一、工作目标         │
│ ● 当前    │ 12   ## 工作目标                │  请于八月~~十~~[十五]日前   │
│ ○ v3 花脸 │ 13 - 请于八月十日前报送。  [还原] │  报送。                   │
│ ○ v2      │ 13 + 请于八月十五日前报送。       │  ……                      │
│ ○ v1      │ ⋯ 折叠 8 行未改动 ⋯             │  [三、保障措施]           │
```

- 时间轴可收起。窄屏时右侧预览可收起，只留代码 diff。
- 取代现在起草页的 `PreviewMode::VersionDiff` 与右侧版本抽屉，两者合成这一套。

## 四、视觉 diff 引擎（新模块，暂名 `src/visual_diff/`）

### 4.1 渲染文本模型
把一个版本（`DraftInput` + Markdown）展开成「视觉块」序列，这一步复用 `export::parse` 的
`MarkdownBlock` 与编号逻辑，保证与导出看到的是同一份东西：

- `Element { field, text }`：版头 / 版记要素（主送、抄送、成文日期……），文本是**显示值**。
- `Heading { level, number, text }`：`number` 单独存放，不参与比较。
- `Paragraph { runs }` / `ListItem { number, runs }`：`runs` 是带样式（加粗、括号楷体）的纯文本片段。
- `Table { cells }`、`Image { src }`、`Formula { tex }`、`AttachmentLabel { number, title }` 等。
- 每个块、每个 run 都带回指源码的字节范围，供联动与还原使用。

### 4.2 比较规则
1. **按章节对齐**：先比较标题序列（只比 `text`），把文档切成章节，再在章节内比较正文。
2. **正文按文字流比**：章节内所有段落拼成一条字符流，段落边界当作「软分隔」、不计入改动——段落
   拆分 / 合并因此不产生标记。结果再按新版的段落切回去。
3. **词级 token**：jieba 分词；数字 + 单位、日期（「8 月 10 日」「二〇二六年九月」）、文号整体作为
   一个 token：「8 月 10 日」改成「8 月 15 日」时整体删旧插新，而不是只在「0」和「5」上各画一个标记。
4. **归并（让它看上去像那么回事）**：
   - 两个改动片段之间夹着的未改动文字 ≤ 2 个字，就吸收进改动，合成一段。
   - 按分句（，。；：！？）统计：改动字数超过分句一半，或改动片段 ≥ 3 段，就整句「删旧、插新」。
   - 阈值写成常量，并准备一组真实公文样例做回归测试来调参。
5. **归一化后再比**：全半角空格、行尾空格、`**` 等标记已在模型里剥离；标点是真实文字，**改了照标**。
6. **移动识别**：未能 LCS 对齐的「删除块」与「新增块」，归一化文本相似度 ≥ 0.8 的配成移动。
7. **要素字段**整体替换：旧值删除线、新值加框，不做词级（日期、机关名拆开读没意义）。
8. **编号**：取新版编号直接显示，不标；新增标题整体（含编号）加框；删除的标题只画删除线文字，
   **不显示编号**，免得编号序列里冒出一个重复的「二、」。
9. **表格**：逐格词级；整行增删则整行加框 / 删除线；列数变化则整表删旧插新。
10. **公式**：整体比较，变了就整体删旧插新。

### 4.3 产物：`RedlineOverlay`
引擎输出的不是带哨兵的 Markdown，而是一份**附着在新版视觉块上的标注层**：每个块 → 若干
`(范围, Same/Deleted/Added)` 片段 + 插在块间的「已删块」+ 移动注记。三个消费方读同一份标注层：

- **egui 预览**：`preview/` 的正文、标题、版头、表格绘制函数增加一个可选的 overlay 参数。
- **DOCX**：`export/docx/runs.rs` 的 `apply_redline` 改为删除线 + 红色、字符边框 + 蓝色。
- **LaTeX**：哨兵的注入从「解析前」挪到「解析后」，标题路径（`tex_escape`）也要支持标注。

一份标注层喂三处，从结构上保证「预览 = PDF = Word」。建议补一个一致性测试：同一份 overlay
分别生成预览片段序列、docx run 序列、TeX 片段序列，三者的 (文字, 类型) 序列必须相同。

## 五、代码层（左侧）的实现要点

- **可编辑的统一 diff 放在 egui `TextEdit` 上**是本方案最大的技术风险：`TextEdit` 的文本就是
  编辑内容，没法像 Zed 那样在行间插入不属于文本的「已删除行」。候选路线：
  1. 自定义 layouter：给删除块前一行的 `TextFormat.line_height` 加高，在让出的空白里用 painter
     画出已删除的旧行（只读、红底），编辑行为不受影响。**首选**。
  2. 退路：行号槽只画删除三角标记，点开后以浮层显示被删的旧行（VS Code quick diff 的做法）。
- 「还原」= 用基准版那一块的原文替换当前字节范围，走编辑器的撤销栈，Ctrl+Z 能撤回还原。
- 代码 diff 每次按键都要重算：沿用 `sync_draft_diff` 的哈希缓存，另加约 150 ms 防抖；视觉 diff
  更重（要分词），放后台线程，预览允许比输入晚一拍。
- AI 待采纳块在数据上是一个带 `source = Ai`、`state = Pending` 的 hunk，不写入正文字符串；
  采纳时才按正常编辑写入并过闸门。

## 七、讨论中补充考虑到的点（设计清单）

1. **Word 与 PDF 本来就不一致**（Word 画不出穿字波浪线）——改用直删除线后三端统一。
2. **跨行方框**：LaTeX 的 `\fbox` 不能断行，现在按标点切块；预览按行画框。三端对「一段新增跨行时
   框在行尾断开、下行重新开框」要定一个统一规则，并各自实现（LaTeX 侧可能要自定义可断行的上下线
   + 首尾竖线，是第二大技术风险）。
3. **删除的标题不带编号**，避免编号序列出现重复号。
4. **段落拆分 / 合并**靠「文字流比较」天然不产生标记。
5. **标点改动照标**；空格、全半角、Markdown 标记不标。
6. **日期、数字、文号按整体 token**，避免碎片化。
7. **黑白打印**：红删除线与蓝方框靠线型也能区分，颜色丢了不丢信息。
8. **花脸稿比定稿长**，页数对不上是必然的（沿用现有说明）。
9. **性能**：长稿边打字边 diff——哈希缓存 + 防抖 + 视觉层后台计算。
10. **还原要可撤销**，否则一次误点就丢了新写的内容。
11. **基准选择要记住**（按稿件记），切走再回来不重置。
12. **gongwen-markdown 技能包**：本方案不改 Markdown 语法，技能包无需同步；若日后新增语法，按
    AGENTS.md 要求同步。

## 八、暂定默认值（实施时可再调）

- 归并阈值：夹缝 ≤ 2 字吸收；分句改动 > 50% 或片段 ≥ 3 段整句替换。
- 移动识别相似度阈值 0.8；移动注记措辞「（本段由原第 X 段移来）」，X 按旧版正文段落序号。
- 颜色：删除红 `#C00000`，新增蓝 `#1F4E9E`；方框线宽 0.5 pt。
- 代码 diff 防抖 150 ms。
