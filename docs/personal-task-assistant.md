# 个人任务助手

个人任务助手位于主菜单「任务助手」，数据保存在稿件库同一 `manuscripts.db` 文件内的独立 SQLite 表；不改 `user_version`。新数据库为空时不写演示任务。所有操作限定于任务数据，不接触公文正文和 `DraftInput`。

## 任务管理

每个任务有稳定 UUID、任务名称、负责人、当前进展、下一步工作、风险问题及应对措施、任务期限、状态、分类、上级、前置、待核对标记和 revision。只有名称必填；负责人从标准词库人员中选择，保存词条 id 与姓名快照；日期空或真实 `YYYY-MM-DD`；文本有长度限制。更新当前进展会覆盖当前值，旧值作为带时间的「进展更新」历史保留。任务可创建、编辑、记进展、完成、重开、取消（需理由）、归档、移出归档、软删除和恢复；关键修改带历史。归档与回收站只读，恢复不会自动重建旧关系。

页面是三栏：左边视图栏（今天与逾期、进行中的工作、等待 · 阻塞、待核对、待整理建议，「已结束」下的已完成、已取消、归档、回收站，以及分类），中间任务列表，右边详情或表单；窗口窄于 900 时视图栏收成列表上方的下拉框，窄于 650 时列表与详情单栏切换。顶栏搜索匹配任务名、负责人、当前进展、下一步、风险问题、分类与关联材料来源，搜索时不受视图限制；列表另可按负责人筛选、按期限或最近更新排序。详情可跳转上级、子任务、前置与后续任务。设计与取舍见 `docs/task-assistant-ui-redesign.md`。

分类单层且每任务一个主分类。新增和重命名均校验唯一性；删除分类必须指定迁移目标，迁移覆盖活动、归档与回收站任务并记历史。删除任务前展示将解除的关系；确认后不级联删除：子任务变独立，后续任务解除该前置并标待核对。

关系图统一按完成依赖方向检测：任务指向前置，上级指向子任务。程序拒绝自引用、循环和“子任务依赖上级”导致的完成死锁。进入进行中或完成前，所有前置必须已完成且核对；取消前置不算完成。完成上级前，所有子任务都必须已完成（取消不算）。重开前置会把进行中的后续标为阻塞；完成后续或上级若受重开影响，会标记待核对，不自动撤销完成事实。

## 材料整理

摘录核对忽略空白及约定的全半角标点差异，仍要求内容连续对应；摘录不能核对时，字段值本身能在原文中找到的，可用字段值作为摘录。没有内容的字段不要求补齐，分类、上级、前置和状态不由 AI 选择。

新建任务的表单顶部可「从文字填写」，编辑任务时展开「从文字补充…」。识别按原文填写任务名称、负责人、当前进展、下一步、风险问题及应对措施、任务期限六栏；没有内容的栏留空。负责人由程序按标准词库姓名和别名匹配，唯一匹配可填入，同名人员要求人工选择，词库未收录则提示不填。其它空白栏直接填入，已有值给出可替换或忽略的建议；AI 标记悬停可看原文摘录，手改后标记消失。「全部撤销」只恢复仍等于 AI 填入值的栏，保留人工修改。保存前不写库；保存时只要仍有 AI 标记，材料快照与任务、来源历史在同一事务落库。重复填写会保留各次原文，合集仍受 1 MB 上限约束。状态、前置与待核对不由 AI 填写。原文另有独立事项时可转到批量整理，当前表单保留。

待整理建议中的材料标题选填，留空会取原文首个非空行并回填标题；截取前 30 字、去首尾标点，过短时使用「粘贴材料 MM-DD HH:MM」。回填的标题没被人改过时，再改原文会一起清掉，不会把上一份的标题挂到新材料上。后台仍校验标题非空、最多 200 字。

识别结果写在材料卡「识别」按钮旁边，带材料标题：新增几条建议（旁边「只看这批」把待整理建议筛到这份材料），或没有需要核对的变化（材料仍存进「材料」）。识别成功且输入框还是交出去的那份原文时清空输入框，下一份从空框开始粘贴。粘贴的材料与已识别的一份标题、正文都相同时不调模型，材料卡里出一张卡片：何时识别过、上次建议待核对 / 已采纳 / 已忽略各几条，按钮「重新识别」「查看这批建议」「打开材料」。页面的成功提示浮在底部居中、几秒后消失（点一下提前关），不占布局；错误仍在页顶常驻可关。

视图栏「材料」列出批量整理识别过的每份材料（时间、来源：粘贴 / 知识库、各状态建议数，顶栏搜索按标题筛），表单「从文字填写」的快照挂在任务历史上、不列在这里。选中一份在右栏看原文快照与它产生的建议，可「重新识别」「在待整理建议中查看」「删除」。重新识别按存下的原文再调模型：这份材料待核对与稍后处理的建议换成新结果，已采纳、已忽略的保留，新结果里与它们类型、目标、摘录都相同的不再生成，结果说明新增、替换、跳过各几条。删除会连同没采纳的建议（待核对、稍后、已忽略）一起删；已有建议采纳进任务时快照保留（任务历史里的「原文」照样能看），只是不再列在「材料」里，再粘贴同一份会提示已删除、重新识别即恢复；没有任何引用的材料整条删掉，之后可当新材料再识别。

可粘贴标题与原文，或从知识库选择一篇资料；也可开启“新入库资料自动整理”。自动整理开关默认关闭、保存在任务数据库；开启后只排队处理之后从现有导入路径新增的资料，不回扫旧库，不自动采纳。手工粘贴和自动整理都走同一条后台识别与候选去重链路。

模型沿用当前 AI 管理中配置的辅助模型和 OpenAI 兼容客户端。资料原文读取与模型请求在后台线程，界面轮询结果；模型失败可重试，批量识别忙时备份恢复保持禁用。单任务填表使用独立通道，不阻止恢复；恢复会丢弃旧结果。可以取消本次结果，程序会等当前请求结束后释放忙状态，不会采纳迟到结果。材料上限 1 MB，输出上限 128 KB、候选最多 30 条，系统不静默截断。自动整理队列最多 32 篇、正文合计 8 MB，超限会提示，资料仍在知识库中，可分批手动整理。

候选支持新任务、当前进展与下一步、负责人、风险、期限、完成证据、意见与待决事项；旧的责任与范围候选仍可读取，责任候选按负责人兼容，范围候选采纳时只应用名称。每条保留不可变材料快照、SHA-256 指纹和真实存在于原文的摘录；意见记录提出主体、针对事项及原意。目标只能是识别时上下文中的任务 ID；上下文之外不得由模型匹配，用户可以在待整理项人工选择目标。已有目标候选记录识别时 revision；人工修改后采纳会过期拦截，用户可显式重新核对当前版本再采纳。新任务候选先进入可编辑草稿，用户可补分类、上级、前置后保存。任务变更、来源历史与候选“已采纳”状态在单个事务完成；已报完成只作为建议，程序不自动闭合任务。稍后与忽略均保留，忽略项可恢复。

模型最多看到最近 50 项未归档、未删除任务；任务多于此数量会明确提示，目标校验也只接受这同一上下文里的 ID。没有有用变化时可成功保存材料快照并产生零条候选；同标题、同正文版本不会自动再识别，要人在卡片或「材料」里点「重新识别」。失败不会保存去重标记。材料表 `task_sources` 新增 `hidden` 列（启动时补列，不改 `user_version`）。

## 真实模型评测

评测集在 `tests/fixtures/task-eval/cases.json`（单任务填写与批量整理两组，附小词库），运行器是
`src/task_ui/eval.rs` 里的 ignored 测试，走产品代码全链，报告写到 `tmp/task-eval/<模型>.md`（含逐例
检查与原始输出）：

```bash
GONGWEN_TASK_EVAL_URL=http://127.0.0.1:12345/v1 GONGWEN_TASK_EVAL_MODEL=qwen/qwen3.5-9b cargo test --locked task_assistant_model_eval -- --ignored --nocapture
```

`GONGWEN_TASK_EVAL_ONLY` 填用例 id 前缀（如 `F05`、`B`）只跑一部分。最近一次结果与发现的问题见
`docs/task-assistant-ui-redesign.md` 7.4。

## 数据安全与验收

任务表使用 `manuscripts.db` 独立连接，可随数据库备份。数据库恢复前释放任务连接，恢复后重新打开；后台识别完成前恢复受忙状态拦截。SQLite 写锁等待最长 10 秒，数据库错误在页面显示。

专项测试：`cargo test --locked task_assistant`。原生界面样张测试：`cargo test --locked task_assistant_samples -- --ignored`，覆盖 1280（详情、表单、填写）、900、760（表单）与 600 宽度并输出 PNG 至 `tmp/`。样张和纯 Rust 测试不能替代 GUI 手工验收。

当前未完成的验收：真实模型端点联机识别（含空候选、失败重试与多任务人工匹配）；GUI 中输入法编辑、备份恢复竞争、筛选组合、关系解除与候选过期重核流程的手工操作。代码层已验证模型响应协议、证据、目标、来源版本去重、事务采纳与过期保护。

## 本机操作顺序

1. 主菜单打开「任务助手」，顶栏「更多 → 管理分类…」（或视图栏末行「管理分类…」）建立工作领域或专项分类。
2. 点「新建任务」，填写任务名称；负责人从词库人员中选择；当前进展、下一步工作、风险及措施、状态和任务期限在表单主区；分类、上级和前置收在「更多设置」，前置用搜索框按名称添加。表单开着时再点「新建任务」会先问是否放弃当前内容。
3. 保存后在列表选择任务：在「更新进展」里替换当前进展（旧值保留在历史），用头部的状态下拉调整状态，选「已取消」会就地要求填写理由；状态被前置或子任务挡住时，原因显示在下拉旁边。「待核对」横条上点「已核对」清除标记。归档与移入回收站在头部「更多」菜单里，归档只适用于完成或取消的任务。
4. 点顶栏「粘贴材料」或视图栏「待整理建议」，粘贴标题和原文，或选择已有知识库资料；核对建议与摘录后采纳。未匹配的建议先选目标任务，右栏随之显示该任务的当前内容便于对照；只有采纳时报过期的建议才出现「以当前版本重新核对」。新任务建议点「编辑为新任务」在右栏打开预填表单。
5. 已忽略、已采纳记录通过「更多 → 显示已处理的建议」查看。任务历史里带「原文」按钮的条目可查看当时依据的材料快照，不受原资料后来修改影响。

手工任务编辑不依赖模型。未保存草稿在页面内切换和全局查找跳转时保留；保存时再次检查版本，避免覆盖其他操作。数据库恢复会清掉旧库的界面草稿与候选缓存。

## 实现与交接

代码位于 `src/task_assistant/`（模型、规则、SQLite、提取协议）、`src/task_ui/`（原生界面）、`src/app/task_assistant.rs`（后台识别协调）。本次由一个实现子代理交付，主代理审查并修复编辑生命周期、组合依赖与多级传播、材料完成证据、事务及过期保护等问题。自动化验证包含原生界面的保存/放弃点击，不只检查纯数据层。

本轮不涉及版本号、安装包、发布或稿件同步格式；任务数据随全量数据库备份，暂不作为 `.gwx` 的任务协作数据分发。
