# 个人任务助手

个人任务助手位于主菜单「任务助手」，数据保存在稿件库同一 `manuscripts.db` 文件内的独立 SQLite 表；不改 `user_version`。新数据库为空时不写演示任务。所有操作限定于任务数据，不接触公文正文和 `DraftInput`。

## 任务管理

每个任务有稳定 UUID、名称、主分类、我的角色、协作分工、目标/完成条件、下一步及期限、任务期限、状态、上级、前置、待核对标记和 revision。名称与完成条件必填；日期空或真实 `YYYY-MM-DD`；正文输入有长度限制。任务可创建、编辑、记进展、完成、重开、取消（需理由）、归档、移出归档、软删除和恢复；关键修改带历史。归档与回收站只读，恢复不会自动重建旧关系。

列表提供关键词搜索（任务名、下一步、协作分工、分类与关联材料来源）、主分类、角色、状态组合筛选，以及今天/逾期、等待、阻塞、已完成、已取消、归档、回收站视图；可按期限或最近更新时间排序。详情可跳转上级、子任务、前置与后续任务。

分类单层且每任务一个主分类。新增和重命名均校验唯一性；删除分类必须指定迁移目标，迁移覆盖活动、归档与回收站任务并记历史。删除任务前展示将解除的关系；确认后不级联删除：子任务变独立，后续任务解除该前置并标待核对。

关系图统一按完成依赖方向检测：任务指向前置，上级指向子任务。程序拒绝自引用、循环和“子任务依赖上级”导致的完成死锁。进入进行中或完成前，所有前置必须已完成且核对；取消前置不算完成。完成上级前，所有子任务都必须已完成（取消不算）。重开前置会把进行中的后续标为阻塞；完成后续或上级若受重开影响，会标记待核对，不自动撤销完成事实。

## 材料整理

可粘贴标题与原文，或从知识库选择一篇资料；也可开启“新入库资料自动整理”。自动整理开关默认关闭、保存在任务数据库；开启后只排队处理之后从现有导入路径新增的资料，不回扫旧库，不自动采纳。手工粘贴和自动整理都走同一条后台识别与候选去重链路。

模型沿用当前 AI 管理中配置的辅助模型和 OpenAI 兼容客户端。资料原文读取与模型请求在后台线程，界面轮询结果；模型失败可重试，识别忙时备份恢复保持禁用。可以取消本次结果，程序会等当前请求结束后释放忙状态，不会采纳迟到结果。材料标题必填、最多 200 字；材料上限 1 MB，输出上限 128 KB、候选最多 30 条，系统不静默截断。自动整理队列最多 32 篇、正文合计 8 MB，超限会提示，资料仍在知识库中，可分批手动整理。

候选支持新任务、进展、责任/期限/范围、完成证据、意见与待决事项。每条保留不可变材料快照、SHA-256 指纹和真实存在于原文的摘录；意见记录提出主体、针对事项及原意。目标只能是识别时上下文中的任务 ID；上下文之外不得由模型匹配，用户可以在待整理项人工选择目标。已有目标候选记录识别时 revision；人工修改后采纳会过期拦截，用户可显式重新核对当前版本再采纳。新任务候选先进入可编辑草稿，用户可补分类、上级、前置后保存。任务变更、来源历史与候选“已采纳”状态在单个事务完成；已报完成只作为建议，程序不自动闭合任务。稍后与忽略均保留，忽略项可恢复。

模型最多看到最近 50 项未归档、未删除任务；任务多于此数量会明确提示，目标校验也只接受这同一上下文里的 ID。没有有用变化时可成功保存材料快照并产生零条候选；同标题、同正文版本不会重复生成候选。失败不会保存去重标记。

## 数据安全与验收

任务表使用 `manuscripts.db` 独立连接，可随数据库备份。数据库恢复前释放任务连接，恢复后重新打开；后台识别完成前恢复受忙状态拦截。SQLite 写锁等待最长 10 秒，数据库错误在页面显示。

专项测试：`cargo test --locked task_assistant`。原生界面样张测试：`cargo test --locked task_assistant_samples -- --ignored`，输出 1280 和 760 宽度 PNG 至 `tmp/`。样张和纯 Rust 测试不能替代 GUI 手工验收。

当前未完成的验收：真实模型端点联机识别（含空候选、失败重试与多任务人工匹配）；GUI 中输入法编辑、备份恢复竞争、筛选组合、关系解除与候选过期重核流程的手工操作。代码层已验证模型响应协议、证据、目标、来源版本去重、事务采纳与过期保护。

## 本机操作顺序

1. 主菜单打开「任务助手」，展开「分类管理」建立工作领域或专项分类。
2. 点「新建任务」，填写名称与完成条件；下一步、期限、上级和前置可按需填写。前置是必须等待的条件，普通查看顺序使用期限排序。
3. 保存后在清单选择任务，记进展或调整状态；要取消任务，进入编辑选择「已取消」并填写理由。归档只适用于完成或取消的任务。
4. 展开「材料整理」，粘贴标题和原文，或选择已有知识库资料；核对候选的当前值、建议值和摘录后采纳。未匹配的候选先手工选目标，过期候选使用「以当前版本重新核对」。
5. 已忽略、已采纳记录通过「显示已处理记录」查看。任务历史中的「来源原文快照」可查看当时依据，不受原资料后来修改影响。

手工任务编辑不依赖模型。未保存草稿在页面内切换和全局查找跳转时保留；保存时再次检查版本，避免覆盖其他操作。数据库恢复会清掉旧库的界面草稿与候选缓存。

## 实现与交接

代码位于 `src/task_assistant/`（模型、规则、SQLite、提取协议）、`src/task_ui/`（原生界面）、`src/app/task_assistant.rs`（后台识别协调）。本次由一个实现子代理交付，主代理审查并修复编辑生命周期、组合依赖与多级传播、材料完成证据、事务及过期保护等问题。自动化验证包含原生界面的保存/放弃点击，不只检查纯数据层。

本轮不涉及版本号、安装包、发布或稿件同步格式；任务数据随全量数据库备份，暂不作为 `.gwx` 的任务协作数据分发。
