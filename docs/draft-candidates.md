# 起草页候选区：设计与实现说明

写稿时暂时用不上、以后可能还要用的文字，移出正文放进候选区；需要时只挑其中一部分插回正文。用户说明见 `docs/help/06-editor.md` 的「候选区」一节。

## 需求取舍（已与使用者确认）

- **归属**：每篇稿件各一份，不做全局共享。
- **取用**：插到正文光标处，用掉的部分从候选里删去，其余留着；想保留就用「复制」。整条用完自动消失。
- **选取**：拖选、双击选一句、三击选一段；不做逐句勾选。
- **整理**：左栏按来源一级小节分组；不做条目命名、不做追加到已有条目。
- **版本与同步**：只随稿件保存，不进版本快照、离线同步 ZIP 与三方合并；复制稿件不带候选。
- **不支持的模式**：版式预览、版本对照没有源码编辑框，不显示候选区。

## 代码位置

| 文件 | 内容 |
|---|---|
| `src/manuscript/candidates.rs` | `draft_candidates` 表（幂等建表，不单开 `user_version` 档位）、整组读写 |
| `src/draft_page/candidates.rs` | 会话状态 `CandidateState`、与稿件库对齐、移入/插入/删去/清空/撤销、断句与分组等纯函数 |
| `src/draft_page/candidate_panel.rs` | 底部折叠条与展开面板、右栏编辑框、端到端 UI 测试 |
| `src/draft_page/editor.rs` | 源码编辑框右键菜单挂接 |
| `src/app/session.rs` | `Ctrl+Shift+X`；关标签与 `remember_session` 时强制落盘 |

## 存储模型

内存里的 `CandidateState.items` 是准数，稿件库只是落盘副本：每次改动把这篇的候选整组重写一遍（条目少，省去逐行对账）。在右栏打字时停手 1.2 秒再写；关标签、切标签、关窗前强制写。

`sync` 每帧比对会话的 `manuscript_id` 与 `loaded_for`：换了记录就从库里载入；新稿还没入库时条目只在内存，一旦拿到 id（首次保存或自动建档）就把攒下的条目写进去。因此各处打开、保存稿件的代码都不需要知道候选区。

## 已知的坑

- **右键丢选区**：egui 编辑框在任何鼠标键按下时都会把选区收成指针处一点（`TextCursorState::pointer_interaction` 里的 `any_pressed`），右键菜单弹出时选区已经没了。`keep_selection_on_secondary` 在右键按住到松开的几帧里把绘制前的选区放回去。正文编辑框与候选右栏共用；`right_click_keeps_the_selection_and_moves_it_into_candidates` 去掉这段修正会失败。
- **`Ctrl+Shift+X` 会顺带剪切**：Windows 上 egui-winit 的 `is_cut_command` 只看 `command && X`，带 Shift 也报一次 `Event::Cut`。快捷键处理时要连同这帧的 `Cut` 事件一起吃掉，否则编辑框先把选区剪进剪贴板。
- **双击只选到逗号**：egui 的 `select_word_at` 把连续汉字当一个词，遇标点停。候选右栏在 egui 选完词后按 `sentence_range` 扩到整句；正文编辑框不改。
- **与编辑框自己的撤销**：候选区的撤销点只在正文未再改动、且 30 秒内有效，正文与候选一起退回。编辑框的 `Ctrl+Z` 只退正文，用它撤回「移入」会让同一段话在正文和候选区各留一份——只重复、不丢字，已在帮助里说明。
- **测试里的连击**：端到端测试用固定步长推进时钟，前后几次点击相隔太近会被 egui 连成三击（整段全选）。双击前要先把时钟拨开。
