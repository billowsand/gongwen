# 接口类技能：设计与实施方案

> 2026-10-05。依据本次产品讨论与现有代码整理。状态：设计稿，尚未实现。
> 本方案补充 `ai-agent-workbench.md` 第 16.8、16.9 节；实施后再更新原文及交接。

## 〇、分层与实施状态（2026-10-05 修订）

讨论后分成两层，先做第一层，技能层（本文第一节起的内容）暂缓：

- **第一层：接口自动填报（已实现，待真机验收）**。数据接口页改为卡片列表 + 详情；
  「从文档添加」粘贴文档或选文件（文本 / Markdown / JSON / YAML 直读，Word / PDF 走
  `doc_import`），程序先解析 cURL、`GET /路径` 请求行、JSON 示例与服务器地址，凭据提成
  `{secret:名字}`，再把**脱敏后**的资料交给起草模型整理名称、说明、参数含义与只读性质。
  合并时程序认出的结构优先；模型给的地址、参数名、返回字段要在资料里找得到，找不到的
  不收并说明。只查询且配置齐全的候选自动用样例值试调一次，调通后按真实返回推断返回映射与
  业务成功判据。改数据的接口不能加入，判断不了的要人勾选确认。
- **第二层：接口类技能**（本文其余部分），以后在第一层的接口上包「什么时候调、怎么串、
  结果怎么解释」。

第一层顺带补的运行层缺口：

- `ApiEndpoint.success`：业务成功判据（`/code` 等于 `0|200`）；HTTP 200 加业务失败、
  返回登录页（HTML）都不再当成功；返回超过 4 MB 直接报错，不再静默截断。
- `http.call` 截掉超过 50 条的部分时告诉模型「共 N 条，只给了前 50 条」。
- `spec_of` 把接口的说明、参数名、类型、样例交给模型（原生工具调用与文本兜底共用）。
- 实测走 `api::trial`，与正式调用同一套「组请求 → 发出 → 状态 → 成功判据 → 映射」，
  出错时留着请求与原始返回给人看；结论记进 `api-tests.json`（只记结论与配置指纹，
  不存返回内容）。指纹不含名称、说明、参数说明与样例；**密钥变更不会让记录过期**。

代码：`src/agent/api_import.rs`（及 `api_import/` 下的 `scan`、`build`、`redact`、`infer`、
`model`）、`src/app/api_settings.rs`、`src/app/api_settings/import.rs`。

待验收：用内网真实接口文档与 MiniMax 2.7 / DeepSeek v4 flash 跑一遍识别；目前只有
脚本模型与本机假服务的测试。

### 0.1 按节写的文档、多接口与密钥（2026-10-05 补）

真机反馈：上传的文档能认出接口，但要填 API Key 的接口没法用。原因三条：鉴权常在文档开头
单独一节，下面的接口只写「请求地址 / 请求方式」和参数表，程序只看 cURL、模型输出里也没有
请求头字段，鉴权整个丢掉；导入页的密钥输入框输入一个字就消失（每帧按「值为空」才画）；
加入以后只有列表底部折叠的密钥表能填，得自己写 `{secret:名字}`。另外表格写法（Word 最常见）
与「请求地址」「请求方式」分两行的写法程序都不认，接口多时全靠模型、模型一截断就整份作废。

已改（程序层，不依赖模型）：

- `api_import/sections.rs`：按 Markdown 标题分节（也认 `2.1 xxx`、`三、xxx`、整行加粗的标题），
  节里认「请求地址：」「请求方式：」字段行、两列键值表、小标题下一行的值，参数表（参数名 / 类型 /
  必填 / 说明 / 示例 / 位置列，按前文「请求参数」「返回参数」分归属；嵌套字段、对象数组跳过并说明），
  以及接口总览表。Word 转出来没有表头行（首行空表头）、键值行与参数表混在一张表里也认。
  方法只在地址以外找（`/fav/delete` 里的 delete 不是方法）。
- 同一地址在总览表、详细一节、cURL 里出现几次的合成一个（`merge_requests`），结构以 cURL 或
  详细一节为准，名称取节标题，参数说明互补；方法明写了又不一样的不合。
- `api_import/auth.rs`：认文档里的鉴权方式（「请求头中携带 X-API-Key」、`Authorization: Bearer …`、
  「URL 参数中带 access_token」、公共请求头表），套到同一份文档里没带鉴权的只查询接口上，**同一个
  密钥只问一次**；cURL 带了、别的接口没带的也照着补。模型输出加了 `auth`（位置、名字、是否 Bearer、
  依据），名字必须在资料里出现过才收，值一律不收。要签名、要先登录换令牌的，说明程序做不了。
- JSON 示例认 Word 转出来的 `\[`、`\_` 转义。地址带 delete / update 等字样的写明依据，要人确认。
- 密钥：空值算没填（以前会发出 `Bearer ` 空令牌）；`Trial::auth_rejected` 认 401/403、200 回登录页、
  业务码 401/403、返回体说未授权或令牌失效，测试记录记 `auth`。
- 界面：导入页候选上方一张「鉴权」卡片，每个密钥一个常驻的打码输入框，写明带法、用在哪些接口、
  状态（未填 / 被拒绝 / 已调通 / 文档示例值）；粘贴后离开输入框，用到它的接口自动重测，输入时
  不自动试调。文档没写鉴权的可在这里选带法加上。详情页加「鉴权」区（粘贴 Key、改完离开输入框自动
  重测；没配的可以加，可选同一服务器的其他接口一起加），实测鉴权没过给提示。卡片标「缺密钥」
  「鉴权没过」，密钥表写明用在哪些接口、哪个鉴权没过，改名时接口里的引用跟着改。

下一步（接入循环，`ai-agent-workbench.md` 的智能体机制）：识别后不止一轮——试调失败由程序分类
（连不上 / 鉴权 / 404 / 400 / 映射为空），能改的交模型用工具改工作副本再试，改不了的问用户
（缺 Key 弹粘贴框），直到调通或多轮不行再停下说明卡在哪；长文档分段盘点、逐个整理，程序按路径查漏。

## 一、产品定位与边界

用户管理的是「政策查询」「月度统计查询」这样的技能。HTTP 接口是技能的数据来源与执行方式。
新增的最终产物是一份完整的 SKILL.md：说明功能、输入、调用流程、结果处理、失败处理和测试用例。
从资料识别到补齐配置、测试、保存，在一个技能编辑流程中完成。

沿用现有红线：外部调用只查询，不改变外部系统状态；正式稿只能由人合并。
接口类技能默认输出查询报告；以后用于起草时仍走工作稿、事实闸门和人工接受。
本次不引入另一套智能体框架，也不增加任意网址访问、脚本执行或递归调用技能的工具。

一个技能可以声明多个接口，按任务组合调用。一个文档中的多个接口不必一一生成技能：
AI 先列出接口与建议能力，用户选择组合，例如「检索政策 → 读取全文」组成一个政策查询技能。

## 二、现状与改造依据

- `agent/skill.rs` 已有 YAML 前置信息、工具白名单、流程、正文提示词和启停。
- `agent/skill_files.rs` 已支持用户技能保存、校验、导入导出；当前打包仅包含 SKILL.md。
- `agent/api.rs` 已有请求模板、输入、独立密钥、返回映射、HTTP 执行与结果限制。
- `agent/tools/http.rs` 已将查询结果放入证据包；限定工具名为 `http.call:<接口 id>`。
- `app/agent_settings.rs` 分开维护技能、接口、调试台，接口已有后台测试。
- `agent/ops/agent.rs::spec_of` 对限定接口只去掉 `api` 参数，未按实际接口生成完整参数定义。
- `agent/router.rs` 已支持 `/技能`、触发词和模型选择，不需要新增一条技能选择路线。

因此，保留工具与引擎，在技能格式中增加接口契约和测试定义，将现有接口配置收为本机绑定。
模型选择与输入框继续使用既有机制，但增加「配置未完成」的可用性过滤。

## 三、界面

### 3.1 技能列表为统一入口

AI 管理 → 技能：顶部为搜索、类型筛选、新增技能、导入、导出。
类型包括「全部」「普通技能」「接口类技能」。默认显示全部。

列表每行显示：名称、用途摘要、类型、启停、配置状态、最近测试结果。
操作为打开、测试、复制、删除。地址、HTTP 方法、技术 id 放在详情中。
状态分开显示，避免把「停用」与「测试失败」混为一谈：

- 配置：待完善 / 待绑定 / 可调用；
- 测试：未测试 / 通过（时间）/ 失败（时间）/ 配置已变更；
- 使用：启用 / 停用。

原「数据接口」分区在迁移阶段保留，改为「连接管理」：维护已有连接与共享绑定，
也给旧技能排查问题。新用户从技能页完成全部日常操作，不需要来回切换。

### 3.2 新增接口类技能

「新增技能」选择「接口类技能」，进入四步编辑流程：

1. **提供资料**：粘贴接口文档、cURL、请求和响应示例；填写可选的业务用途。
   第一版支持文本与文本文件（Markdown、TXT、JSON、YAML）；提供多个资料片段入口。
   后续再支持 PDF、Word、OpenAPI、Postman，第一版不自动访问文档 URL。
2. **识别与选择**：展示识别出的接口、用途、查询性质和资料出处；选择组成该技能的接口。
   缺信息时标出具体缺项，已有配置保留。识别或修正不自动发起外部请求。
3. **完善技能**：填写业务名称、用途、调用规则、输入、返回内容和本机连接。
   默认展示中文表单，请求头、JSON 模板、指针等置于高级配置；可查看完整 SKILL.md。
4. **测试与保存**：填测试参数，运行接口测试或技能试运行，查看结果，再保存并选择启用。

步骤可往返，不要求必须联网测试才能保存。未完成的可保存为停用草稿；配置完整但未测试的
可以启用，保留「未测试」标记。结构不合法或必需绑定缺失则不可运行，并准确说明原因。

### 3.3 技能详情

详情包含四个标签：

- **功能与调用**：用途、适用场景、输入、流程、输出与失败处理；
- **连接配置**：每个接口的地址绑定、密钥状态、请求与返回的高级配置；
- **测试**：结构检查、接口测试、技能试运行及调用过程；
- **SKILL.md**：完整源码，允许高级用户编辑。

SKILL.md 是唯一的技能定义来源，表单由解析结果生成，不独立保存第二份规则。
表单修改只更新对应 YAML 节点，保留未知合法扩展、正文与未修改的流程。
遇到表单无法理解的手写复杂流程，提示使用源码编辑，不能静默简化或覆盖。
在未修改时保持原文；切换源码/表单前检查当前缓冲区，解析失败留在源码页修复。

## 四、文件与 Skill 契约

### 4.1 定义与本机绑定

推荐保留三个存储域：

| 文件 | 内容 | 导出 |
|---|---|---|
| `skills/<id>/SKILL.md` | 功能、接口契约、流程、提示词、测试用例 | 是 |
| `api-bindings.json`（新增） | 技能 id + 接口别名 → 服务地址、密钥引用，或旧接口 id | 否 |
| `api-secrets.json`（沿用） | 实际凭据 | 否 |

接口契约包含方法、相对路径、参数、请求模板、映射和成功判据；部署地址通过 `service` 绑定。
技能编辑器可同时查看和修改两者，因此「完整文档」与「本机可执行」属于同一个产品对象。
跨机器导入后提示补齐绑定，不把内网地址和密钥夹带到分享文件中。
第一版原始资料仅在编辑缓冲区中使用，不保存原始 cURL、完整响应和 Token。
可保留脱敏后的必要说明与样例；字段来源备注不能包含实际凭据。

### 4.2 格式扩展

在现有前置信息中增加显式字段 `kind: http` 与 `http:`，后者包含：

- `version`：契约版本，第一版为 1；未知版本拒绝执行，保留原文。
- `endpoints`：以技能内别名为键的接口契约。
- `tests`：结构化接口测试与自然语言技能试运行用例。

不是新的 Skill 格式；普通技能不写这些字段，按现状解析。
当前前置信息有 `legacy` 参数收集，新增字段必须显式解析与校验，不能落入 legacy 后被忽略。
接口类技能禁止无范围的 `http.call`；必须逐个声明 `http.call:<别名>`。
新增别名由程序在当前技能作用域解析，不能被同名旧接口抢占。

### 4.3 示例（拟新增格式，不是当前可运行文件）

```yaml
---
name: 政策查询
description: 按关键词查询政策原文，返回标题、文号、正文和出处
kind: http
hint: 例如：查询支持中小企业发展的政策
triggers: [查询政策, 找政策依据]
when: { text: any }
output: report
tools: [http.call:search, finding.add, note]
params: { max_turns: 6, max_calls: 8 }
http:
  version: 1
  endpoints:
    search:
      description: 按关键词检索政策原文
      service: policy_service
      access: query
      method: POST
      path: /api/policy/search
      inputs:
        - name: keyword
          kind: text
          required: true
          description: 政策主题或名称
          example: 中小企业
      headers:
        - name: Authorization
          value: "Bearer {secret:policy_token}"
      body: '{"keyword":"{keyword}"}'
      response:
        success: { pointer: /code, equals: 0 }
        mapping:
          list: /data/items
          id: id
          title: title
          text: content
          source: issuing_unit
        destination: evidence
      timeout_seconds: 30
  tests:
    - name: 关键词查询
      endpoint: search
      args: { keyword: 中小企业 }
      expect:
        status: 200
        list: /data/items
        list_type: array
        item_required: [id, title, content]
        min_items: 0
    - name: 查询任务试运行
      request: 查询支持中小企业发展的政策，并说明出处
      expect_tools: [http.call:search]
flow:
  - step: agent
    prompt: 查询与整理
---
```

正文至少包含功能范围、参数说明、调用顺序、结果解释、失败处理、测试说明，
并提供 `## 查询与整理` 提示词，显式使用 `{request}`，写清参数来源、如何询问缺项、
如何形成 `finding.add` 结论、查无结果如何答复、不得编造返回中没有的事实。
程序可将已验证的契约摘要注入步骤上下文，不能假定所有 Markdown 正文都会被引擎读到。

示例中的 `access: query` 是声明，不能证明接口只读。识别阶段须提供文档依据；
明确为提交/删除/审批的接口不允许加入；性质无法判断的保留待确认状态，未确认不能启用。
GET 与 POST 都要检查用途，不能靠 HTTP 方法判断是否改变外部系统状态。

## 五、智能生成

### 5.1 使用现有大模型

资料解析使用当前起草模型 `ModelRole::Draft`，不要求额外配置模型。
模型服务未配置时保留手动新增入口，并在智能分析按钮旁说明缺少模型。
生成器是专门的后台配置任务，不获得正文写权限，也没有 HTTP 工具或文件执行权限。

先用确定性解析识别 cURL、JSON 等结构，再将脱敏资料和业务用途交给模型。
模型返回受限的「候选技能」结构，由程序反序列化、校验、生成 YAML 与 Markdown；
不直接执行模型输出的代码或命令，也不直接保存模型任意拼出的 SKILL.md。
资料中的指令当作资料内容，不能提升为系统指令或放宽工具权限。

### 5.2 字段来源与缺项

候选结构应带接口清单、建议技能组合、字段来源、缺失信息、只查询依据和不支持项。
字段来源分为「资料明确提供」「用户补充」「AI 建议」，在编辑器中可查看原文片段。
名称、用途、触发词可由 AI 建议；地址、参数名、鉴权、返回路径不得以猜测替代资料。
基础地址缺失时让用户填写；没有响应样例时，允许先完成请求绑定，再显式测试取得响应，
随后用脱敏响应补全返回映射。响应不自动上传，用户点击「根据返回完善」后才分析。

第一版只支持现有执行能力：GET、查询用 POST、JSON 请求体、JSON 响应、文本/数字/布尔输入。
数组输入、上传、WebSocket、动态签名、自动登录、分页循环等不支持能力须明确标注，
不能生成一份看似完整但无法执行的技能。有数组的响应列表不受此输入限制。

### 5.3 凭据处理

在模型调用前提取 Authorization、Cookie、API Key、已知 URL/请求体凭据字段，
转为本机密钥与占位符。提供「将发送给模型的资料」预览，允许继续遮蔽自定义敏感字段。
不能承诺规则能识别所有敏感内容；编辑器明确显示所用模型服务及实际发送内容。
所有请求日志、原始返回预览、错误信息同样经过脱敏；测试记录不保存完整返回。
共享服务的凭据由绑定映射到具体本机密钥，契约只写逻辑密钥名。

## 六、运行与调用

加载接口类技能后，从 SKILL.md 契约与本机绑定编译出当前运行快照：
有效的 ApiEndpoint、技能内别名表、工具参数规格与测试定义。
新契约不再写入 `apis.json` 形成第二个权威定义；旧接口继续从该文件读取。

对外仍使用 `http.call:<别名>`，在工具执行入口按当前技能作用域定位，
内部结果键使用稳定的技能 id + 接口别名标识，避免不同技能的 `search` 证据冲突。
已有旧技能仍按原全局接口 id 解析，旧证据键不改。

必须补齐 `spec_of`：接口描述、输入类型、必填、说明全部进入 ToolSpec。
原生工具调用与文本兜底共用同一份规格，程序仍在执行前校验必填、类型和允许参数。
调用参数只来自用户请求、已确认输入或前步结果；未填必需参数要先问用户。
修改运行中的配置不改变当前调用；下次发送使用新快照。

AI 输入框继续用 `/政策查询` 或现有路由选择技能。配置不完整的技能在列表中显示原因，
不参与自动路由；启用状态、配置完整性与测试结果分别判断。
第一版其他起草技能若要使用同一数据源，继续通过已有接口配置与白名单，不新增技能调用技能。
后续如需复用新契约，另行增加显式依赖绑定，不能暴露全部用户接口给自由任务。

## 七、测试闭环

### 7.1 三种检查

| 检查 | 是否访问接口 | 判据 |
|---|---|---|
| 结构检查 | 否 | Skill、流程、白名单、绑定、参数、模板、映射、只查询状态合法 |
| 接口测试 | 是，用户点击触发 | 请求准备、HTTP 状态、业务成功字段、返回形状、映射结果 |
| 技能试运行 | 是，用户点击触发；使用模型 | 真实引擎与调用轨迹、必需工具调用、确定性断言、最终查询答复 |

接口测试复用正式调用的 prepare → execute → 校验 → map_response，不能另写一套请求。
HTTP 200 但业务 code 失败、返回 HTML 登录页、字段错位都不得标为成功。
业务成功字段与断言来自资料/用户定义；没有定义时显示「未配置业务成功判据」。
空数组可以是合法结果，只有测试明确要求非空才算失败；空样例不能证明条目字段已验证，
显示「联通通过，条目字段待验证」，保留之前通过脱敏样例的映射检查信息。

### 7.2 结果展示

接口测试显示分阶段结果、耗时、脱敏请求、HTTP/业务状态、原始返回和提取后的业务条目。
把错误定位到具体动作，例如「Token 未填写」「/data/items 不是数组」「正文 content 缺失」。
响应达到现有读取上限时显示限制原因，不把截断的结果当完整成功。

技能试运行使用独立 Board 与证据包，沿用引擎事件展示调用顺序、参数与答复；
不写当前稿件或正式会话，不允许写工作稿工具，不借测试机会访问未声明的接口。
测试成功说明程序断言通过；模型答复的业务正确性仍由用户查看，不能由模型自评定为通过。

### 7.3 记录、过期与取消

测试记录单独存 `api-test-results.json`，仅保留用例 id、时间、阶段状态、摘要和配置指纹。
实际响应、Token、未经脱敏的参数不落盘。详情预览仅在当前会话内。
指纹包含规范化契约、流程、测试定义及本机绑定；凭据变更通过本机修订号使记录过期，
不保存密钥内容或可用于离线猜测的密钥摘要。
接口测试和技能试运行分别计算指纹，单纯正文说明修改不必使接口联通结果过期。

后台任务可停止；停止后不再发下一次请求，已发出的阻塞请求按超时结束，
通过任务 id 防止旧结果回填新编辑器。修改配置后旧测试结果只作历史，不能覆盖新状态。

## 八、保存、导入导出与兼容

用户点「保存」同时保存 Skill 和本机绑定；所有内容先校验、写临时文件，再替换。
跨文件更新要有事务日志/恢复步骤，不能只依次写两个文件后声称原子保存；
加载时发现未完成保存应恢复到上一份一致状态。保存期间运行层继续使用旧快照。
草稿可保存但不加载执行，不得出现旧技能已被覆盖而新绑定未保存的半成品。

导出仍以 SKILL.md 为核心，包含接口契约与脱敏测试用例，不包含本机绑定、凭据、
测试响应和测试通过记录。导入严格校验新字段；同技能 id 冲突展示差异，让用户选择覆盖或副本，
不沿用目前接口导入直接按 id 覆盖的方式。

旧技能与 `apis.json` 无需强制迁移。提供「将连接创建为接口类技能」：
选旧接口、填写业务用途，AI 生成 Skill，先绑定到原接口 id，原技能调用不受影响。
此类绑定明确显示「使用共享旧连接」；若转为技能内契约，采用显式复制动作，之后互不覆盖。
删除技能只删除自身定义与私有绑定；共享旧接口和共享密钥不级联删除。
默认导出旧连接转换得到的技能时，将有效配置转为脱敏契约，不能只导出一个无解释的旧 id。

## 十、实施顺序与验收

### 第一期：契约与运行基础

显式解析新格式、绑定编译、参数规格、业务响应校验、测试断言与指纹。
先用手写示例 Skill 和本机假 HTTP 服务跑通，无需依赖真实模型。
验收：普通/旧接口技能兼容；别名隔离；参数与白名单拦截；HTTP 200 业务失败被识别；
测试和正式调用产生相同映射结果；保存中断可恢复。

### 第二期：统一技能管理与测试

列表、详情、手动新增、绑定编辑、接口测试、源码编辑、草稿与启停，旧连接转换和导入导出。
验收：一页完成创建与测试；换配置不显示旧成功；共享连接不误删；源码/表单不丢自定义内容；
换机器导入提示绑定，导出不泄露地址和凭据。

### 第三期：智能新增与完善

文本/cURL 资料识别、多个接口选择、字段来源和缺项、响应补全、后台生成与取消。
验收：文档可生成可运行 Skill；仅有请求时不编造映射；不支持能力准确报出；
凭据在模型输入与日志中脱敏；模型输出不合法时保留已编辑内容。

### 第四期：完整技能试运行与真机验收

真实引擎试运行、调用过程、答复、确定性断言、结果过期、交接说明。
验收：用户用自然语言完成真实查询；缺参会询问；测试不污染稿件；
实际部署模型的原生工具调用与文本兜底都拿到完整参数；网络/业务/映射失败可定位。

完成每一期同步 `ai-agent-workbench.md` 第十三节交接与第 16.8、16.9 节。
代码改动运行 fmt，及与改动相关的解析、假 HTTP、路由、保存恢复、试运行隔离测试；
最终运行仓库要求的检查。设计文档本身不要求构建或重新生成 PDF 样张。

## 十一、第一版范围

四期构成第一版完整闭环，不能把智能新增和测试长期留为后续可选项。
第一版包含粘贴资料、文本导入、多接口技能、结构化 Skill、本机绑定、接口测试、技能试运行、
旧配置兼容和脱敏导入导出。复杂文档读取、规范文件专用导入、登录续期、动态签名、
自动分页、其他技能引用新接口契约另行设计。
