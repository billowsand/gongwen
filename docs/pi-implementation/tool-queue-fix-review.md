## 根因与修复

用户报告的错误来自 src/pi_agent/process.rs 的单槽保护。原桥的两项并发调用会同时发出
两条 tool_request；主代理用基线代码和自造参数离线复现 emitted=2，第二条撞上 pending_tool。
这属于 host 与 Rust 的调度契约不匹配，与模型输出长度无关。

Pi 将桥改为有界 FIFO：调用可同时入队，向 Rust 一次只发送一项，当前 callId 的结果返回后
才发送下一项。工具和提问共用队列；只有真正发出提问才暂停计时。取消拒绝在途与排队请求，
不再发送后续项；未知、排队、重复、迟到的回复不能串单。工具/问题预算不变。
Rust 的单槽、权限、事实来源持久化和交付保护保持原样，没有用提示词禁止模型批量调用。
