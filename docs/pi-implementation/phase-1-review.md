## Findings 与处置

| 优先级/性质 | 问题 | 修正 |
| --- | --- | --- |
| P1 how | Rust 使用 read_until/lines 读完后才检查大小，无换行输出可无限分配 | 读取时限制字节数；stderr 也限额；stdout 改有界队列 |
| P1 how | 同步写 init 可能被不读输入的 host 堵住，主循环不能超时/取消 | stdin 独立写线程，控制消息有界排队；主循环仍可超时回收进程 |
| P1 how | 已排队的 completed 可在取消后被接受，且收到 completed 就成功，不核对真实退出 | 取消优先；完成后限时等待并确认正常退出；异常或不退出均不交付 |
| P1 how | 只有单文件上限，模型可建立很多文件耗尽磁盘 | 写入前检查 work 总量 64 MiB、文件/目录总数 1024，含将创建的父目录 |
| P1 how | JSON.parse 报错可能带 init 原文片段，其中可能含密钥 | 解析错误只给固定文案，不回显原文；增加回归 |
| P2 how | 输出上限过大时虚构更大的上下文窗口 | 保留真实窗口，收窄输出预算 |
| P2 how | 宿主提示词禁用表格，与共享公文技能冲突 | 表格/标题/附件写法以技能文件为准，消除重复矛盾规则 |
| P2 how | 用是否出现 U+FFFD 判断 UTF-8，误拒合法原文符号 | JS 对字节严格解码，Rust String 不重复误判；增加非法字节/合法符号回归 |
| P2 how | Pi 交付逻辑和测试让 jobs.rs 超过约 2000 行 | 拆到 src/app/pi_jobs.rs，app.rs 登记；jobs.rs 只保留事件路由 |

后两项拆分属于主代理批准的最小维护范围扩展；没有拆分旧引擎或改变小模型路径。
