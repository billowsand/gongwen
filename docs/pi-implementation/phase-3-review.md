# 第三阶段主审与验收

2026-11-02。基线 `d7c236e`；由用户指定的本机 Pi 实现，主代理编写两轮提示词、审查、修正及验收。
本阶段不改版本、不提交、不推送、不发布。原始 worker 报告保留，不代表最终验收结论。

## 实现结果

- 同一工作区和 Durable SQLite 恢复；已交付成品使用不可变快照及回执重放，绑定运行与请求 ID、字节数、SHA-256，避免重跑模型或重复交付。
- 每轮保存正式基线、材料、模型引用、纯用户答案与事实来源。会话保存运行引用；库内稿件必须先保存引用才启动。未保存新稿明确提示重启恢复限制。
- Rust 文件锁覆盖完整运行生命周期，Node SQLite 独占锁覆盖孤儿 host；进程退出即释放。中断的不可安全重放工具由模型先读实际文件再继续，异常恢复循环有上限。
- GUI 准备工作在后台完成，主线程只接收就绪事件、保存引用、确认开跑。取消、过期事件、保存失败均有收尾；准备失败保留原提案。
- 固定 Node 22.22.3、Pi 1.4.0、host 0.2.0/协议 2。运行时包含完整锁定生产依赖、许可证及逐文件清单；目标机无需 npm、Python 或全局 Pi。构建脚本可使用本地官方压缩包及完整 npm 缓存。
- Windows、deb、Arch 打包及 CI 接入严格校验；缺少或不匹配的 Pi 运行时会阻止打包。Linux 增加 Node 的 GLIBC、GLIBCXX、解释器及动态库审计。

## 主审修正

重点修正了后台准备与 GUI 实际桥接对象不一致、重启错误走新任务分支、请求内容/哈希顺序、恢复工作区层级、材料角色与哈希校验、正式文种及选区过期检查。

来源快照改为内容寻址的 `sources/<SHA256>.md`，关键状态落盘失败必须上抛；旧来源不被中断覆盖。用户回答只把纯答案作为事实，模型问题中的假设不进入事实台账。成品仍经现有强制闸门和人工接受路径进入正式正文。

补充 Rust 全生命周期锁、桥接结束时清理迟到回答、执行 Node 前验证其哈希、恢复回执请求 ID/大小校验，以及完成事件之后异常不能被成功退出定时器覆盖的回归。

另审查并修正 Linux Node 安装目录、带连字符的平台配置读取、Debian libstdc++ 依赖、Arch/CI 审计工具安装及源测试依赖准备。范围补充包括 `packaging/debian/depends.sh` 与 `src/app/session.rs` 必要的会话保存可见性。
