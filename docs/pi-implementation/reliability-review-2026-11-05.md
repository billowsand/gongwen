## 已修复

1. **P1：接口重定向可能转发自定义鉴权头/请求体。** `agent::api::send` 原先使用默认跟随重定向的 HTTP 客户端；即使标准 Authorization 被客户端剥离，自定义 X-Api-Key 等并没有这份保证，307/308 也可能转发请求体。新增 `net::api_client` 禁止自动重定向，3xx 按失败处理。原来依赖跳转的配置须改成最终接口地址。新增双本机监听端口测试，验证原请求带密钥、重定向目标未收到连接。
2. **P1：清理误把坏运行记录当成孤儿，可能删掉尚未取回的成品。** `prune_workspaces` 原先将 `read_from` 的所有错误视为没有记录，包括 JSON 损坏、权限异常等。现在只有确认 `run.json` 不存在才进入孤儿清理；清理锁一直持有至删除结束。新增八天前目录夹具，验证坏记录与成品保留、真正孤儿删除。已有运行占锁保护测试继续通过。
3. **P2：单条接口资料被截断，却仍上报 `truncated=false`。** 原判断只看条目数，正文超过 2000 字符被直接裁切。现在单条返回 `text_truncated`，聚合截断标志覆盖条目和文本，并明确要求缩小查询、不能按片段作完整统计。证据只保存实际交给模型的部分。新增一条长中文资料回归。
4. **P2：独立文字复核被写作模型配置连带禁用。** `revise_chat` 原先首先解析 `aux_chat()?`，Pi 提供商被删/停用会让有效的独立复核配置也失败。现在独立提供商复核不解析写作配置；借用写作模型时仍如实报错。新增失效 Pi + 有效复核的回归。
5. **本机运行时落后于源码。** `runtime/pi` 的 manifest 虽标 0.3.5，`bridge.mjs` 与 `prompt.mjs` 尚未包含最新接口接线。已用缓存的固定 Node 归档和 `npm ci --offline --omit=dev --ignore-scripts` 重建 darwin-arm64 运行时，通过完整 manifest 验证和禁止公网验收后替换；旧目录留在 `tmp/pi-runtime-before-review-*`。这是本机忽略目录产物，其他平台仍应由发布流水线重建。

## 后续工作

1. **P2：停止后慢领域工具仍可能继续占用资源。** `src/pi_agent/process.rs` 在独立线程调用 `tools.call`，停止会回收 host、丢弃迟到结果，但不会停止该线程里的 HTTP 请求/检索/LLM 重排。反复停止重开可能重叠消耗连接、模型额度和线程。不是迟到结果写正文的问题；已有测试证明迟到结果不会交付。完整修复需要将取消信号贯穿 `PiKnowledge` / `PiApis`、共享检索与网络层，并增加在途资源限制；本次没有以等待线程结束的方式阻塞停止按钮。建议下一轮优先做。
2. **P2：长接口结果缺少通用继续读取能力。** 当前 `api_call` 最多返回 20 条、每条 2000 字符；共享映射层本身最多保留 3000 字符。此次已避免伪装完整，但无筛选/分页参数的接口仍无法取得后半内容。需要新增本轮有界结果缓存和按位置读取工具，并打通 host schema、恢复快照及体积预算；只增大常量不能解决长资料问题。真实接口本身有分页参数时可以按该参数继续调用。
3. **发布验收仍有资源与环境依赖。** 需补 20 万汉字/256K 上下文压力、较强模型同题业务对照、真实知识库与接口，以及干净机安装/升级、写入撤销、进程强杀恢复、多窗口竞争、Windows/Linux/macOS 打包与字体/签名整链。当前本机假模型测试和 darwin-arm64 离线运行时验收不覆盖这些结果。本次未调用收费外部模型，也未操作用户实际稿件。

旧 `engine/router/ops/skill_job` 与检查点兼容仍服务历史记录，不建议在上述验收完成前大批删除；沿用 `phase-5-review.md` 的退役边界。
