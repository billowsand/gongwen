# 设置页风格学习统一到 Pi

2026-11-04。用户要求风格学习的后端统一由Pi执行，入口可留在设置里。基线为 `831db28a` 加上一轮已完成、尚未提交的写作上下文改动；本轮保留这些改动，不提交、推送、发布或安装。

## 交付

- 设置页「AI 管理 → 风格」保留新建、编辑、重新学习、保存和导入导出。选择1–10篇库内样稿，也可通过统一异步文件对话框上传文件；在后台转换成文本，不自动导入知识库。
- 新标准技能 `gongwen-style-learn`（含格式参考）由内置资源嵌入，可在技能管理页复制编辑、启停和导出。它是设置页入口技能，不出现在正文输入框；常规写作不带它，风格任务只带它。
- 设置页不再调用 `LmBackend` / `assist_chat` / `style::learn`。`pi_agent::style_learning` 仅准备统计与样稿、组装现有PiJob、调用一次现有run、解析结果，不另写模型调用或调度循环。
- 同一个Pi模型配置、实际窗口探测、文件工作区、Durable Harness、预算/阶段、取消/超时、不可变回执和进程回收链。缺Pi配置明确失败，不回落辅助模型。
- `submit_style` 交 `work/style.json`：只允许name/note/occasions/description/example_numbers，64 KiB上限。候选编号必须存在且不重复；身份、来源、统计、启用、默认状态由程序与用户管理。风格任务不注册正文提交、外部资料/表单工具。
- 回执kind为style、快照为final.json，仍走submitted/completed传输和哈希核验，Rust返回独立PiOutcome::Style。普通稿件拒收风格产物；风格任务拒收正文/清单。设置页结果通道与稿件任务通道隔离，风格不能进入正文或提案。
- 内容先送风格编辑器，点保存才写styles.json。取消后的排队结果丢弃，原档案不变；失败保留样稿选择以便重试。重新学习保留用户的id、名称、说明、文种、场合、默认、启用和使用次数，只更新学习内容与来源。
- 上传样稿以角色style_sample保存在本机Pi工作区。StyleProfile新增带默认值的learning_workspace，重新学习前验证工作区类型、材料索引与哈希；跨机导入的旧工作区不可读时明确报错，可重新选样稿。库内样稿仍按真实来源id读取当前内容。
- 不对新风格描述运行旧事实疑点扫描。原StyleProfile字段与导入导出格式兼容；共享模块里的旧模型学习函数仅供历史流程兼容，新设置入口不再调用。

## 范围与兼容

host内部补丁0.3.4，协议3和Pi依赖1.4.0保持；应用根版本不变。新运行需要同步的host文件；旧中间运行仍受既有host版本保护。原写作上下文、大材料、日期与词库改动保持。

生成的style.json是Pi的内容草稿，用户保存后成为现有风格库档案，导出沿用既有档案导出按钮。样稿库和正式正文不因学习而改变。

当前设置页提供停止及重新学习，不新增崩溃后“接着学习”按钮；Harness/回执底层恢复能力仍由相同内核处理，已有回执可重放。未扩大到任务助手、数据接口和其它辅助调用。
