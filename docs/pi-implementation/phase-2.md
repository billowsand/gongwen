## 明确契约

### 独立模型与技能

- 配置新增 `pi_model: ModelRef`，缺省空、向后兼容；AI 管理→模型服务复用现有 model_picker 增加“智能写作（Pi）”。空值时给出明确配置提示，不偷偷回落到9B起草模型。地址密钥仍只在 providers 中，不落到工作区/argv/日志。
- 生成参数可以先沿用现有生成设置并在说明里写清，不能放大实际窗口。小模型的 draft_chat 不因配置 Pi 改变。
- 新增5份标准技能（英文 name，中文 description/正文）：gongwen-draft/revise/review/imitate/research；共用现有 gongwen-markdown 的语法/文种/模板。标准 frontmatter+自然语言步骤，不使用 flow、step、程序变量插值。
- Rust 以本地资源安装到只读技能目录；host 列出技能索引、按需读完整文件。提供 Pi 专用技能选择/自动选项，不能静默忽略输入框上旧技能的已选状态。不要把旧15种技能全部硬映射成流程。
- 修复第一阶段提示词里与技能文件冲突的文案。技能只是指导，权限与交付关卡在程序里。

### 材料、来源与工具桥

- 将粘贴材料和 @引用在后台读取为本轮快照，以安全的编号文件名写 input/materials；保存标题、来源、角色、内容哈希。读不到应明确失败，不静默丢弃。正文与材料读取都限体积。
- 必须区分事实材料与写法/结构样稿：可提供一个简单的 Pi 引用用途选择（事实材料/写法样稿/结构范文/来函），或对仿写技能的样稿用途明确展示。角色由用户/程序确定，不能让模型把样稿升级成事实证据。原稿与用户真实要求可作为来源；模型自己的摘要、候选稿、任意聊天不是新增事实来源。
- 标准工具至少包括 doc_elements（只读当前表单）、kb_search/kb_read、ms_search/ms_read、vocab_search、check_document。只读领域服务复用已有 KnowledgeSearch/RagSearch、ManuscriptSource/SqliteManuscripts、词库与 validator/proofread/ai_guard，不为了复用创建旧 Board+Skill+engine Env。可新增窄接口/测试替身；不重做向量索引。已填写的表单可读，避免反复提问；授权字段仍不得建议、出题或回写。
- embedding/rerank 仍用现有知识库设置与 Rust 检索链，不得拿 Pi 起草模型替代 embedding 或变更已有索引向量空间。
- host 发 tool_request，Rust 后台验证工具名/schema/参数并执行，再以关联调用ID回复。双方限定请求/结果/次数，工具不能写正式稿/表单。工具异常是结构化失败；错run/call ID和迟到回复拒绝。不是对外开放的MCP服务器。
- Rust 登记实际返回给模型的证据（ID、来源/版本或哈希、片段、角色）。提交和 check_document 使用同一事实台账，不采信模型自报的引用清单。样稿的日期、人物、数字不能过事实闸门。
- vocab_search 只证明规范名称/词条存在，不证明某单位或人员参与本次事项；不能把词库整项结果自动加入事项事实台账。正文中的责任、参与等事实仍须材料/实际证据/用户确认支撑。
- RAG 可能阻塞，不能把网络检索放UI线程，也不能让主进程协议循环堵在检索上而失去取消/超时。已停止任务的工具结果必须丢弃。坚持第一阶段的有界管道、stderr脱敏、正常退出判定与工作区配额。

### 选区、追问与交付

- 选区基于Rust的正文快照/UTF-8边界；最终仍交完整Markdown，确定性比较选区前后文本是否不变。模型不提供偏移；出现越界改动必须拒绝提案，不能自动全篇接受。正文动过的过期提案保护保留。
- 未采纳的“再短一点”默认基于当前候选稿，最终提案仍对照真实正式稿。若候选有排除块，使用排除后的内容；已部分采纳后下一轮使用当前实际正文。不能把旧候选里的无来源事实当成新来源，也不能覆盖用户运行期间的新输入。
- 为追问保留必要的要求/材料/证据快照和已确认答案；不把model总结变成事实，不把密钥存进会话。旧会话JSON缺新字段照常读。跨重启续跑依然留阶段三，不假装已完成。
- 生成/修改用显式 submit_document；审核/问答可用显式 finish_report 交结构化侧栏清单。没有这两种明确交付都不能把最后聊天当成功。不把审核清单装成替换正文的提案。
- 提交前的检查调用与最终强制关卡复用；关键事实/来源、授权要素、引用保全、软校对都保留。

### 问用户

- ask_user 由模型按需调用；一次最多3题、每轮最多2批。复用 `clarify::agent_questions` 等纯校验/题面逻辑拦授权要素，不调用旧 engine::apply_answers。
- 题目在现有侧栏显示，用户能选项/自由输入/跳过，答案绑定本轮问题ID；重复/旧轮回答不回投。等待期间可停止，关闭/取消能回收host。人等待时间不计入模型执行超时。
- 题目与回答只影响Pi上下文和工作文件，不直接写DraftInput或正式稿。进程被关闭时明确显示中断，跨重启恢复不在本阶段冒充实现。
