日期：2026-11-01。基线：`a9ed9eec3015c673d1804a73215deb656176cea3`。
实现：本机 Pi Coding Agent 1.4.0（RPC，DeepSeek V4.1 Flash）；主代理负责提示词、审查、修正及验收。

## 交付范围

独立 `pi_model` 配置；5 份标准 SKILL.md；粘贴及 @ 引用材料快照与用途；7 个只读领域工具；

## 主审发现与修正

以下都是明确契约下的实现缺陷（how），已修正：

1. 下一轮虽然计算了候选基准，却只把正式正文写入工作区。增加只读 `input/candidate.md`
   与本轮说明，正式快照保留；候选稿不能作为新事实的来源。
2. 追问需要保留上一轮真正的依据。原始依据与正式基线、提案正文绑定；仍有效时写为编号材料，
   由模型读取。正文变动或提案被替换后不再沿用。部分排除仍沿用该提案的原始依据，
   部分接受后下一轮改以实际正文为基准。跨重启的依据恢复留第三阶段。
3. 用户作答没有进入来源台账。仅登记实际回答值，不把模型问题里的假设登记成事实；
   `check_document` 和最终交付都能使用这些回答。
4. 选区外不变只检查了模型原稿。对 `reviewed_draft` 规整后的实际提案再跑一次交付检查，
   避免清洗/标题规整改变无关文字。
5. 审核清单只在临时卡片中，摘要也未保存。完整摘要与条目进入现有轮次正文存储；
   重启后以历史轮次内容回看，不依赖仍在运行的 Pi 进程。
6. 修正模型设置文案：普通技能与 Pi 各自选模型；Pi 执行上限 15 分钟，等回答暂停计时，
   不声称沿用起草页超时配置。

新增或补充候选文件与正式快照隔离、用户答案进入事实来源、报告会话重载、
候选依据绑定/过期、报告内容完整性等回归。原工具越权、取消、异常退出和事实来源测试保留。

## 剩余边界

- 粘贴材料共用一个用途，@ 引用共用另一个用途；同一轮可以“事实粘贴材料 + 样稿引用”，
  同一组内逐份不同用途尚不支持。Pi 原报告“必须分两轮”的说法过宽，以此处为准。
- 仅支持侧栏锁定选区；未锁定的编辑器临时选区明确拒绝。全篇规整可能导致选区交付被拒绝，
  会明确显示原因，不放宽保护。
- 运行中的问题/任务不跨重启恢复；审核报告文本已经可保存，不能把它与运行恢复混为一谈。
- 跨重启恢复、候选原始依据持久化、成品去重、多窗口与固定运行时离线分发属于第三阶段。
- 旧内置技能标签不会执行为 Pi 流程，本轮上下文会注明；后续默认入口迁移仍待第四阶段。
- 工作区另有并行任务修改 `src/draft_page/heading_focus.rs`、`assets/help/06-editor.md`，
  不属于 Pi 本阶段，未改写、未纳入提交。
