## 已确认 how 问题

1. eval 的事实语料错误包括写法样稿/全部风格范例、未实际调用的知识库与稿件、未回答的问题答案；会掩盖模型搬用样稿事实。改为仅事实材料、已填描述要素、实际返回的资料和实际回答。
2. 选区精简任务要求 80 字，夹具判据却是 100；改为 80，不能放宽判据迁就输出。
3. 新增 with_all_sources 用 allow(too_many_arguments) 掩盖八参数接口；改为显式来源容器，保留生产/测试注入边界。
4. eval 按每个数据块独立 UTF-8 解码可能破坏跨块中文；输出累计上限也只限制未拆行缓冲。改为流解码和真实累计计数。
5. eval 允许复用已有非空输出目录，可能读到旧 Durable 回执；拒绝此类复用，重判已有结果只走 --check。
6. 原旧技能入口测试按子串“润色”判不存在，误拒新技能说明；改为精确入口文本匹配，恢复自然的技能说明，不弱化入口限制。
7. 工具 check_document 的提示仍称人工接受提案；同步为直接写入契约，风格列表字段增加返回长度限制。
8. 事实审核不能把待核正文自身当独立出处；当前正文只作核对对象，来源核实必须独立证据。
9. 提炼并改稿的组合任务不能先 finish_report 再 submit_document（host两种交付互斥）；改为内部提炼、最终单份正文。
10. 政策核对将外部引文文号与本稿表单授权文号混淆；明确可依据政策原文建议正文引用更正，仍不写授权表单。
11. 真实复函把来函接收者当作复函接收者；补收发关系自查。进一步查出原评测要求 Markdown 写主送抬头，与公共语法禁止重复表单要素冲突。修正为正文禁止两种抬头，交付说明必须给正确来源的主送建议，不写表单；原错误输出仍失败。材料成文参考也移除主送进入正文的指令。
12. 材料冲突初测字面通过，但人工看稿发现擅自将冲突时限安排为两阶段，且新增通报处分。补技能明确禁止此类消解与无依据部署，判据加入对应禁项；初测不能算业务验收通过。
13. 选区精简初测保留了单位名称但改变汇总/报送职责，补关系保护指引与更具体的责任短语判据；不是只看数字单位有没有出现。
14. 研究报告初稿字面有出处，但将无资料支持的数据孤岛、人才和经费问题当成本市事实；补资料边界/待调查指引，判据要求说明局限并排除已发现的无据陈述，人工继续核对全部关键判断。
15. 选区评测在整篇匹配必保事实，选区外抬头可掩盖选区内单位名称被简写；必保事实改为在选区内匹配，新增隔离单测，不允许无关原文贡献命中。
16. 复函重测已正确识别收件单位且未替用户表态，但漏了「特此函复」结语；补业务必含判据与明确的结尾指引，不能只因前面判据通过就当完整成品。
17. 冲突重测不再编两阶段，但正文仍选择较早日期，只在交付说明提两个日期；补主技能明确禁止「正文选一个 + 泛化待核实」，正文占位必须保留两处具体原话及来源。
