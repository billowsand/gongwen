## 主审已发现与修正的 host 问题（how）

1. 空白起草被成果文件的拒空规则误拦：真实Qwen首次冒烟两项均在调用模型前失败；只对输入身份读取允许空正文，登记成果继续拒空。
2. 长单行截断后误标全文已读：新增字符范围与明确续读位置，回读测试验证尾部与代理对均不丢失。
3. 替换成果后依赖查到旧invalid版本：改查有效登记，重建后不再被旧版本误失效。
4. 同一内容更改依赖/章节时幂等判断错误：比较依赖和章节；重复引文从当前块起点定位。
5. 最后一步可提交不同文件绕过已登记合稿：交付前复核全部阶段依赖、文件及合稿哈希/路径。
6. 同一阶段失效重跑可能重放已完成的旧submission：请求身份加入登记版本摘要。
7. 恢复Harness前阶段权限未还原：持久化active cursor，恢复时先还原当时单元，再收尾旧任务。
8. 多个材料块仍在一个大步骤中执行：改为每块独立短任务；阶段之间在空闲边界reset，以任务、工作文件与已确认回答接续。
9. 用户回答可能随阶段reset丢失：答案保存在宿主登记，下一阶段显式提供。
10. 实际压缩只按服务窗口而未约束工作预算：真实窗口不改，调整压缩预留使阈值与工作预算相符。
11. 小任务绕过最低预算检查：最低预算不足时先报错；离线模拟端点的正常路径窗口相应提高，不削弱压缩/交付断言。
12. 大纲超12节静默丢尾、依赖超24项静默裁切：显式拒绝超出章节，依赖上限与登记单元上限一致。
13. Windows短暂占用使高频登记原子替换失败：仅对Windows占用错误有限重试rename，始终保留旧件、不以删旧文件兜底；补实际故障注入测试。

Rust/UI独立只读审查发现：真实窗口字段误用、恢复策略未持久化、旧卡片rerun仍进旧引擎、同名引用删除串用、复制残留用途、知识读取固定页长等；交给Pi按独立文件范围修正，主代理不同时修改Rust。

## 产品验收边界

本阶段可交付开发测试版，不能声明 5D/5E 的所有门槛已完成。新任务统一 Pi，旧写作任务只读兼容已收口；旧共享引擎、旧检查点兼容源码暂存，既不把旧 checkpoint 当 Pi checkpoint，也不在模型效果尚不稳定时强删。API、知识库和辅助模型配置继续可用。

Qwen 工具遵循、依据检索与复函主送判断仍不稳定；事实疑点按用户决定只提示，不新增人工勾选门槛。下一轮应优先衡量这些失败及真实知识库效果，而不是增加第二套写作框架。未测20万汉字压力、较强模型同题对照、干净机安装/升级及 Linux 真机；用户随后进行 GUI 测试。

本轮七牛 MiniMax 补测被自动审批拒绝：动作涉及读取七牛凭据并请求外部模型，审批未认可当前授权覆盖该目的地；请求未执行。未改走其他路径规避，较强模型对照保持未验收。
