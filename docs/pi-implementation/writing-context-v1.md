2026-11-04，基线 `831db28a`。用户确认按讨论实施；本轮修改源码和文档，不自动提交、发布或安装。

## 产品取舍

- 主使用场景是 256K 及以上窗口。按实际部署容量规划，不伪造最低窗口；未校准模型不再封顶 96K，也不因材料篇数或旧短步骤偏好自动细分。保留明确的“倾向分阶段”选择和容量不足时的有界失败。
- 材料优先整篇；超限优先选大章节边界，其次段落，最后才按字符范围拆分。不切断 Unicode 代理对。每步保留材料目录与任务目的，可回读全局。
- 每轮由 Rust 读取本机当前日期、星期、UTC 偏移、本周/下周及明天，随 `task.writingContext` 主动交给 Pi，阶段 reset 后重新提供。原任务开始日期另存，恢复时不把它冒充今天。`current_date` 可以在跨日或等待用户后重新取实时日期。材料明确日期、既定期限不自动顺延，成文日期等表单字段权限不变。
- 标准组织背景优先提供明确提到的单位/人员，小词库提供全部单位；大词库提供职能相关候选及上级关系。提供规范名、对外名、简称、职能、所属单位、职务及人员简介。主动背景有 32 KiB 条目预算，未列出的明确标记可继续查询。
- `vocab_search` 复用已有职能/简介匹配，支持 `unit` 筛所属单位、`offset/limit` 分页，返回完整身份与所属关系，不靠同名猜人；未命中保留材料中的明确人名。正文责任分工可参考单位职责，不能据此写表单授权字段。
- Pi 交付和 `check_document` 不执行事实核查，不再生成事实疑点卡片。保留格式、文字规则、引用保护、哈希/体积/路径、基线/选区/只读、精确撤销及权限保护。现有 AI 文字复核不变。
- 全面审校 `gongwen-review` 和政策核查 `gongwen-policy-check` 从新任务目录退出，包括同名用户副本；用户文件和历史结果保留。六份在用技能同步日期、组织背景和材料处理口径。

## 实现与兼容

- `src/pi_agent/writing_context.rs` 提供日期与组织背景、词库查询；`process` 的 Init 主动提供背景，host 的常规用户消息与阶段消息都包含背景。数据作为数据交给模型，不作为可执行指令。
- host 预算取消 96K 封顶，接近材料可用预算（90%）才自动分阶段；单次阅读随实际预算扩大，文件阅读上限 240K 字符，分块上限 160K 字符，知识/稿件全文阅读上限 160K 字符；均保留分页与未读范围。工具返回快照上限同步放大到 1 MiB，避免大块阅读后因快照大小失败。
- 分块计划与规划预算保存在宿主 `progress.json`，恢复复用原范围，不按新窗口重算后套用旧单元。当前可用容量低于原规划时明确要求恢复原窗口或从头写；没有完整计划的旧中间记录不冒充可安全续接。
- host 内部补丁版本 `0.3.3`，协议仍为 3，Pi 依赖仍为 1.4.0；应用根版本不变。0.3.2 等旧运行继续按既有 host 版本保护，只能查看/取回已有成品或从头写，不能直接恢复旧中间任务。
- `DeliveryReport.advisories` 和旧来源快照结构保留历史兼容，新交付不产生事实疑点。旧流程提案、文字复核的原有闸门不改变。
- 同步修复服务自报最大窗口遮盖较小实际加载窗口的问题，修复非 Windows `hidden_command` 未使用可变绑定导致的严格 clippy 错误。
