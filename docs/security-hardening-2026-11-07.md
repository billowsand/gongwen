# 2026-11-07 敏感明文与文件名收口

本轮按用户确认实施：敏感数据默认不以明文落盘，必须释放到普通文件或外部系统时明确确认。用户确认此前没有使用全量备份，因此备份直接采用新格式，不保留旧 ZIP 恢复兼容；稿件 `.gwx` 的旧 ZIP 导入兼容继续保留。

## 已实现

- **数据库迁移恢复**：迁移目的文件和旧库使用固定状态名称，同时接管过去按 PID 命名的残留。原库改名后中断，重新解锁先恢复原库；新库就位后必须完成完整性检查，才能擦除旧库和 sidecar。清理失败返回错误，不再宣称加密完成。目录交换在 Unix 同步目录项；未知/冲突状态保留全部数据并明确失败。
- **普通模式与记住密码**：首次跳过应用锁须勾选明文风险；旧版跳过标记没有风险确认记录的，下次启动重新引导。只有启用应用锁后才能记住稿件包密码；旧明文密码在载入时清理，停用应用锁时也清除记住的密码。没有添加系统凭据库或可从程序逆向得到的固定解密密钥。
- **迁移排除名单**：只豁免运行目录中的已知锁文件及其 SQLite sidecar；普通 `.tmp`、名称含 `.lock` 的业务附件不再整体排除。
- **进程转交**：保留实例文件锁，通过仅绑定 `127.0.0.1` 的临时回环连接与随机认证令牌转交。路径只经内存传递；磁盘 endpoint 只有本轮端口和令牌，不含用户路径、应用密码或数据密钥。旧 `inbox` 明文请求在成为主实例时清理，失败上报。接收端确认已入内存队列后，发送方才退出。
- **名称与内容一起保护**：接口定义集中为 `apis/services.json`；用户技能集中为 `pi/user-skills.json`。Pi 工作文件使用 `work-files.json`，本轮技能快照使用 `skill-files.json`，均由 GWA2 密封。Node 提供虚拟读写、目录、大小、追加、改名与删除；模型仍使用原逻辑路径，业务名称不再成为物理文件名。技能快照只读。旧工作文件先保存容器，再逐个清理，失败可重入；路径别名按 realpath 统一处理。
- **预览、直接打印、另存内存化**：花脸稿预览和起草页直接打印由内存 PDF 驱动。CUPS 经 stdin 接收 PDF，Windows 直接解析字节后交给 GDI，均不创建送打缓存。另存中的 Word/PDF/Typst 包先在内存生成，再原子写入用户选择的目标；输出捕获期间不创建文稿目录或隐藏导出清单。印制追溯码也在内存成品上加盖。
- **剪贴板**：加密工作区中的 egui 文本/图片复制、文件复制先确认历史记录、同步和第三方工具的副本风险。剪切在编辑器删除源文字之前确认，取消不重放剪切事件。确认只对本次操作有效。
- **诊断**：加密工作区的 Rust panic 不再调用会把完整 panic 内容写入 stderr 的默认 hook；详细信息仍走加密诊断。

## 新版全量备份

- 仅在应用锁已启用、当前库已完成加密后提供备份。另一槽位若仍有明文数据库，必须先解锁该槽位完成迁移。
- 使用独立备份密码加密 7z 内容和文件头，AES-256、显式 `2^19` SHA-256 派生轮数，各条目使用新盐/IV。不在本机记住备份密码。
- 内部保留 SQLCipher/GWA 密文，包含格式标识。仅接受新版 7z，拒绝旧 ZIP；公共帮助截图可以保留公开字节。外层文件名和总大小仍可见。
- 当前槽位仍用带密钥的 SQLCipher 一致快照；另一槽位拒绝有未检查点 WAL/日志的库，使用两次完整 SHA-256 读取核对密文副本。归档读写采用有界流，避免整份大数据库进入内存。
- 恢复先输入备份密码，检查签名、格式、条目数量/大小/总量、路径、重名与属性，再由用户确认覆盖。暂存目录只写密文业务载荷，校验失败不替换当前数据。换入失败保留原有回滚逻辑；恢复后仍需备份当时的应用锁密码解锁。
- 恢复前的旧数据原样留底；如果旧数据未加密，确认框明确说明留底仍是明文。新备份不自动擦除用户的历史副本。

## 验证与发布

Pi host 升为 **0.4.1**，协议保持 **4**（消息格式未变，运行时版本检查要求匹配新的文件层）。本机 darwin-arm64 随包 host 已同步并重新生成 manifest；其他发布目标需要按现有 staging 脚本重新组装。

已完成 Rust 全量单线程回归 **3017 通过 / 0 失败 / 91 忽略**；Node 宿主 **121 通过 / 0 失败 / 1 跳过（Windows 专用）**；`cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings` 和 Windows 打印后端 msvc 交叉 clippy 通过。帮助 PDF 已重新生成（234 页），目视核对打印、查看器与数据备份章节的相关页面，无新增裁切或重叠。重点回归包括：迁移中断恢复与保留原库、明文密码禁存与清理、隐名文件树重启/改名/旧目录迁移/路径别名/只读快照、剪贴板确认、内存输出连隐藏清单也不落盘、模拟 lp stdin 送打、新版备份错误密码/旧 ZIP 拒绝/路径与重名拒绝/WAL 一致性/回滚。

## 实际边界与待验收

- 内存文件树为有界整容器原子重写；上限 512 MiB（包含编码开销），长工作文件和大量技能仍需真实模型压力验收，不把小样本通过当成长会话性能保证。
- 仍不能撤回系统打印队列、打印机、纸件、剪贴板历史、外部软件或模型服务端的副本。普通文件导出继续保留单次风险确认。
- 替换/覆写/删除不保证擦除 SSD、文件系统快照或系统备份中的历史副本；交换文件、休眠、崩溃转储和已解锁进程被读取仍是系统边界。
- Windows 这里只做打印后端交叉类型与 clippy 检查；真实打印、三平台文件占用/断电/原子改名/大备份恢复和实际模型仍需真机验收。
