# 任务助手界面改版与「粘贴填表」设计

> 2026-10-28 审阅 63b3c5f（新增个人任务助手与材料整理闭环）后写成。数据层、规则与事务
> 保护基本可用，问题集中在界面：信息架构、流程衔接与「粘贴文字让模型填表」的入口。
> 本文只改 `src/task_ui/` 与少量 `src/task_assistant/extract.rs`、`src/app/task_assistant.rs`，
> 不改表结构，不改候选的事务采纳与过期保护。

## 一、审阅结论

### 1.1 流程闭环：数据层闭合，界面层断开

数据层的几条链是闭合的：创建 → 进展 → 状态（前置 / 子任务校验）→ 完成 / 取消 → 归档 →
回收站 → 恢复；材料 → 快照 + 指纹 → 候选 → 编辑 → 采纳（单事务、revision 过期拦截）/
稍后 / 忽略 → 恢复。问题在界面上，这几条链在用户眼里是断的：

| # | 断点 | 现状 | 位置 |
|---|------|------|------|
| F1 | 识别结果没人看见 | 识别完成只在页顶冒一句 notice；「材料整理」默认折叠在页尾，没有待整理数量；开了自动整理后，后台产生的候选更是无从察觉 | `mod.rs:549`、`app/task_assistant.rs:83` |
| F2 | 新任务候选跳走 | 在页尾候选卡点「核对并编辑新任务」，草稿出现在页顶右栏的 480px 滚动区里，用户还停在页尾，看不到表单 | `mod.rs:706-718` |
| F3 | 按钮无故变灰 | 已有草稿时「新建任务」「核对并编辑新任务」被禁用，不说原因 | `mod.rs:85`、`mod.rs:708` |
| F4 | 待核对清不掉 | 「待核对」只能进编辑表单取消勾选再保存，详情里没有一键「已核对」 | `mod.rs:343`、`mod.rs:907` |
| F5 | 状态按钮报错位置远 | 详情里点「已完成」被前置挡住，错误显示在页顶，和点击位置隔了一屏；按钮也不标当前状态 | `mod.rs:410-429`、`mod.rs:93` |
| F6 | 取消任务路径隐蔽 | 快捷状态按钮里没有「已取消」，必须进编辑选状态再填理由，界面不提示 | `mod.rs:411-417` |
| F7 | 提示永不消失 | `error` / `notice` 只在保存成功时清一次，其余操作的旧错误一直挂着，与新提示叠在一起 | `mod.rs:93-98` |
| F8 | 取消理由串用 | `cancel_reason` 保存后不清空，下次取消别的任务会带上旧理由 | `mod.rs:910`、`mod.rs:944` |
| F9 | 归档视图「粘住」 | 进归档 / 回收站视图时把 `show_closed` 置真，离开后不复位，「我的工作」里从此混着归档项 | `mod.rs:99-101` |
| F10 | 重新核对常驻 | 「以当前版本重新核对」对没过期的候选也显示，用户不知道何时该点；改目标下拉又会静默重核 | `mod.rs:737-783` |
| F11 | 粘贴门槛高 | 材料标题必填（≤200 字），随手粘一段领导交办的话也要先想标题 | `app/task_assistant.rs:176` |

### 1.2 「粘贴一段文字，让模型填表」：有能力，没入口

现有「材料整理」做的是**多任务批量识别**：一段材料可能产生新任务、进展、期限调整、意见等
多条候选，逐条人工采纳。这对会议纪要、周报是对的，但用户最常见的动作其实是**单任务填表**：
收到一条通知或一句交办，想新建一个任务，表单有名称、完成条件、下一步、两个期限、协作分工、
角色、分类近十项。现在要么手填，要么绕到页尾粘贴 → 识别 → 找到候选卡 → 点核对 → 回页顶改，
五步跨两屏。

缺的不是模型能力，是**在表单里就地完成**的入口。设计见第三节。

### 1.3 界面：布局与组件

截图 `tmp/task-assistant-1280.png`、`tmp/task-assistant-760-edit.png` 暴露的问题：

1. **没有信息层级。** 所有内容（筛选、设置、列表、详情、分类管理、材料整理）平铺在一条
   竖向滚动里，主次全靠位置；「分类管理」和「材料整理」是同级折叠头，和任务列表抢同一层。
2. **固定 480px 的两栏嵌在整页滚动里。** 1280×900 下页面下半截空白，右栏详情却被裁掉要内
   滚；760 宽时编辑表单只露出一半，「保存」要在内层滚动区里找。双层滚动是 egui 页面里最难用的形态。
3. **设置混进筛选条。** 「新入库资料自动整理」是持久设置，和关键词框、「包含归档与回收站」
   挤在同一行；「筛选」框没有提示文字。
4. **筛选重复。** 「视图」下拉（今天 / 等待 / 阻塞 / 已完成 / 归档 …）与「状态」下拉、
   「包含归档与回收站」勾选三者语义重叠，组合起来还会出现「视图=等待 + 状态=已完成」这种空集。
   760 宽时筛选行折成三行，「全部分类」孤零零一行。
5. **列表行信息密度低、状态不显眼。** 每行三行纯文字，状态、逾期、待核对都是同色小字；
   只有第一行能点。
6. **详情动作没有轻重。** 「编辑」「归档」「移入回收站」都是撑满宽度的同款按钮，危险操作与
   常用操作一样重；「记进展」输入框没有标签和提示（截图里是一条空白框）。
7. **表单是一长条。** 十几个字段一列到底，必填与选填、常用与少用不分；日期是自由文本；
   「前置任务」把**所有**任务列成勾选框（连归档的也列），任务一多就是一面墙。
8. **候选卡字段全开。** 每张候选卡不分类型都铺 8 个可编辑行（意见类候选也有「建议名称」
   「建议完成条件」），当前值与建议值不对照，用户看不出「改了什么」。
9. **没用项目自己的组件。** `theme::widgets` 已有 `primary_icon_button`、`chip`、`notice`、
   `field`（带提示、与按钮等高）、`segmented`、`caption`、`metric`，`theme::chrome` 有
   `card` / `clickable_card`，其他管理页（技能、数据接口、服务商）都在用；任务助手一个没用，
   观感与全应用不一致。
10. **历史时间是原始 RFC3339**（`2026-10-28T14:20:31.123+08:00`）。

### 1.4 顺带发现的性能问题

egui 每次鼠标移动都重绘，下列查询每帧都跑：`store.list(true)`、`store.candidates()`、
`store.categories()`（一帧两到三次）、选中任务的 `history` 与 `sources`、知识库
`list_docs`（展开材料整理时）、每张展开候选的 `candidate_source`。最重的是搜索：关键词非空时
**对每个任务各查一次** `source_matches`（`mod.rs:268`），N 个任务就是每帧 N 次 SQL。

## 二、改版后的页面结构

```
┌ 顶栏 ─────────────────────────────────────────────────────────────────┐
│ 任务助手   [🔍 搜索任务、下一步、协作方、材料原文      ]  [粘贴材料] [＋新建任务] [⋯] │
├ 视图栏 ──────┬ 列表 ─────────────────────┬ 详情 / 表单 ──────────────────┤
│ 今天与逾期 3 │ [角色▾] [按期限|按更新]     │ 标题        [状态▾][编辑][⋯]   │
│ 进行中的工作 │ ┌──────────────────────┐   │ ⚠ 待核对说明         [已核对]  │
│ 等待·阻塞  2 │ │收集试点单位反馈 逾期2天│   │ 完成条件 / 下一步 / 期限 / 分工 │
│ 待核对     1 │ │下一步：催报三家…       │   │ 关系：上级 前置 子任务 后续     │
│ 待整理建议 5 │ │[待核对][负责]          │   │ 记进展 [_______________] [记录] │
│ ── 已结束 ── │ └──────────────────────┘   │ AI 建议（只属于本任务的候选）   │
│ 已完成       │  …                          │ 历史（时间线）                  │
│ 归档·回收站  │                             │                                │
│ ── 分类 ──   │                             │                                │
│ 专项推进   4 │                             │                                │
│ 管理分类…    │                             │                                │
└──────────────┴─────────────────────────────┴────────────────────────────────┘
```

### 2.1 骨架

- **三栏，不再整页滚动。** 视图栏固定宽 150–170；列表约 38%；详情吃剩余宽度。三栏各自
  一个 `ScrollArea`，高度 = `ui.available_height()`，不再写死 480。宽度 < 900 时视图栏收成
  列表上方的下拉；宽度 < 650 时退化为「列表 ↔ 详情」单栏切换（详情顶上有「‹ 返回列表」），
  做法照 `skill_manager/browser.rs:42` 的宽窄分支。
- **顶栏只放三类东西**：全局搜索（`theme::field`，提示「搜索任务、下一步、协作方、材料原文」）、
  两个创建入口（「＋ 新建任务」主按钮 `primary_icon_button`，「粘贴材料」次按钮）、`⋯` 菜单
  （分类管理、新入库资料自动整理开关、显示已处理的建议）。设置从筛选条里搬走。
- **错误与提示就近显示。** `error` / `notice` 改成带时刻的一次性消息：页顶用 `theme::notice`
  显示，4 秒后或下一次操作时清掉；表单校验错误显示在表单底部保存按钮上方；状态切换失败显示在
  状态下拉旁边（修 F5、F7）。

### 2.2 视图栏（取代「视图 / 状态 / 包含归档」三个控件）

一列 `nav_button` 式的条目，每项右侧带数量（0 不着色，规则同 `theme::metric`）：

| 条目 | 含义 | 数量着色 |
|------|------|---------|
| 今天与逾期 | 任务期限或下一步期限 ≤ 今天，未结束 | 逾期数用 `danger` |
| 进行中的工作（默认） | 未结束、未归档、未删除 | 不着色 |
| 等待 · 阻塞 | 等待、阻塞或前置未完成 | 不着色 |
| 待核对 | `needs_review` | `warning` |
| 待整理建议 | 状态为待核对 / 稍后的候选 | `accent` |
| 已完成 / 已取消 / 归档 / 回收站 | 「已结束」分组下 | 不着色 |
| 分类… | 每个分类一行，点击即按分类过滤；末行「管理分类…」开弹窗 | 不着色 |

- 归档、回收站是视图本身，不再需要「包含归档与回收站」勾选，`show_closed` 字段删掉（修 F9）。
- 「状态」下拉删掉：状态由视图表达；列表里每行有状态 chip。保留「角色」一个下拉与
  「按期限 / 按更新」一个 `segmented`。
- 「待整理建议」常驻且带数，F1 的「识别完成没人看见」由此解决；识别完成的 notice 也改成
  「识别完成，3 条建议待核对」，带「去看看」按钮跳到该视图。

### 2.3 列表行

用 `theme::clickable_card`（或带底线的整行可点区域，密集列表优先后者），整行可点：

```
收集试点单位反馈                           [逾期 2 天]
下一步：催报三家未交单位 · 10-30
[待核对] [负责] [专项推进]
```

- 右上角只放一个最要紧的期限 chip：逾期（danger）> 今天到期（warning）> 普通日期（中性）> 无。
- 第三行 chip：待核对（warning）、阻塞（danger）、角色、分类；状态是「进行中的工作」视图里
  的默认值时不重复显示。
- 列表为空时给邀请而不是空白：「还没有任务。新建一个，或把通知、纪要粘贴进来让 AI 拆分。」
  带两个按钮。

### 2.4 详情

- **头部一行**：任务名（标题字号）+ 状态下拉（显示当前状态，选「已取消」时就地弹出理由输入，
  修 F6）+「编辑」+ `⋯`（归档、移入回收站，危险项用 `danger` 色，修 1.3-6）。
- **待核对横条**：`theme::notice(warning)` 写明原因（取最近一条「依赖复核」或「采纳材料建议」
  历史的摘要），右侧「已核对」按钮一键清除并记历史（修 F4）。
- **关键信息网格**：完成条件 / 下一步（含下一步期限）/ 任务期限（逾期时 danger 色并写「已逾期
  N 天」）/ 协作分工 / 分类 · 角色，两列 `Grid`。空值写「未设」，不写「（稍后补充）」。
- **关系**：上级、前置、子任务、后续用 chip 排一行，chip 上带对方状态色点，点击跳转；没有关系
  时整块不显示。
- **记进展**：带标签和提示的多行输入（`hint_text`：「今天的进展；粘贴整段材料可让 AI 提更新建议」），
  回车或「记录」提交。粘贴内容较长（多行或 > 80 字）时，按钮旁出现「让 AI 提更新建议」（见 3.2）。
- **AI 建议**：只列 `task_id` 为本任务的待核对候选，形态见 3.3。
- **历史**：时间线，时间格式化为 `10-28 14:20`（跨年显示年份）；有来源的条目带「原文」小按钮，
  点开是来源快照弹窗，取代现在的两层折叠。

### 2.5 表单（新建 / 编辑）

- 表单在详情栏内，**保存 / 放弃固定在底部**（表单内容自己滚动，底栏不滚），修 1.3-2。
- 顶部是「从文字填写」块（见 3.1）。
- 字段分三组，常用在上：
  1. **要做什么**：名称*、完成条件*（多行）。
  2. **怎么安排**：下一步、下一步期限、任务期限、状态、我的角色（两列排）。
  3. **更多设置**（默认折叠，编辑已有任务时若有值则展开）：分类、协作分工、上级、前置。
- 日期是文本框加一枚日历按钮，日历弹出中文月历（年月翻页、点日即填、今天、清除），
  文本框照常可用输入法键入；两个期限的先后提醒放到对应字段下方。（原拟用
  `egui_extras::DatePickerButton`，它的按钮、星期与月份都是英文，改为自写，见 `task_ui/date.rs`。）
- 前置任务改成「已选 chip + 搜索添加」：输入框按名称过滤未删除、未归档、非自身的任务，
  最多列 8 条；已选的以可删除 chip（`removable_tag_button`）显示。
- 已有草稿时「新建任务」不再变灰：点了弹确认「当前表单未保存，放弃并新建？」（修 F3）；
  候选卡的「编辑为新任务」同理。

### 2.6 弹窗收纳的低频功能

- **分类管理**：`⋯ → 管理分类…` 打开窗口，每个分类一行：名称（可就地改名）、任务数、
  「删除…」（点后选迁移目标再确认）。取代现在「一个下拉同时当删除源和改名源」的写法。
- **新入库资料自动整理**：在 `⋯` 菜单里做成勾选项，旁边一句说明「只处理之后新入库的资料，
  结果进『待整理建议』，不会自动采纳」。

## 三、粘贴填表

三个场景，共用同一套校验口径（证据必须是原文连续摘录、日期必须真实、引用的任务 / 分类必须
在上下文里、未明确就留空），都**只改界面上的草稿或候选，不直接写任务**，保存或采纳仍由人点。

### 3.1 新建 / 编辑表单里的「从文字填写」（单任务）

```
┌ ✨ 从文字填写 ──────────────────────────────── [识别并填入] ┐
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 粘贴通知、纪要片段或领导交办的话                       │ │
│ └──────────────────────────────────────────────────────┘ │
│ AI 只填空白栏；已有内容的栏给出「建议改为」，保存前都可改。   │
└──────────────────────────────────────────────────────────┘
```

- **交互**：多行输入（默认 3 行，粘贴后自动增高到 8 行），「识别并填入」主按钮；识别中显示
  `theme::spinner` 与「取消」。新建任务时此块默认展开、表单为空时光标默认落在这里；编辑已有
  任务时默认折叠成一行「从文字补充…」。
- **填入规则**：
  - 目标字段为空 → 直接填入，字段边框与右侧 `AI` chip 用 accent 色标记，悬停 chip 显示原文摘录；
  - 目标字段已有值且建议不同 → 不覆盖，字段下方出现一行「AI 建议改为：…　[替换] [忽略]」；
  - 用户改动过某字段后，该字段的 AI 标记自动消失（以字段当前值不等于填入值为准）；
  - 表单底部一行汇总「AI 填了 5 栏，2 栏有不同建议」，带「全部撤销」。
- **可填字段**：名称、完成条件、下一步、下一步期限、任务期限、协作分工、我的角色（只能是
  负责 / 配合 / 跟进 / 关注，原文看不出就不填）、分类（只能从现有分类里选，否则留空）、
  上级（只能从上下文任务里选，否则留空）。状态、前置、待核对不由 AI 填。
- **一段话里有多件事**：模型结果带 `others`（原文里还提到但没填进本表单的事项数）。> 0 时
  在块底部提示「这段文字里还有 2 件事」，按钮「转到批量整理」把同一段文字交给现有材料整理
  链路（3.3），本表单保留。
- **来源留痕**：保存时若本表单用过 AI 填写，把粘贴原文按现有规则写入 `task_sources`
  （同一指纹复用），并在「创建」历史里挂 `source_id`，详情的历史能点开原文。为此 `Store` 需要
  一个在 `save` 事务里顺带落来源的入口（`save_with_source`），不新增表。

**实现要点**

- `extract.rs` 新增 `prompt_fill(source, categories, tasks, current: &Task)` 与
  `parse_fill(raw, source, categories, tasks) -> Result<Fill>`。`Fill` 是每个字段一个
  `Option<FilledValue { value, evidence }>` 外加 `others: usize`。校验复用 `parse_response`
  里的证据、日期、长度判据（抽成私有函数共用），分类与上级不在清单里时**置空而不是整批拒绝**
  ——单任务填表场景整批失败的代价太高；证据不在原文里的字段同样逐个丢弃，并在结果里计数
  「n 栏因无法核对出处已丢弃」。
- `app/task_assistant.rs` 新增 `start_task_fill`：与 `start_task_material` 同样在后台线程调用

### 3.2 详情里的「让 AI 提更新建议」（单任务更新）

- 在「记进展」框里粘贴了较长的文字时出现按钮。点击后走**现有**批量识别链路，但上下文只给
  当前这一个任务（`tasks = [当前任务]`），`source_ref = "task:<id>"`，标题自动生成。
- 结果候选的 `task_id` 必然是当前任务，直接显示在本任务详情的「AI 建议」区（3.3 的卡片形态），
  不需要再选目标。
- 「记进展」原文本身是否同时记为一条进展，由用户在结果出来后决定（建议区顶部给「同时把原文记为
  进展」勾选，默认不勾）。

### 3.3 「待整理建议」视图（多任务批量，取代页尾「材料整理」）

- 顶部是材料输入：标题（**选填**，提示「留空则取首行」）、原文多行框、「识别」按钮；右侧
  「从知识库选一篇」下拉。顶栏的「粘贴材料」按钮直接跳到这里并聚焦原文框。
- 下方候选**按来源材料分组**：组头是材料标题、时间、条数，带「查看原文」与「本组全部忽略」。
- 每张候选卡按类型只显示相关字段，并以**当前值 → 建议值**对照：

  | 类型 | 卡片内容 | 主按钮 |
  |------|---------|-------|
  | 新增任务 | 名称、完成条件、下一步、期限、分工（只读预览） | 编辑为新任务（在详情栏打开预填表单，同时视图保持在此处） |
  | 进展 / 期限 / 范围 / 分工 | 目标任务 chip；有变化的字段逐行「旧值 → 新值」，可就地改新值 | 采纳 |
  | 完成证据 | 目标任务；摘录；该任务的完成条件 | 确认完成 |
  | 意见 / 待决 | 提出主体、针对事项、原意 | 记入历史 |

  次按钮统一为「稍后」「忽略」；摘录以引用样式显示在卡底，「查看原文」打开来源弹窗并高亮摘录。
- 目标任务为空时，卡片顶部是「选择目标任务」搜索下拉（同 2.5 前置选择器），选定前主按钮不显示。
- 「以当前版本重新核对」只在采纳返回过期错误后出现在该卡片上（修 F10）。改目标下拉仍按所选
  任务的当前版本重核（采纳要求候选记录的目标与所选一致，不重核就采纳不了），但右栏随即切到
  该任务，用户采纳前能看到它的当前内容。
- 「保存候选修改」按钮去掉：就地改的值在采纳时一并保存（现状采纳已经会先 `edit_candidate`），
  切走前若有未采纳的改动自动 `edit_candidate` 存一次。
- 已采纳 / 已忽略的记录从 `⋯ → 显示已处理的建议` 打开，作为组内折叠的灰色行。

### 3.4 标题自动生成（修 F11）

材料标题留空时，界面在发请求前补上：原文首个非空行，去掉首尾标点，截前 30 字；首行过短
（< 4 字）时用「粘贴材料 MM-DD HH:MM」。不用时间作默认标题的主体，是为了保留「同标题同正文
不重复识别」的去重效果——同一段文字粘两次仍得到同一指纹。后端「标题必填」的校验保持不变。

## 七、要素精简（2026-10-29 用户审阅后定）

### 7.1 用户意见

1. 要素太多、填表限定太严：一两句话覆盖不了所有要素，智能填写应「有啥填啥」，保证一次能录完。
2. 一个任务主要就是：任务名称、负责人、当前进展、下一步工作、主要风险问题及应对措施。
3. 「负责人」是这个任务的实际负责人，不是「我的角色」里的「负责」；必须从标准词库里选，
   以后才能按词库区分各单位的职责。

### 7.2 决定

| 项 | 决定 |
|----|------|
| 主表单 | 任务名称（唯一必填）、负责人、当前进展、下一步工作、风险问题及应对措施、状态、任务期限 |
| 收进「更多」 | 分类、上级、前置（关系规则不变） |
| 去掉 | 目标 / 完成条件、我的角色、协作分工、下一步期限（旧列留在库里不删，界面不再读写） |
| 负责人 | 只选**人员**词条，所属单位随人员带出，不单独选单位；存词条 `id` 与选定时的姓名快照 |
| 当前进展 | 一个字段；更新时覆盖，旧值靠历史保留（每次更新记一条带时间的「进展更新」） |
| 风险与措施 | 一个多行文本框 |
| 智能填写 | 只填原文里有的，没有就空着；摘录比对放宽到忽略空白与全半角标点差异；负责人由程序按词库姓名 / 别名匹配，模型不看词库 |

批量材料整理的候选类型随之对齐（见交接说明）。实现交给 Codex，任务说明在
`tmp/task-assistant-fields-handoff/TASK.md`。

评测揪出的三个真问题（都在修正里）：
1. **填写一栏都填不上**：提示词的示例 JSON 每栏都是 `null`，结构要求只在文字里，小模型照示例给
   `"name":"…"` 这种裸字符串，全部被当成「无法核对出处」丢弃。改为给一个带 value / evidence 的完整
   示例；解析也接受裸字符串，值本身在原文里就收（编出来的如「待开始」照样丢）。
2. **代码块包裹**：模型把 JSON 包在 ```json 代码块里，整条结果解析失败。`json_body` 取第一个 `{`
   到最后一个 `}` 再解析，两条链共用。
3. **编造年份**：批量提示词没有给今天日期，「12月15日前完成」被写成 2023-12-15，且是合法日期能过
   校验。现在两条提示词都给今天日期；`date_supported` 要求日期在原文里有出处，只写月日时必须是今天起
   最近的那一个，对不上就丢这一栏（批量里纯期限候选整条拿掉，`check_proposal_dates`，只在模型刚返回
   时调用）。

未通过的一例：B06 停水通知被提成一条新任务候选——属模型判断，候选仍要人点采纳，不为 9B 小模型
调提示词（LM Studio 只验链路，内网 MiniMax 2.7 / DeepSeek v4 flash 再测）。

## 八、材料库与重新识别（2026-10-29 用户审阅后定）

### 8.1 用户意见

1. 识别过但没采纳的材料不能再识别一次。
2. 识别过的材料没有地方存放、查看与管理。
3. 粘贴同一份材料只回一句「之前识别过，没有重复生成」，体验差。
4. 识别结果提示放在页顶，每次出现都把下方三栏挤一下。

### 8.2 决定（四问均取推荐项）

- **重新识别**只替换这份材料待核对与稍后处理的建议；已采纳、已忽略的保留，新结果里
  同类型、同目标、同摘录的跳过（`Store::rerun_extraction`，返回替换 / 新增 / 跳过数）。
- **粘贴识别过的材料**不调模型，材料卡里出卡片：识别时间、上次各状态建议数、
  「重新识别」「查看这批建议」「打开材料」「关闭」（`inbox::known_card`）。输入框不清。
- **视图栏新增「材料」**（`src/task_ui/materials.rs`）：列表 + 右栏原文快照、产生的建议、
  重新识别、在待整理建议中查看、删除。待整理建议可按材料筛（`State::inbox_source`，顶部条
  「只看「…」的建议 · 显示全部」）。
- **删除**连同未采纳的建议一起删；被任务历史或已采纳建议引用时只置 `task_sources.hidden=1`，
  快照留着，历史「原文」照常；无引用整条删除，指纹释放。
- 结果写在「识别」按钮同一行、带材料标题；成功提示改为页面底部浮动提示（`toast`），不占布局。

### 8.3 实现与出入

- `CandidateRow` 加第六项 `source_id`；`Store::sources` / `source_by_fingerprint` /
  `rerun_extraction` / `delete_source`；`has_source` 删除。后台线程新增 `Material::Rerun`，
  按快照原文调模型；识别过的材料由线程查出 `SourceRow` 交给界面，不落库。
- 材料库不列表单「从文字填写」的快照（`source_ref='fill'`）。来源只分「粘贴 / 知识库」，
  自动整理与手选知识库资料同为 `knowledge:` 前缀，暂不区分。
- 样张新增 `tmp/task-assistant-1280-materials.png`、`600-materials`；`-inbox` 改为展示识别过卡片。
- 待真机验收：粘贴同一份 → 卡片 → 重新识别的整条链（模型调用与 8.2 计数），删除后再粘贴的提示。
