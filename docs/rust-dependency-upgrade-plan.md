# Rust 依赖升级计划

日期：2026-10-01。依据本次依赖评估与项目的同步、送批材料、版本对照及 AI 架构约束。

**安全决定先做什么，功能稳定决定能否交付，实测性能决定后续升级的价值。每批独立修改、验收和回退。**

本文件记录实施计划与进度。升级在独立分支进行，并已对齐 0.7.0 发布提交；主工作区的发布工作独立保留。依赖目标沿用 2026-10-01 已核查的稳定版本，实施前再次核对目标是否被撤回或有新的安全修复，不自动追随预发布版，也不在本计划中预定发布版本号。

## 第 0 批：建立可对照的基线

1. 在实施时记录选定的 Git 提交、完整锁文件、Rust 版本、运行时资产与字体校验值；已有发布工作完成或明确隔离后，从确认的基线开独立升级分支。
2. 保留旧正式版安装包，以及升级前构建的应用，用于交叉导入与回退。复制测试数据库、配置、用户词、学习数据和资源，真实数据不作为破坏性试验对象。
3. 建立一套固定样本：短/长公文、研究报告、中文公式、Mermaid 图、红头呈批件、花脸稿、词表 XLSX、新旧同步 ZIP、包含送批清单和随行件的包。
4. 运行现有格式、编译、静态检查和测试，记录沙箱失败的具体测试与原因。“约 5 个预期失败”不能用于免除任何新增失败；在正常环境与 CI 中复核。
5. 建立性能基线：同一机器、release 构建、相同数据和字体。记录应用启动、词典加载、长稿扫描与 diff、XLSX 导入导出、典型 PDF/SVG/公式渲染的耗时与峰值内存；这些路径按相应升级批次复测，不要求每次全部重测。

性能采样建议：启动和词典首次加载独立重复 5 次；可重复的操作至少 30 次，分别记录首次与热运行表现。比较中位数和较慢样本，记录样本规模、计时范围与缓存状态。若关键路径稳定退化超过约 10%，重测并定位原因；小于计时噪声的差异不视为收益。此阈值是建议的调查线，安全补丁不以必须提速为交付条件。

送批材料当前仍有真机验收待办，应在 4B、5A、6 之前补齐：混合文种逐件 TeX 编译到合并 PDF、目录与奇偶页补白、归档钉版、两套数据库 ZIP 往返。发现原有缺陷时记录并独立修复，避免把原有问题误判成依赖升级回归。

## 第 1 批：优先消除已确认的安全问题

### 1A：网络 TLS 补丁

- 仅定向更新 rustls 到 0.23.45，继续使用 reqwest 0.12.28；查看锁文件差异，解释解析器必须联动更新的依赖，不执行全量无目标更新。
- 验证本机 LM Studio/Ollama 的 HTTP 连接，以及测试 HTTPS 服务的证书验证、错误证书拒绝、超时与取消；测试使用本地服务或测试账户。
- 运行现有 HTTP/SOCKS/系统代理测试，核对 localhost、IPv4/IPv6 回环地址仍绕过代理。
- 重新扫描锁文件，确认 RUSTSEC-2026-0285 不再匹配。模型响应继续只进入待采纳建议，既有确定性闸门不变。

修复依据：[rustls 安全公告](https://rustsec.org/advisories/RUSTSEC-2026-0285.html)。当前依赖约束允许该补丁，reqwest 0.13 的 TLS 配置迁移无需混入这一批。

### 1B：Excel 导入解析器

- 更新 calamine 到 0.36.1，让其采用已修复的 quick-xml 0.41 系列；根 zip 继续保持 4.6.1，使加密同步的直接依赖迁移独立进行。
- 允许 calamine 间接引入 zip 8.6，暂时存在两套版本属于有意取舍；记录依赖树，安全批次不以消除重复版本为验收条件。
- 复用 vocabulary_xlsx、proofread_xlsx 的往返测试，核对单位/人员编码、中文、前导零、空单元格、空白行、重复项与不合法行的处理。
- 补充必要的业务样本：共享字符串和行内字符串、ASCII 首尾空格、xml:space="preserve"、中文全角空格、Strict OOXML 与损坏文件。未经解释的词条内容变化、字段丢失或误覆盖阻止交付。
- 用有大小与资源上限的恶意属性 XML 样本验证已报告的 CPU 耗尽问题，避免无界压力测试；复核异常输入报错和导入过程的写入边界。
- 重新扫描锁文件，确认 quick-xml 0.37.5 及其匹配公告消除；不强行把父库要求的 0.41 覆盖成 0.42。

[calamine 变更日志](https://github.com/tafia/calamine/blob/master/Changelog.md)说明其安全修复和新版的文本空白处理变化。公告 0195 针对 NsReader，本次未证实旧 calamine 使用该路径；回归验证以实际使用路径为准。

安全批次通过两平台检查与专项验收后，可独立交付，不等待后续性能或 GUI 升级。回退任一提交会恢复相应旧版本的已知风险，必须同步记录并继续处理，不把回退当作安全问题关闭。

## 第 2 批：兼容维护，按业务域拆开

| 子批次 | 目标 | 验收重点 |
| --- | --- | --- |
| 2A 编码与身份 | encoding_rs 0.8.42、uuid 1.26.1 | UTF-8/GBK/UTF-16 导入、损坏编码处理；UUID 生成/解析、旧稿件身份和版本图校验值 |
| 2B 输入法外部依赖 | jiff 0.2.37、thiserror 2.0.21、zerocopy 0.8.59、toml 1.1.6+spec-1.1.0 | .qj 数据读取、候选与用户学习、配置往返、损坏数据报错 |

本批目标都在既有兼容范围内，优先定向更新锁文件；只有跨兼容范围或需要声明新的最低修复版本时才改清单。thiserror 1.x 与 toml 0.8 是其他父库的依赖，不能为了统一数字跨主版本覆盖。输入法内核源码、数据格式和学习目录不随本批迁移。

rusqlite 新补丁的明确变化主要是降低 MSRV，因此 2C 可以暂缓，不为此单独发版。[发布说明](https://github.com/rusqlite/rusqlite/releases/tag/v0.40.2)。

## 第 3 批：分词正确性与性能

分两个提交对照：先到 0.10.4，确认正确性变化，再评估 0.11.0；分别留结果，出问题时能定位到哪一步。

- 固定样本覆盖中文专名、机关简称、用户词、英文数字连续片段、日期、金额、文号、公式、标点和空白。
- 验证词典加载、词性标注、全文扫描；复核 visual_diff 的日期/数字单位/文号/公式保护规则与真实公文样本。
- 必须通过 generated_edits_always_restore_both_sides 等既有不变式：去新增可还原旧文，去删除可还原新文。分词边界可以因上游修复合理变化，吃字、重字、标错范围不允许。
- 对比词典首次加载、短稿/长稿分词、扫描和花脸稿重算的耗时及峰值内存。记录运行时收益，不能以编译更快或依赖更少代替用户体验指标。
- 0.11.0 若没有可复现收益且带来明显回归，可先交付 0.10.4；修复收益与性能收益分别判断。

依据：[0.10.4](https://github.com/messense/jieba-rs/releases/tag/v0.10.4) 的分词修复与 [0.11.0](https://github.com/messense/jieba-rs/releases/tag/v0.11.0) 的词典、HMM 和分配优化。

## 第 4 批：表格导出与 ZIP 维护

### 4A：先升级表格写入库

更新 rust_xlsxwriter 到 0.99.1。核对表名、列宽、冻结行、格式、人员/单位编码、下拉验证、工作表保护与可编辑区域；导出再用 calamine 回读，并在实际 Excel 或 WPS 中抽样打开。对比归一化的单元格内容和结构，不要求 ZIP 文件字节完全相同。

关注大词表导出耗时、内存及生成文件体积；确认收益后再判断是否值得进一步合并 zip 版本。

### 4B：再升级根 ZIP 库

前置条件：当前同步与送批材料的真机基线通过。阅读 offline-sync-redesign.md 与 send-package-design.md 后，将根 zip 更新到 8.6.0，只做必要的 API 适配，不混入协议、加密策略或数据库结构变更。

必须验证：

1. 历史 v1 包可读；当前协议兼容的旧版与升级版之间双向导入；中文文件名和中文密码、图片/PDF、词库与送批清单完整。
2. 两个独立数据库 A→B→A，重复导入幂等；UUID、双父版本关系、payload_hash、归档钉版和清单顺序正确。
3. 同整数 id 的不同稿件不误合并；分叉冲突仍需用户处理；内容相同而清单不同的选择有效。
4. 错密码、篡改、缺失资源、同名冲突与不安全路径被拒绝；失败不留半个数据库结果，不覆盖本地资源或已有输出。
5. DOCX 重打包、花脸稿、技能包 ZIP 和其他直接使用 zip 的路径通过；新旧成品均能由对应软件正常打开。

不以支持此前本来不兼容的应用协议为目标。若必须升级 ZIP 或数据库格式，应拆成独立方案并重新评估数据回退能力。本批不自行承担格式迁移。

## 第 5 批：GUI 与平台组件分别升级

### 5A：egui 同步升级

eframe、egui、egui_extras、egui_kittest 一起到 0.36.2；检查输入事件变化、API 适配和截图差异，保持现有字体与导出规则。

真机重点：应用内拼音输入法、候选选择、辅码/音形、快捷键、选区与拖动、撤销/重做、长稿滚动与缩放、版本 diff 两栏联动、花脸稿标记、公式和 PDF 标签。复核图形快照时逐项解释差异，不批量接受全部新快照。

Windows x64 与 Linux ARM64 都验收；GUI 改动与性能升级分开归因。版本依据与事件变化见 [egui 变更日志](https://github.com/emilk/egui/blob/0.36.2/CHANGELOG.md)。

### 5B：文件选择器单独升级

到 rfd 0.17.2 时，修改 linux-portal-dialogs 去掉已移除的 rfd/async-std，并按新版后端核对 D-Bus 与 Wayland 的构建/运行条件，保留默认 GTK3 方案。

分别验证 Windows、Linux ARM64 GTK3，以及项目支持的 portal/Wayland 环境：打开、保存、选文件夹、多选、取消、中文/空格路径、扩展名过滤。验证 Debian buster 构建与 Ubuntu 20.04/麒麟环境的实际启动；未具备 portal 实测环境时，该变体仍标为未验收，不能用 Windows 测试替代。

上游 [rfd 0.17 说明](https://github.com/PolyMeilex/rfd/releases/tag/0.17.0)提示 portal 后端完整重写，因此 5B 不作为前面批次的前置条件。

## 第 6 批：维护性迁移，满足条件再启动

目标是逐步替换停止维护的字体依赖。先绘制依赖清单、核对稳定父库的配套情况，再确定迁移范围；不将 resvg 0.48.1 单独加入后就宣称旧字体依赖已清除。

- 根代码中 ttf-parser 的字体命名、度量和测量逻辑可独立评估迁往 skrifa；必须核对同一字体的字宽、行高、基线与集合索引。
- resvg/usvg 0.48 系列已经使用 skrifa/harfrust，但当前 merman 与 svg2pdf 仍带入旧链；等稳定版配套，或另立适配方案。merman 0.8 alpha 不进入正式升级目标。
- 保留 vendor/latex-rust 的中文字体回退补丁；本批不启用其旧 egui feature，也不直接替换整目录。tiny-skia 0.12 只在本地 renderer 完成适配时升级。
- 使用中文节点、特殊字形、长标签、甘特图、透明度、SVG 滤镜、中文嵌套公式做对照。预览、PNG、PDF 和 DOCX 图像均须完整，允许的排版差异需逐项说明。
- paste 的迁移随 biblatex/simba 等父库跟进；不把停止维护公告描述成已确认可利用漏洞。

迁移依据：[ttf-parser 公告](https://rustsec.org/advisories/RUSTSEC-2026-0192.html)、[rustybuzz 公告](https://rustsec.org/advisories/RUSTSEC-2026-0206.html) 与 [resvg 字体后端变更](https://github.com/linebender/resvg/blob/v0.48.1/CHANGELOG.md)。

## 每批共同的交付与回退规则

- 每批单独提交，提交包括清单/锁文件、必要 API 适配和对应验证记录；不顺手更新无关库，不删除或放宽已有确定性规则与测试。
- 局部验证通过后，完成 cargo fmt --all -- --check、cargo check --locked --all-targets、cargo clippy --locked --all-targets -- -D warnings、cargo test --locked --all-targets。批次结束跑一次相关完整检查；新改动或新失败才增加重复测试。
- 两平台 CI 通过，涉及界面、安装、字体、TeX 或平台后端的批次补相应真机验收；Linux ARM64 保持 GLIBC 2.28 和干净 Ubuntu 20.04 的安装启动要求。
- 复查锁文件与安全公告，分别记录“漏洞匹配已消除”“停止维护仍存在”“特定平台未验收”，不能混成一个全绿结论。
- 拒收数据损坏、旧格式不兼容、无解释的输出丢失、AI 越权写入、新增确定性检查失败；性能回归先定位，解决或明确可接受取舍后交付。
- 开发安装包用于本机验证，正式发布另走仓库发布流程；安全批次可以先发，其余批次验收完成后再决定发布组合。提交/发布按后续实施任务授权进行，本计划不执行这些操作。
- 回退以该批提交为单位，清单、锁文件和必要适配同步回退；不回滚用户数据。若方案产生不可逆数据迁移，暂停该批并拆出迁移设计。
