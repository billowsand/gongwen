## 公文助手 v0.10.5

本版本把「**敏感数据不落明文**」这条线做完，并把加密导出做成**可选项**：设置页可以开启独立密码的加密导出（默认开启），开启后 Word 与 PDF 用各自的打开密码、源码包与份号清单用内容和文件名一起加密的 7z；关闭时明文导出每次先确认风险。稿件包改用同样口径的 7z，全量备份也换成加密 7z。**图片、PDF 插图与图表缓存并进加密的稿件库**，磁盘上不再有 `images/`、`mermaid-cache/` 目录，也看不出原来是什么图。

### 加密导出：独立密码、可选开关、明文逐次确认

- **加密导出默认开启**：设置页「导出格式」新增「加密导出文档」，另设一个**与登录密码不同的导出密码**，不由登录密码派生。新设的导出密码要与两套登录验证器做只读比对，命中任一个就拒绝（不提示命中了哪一套）；改登录密码时也不允许改成与保存的导出密码相同。
- **Word 与 PDF 用原生加密**：PDF 走 AES-256 标准安全处理器 V5/R6，正文与元数据一起加密，打开密码与所有者密码都非空，不用「禁止复制/打印」冒充保密；Word 走 Office Agile Encryption（AES-256-CBC、SHA-512、10 万次派生），整个 OOXML 包加密，文件仍是 `.docx`，不用普通 ZIP 加密糊弄。
- **源码包与份号清单改用 7z**：Markdown / Typst 源码包由 `.zip` 改 `.7z`，AES-256 且文件头加密（不输密码连包内文件名都看不到）；份号清单与单独的写作成果也走同一口径。
- **不提示与逐次确认分清**：勾选加密导出时直接出加密成果，**不弹风险确认**；取消勾选后每次明文导出都先确认「导出文件可能泄露信息」，确认才写，取消或按 Esc 不生成文件。未启用应用锁时文档按明文导出，同样每次确认。密码没设、设置损坏或失去解锁密钥一律导出失败，**不自动降级**成明文。
- **覆盖范围**：普通导出与快捷导出、重新导出到指定位置、花脸稿、签收记录单、传发任务单、送批材料合并 PDF、稿件库 PDF 附件另存，以及内存 PDF 的「另存并系统打开」——主文与附属文件用同一把导出密码。稿件包、批量 PDF 集合与全量备份各有自己的包密码，不与这个开关混用；词库、风格档案等其他普通文件出口仍逐次确认明文风险。
- **应用内仍能看**：PDF 查看器在后台用当前保存的导出密码解密到内存再渲染，不写临时文件；打印同样先解密。换过密码的旧成品不会自动改密，应用内打不开时提示用系统阅读器输入旧密码。
- **边界写在明处**：导出密码单独以槽位密封的密文保存，**能解锁本机数据的人仍可能取出这把导出密码**——它不是两套互不解封的密钥系统，界面上说清楚这一点。文件名与文件大小始终可见；解密、解压、外部另存、打印队列、纸件与系统缓存都在应用控制范围之外。

### 稿件包与全量备份：都换成加密 7z

- **稿件包改用 7z**（`.gwx` 后缀不变）：内容与包内文件名一起用 AES-256 加密，按文件签名识别格式——**旧 ZIP 格式的 `.gwx` 与 `.zip` 稿件包照常导入**，旧密码照常可用，新包的清单版本 1/2/3 继续兼容。新包需要新版公文助手才能导入，**改成 `.zip` 后缀不能让旧程序读**。打包在固定内存快照后于后台进行，不生成明文中间文件。
- **全量备份改用加密 7z**：要求先启用应用锁并完成加密，另一槽位若还有明文库要先解锁它完成迁移。备份用独立备份密码加密内容与文件头，条目各用新盐与 IV；恢复要先输密码，再校验签名、格式、条目数量与大小、路径、重名与属性，用户确认后才替换。**只支持新版 7z，不保留旧 ZIP 恢复兼容**（此前确认未使用过旧备份）。恢复暂存目录只写密文，校验失败不碰当前数据；恢复后仍需备份当时的应用锁密码解锁。
- **批量 PDF 集合**同样改为 7z，包本身加密，解压出来的普通 PDF 仍需自行保管。

### 资源入库：磁盘上看不出「这是什么图」

- **图片、PDF 插图与图表缓存并进 SQLCipher 主库**：新增资源表（内容按 SHA-256 去重的 BLOB + 逻辑引用别名），与稿件库同库同密钥。新引用形如 `images/<编号>`，**不含原文件名、扩展名与时间**，格式按魔数判断，不再看路径后缀。预览、导出、DOCX、Typst 与稿件包统一走资源层读写。
- **旧稿照常能用**：旧图片在工作区入口解密后迁进库，校验点落盘再覆写删除；别名保证旧正文、历史版本与旧稿件包里的 `images/<原名>` 引用继续有效，**不改历史版本的正文**。稿件包导入在事务内写资源表，不再生成 `images/` 文件。
- **图表缓存也进库**：Mermaid 缓存按内容哈希引用，警告单独存文本对象，上限 512 条自动裁剪。换过密钥的旧缓存按「可读才算命中」判定，解不开就重渲染并用当前密钥覆盖，**不再卡在占位图上**。
- **可靠性修复**：资源写入在提交失败时回滚清场（否则事务残留在共享连接上会让后续每次写入都失败，直到重启）；校验点显式读出 busy 标志；同步导入的同名冲突检查补上磁盘回退，不再静默遮蔽别稿的插图。

### 敏感明文收口：备份、进程转交、打印与剪贴板

- **进程转交不再写业务路径**：保留实例文件锁，改用只绑定 `127.0.0.1` 的临时回环连接加随机认证令牌转交。路径只经内存传递，磁盘上的 endpoint 文件只有本轮端口与令牌，不含用户路径、应用密码或数据密钥。旧 `inbox` 明文请求在成为主实例时清理，清理失败直接上报。
- **打印全程内存**：花脸稿预览与起草页直接打印都由内存 PDF 驱动。CUPS 经 stdin 收 PDF，Windows 直接解析字节交给 GDI，**都不再生成明文送打缓存**；印制追溯码也在内存成品上加盖。另存则先在内存生成所选成品，再原子写入用户选定的位置。
- **名称与内容一起保护**：接口定义集中为 `apis/services.json`，用户技能集中为 `pi/user-skills.json`，Pi 工作文件与技能快照由密封容器保存，模型仍用原逻辑路径而业务名称不再成为物理文件名。
- **剪贴板先确认**：加密工作区里复制或剪切文字、图片与文件前先确认外部副本风险（系统历史、跨设备同步、第三方工具）；剪切在编辑器删掉源文字之前确认，取消不重放剪切事件。确认只对本次操作有效。
- **普通模式也要说清楚**：首次选择不启用应用锁须确认明文风险；只有启用应用锁后才能记住稿件包密码，旧版留下的明文密码会被清理。
- **数据库迁移可恢复**：迁移中断后重新解锁会先恢复原库，新库就位后必须通过完整性检查才擦除旧库与 sidecar，清理失败就报错，不再宣称「加密完成」。

### 质量检查

- 三平台 CI 门禁（格式、clippy、3030 余项自动化测试）全部通过。
- 本版新增的关键测试：加密导出按格式分别验证（Word 用独立解密库还原原字节且错误密码还原不出、PDF 无密码拒绝渲染且正确密码能由 hayro 打开并数出页数、7z 无密码读不到目录）、全格式与两类随行单据端到端加密、缺密码 / 格式不支持 / 失去密钥一律不降级、导出密码独立且禁止反向设为登录密码、加密不提示而明文逐次确认、取消确认不写文件、资源库别名保证旧正文与旧包引用继续有效、Mermaid 换密钥后重渲染落得了盘、迁移中断恢复与保留原库、隐名文件树的改名与只读快照、剪贴板确认、内存输出连隐藏清单也不落盘、新版备份拒绝旧 ZIP 与错误密码并可回滚。
- 发版前另修掉本版新测试在 CI 上的三处失败：CI 没有随包 `runtime/fonts` 排不了 PDF（按仓库既有约定收窄到不依赖字体的格式），以及 Windows 上主实例独占锁住的 `instance.lock` 读不了（改为对实例锁断言大小为 0）。

### 已知限制

- 应用锁、资源入库、加密导出与加密备份**仍待真机验收**：三平台上的锁屏、迁移耗时、断电恢复、真实 Word / WPS 打开与打印、以及大备份往返都要在目标机上过一遍。
- 智能写作的隐名文件树与加密长会话在真实模型下的性能与稳定性未测；Pi 宿主已升到 **0.4.1**（协议仍为 4），随包运行时由发布流水线按仓库里的 `pi-host` 源码重新组装。
- 加密导出只保证文件自身加密：文件名与大小可见，解密后的外部副本、系统打印队列、纸件、剪贴板历史与外部模型服务端的留存都不在应用可控范围。
- 替换、覆写与删除不保证擦除 SSD、文件系统快照或系统备份中的历史副本。
