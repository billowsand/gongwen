## 公文助手 v0.6.0

本版本给应用装上**自带的中文输入法**：打开就是中文输入，不再依赖系统输入法，也不受别的应用装了哪套输入法影响；同时随包发布新的运行时资产（含输入法词库与整句模型）。因为集成了 GPL 的输入法内核，许可证由 MIT 改为 GPL-3.0-or-later。

### 输入法：应用内拼音

- **引擎、词库与整句模型都在本进程里**。没有独立进程、没有命名管道、没有系统输入法：拼音切分、候选排序、整句转换与选词学习全部在应用内完成，平台无关（Windows / macOS / Linux 同一套代码）。词库 9.3 万条、bigram 语言模型 486 万组随包分发。
- **在本窗口关掉系统输入法**。接管键盘时把 egui 报给后端的 IME 输出摘掉，后端据此调 `set_ime_allowed(false)`：Windows 落到 `ImmAssociateContextEx`，Linux / macOS 落到各自的 text-input 协议——三平台同一行代码，而且**只影响本窗口**，切到别的应用系统输入法照常。
- **上屏走 egui 自己的文本插入通路，不用预编辑**。预编辑文本会被真的写进文本框，而文本框一失去焦点就没人负责删掉那段拼音；所以拼音只活在引擎里，画在自己的候选窗里，正文里到上屏为止一个字都没有。
- **候选窗两行**：上面一行是拼音串（带光标位置）与页码，下面一行是候选。挤在一行时拼音、候选、页码混作一团，读的人分不清哪个是打的、哪个是选的。两行之间不画分隔线，靠字号与颜色分层（拼音小字弱化、候选正文色），候选块的内边距与行距都收到最小，窗口高度压在 40 余像素，投影跟主题走；中英指示只在状态栏出现，不在候选窗重复。
- **状态栏最右的中英指示**，整块可点；单击 `Shift` 也能切，默认中文。它是「现在到底在中文还是英文」唯一的常显提示，所以放在最右、且不受「是否打开稿件」影响。
- **公文词表同步给输入法**：词表里的本单位专名、公文套语导出成附加词库，系统输入法永远不知道「某某处」「某某函」该怎么打，这是自带输入法最直接的理由。词频以「出现篇数」为主信号而不是出现次数（同一篇里反复出现的词不该压过跨篇常见的词），封顶保证再高频的专名也压不住基础词库里的常用词。设置页一键同步，改完词表不用重启。
- **学习数据与公文同一个用户目录**（`config_dir()/ime/`）：词频、用户词、个人 n-gram、敲错表、词表导出的附加词库都在这里，删掉这个目录就等于让输入法忘掉使用者。退出前与运行中每 60 秒各落一次盘。
- **输入方案**：全拼、小鹤 / 自然码 / 微软 / 搜狗双拼，以及小鹤辅码（形码）。**辅码表不随包**——该表权利归方案作者、上游未取得再分发授权，所以做成设置页「选方案 + 导入码表」，码表保存在本机用户目录；没导入时只是辅码关着，不影响其他输入。
- **中文模式下全角标点**（`，。：；`），英文模式与数字后的小数点始终半角。
- 引擎里的意外不会把文稿带走：按键路径整个套 `catch_unwind`，拦下之后卸载引擎、退回系统输入法。

### 运行时资产 v0.5.0（含输入法数据）

- 四个平台的 runtime 包各加入 `ime/dict.qj`（词库）与 `ime/lm.qj`（语言模型），体积各增约 20 MiB。
- **这两项必须写进各平台的 `SHA256SUMS.<suffix>.txt`**：打包脚本只按清单复制文件，漏写不会报错，只会让装完的包静默退回系统输入法。发布流水线因此新增了一道冒烟检查——**真的装配一次引擎并查一个词**，而不只是看文件在不在（文件在而格式不配套、路径变了，都只有装配一次才暴露得出来）。
- `lm.qj` 是可选的：不带它时输入法退到词级候选 + 个人 n-gram，逐词选照常，只是「一句话全拼到底再空格」的整句候选会变差。

### 质量检查

- 三平台 CI 门禁（格式、clippy、900 余项自动化测试）全部通过。
- 输入法本身 48 条测试用一份手写的迷你词库装配真引擎，**不依赖随包的 `.qj` 数据**，所以开发机上没有数据也能跑；覆盖整条链路：敲拼音 → 出候选 → 空格上屏中文、数字选词、退格、Esc、单击 Shift 切中英、Ctrl 组合键放行、全角标点、无数据时退回系统输入法、接管键盘时确实关掉了系统输入法。
- 发布流水线新增的输入法冒烟测试（四个平台都跑）直接断言词库条数、语言模型组数与一次真实查询的候选非空。
- 候选窗、状态栏指示、设置页输入法分区与辅码导入的界面均按三平台同一套代码实现。
