## 公文助手 v0.6.9

本版本把**应用内拼音输入法做成完整产品**：补上自定义短语、四码唯一自动上屏可关、组句里退格/Ctrl+数字/Shift+点击等细节，并加了小鹤音形（简码与开头四码叠在双拼整句上，码表由使用者导入）。排版方面，**「1.」级标题连编号一起加粗**，**紧缩模式按源码空行决定标题是否接排**，**白头件与红头呈批件共用成文日期居中于「落款单位 + 签字空间」**；研究报告新增**引文与文框（`>` 引用块）**，锚点按光标所在块自动起名与重复提示。

### 输入法：应用内拼音输入法打成完整产品

- **小鹤音形（简码与开头四码）叠在双拼整句上**。设置页「小鹤音形」导入使用者自己的小鹤音形码表（搜狗自定义短语格式，UTF-16/GBK 自动识别），存到 `config_dir()/ime/yinxing/`，不随包、不入库；双拼选小鹤时生效。缓冲区从空敲 1–4 键，简码/二简/三简/四码排在候选最前、空格上屏；接着敲第 5 键就当整句双拼，句中不认音形码。三码、四码重码随使用调频，一简二简固定。公文词表里码表没有的专名按小鹤词组规则补码。四码唯一自动上屏做成开关、默认关（拿真实码表模拟 10 句常用公文，不加 `'` 直接打整句错 7 处）。
- **辅码两键恰好也是音节时改为辅码优先**。小鹤双拼下 `dy` 既是「沃」的辅码又是音节 `dun`；新增 `FumaCodes::Pair` 档，两键不从解码里剥掉、两种读法并存，盖满辅码键之前那段拼音、两码全对的候选顶到最前（压过整句、英文与快捷候选），选中时连两个辅码键一起吃掉；按两个音节读时这两键照旧留作下一个音节。
- **自定义短语：敲输入码在固定位置出常用套语、单位全称**。配置 `ime.phrases`：输入码、候选位置（1–9）、上屏文字（可换行）、启用开关；设置页输入法分区加短语表，改完立即生效，不合法时提示原因、引擎沿用上一份。
- **候选窗可竖排、可放大字号**。设置页「候选排列」（横排 / 竖排）与「候选字号」（100% / 125% / 150%），字号连同星标、词表圆点等画出来的记号一起放大、间距不动；竖排时候选按自身宽度左对齐，不撑满整列，免得候选窗被撑到视口那么宽。
- **小鹤辅码 / 音形（`ime-dev-tables` 编译开关）**：开启时把 `assets/fuma/danzi.txt`（小鹤辅码）与 `quan.txt`（小鹤音形，UTF-16LE）编进二进制，启动时装进 `config_dir()/ime/`（只在文件不存在时写、不覆盖使用者的表），本机开发包（`scripts/package-dev.ps1`）默认带这个开关。**两份码表权利归方案作者、无再分发授权**：只给本机自用，文件被 `.gitignore` 挡住，发布流程与 CI 都不带这个开关。
- **启动时双拼方案没推给引擎的 bug 修了**：`new` 没把双拼方案与全角标点设进引擎，之后每帧 `apply_settings` 见设置没变又直接返回，引擎一直停在全拼。设置推给引擎的事收进 `bare()`，`new` 与测试入口共用。
- **启动时按配置装配输入法，关掉了就不读词库与语言模型**：此前一律按默认设置（启用）装配，配置里关掉的也照样加载词库与 44 MB 语言模型。
- **组句中 Ctrl+数字删掉候选的学习记录**：学错的词、误造的用户词可删；拼音留着接着选，结果写进状态栏。词库自带的词删不掉。
- **组句中 Shift+点击不再误切中英**：鼠标按下、滚轮打断 Shift 单击判定（Shift+点击是扩选）；按住 Shift 超过 500 ms 再松开不算单击；组句中单击 Shift 切英文时已敲字母原样上屏。
- **组句中的快捷键、Delete 与粘贴不再落到候选窗背后的正文上**：Ctrl/Alt+退格、Ctrl/Alt+左右按音节删、按音节挪拼音光标；Delete 删光标后的字母；其余快捷键、Tab、剪切与粘贴先把拼音原样上屏，按键本身照样交给应用；单按修饰键不算快捷键，拼音留着。
- **密码框、接口地址等 ASCII 字段不走应用内输入法**：控件画完后用 `ime::exempt` 逐帧声明，焦点落在这些字段就不接管键盘——密码框里敲的字母此前会明文出现在候选窗拼音串里，组句中的数字会把汉字选进密码。
- **光标离开刚上屏的位置时断开上文**：回车、方向键、Home/End、翻页、Delete、Tab、快捷键、粘贴与鼠标点击调引擎的 `break_chain`，下一个词按句首记，不再拿别处刚打的词当上文；之后的退格也不再被当成「删掉刚选错的词」。Esc 不挪光标，照旧原样放行。
- **没在组句时的退格告诉引擎**：选错删掉重打时撤回那次学习。引擎的 `note_backspace` 接上，上屏的词被整个删掉、接着重打同一段拼音选了别的词，那次选错记下的词频退回去。退格本身照样交给文本框。
- **词表改动后自动同步给输入法**：接受、拒绝、改读音、手动加词、清空与扫描完成都走同一个 `lexicon_changed`，最后一次改动后安静 2 秒就把词表同步成输入法的附加词库，不必再去设置页手动点。
- **设置页输入法分区重排**：全部按「左列标签、右列控件」排，分组改为输入方案 / 小鹤音形 / 候选窗 / 自定义短语 / 公文词表 / 按键速查；引擎状态压成一句话（词库 9.3 万条 · 整句模型已加载）；候选窗设置不再混在输入方案里。

### 排版：标题加粗、紧凑接排、日期居中

- **「1.」级标题连编号一起加粗**：#### 标题（默认编「1.」）与 ##### 一样按「加粗文字」设置排粗体，编号一并加粗；单独成段与紧缩接排都生效，预览、Word、PDF 三端一致，左侧导航标签随纸面同步。同步技能包字体表与字体设置说明。
- **紧缩模式按源码空行决定标题是否接排**：紧缩模式选中的那一级标题，只有与下一段正文紧挨着写、中间不空行才合成一段；空一行则照常单独成段，与列表「贴着写并入上段、空一行独立成段」同一口径。`compact_heading_flags` 多收各块起始行号，预览、Word、PDF 三端共用同一判定。同步技能包、README、使用帮助与设置页说明。
- **白头件与红头呈批件共用成文日期居中于「落款单位 + 签字空间」**：白头件落款单位右侧留有 4 cm 签字位，但成文日期仍与单位右对齐，应与红头呈批件一样落在整段正中。`gonghan-gwa.cls`：白头件与红头呈批件共用 `\gwa@roomsignature`，单位块宽度参数改名 `\SignatureUnitWidth`，白头件导出时同样写入；Word 去掉白头件日期右对齐特判；预览的落款辅助布局同样居中；单位块宽度封顶到「版心 − 签字空间」，长单位名折行时日期不出版心。

### 研究报告：引文与文框，锚点自动起名与重复提示

- **引文与文框（`>` 引用块）**：行首写 `> `（大于号加空格）的连续几行是引用块。**引文**排成楷体、与正文同字号，左右各缩进两字，以 `——` 开头的一行是出处，靠右排；**文框**首行写 `> [!名称] 标题`，排成细框、浅灰底，名称写什么印什么（专栏、案例、例子、做法都行），每种名称各编各的号，口径与图表相同（章号.序号，不编号章里流水号，附录 A.1），不占表号。文框里的脚注印成括注、行内公式印源码（与表格单元格同一规矩）。PDF（`md2tex.cls` 新增 `mdxquote` / `\mdxboxstep` / `\mdxboxtblr`）、Word、预览、版本对照三端一致；公文文种按普通段落排，文框名称与标题降为一段加粗文字。行首要印一个 `>` 时写成 `\>`，`>5%` 仍是正文。
- **锚点按光标所在的块自动起名**：「研报 › 锚点」按光标所在的块自动挂锚点，前缀按对象（`part`/`chap`/`sec`/`fig`/`tbl`，文框按名称），后面是标题拼音，全文不重复；光标在表格、文框里时挂到表题行、首行；引不出号的块不挂并说明原因。
- **重复锚点改为逐处提示、带位置**：导出 PDF 会因此中止，旧文案说「以先到的为准」不对，进必改清单；交叉引用下拉与技能包检查脚本同样提示。
- 同步技能包文档、使用帮助、起草与润色提示词，`vendor/mdx/README` 记下待同步回上游的改动。

### 界面细节

- **稿件管理：单篇删除改为按钮旁的确认气泡**：确认条原先插在列表上方，离删除按钮太远，一出现整个列表就下移一截；改为贴着删除按钮（窄屏时贴着「•••」）弹出的独立图层，点外面、按 Esc 或再点一次删除按钮即收起。
- **光标按字形高度绘制**：egui 的 `TextEdit` 把光标画成整行高（再上下各多 1.5 px），而编辑区设了固定行高，光标因此比字高出近一倍、空行上尤其显眼。新增 `draft_page::caret`：绘制编辑框期间关掉 egui 自带光标，事后按光标旁字形的字体框补画一条；跳过实时排版里压成近零宽的隐藏标记，空行借相邻行的字高，闪烁节奏照搬 egui。起草页两种编辑模式与版本对比编辑器统一使用。
- **macOS 冬青黑体（`fix(theme)`）：新版 macOS 找不到苹方时系统默认界面字体是冬青黑体，line gap 是半个字高，按钮与下拉框里的字明显靠上**。把字形下移半个 line gap、上下各分一半，line gap 为 0 的字体不受影响（macOS only，Linux/Windows 不走这条路径）。
- **新增 `scripts/package-macos.sh`**：macOS 上从源码构建后组装 `.app` bundle（仅供从源码使用者使用，发布流水线仍只产 Windows / Linux ARM64 两个平台包）。

### 质量检查

- 本地 `cargo fmt --all -- --check` 与 `cargo clippy --locked --all-targets -- -D warnings` 全部干净。
- 本地 `cargo test --locked --all-targets --no-fail-fast` 实测 **1343 条用例通过、0 条失败、35 条 ignored**（含须完整内置 Tectonic runtime 才跑的 LaTeX 编译回归测试）。
- **修复 Linux ARM64 CI 红**：v0.6.8 收尾后，main 上两次 CI 都因 `preview::tests::white_paper_signature_stacks_units_right_aligned_and_spreads_short_abbr` 在 Linux 上飘 ~4.3 px 而失败（Windows 通过）。这是字体度量依赖——断言「成文日期中点应在单位与签字空间中间」按 em→px 算单位块宽度，Linux 度量与 Windows 度量在这一点上有 ~4 px 漂移，结构断言（不与单位右对齐）仍守得住。把容差从 `3.0` 放宽到 `8.0`，产品行为不变、Windows 实测仍贴 0，CI 也过。
