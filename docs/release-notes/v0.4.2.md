## 公文助手 v0.4.2

本版本让 Markdown 源码模式也看着像成稿——标题、正文与标记六处可各选字面；并修掉切明暗主题后编辑区停在旧配色、复用失效字形坐标的两处毛病。

### 源码编辑器的 Markdown 字面

- 「设置 → 字体」新增一节「源码编辑器的 Markdown 字面」：文档标题、一级标题、二级标题、三级及以下标题、正文，以及「标记及行内代码」六处各自选字面，可选编辑器字体与小标宋、黑体、楷体、仿宋。公文字面与预览、导出同源——在「编译字体」里把正文换成本机仿宋，编辑器里的仿宋跟着换。
- 预置三套模板：**编辑器字体**（默认，与以往完全一致）、**标题随公文**（只有标题换公文字面，正文仍好编辑）、**与公文一致**（正文也排成仿宋，最接近打印稿）；逐项改出来的组合显示为「自定义」。
- 只换字面，不动字号与行距，导出结果不受影响；`#`、`|`、`**` 这些只在源码里出现的符号默认留在编辑器字体上，仍然一眼可辨。要连字号行距一起按公文排，原有的「实时排版」模式照旧。
- 旧配置缺这一项时按默认值补齐，升级上来显示不变。

### 主题与配色

- 修：切主题（尤其明暗互换）后 Markdown 编辑区仍画着上一套颜色，改字或挪光标才恢复。高亮缓存的键里补上配色版本号，主题与纸面每变一次就加一，切完的第一帧即重新上色。
- 修：明暗互换后编辑区缺字、糊成一片或串字。egui 会在配色变化后的下一帧整份重建字形图集，旧 galley 里记的图集坐标随之全部作废，而缓存键此时一个字节都没变。现在缓存只存排版任务（`LayoutJob`），排好的 galley 每帧重新向 epaint 要一次；若 epaint 确实重排过，标题居中等后处理一并重做。
- 修：在菜单里切主题的那一帧，根 `Ui`、Markdown 编辑器与滚动区早已按旧主题创建，会画出新旧混绘的一帧。切主题后作废当前 pass 重跑，整帧从第一帧起就是同一套主题。
- 修：实时排版的纸面写死了纯白与纯黑，深色纸面下成了浅字压白纸。改为与预览页一致，从纸面主题取纸底、墨色与投影；明色纸下取值与改动前逐字节相同。

### 工程与维护

- 给共享 jieba 分词器的用例加串行锁：jieba 是进程级全局状态，`cargo test` 多线程跑时，一个用例刚挂上用户词典，另一个用例的 `install_user_dict("")` 就抢在断言前把词典撤掉，`user_dict_keeps_a_local_abbreviation_together` 偶发失败而单跑不复现。25 轮并行压测：改动前失败 1 次，加锁后 85 轮 0 次。对用户无影响。
- 新增 `AGENTS.md`，记录技术栈、常用命令、模块组织、三条 AI 红线与发布约定；`.pi/settings.json` 入库共享，`.pi` 的依赖安装目录不入库。均与运行时行为无关。

### 质量检查

- 三平台 CI 门禁（格式、clippy、全部自动化测试）全部通过；本机 771 项测试通过、20 项环境依赖测试按设计忽略。
