## 公文助手 v0.9.0

本版本把 AI **重新设计**成一个能干活的智能体工作台：右侧 AI 侧栏按技能干活，数据接口以 OpenAPI 为中心并能用「用例 + 一句话」证明模型调得对，智能体内核完成工具契约、提案逐块接受、用量留痕与检查点续跑四期加固。三条红线一条没松——AI 依然不能直接写正文、依然碰不到公文要素、产物落地前照样先过三道确定性闸门。

### AI 侧栏与技能：从输入框到智能体

- **技能成为干活的单位**：一个技能是一份 `SKILL.md`（流程 + 参数 + 工具 + 各步提示词）。内置十二个技能覆盖起草、修改、审核三类；输入框敲 `/` 选技能、敲 `@` 引用文章（按技能 `references:` 声明当证据 / 基准稿 / 材料 / 来函）；会话随稿件保存，可直接追问「再短一点」。
- **自主步骤**：流程里写 `- step: agent`，模型自己决定调哪个工具——读正文、检索知识库和稿件库、算日期数字、改工作稿、记结论——程序执行每一次调用并在过程里留一行；优先用服务端的原生工具调用，不支持时退回文本协议。
- **确认题改成结构化输出**：澄清题走 json_schema，端点不支持时退回文本约定。
- **在左侧 Markdown 区展示 AI 工作稿**：起草过程看得见，工作稿与正文分区对照。
- **标准词库补职能任务与个人简介**：人员与单位各有职能描述，供 AI 分配任务时参考；单位树支持同级拖拽排序。
- **动笔前先问清六要素**：按文种清单问时限、对象、联系人；确认题附 AI 建议写法并带上所在小节与整句；按回答修订由 AI 把答案写进所在段落，闸门不过才直接替换；查不到的依据类缺口由 AI 写成概括表述。
- **侧栏说「把 AI 工作稿提交到正文」时弹写入确认卡**（不再交给模型自己决定）；写作风格档案可从指定稿件学习，起草与改写时按文种与场合自动选用。

### 提案逐块接受（内核加固第 2 期）

- **审阅窗里逐块取舍**：每个变更块旁新增「不要这处」按钮（悬停「排除这处改动，接受时保留原文」），点过变「恢复这处」、整块变灰并挂「保留原文」标签；有排除时底部主按钮变成「接受其余 N 处」。
- **关键事实变化清单随排除实时变短**：被排除块带来的变化不再列出也不再要求勾选；勾了核对项之后清单又变了，勾选自动作废要重勾。
- **排除组合造出清单之外的关键事实变化会被拦下**，提示恢复部分排除或让 AI 重做。
- **合并后的正文重新过闸门**：要素校验重跑，版式估算按合并结果重算，被排除块里才有的版式问题不跟进来。
- 落地后卡片状态变成「已写入正文（排除 N 处）」，会话记录写明「排除了 N 处改动」，写入确认卡摘要追加「（已排除 N 处，只写入其余改动）」。

### 工具契约与结构化输出（内核加固第 1 期）

- **内置工具与数据接口共用一套参数契约**：参数带类型与 JSON Schema，必填、多余、类型、枚举、数组元素、对象必填各一层校验，不合格不发请求；错误连同参数签名与正确示例回给模型让它改一次。
- **工具多时两级访问**：可用的工具超过 24 个（或接口超过 12 个）时，模型改用 `tool_search` / `tool_call` 先搜后调，界面上会多一行「找工具：…」。
- **自主步骤的过程里多了三行**：「找工具：…」「模型要调「X」：无此工具，已拒绝」「自主步骤调用 X 没有做成：…」。

### 用量、留痕与备用模型（内核加固第 3 期）

- **每轮卡片末尾记用量**：「模型调用 N 次 · 约 输入 X / 输出 Y token · 用时 M 分 S 秒」（「约」只在有估算时出现，token ≥1000 缩写成 `1.2k`，用时含挂起答题前那段、续跑时累加）。
- **提案卡留痕**：卡片抬头下写「技能 · 模型 · 证据 K1–K3、K7 · 时间」，记不到写「未记录模型」、没引用证据写「未引用证据」；侧栏卡片、审阅窗顶部、左侧工作稿顶部都出现，接受或放弃后仍随会话保留。
- **备用模型**：AI 管理页的「模型服务」里，文字起草与文字复核各可配一行「备用模型（可不选）」；主模型不可用时自动改用并当场说明「主模型 X 不可用（…），本次改用 Y」。已经开始吐字后出错、点停止、上下文溢出都不切换；辅助角色（澄清、核对、自主步骤）优先用复核备用，无则沿用起草备用。
- **知识库页显示检索耗时**：「N 篇 · N 块 · 最近一次检索 3.6 秒」。
- 流式用量读取并记住字段降级；服务端不返回用量时按字符估算。

### 检查点与崩溃续跑（内核加固第 4 期）

- **引擎每一步成功后自动把检查点存进稿件库**（挂起答题也算一步）；「已中断 / 已停止 / 失败」三种卡片上多一行「可接着跑：已完成 某某步骤 · 时间」与三个按钮 **接着跑 / 从头重来 / 丢弃**。
- **从这里重跑**：折叠块里折叠列出这一轮存下的检查点，每条右侧一个「重跑」；**正文在那一步之后改过就整轮拒绝**并说清原因，给出「接着跑 / 从头重来」两个出路。
- **恢复只有一个入口**：「答完题接着跑」与「崩溃后续跑」最终调同一个函数，闸门、定稿、提案只有一份；只读区（授权要素、日期）按界面当前值重灌，发起时说的话、锁的选区、引用的文章、写法风格沿用本轮原值。
- 保留策略为「首 + 近 5」共 6 份；单份超 512 KB 时证据包只留最近 20 条并标「证据已省略」；写盘失败不中断流程，只在卡片说明区留一句「检查点没存上：…」。
- 审阅窗第 4 期修复：崩溃续跑比对技能指纹、路径列坏了不拿序号顶替、重跑提示给字数。

### 数据接口：以 OpenAPI 为中心（工作台三期）

- **中心格式**：一个服务一份 OpenAPI 文件（存配置目录 `apis/`，可在 Postman / Apifox 打开）；支持导入 OpenAPI 3.0 / 3.1、Swagger 2.0、Postman 集合与环境、cURL，导出为 OpenAPI（不带密钥与本机环境地址但带用例与期望）。旧的 `apis.json` 首次打开自动按服务器分组迁移、原文件留成 `.bak`（无提示）。
- **接口用例**：每个接口配一组「用例 + 期望」，五种期望（不为空 / 至少几条 / 等于 / 包含 / 有字段）用 JSON 指针写；「全部 N 条用例跑一遍」逐条实测并留记录，也可「AI 编几条用例」。
- **运行记录**：状态片显示「用例 5/6 通过 · 时间」「配置改过，需重测」等；记录只存结论与一句原因，不存返回内容与参数值。
- **说一句话让 AI 调**：一句用户问法 → 模型挑接口、填参数；选对且校验过了可把参数锁定后「存为 AI 用例」，「全部 N 条 AI 用例跑一遍」记正确率，「AI 出几个问法」生成候选问法。判定口径是**接口选对 + 写明的参数对 + 调用成功**。
- **只查询的接口才给 AI 调**：会改数据的接口发前要人工确认，不参加「全部跑一遍」也不给 AI 调；「只查询」这个勾程序与模型只能往严的一边改。
- **界面减负**：列表按服务器分组、密钥按服务共用一把 Key、详情页收敛为三个页签（接口说明 / 试一下 / 技术配置）、多行输入限高。

### 模型服务商管理

- 模型地址与密钥收进「**模型服务商管理**」（预设模板 + 提供商卡片）；「模型服务」按功能（对话 / 向量 / 重排）选模型；旧内联地址字段随启动自动迁移。
- 模型选择器按用途过滤（对话 / 向量 / 重排）；知识库文档列表改为紧凑表格，修复长标题挤掉删除按钮；数据接口页与技能管理重设计。

### 界面与交互

- **统一模态确认框**：关闭稿件与退出汇总、稿件批量删除与导出 PDF 与 ZIP 密码、精确移动、知识库导入与删除确认、归档确认、ZIP 导入预览与待处理合并、版本切换、提交与回退、关闭确认全部改用模态；模态统一收走背后焦点并停用快捷键。
- **按钮与控件**：关闭确认、版本提交与 AI 提案按稳定标识绑定操作对象；小按钮去掉竖向内边距避免被行高裁切；浮层列表（交叉引用、词库下拉、快速查找、标题聚焦）改用统一的滚动高度设置。
- 顶栏右端新增快捷查找与换肤按钮；起草页支持导入电子版 PDF。
