## 公文助手 v0.9.3

本版本把「AI 问什么、答完怎么落地」抽成一套通用的**人机决策模块**（待决事项、事实冲突、多选取舍、证据取舍、方案比选、自主步骤中途提问），公文**表单要素**随之由 AI 打点：动笔前按标准词库出题与给建议、采纳才写表单；单位词库的全称改为各自维护，界面新增第十一套主题「锤子稿纸」，要素里的单位下拉框支持汉字 / 全拼 / 首字母检索。

### 人机决策：问什么、答案怎么改流程

- **挂起出口统一，答案能改变流程**：清单确认、多选题、证据取舍、方案比选都走同一个挂起出口（决策形态随挂起交给界面，界面按形态画卡片）；技能流程里的 `when` 条件支持取值比较（`{ var: x, eq: 值 }` / `{ var: x, in: [值…] }`），**选择题的答案能决定下一步走哪**，技能校验会检查写法。旧会话里挂着的大纲确认读回时自动补成可修订的清单确认。
- **待决事项**：正文里还留着「【待核实：…】」时，侧栏顶上一行「正文里还有 N 处待核实 · 逐条填写」，点开把占位列成题（一批 4 道，与交付后的缺口题同一套，其余答完再列）；答完 AI 把答案写进所在段落，仍以**对照当前正文的提案**交给你确认。正文自列出之后改过，这批回答不落地，按现在的正文重新列一遍；有没答的题、没处理的提案或正在跑的一轮时不列。
- **事实与材料对不上时给候选**：来源不明的数字、日期在材料或资料里写着别的值时，题干直接问「按哪个写？」，选项里多一条「按材料：15项」（出处是资料时写成「按《题名》：…」）并附出处里那句话的摘录。**只有一个候选时推荐它**，几个候选说不准就推荐先「改为待核实」。材料之间互相打架的不做。
- **多选取舍**：清单确认卡片可以逐条勾选（默认全勾，不能改字、不能让 AI 重列），勾中的项按原值落地；多值要素（主送、抄送、呈报领导）与清单取舍都走它。
- **证据取舍**：政策研究报告在大纲确认后先按整份大纲检索一轮，查到三份以上资料时逐份列出（附摘录），勾掉的不再进证据包，**之后的逐章检索与补缺口也不会再找回来**；你 `@` 引用的文章不参与取舍。证据编号顺带改成只增不减，剔掉资料后再并入不会撞号。
- **方案比选**：新算子 `compare` 让模型出 2–4 个整段候选并排显示（去空、去重、去编号前缀、限 600 字，带了出处里没有的日期数字文件名的版本直接丢掉），挑一个或自己写，不设推荐项；只剩一个直接用。政策研究报告拟题名用它——拟三个不同角度的题名请人挑，题名只进 AI 工作稿，不回写文档要素。
- **自主步骤中途提问**：声明了 `ask.choice` 的技能（自由任务）里，自主步骤可以停下来问一次：一次最多 3 题、一步最多问 2 次，提问即结束本轮，答完从头重跑这一步并附上一轮进度；问题过长、选项不是 2–4 个、问到密级文号签发人成文日期这类授权要素或问文种的整批打回。

### 公文要素：动笔前出题与建议，采纳才写表单

- **动笔前接入要素抽取**：先核对要求与材料里写没写主送、抄送、发文单位、承办单位、联系人、呈报领导、落款单位。写明且唯一对上标准词库的直接进**建议卡**；没写、或写了对不上的出成**选择题**，选项全部由程序给——材料里对上的名称排前面标推荐，人员只列承办单位的人；字段题单独占名额，不再挤掉六要素的「何时」「何法」，也不会让「何人」被漏问。
- **要素建议卡**（挂在侧栏这一轮卡片上）：**采纳**（多值按词库顺序写入；发文单位采纳时机关代字按表单规则带出）、**全部采纳**、**替换**（表单里已有别的值、与材料不一致时不参与全部采纳）、**撤销**（按采纳前的整表快照还原，连续采纳要倒着撤，采纳后表单又动过就不让撤）；建议生成后表单改过要点「仍然采纳」，词条被删或文种不适用则不让采纳；交付提案时还有未采纳的建议会点名提醒。**写表单只有 `element_fields::apply_field` 一条路径**，AI 自己永远不改。
- **授权类要素永远不出题、不建议**：密级与保密期限、文号、份号、签发人、成文日期、版记印发机关与印发日期只由人在表单里填。描述类扩到发文单位、落款单位、呈报领导、承办单位、联系人、联系电话：单位与人员必须是标准词库里的词条，标题与附件说明取自材料原文，值都注明出处。
- **开关拆开**：`elements: false` 只关六要素检查；新增 `fields: false` 整个关掉表单要素（不抽取、不出题、不出建议卡）；`field_questions: 0` 只出建议不出题。
- **复函自带「要素抽取」节**：主送填来函落款署名的发文机关，来函抬头（通常是本单位）不填进主送；来函 `@` 进来或整段粘贴即可，无需改代码。
- **第一期的地基**：新建 `src/element_fields.rs`——字段登记表（中文名、适用文种、必填、读值函数）与统一写值入口，表单的发文单位、主送、抄送、呈报领导、落款单位、承办单位下拉框全部改走这条路径，与 AI 建议采纳是同一条代码路径。

### 单位词库：全称各自维护，代字随发文单位联动

- **单位的规范名与对外名各自维护全称**，层级只用于排序、筛选与重复前缀省略，不再上溯拼接上级名称；主送、抄送按输入顺序显示，只有连续单位的共同上级能证明前缀归属时才省略前缀。
- **公函机关代字绑定当前发文单位**（联合发文取主发文单位），表单里改为只读展示；单位未维护代字时清空，不再沿用上一个单位的文号。

### 界面：第十一套主题与要素检索

- **锤子稿纸（Smartisan）明色主题**：灰棕渐变工具栏、浅木纹底板、横线稿纸与拟物页签，源码与对照模式都支持，成为第十一套主题。木纹每帧只生成可见的那部分——被不透明卡片整片盖住的列与段不再绘制，露出的纹线与整幅绘制逐点一致；对照模式两栏不再各铺一层。
- **单位选择框支持检索**：汉字、无声调全拼、拼音首字母、简称、别名与层级编码都能过滤，多音字按逐字匹配推进，多关键词取交集；检索不改变选中值、词库顺序、主送 / 抄送互斥与统一写值路径。筛选结果每帧不再整体克隆（下拉框开着时不再每帧重建索引与结果）。

### 提示词与模型接入

- **起草提示词的附件写法统一**：各文种从旧写法（`# 附件1` + `## 附件标题`）统一为「每份附件前 `<!-- [附件] -->` + `# 附件正式标题`」；有附件区段时不得手写附件说明，附件编号与附件内标题编号都不得手写；白头件 / 红头呈批件明确大节用 `##` 标题、编号由程序给；输出契约与行文规范对齐（直接引语与历史材料保留原日期表述）；清掉 Word / LaTeX 残留。
- **要素抽取提示词两轮修订**（DeepSeek V4 Flash 与 MiniMax M2.7 联机实测 14/20 → 20/20、17/20 → 20/20）：格式示例改用真实字段名并写明它只是示例；单位完整名整个摘取、只截取职务部门尾缀；摘录对不上词库时，把摘录里包含的词库名称排进候选（「市应急局办公室」能一键选到「市应急局」）。
- **OpenCode Go 接入**：普通补全、流式补全与原生工具调用共用 `gongwen-assistant/<版本>` User-Agent 与 `x-opencode-session`（只对 opencode-go 预设的服务商发送），侧栏任务、追问、历史压缩与检查点续跑使用会话 UUID；补齐 OpenCode Go 预设并简化密钥配置，标识不写入配置文件、重启换新。
- **修正模型上下文估算与手工窗口继承**：新版 DeepSeek 的窗口规模表按版本先于系列兜底匹配，手动窗口加到 512k / 1024k；选技能等辅助步骤用复核模型（未配置时沿用起草），沿用起草时继承起草窗口；超长报错写出实际模型名。
- **AI 输入框**：长文本布局修复（输入区随内容增高、上限窗口高度的四分之一，底栏标签区单独滚动）；一次粘贴超过 2000 字或 30 行时收成「粘贴材料 · N 字」标签，作为标明来源的材料并入本轮请求，不再把输入框撑爆。

### 文档

- **README**：硬数字按本版重新数（约 22.7 万行 Rust、2013 项自动化测试），内置技能数更正为十五个，新增「问清楚再动手，答案能改变往下怎么走」一节，补单位下拉框可检索，红线 2 的要素清单与来源口径（单位与人员取自词库、标题与附件说明取自材料原文）按现状改写。
- **使用帮助**：13 章补多选题目卡、待决事项与事实冲突候选、粘贴材料标签，09 章「存疑清零」补侧栏「逐条填写」入口；顺手改正两处过期说法——视图「五种」→ 四种（`content.rs` 摘要与 07 / 08 / 20 章的三处交叉引用）、主题「十套」→ 十一套（02 章摘要与手册目录）。`assets/help` 与 `docs/help` 两处副本逐字一致，25 章 = 正文 22 + 附录 3 的章节口径不变。

### 质量检查

- 两平台 CI 门禁（格式、clippy、**2013 项自动化测试**）全部通过。
- 本版新增的关键测试：要素建议卡的采纳 / 全部采纳 / 替换 / 撤销 / 过期检测 / 词库与文种校验 / 撤销倒序（`ui_tests`）与 `Event::FieldSuggestions` 通路（`engine_tests`）；要素抽取的分类表逐行断言、授权类拦截、旧会话反序列化兼容；决策形态随挂起、旧会话补形态；多选取舍的勾选落地与编号只增不减；木纹剔除后「露出部分与整幅绘制逐点一致、被盖住的不生成」；单位前缀省略与代字联动；检索不改变选中值。
