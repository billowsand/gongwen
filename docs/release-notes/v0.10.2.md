## 公文助手 v0.10.2

本版本主要给**智能写作（Pi）的运行链补稳定性**，并第一次把 **macOS 打包与 CI 补齐**：长材料任务的来源落盘不再把整轮打断，工具额度、超时、退出接管、并发与 Windows 文件占用这些会在真机上咬人的地方逐项收紧；macOS 有了 `darwin-arm64` / `darwin-x64` 运行时条目、`.app` 组装、可选签名公证与 `macos-14` 的 CI 作业；Linux 的 CI 不再「假绿」，Pi 的进程 / 锁 / 交付测试会真正执行。

### 智能写作（Pi）：运行稳定性

- **事实来源不再整轮重写、也不再因超过 8 MiB 中止本轮**：每次工具返回与用户回答后只写**单项** `sources/items/<sha256>.md`，再写一份很小的 `sources/index-<hash>.json` 索引，运行记录指针原子切换；单项 2 MiB、索引 512 KiB、恢复读取总量 8 MiB，旧格式 `sources/<hash>.md` 仍可读。索引清理只在指针切换成功后执行（保留最近 2 个版本 + 当前指针），不会在「写新索引成功、改指针失败」时删掉旧指针仍引用的来源；落盘失败只留一行提示、不再中止已花掉模型时间的任务；交付收尾对来源写失败降级留痕，堵住「接着写」重放回执时在同一错误上无限循环。
- **工具调用额度对齐**：常规 60 次；分阶段由宿主按阶段追加，硬上限 **84 次**（此前 Rust 侧按 60 判，分阶段长任务会在第 61 次被误杀）。超过时错误里说明可以「接着写」。
- **单轮执行上限放宽到 30 分钟**（等用户回答的时间不计），卡片上直接显示「执行上限 30 分钟」；能力校准单轮 120 秒 → 300 秒、总 15 分钟，并把「超时」与「能力不足」分开统计，不再把超时轮次当成模型能力差。
- **退出与关标签接管**：关窗口时取消正文写作、风格学习与能力校准并最多等 1.5 秒；关标签时若这一篇还有 Pi 任务，先确认再取消，不再留下持着工作区锁、看不见的 Node 子进程，也不再静默丢弃已交付成品。
- **并发与队列**：新增全局 Pi 任务门禁，正文写作、风格学习、能力测试共用；同一时间只跑一轮，避免两个 Node 进程抢同一个本地模型后一起超时。校准遇到写作在跑时会让行并说明原因。
- **失败状态回写**：失败 / 超时 / 停止后按盘上 `run.json` 的真实状态更新卡片（不再一律显示「上次运行没有收尾」）；运行记录收尾写盘失败会出现在错误串里，不再被吞掉。
- **恢复更严**：接着写前按 `input/skills.json` 回验技能快照的每个文件哈希，不再只查文件是否存在。
- **stderr、心跳与退出窗口**：host 诊断的单行超过 32 KiB 时只跳过这一行并继续排空（此前会永久停止排空、可能把子进程卡到超时）；协议里的 ping/pong 真正用起来（30 秒静默 ping、60 秒无响应判失联）；host 报完成后等待退出的窗口从 2 秒放宽到 10 秒，慢盘 / 安全软件下不再把已落盘的成品判成失败。
- **Windows 文件占用**：配置目录写入遇到杀软 / 索引器的短时占用（`os error 32/5`）会退避重试，不再一次占用就中止整轮。
- **生产 host 环境与代理**：Node host 改为 `env_clear` 后只注入最小环境白名单，不再继承用户的 `NODE_OPTIONS` / `NODE_PATH` / `LD_LIBRARY_PATH`；应用里的代理设置换算成 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`（含小写形式与 `NODE_USE_ENV_PROXY=1`）传给 host，直连模式写 `NO_PROXY=*`，跟随系统模式透传系统代理变量。
- **工作区不再只增不减**：准备失败不再留下孤儿运行目录；新增自动清理（每个稿件保留最近 3 轮，只删已写入正文的旧轮次或无 `run.json` 且超过 1 小时的孤儿、且最后修改超过 7 天；带运行锁的目录不删）。AI 管理页显示 `Pi 工作区占用 X MB（N 轮）` 并提供「清理旧工作区」按钮。
- **交付路径与内部路径收紧**：成品路径拒绝任意位置的 `:`、控制字符、空段、以 `.` / 空格结尾的段与 Windows 设备保留名；正文里残留的内部路径名单补上 `pi/workspaces`、`final.md`、`skills.json`、`style-guide.json`、`session.sqlite` 等标记。

### Linux 与 macOS

- **macOS 运行时**：`packaging/pi-runtime.json` 增加 `darwin-arm64` / `darwin-x64`（Node 22.22.3 官方 `.tar.gz` 与官方 SHA-256）；Rust 侧平台判定改为**运行期**判断，未知平台明确报错，不再把 macOS 当成 Linux；首次校验后按文件指纹缓存，避免每次开跑都重读 manifest 和哈希 83 MB 的 Node。
- **macOS 组装与打包**：`stage-pi-runtime.sh` 支持 darwin、`shasum -a 256`、`tar -xzf` 与 BSD 工具；`package-dmg.sh` / `package-macos.sh` 会校验并复制 `runtime/pi`、保证 `bin/node` 可执行位，新增 `--require-pi`；`package-dmg.sh` 先签 node 再签 bundle（`--options runtime --timestamp --entitlements`），可用 `notarytool` + `staple`，没有证书时走 ad-hoc 并明确告警。新增 `packaging/macos/entitlements.plist`（Node 的 JIT 权限）与中文 `packaging/macos/README.md`。
- **Linux / macOS 开发运行时**：新增 `scripts/pi-dev.sh`，在 Linux / macOS 上用符号链接搭出 `tmp/pi-runtime` 并打印 `GONGWEN_PI_RUNTIME_DIR` / `GONGWEN_PI_NODE` 两行 export。
- **CI/CD**：Debian buster 作业现在会组装 `linux-arm64` 运行时并把 `runtime/pi/bin` 加进 PATH，Pi 的进程 / 锁 / 交付 Rust 测试真正执行（此前静默跳过）；Linux 与 Windows 作业补 `shipped_pi_runtime_manifest` 的端到端校验；新增 `macos-14` 作业跑 fmt / clippy / test、Pi host 测试、离线验收、release 构建与 `.app` 打包；release 新增 macOS arm64 的 `.dmg` 资产（未配置签名 secrets 时为未签名包，Gatekeeper 会拦，需右键打开）。
- **`.gwx` 在 macOS**：双击暂不支持（未接 Apple Event open-file），请用拖放或应用内导入；Linux 的 MIME / desktop 关联不变。

### 已知限制

- macOS 包默认未签名 / 未公证（需要配置 `MACOS_SIGN_IDENTITY` / `MACOS_NOTARY_PROFILE` 并导入证书）；x64 包暂不随发。
- Linux 真机、Windows 干净机、较强模型同题对照仍未验收；Pi 不做事实核查，交付前请自行核对关键事实。
- 失败类型仍是可读中文串（未做分类枚举）；旧 `src/agent` 代码尚未退役。
