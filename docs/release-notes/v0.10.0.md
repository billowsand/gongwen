## 公文助手 v0.10.0

本版本把**任务助手收成了五件事**——名称、负责人、当前进展、下一步工作、风险与应对措施——负责人只能从标准词库选人，识别过的材料也有了「材料」库；输入法的找字网格补上缺字的一行，候选窗还能单独选字体；标准词库的单位与人员改为按**永久身份**关联，同名不再张冠李戴；公函多了可单独导出的**签收记录单**；发布页第一次带上 **Arch / Omarchy 的 pacman 离线安装包**。

### 任务助手：要素精简为五项

按实际使用改的：一个任务主要就是**任务名称、负责人、当前进展、下一步工作、风险问题及应对措施**，另留状态与任务期限，不必为了保存去凑字段。

- **填表就五样**：名称是唯一必填；分类、上级、前置收进「更多设置」，关系与完成依赖的判定规则不变。「目标 / 完成条件」「我的角色」「协作分工」「下一步期限」不再出现在界面（旧库的列不删，老库按缺列自动迁移）。
- **负责人只从标准词库选人**：搜索框认姓名、职务、单位与别名，同名不同单位分列显示，选中人员时**所属单位随人带出**；存的是词条身份与选定当时的姓名快照，词条后来改名、调动甚至删掉，任务里仍显示当时的姓名并提示核对，不会悄悄换人。
- **当前进展就地更新**：详情里平时按正文显示，点「更新进展」才变成输入框（`Ctrl+Enter` 更新、`Esc` 放弃），旧进展留在历史里，不再在键值行和输入框里重复显示同一个值；没改动不写重复历史。
- **详情按重要程度重排**：标题 → 操作 → 提醒横条 → 事实条（负责人、任务期限、分类）→ 三块正文 → 关系 → 历史时间线（时间与动作同一基线，标出条数）。
- **列表只留该抢眼的标签**：待核对、阻塞、有风险做成标签，负责人、状态、分类改为淡色文字；视图数量、负责人筛选与排序并成一行，中栏窄时自动换行。

### 任务助手：智能填写与材料库

- **「从文字填写」六栏、有啥填啥**：名称、负责人、当前进展、下一步、任务期限、风险与措施，原文里有的才填；摘录比对忽略空白与全半角标点差异，日期必须有出处；核对不上的栏逐栏丢弃并计数，不整批作废。
- **负责人不交给模型自由发挥**：模型只挑出人名，程序再拿词库的姓名与别名去匹配，唯一命中才落词条并带出单位；同名或不在词库里，提示原文提到的是谁，由人在搜索框里选。
- **模型协议容错**：接受被代码块包裹的 JSON、裸数组与缺 `evidence` 字段；重复候选去重；错误提示不再一律「没有变化」，改为说明模型没找出任务或进展，并指向重新识别与从文字填写。
- **批量候选对齐新要素**：新增任务候选显示名称、负责人、当前进展、下一步、期限、风险；另有进展反馈、负责人调整、风险变化、期限调整、相关意见 / 待决事项；没有目标任务时可「建成新任务」。摘录对不上时，只允许**较长的正文字段**顶替摘录，人名、日期这类短值不行，免得两三个字就替谎话背书。
- **「材料」视图（新增）**：识别过的材料都收在这里，右栏看原文快照与它产生的建议，可**重新识别**（只替换还没处理的建议，已采纳 / 已忽略的保留，相同的跳过）、「在待整理建议中查看」、「删除」。删除时若已被任务历史或已采纳建议引用，只把材料藏起来，历史里的「原文」照常能点。
- **粘贴识别过的材料不再只回一句话**：直接出卡片，写着识别时间、上次各状态的数量，可「重新识别 / 查看这批建议 / 打开材料」；识别结果写在「识别」按钮同一行，成功提示改为页面底部浮条，不再挤动三栏。
- **真实模型评测集**：`tests/fixtures/task-eval/cases.json`（单任务填写 14 例、批量整理 9 例，含同名人员），走产品代码全链；本机 qwen3.5-9b 实测填写 14/14、批量 9/9。评测揪出的三处真问题（示例 JSON 全 null 导致一栏都填不上、代码块包裹解析失败、编造年份）都在代码里修掉了。

### 输入法：找字网格与候选窗字体

- **两码起可展开找字**：按向下、下一页或点候选窗箭头展开滚动网格，每行与候选条一样多格，露四行，滚轮或滚动条翻；还要打的码像注音一样以小字标在字的上方，各格同宽同高；只列单字，词组仍在候选条上选。
- **网格里改候选不收起**：置顶、调序、屏蔽后网格保留原处，筛选、高亮与滚动位置不变；竖排候选向下先在本页逐个挪，到底再展开；一码不展开也不补逐码提示。
- **新增「输入法字体」设置**：在「字体」里单列一行，用来定候选窗的字词、编码与提示，默认跟随界面字体，文件失效时自动回退。
- **修掉第 4 行被裁**：网格原先按「格高」算行距，而横向行带至少 30px——候选字体比界面字体小、或本机没有中文字体而回退到内置字面时，一格只有 27px，行距少算 3px，第 4 行被裁掉一截。现在行高取两者较大值，`show_rows` 与实际行距同源，键盘翻页与滚动位置也跟着对齐。
- 另修：逐码提示的翻页限制、点候选窗空白处丢掉正在打的码、表头与网格互相撑宽。

### 标准词库：永久身份与同名消歧

- **单位、人员按身份关联**：每个单位与人员有永久全局身份，改名、排序、调动、改业务编码都不改变身份；父单位与所属单位按身份存，名称只用于检索与显示。单位移动、人员调动后，已保存稿件与表单不会指向别处。
- **同名不再猜配**：人员同名按单位分列，电话、职务不再当作「是同一个人」的证据；不唯一时明确留待核对，绝不猜配。Excel 导入导出补上身份编码与父单位身份编码列，旧表仍按旧规则还原后再完整校验。
- **词库树改为统一列网格**：固定 28px 行高、按坐标摆列，修掉纵向列表里套右到左布局导致首行撑满整屏的问题；展开箭头槽统一预留、加缩进参考线，拖动与「＋」悬停才显示，整行可点选、双击展开收起，右键出同一菜单。

### 导出：公函签收记录单

- **单独一份单据**：公函可按所选 PDF / Word 格式独立导出「公文签收记录单」，不拼进正文，可单独打印、单独送达；没选 Word 或 PDF 就不出对应格式，别的文种忽略这个选项。
- **自动汇总签收单位**：主送在前、抄送在后，同名按最终显示名去重，一单位一行；保留手写签收空间，跨页时整组重复表头。
- **版式重做**：去掉逐行重复的「密级」列（密级只在要素行印一次），表格改为序号 / 签收单位 / 签收方式 / 签收人 / 签收日期五列，签收方式两个勾选项上下叠放不再折字；内容行最低 18mm，表头两端同高；送文信息横线加长到能写 11 位手机号、行距放宽、整块不拆页；页码回到版心居中；要素缺失留手写横线，主送抄送都没填时留 5 行空行，长标题悬挂缩进。
- **文件名统一截短**：导出文件名限 42 个字符，同一次导出的 Word / PDF 与单独导出共用同一截短主干（原先各算各的，同一份稿子的两个文件截在不同位置）；截断处不留半截分隔符或开括号；「打开最近导出」在同一目录里按修改时间取最新。

### 界面主题：跟随 Omarchy 即时生效

- **不用再点一次**：后台每秒比对 Omarchy 主题目录的指纹（真实路径、`colors.toml` 的修改时间与长度、主题名），变了才重读；读到新主题就重套样式，并在状态栏说明主题名。
- **失败不闪回**：中途缺文件或读失败时保留上一份配色，下一秒重试。
- **直角平面外壳**：MDEX 与跟随 Omarchy 共用一套直角细线外壳（`theme::square_chrome()`），标题栏的品牌图标仍只属于 MDEX。

### 发布：Arch / Omarchy 的 pacman 包（首发）

- **第六个资产**：`gongwen-assistant-0.10.0-1-x86_64.pkg.tar.zst`，Omarchy 4 的 amd64 机器 `pacman -U` 离线安装，与 deb、Windows 安装包一起附 SHA-256。
- **在 Arch 里构建**：`archlinux:base` 容器内用 linux-portal-dialogs 变体编译（原生 Wayland + XDG Desktop Portal，不依赖 GTK3），`makepkg` 打包，二进制链接的是 Arch 自己的库。
- **依赖不手抄**：`ldd` 出的动态库用 `pacman -Qoq` 反查归属包，再补上 winit 运行时 dlopen 的那几个与桌面集成要的基础包，逐个用 `pacman -Si` 核对包名确实存在——写错一个包名 `pacman -U` 会直接拒装。
- **装一遍再发**：新增 verify job，在干净的 Arch 容器里真 `pacman -U` 一次，核对文件落位、属主与动态库，再用 Xvfb 真开一次窗口。

### 字体：公文仿宋、楷体换新

随包 runtime 更新到 `gongwen-runtime` v0.8.2（`RUNTIME_RELEASE_TAG` 同步）。

- **公文仿宋、公文楷体重新合成**：字形更新、字体内自带 hinting 与内嵌位图；文件名与家族名（`GW FangSong` / `GW Kai`）不变，稿件、模板与本机字体设置都不用动。
- **分工不变**：汉字取方正 GBK 系列，西文、数字、带圈数字与弯引号取仿宋_GB2312 / 楷体_GB2312（逐字比对过轮廓）。
- **全角标点的笔形改取 GB2312 字形**（`，。、；：！？（）《》` 等）：字宽仍是 1em，断行与标点收缩不变；行距、基线由版式模板显式指定，纸面尺寸与分页不随字体度量漂移。
- 其余字体（黑体、书宋、小标宋、页码的宋体拉丁子集、研究报告的 JetBrains Mono 与 TeX Gyre Termes）与三份授权文本不变；`runtime.zip` 与 `SHA256SUMS.txt` 逐行核对通过。

### 质量检查

- 两平台 CI 门禁（格式、clippy、2596 项自动化测试）全部通过；帮助的三道机械检查（文件清单、交叉引用、Mermaid 图排版不超版心）与整本 PDF 样张通过。
- **修掉 CI 连续三次红的找字网格断言**：不是测试脆弱，而是行距少算 3px 的真问题——Linux ARM64 构建机没有中文字体，候选窗回退到内置字面就复现。除按行带修好布局，另加一条**用随包固定字面**复现的回归测试，三平台量出来的数一致，不再依赖机器上装了什么字体。
- 新增覆盖：任务助手五项要素与词库负责人（同名、词库外人员、词条删除）、进展就地更新的历史规则、材料库重新识别的替换 / 跳过计数与删除只隐藏、批量证据顶替的字数门槛；标准词库身份合并与同名消歧；签收记录单单页 / 多页样张；导出文件名在各格式间一致。
