## 公文助手 v0.10.4

本版本把**加密工作区做实**：应用管理的图片、PDF 插图与图表缓存全部落盘加密，智能写作（Pi）的工作目录与长会话、历史快照、自定义技能也纳入保护；双槽备份改成先隔离校验再换入、失败可回滚。**加密工作区恢复打印**——不再硬性禁止，而是每次先确认「打印队列、纸件与打印机缓存不在保护范围内」再放行。导出改成固定目录、同名直接替换，另存按当前正文重新生成。同时修复**麒麟 V10 打开即崩**（X 图形环境探测 + 软件渲染兜底）。

### 加密工作区：资源落盘加密与密钥生命周期修复

- **图片、PDF 插图与图表缓存落盘加密**：启用应用锁后，正文引用的图片、PDF 插图、Mermaid 图表缓存改为整文件 AES-256-GCM 封套，原子写 0600、读取透明解密；图表缓存改按槽位隔离（真实槽 / 诱饵槽各一份），错槽或失钥时重新渲染而不是读出别的槽的图。预览、Word / PDF 导出、Typst 排版、研究报告内存快照、稿件包与同步包往返全部走解密读；外部导入的原件不经过这条通路。
- **PDF 附件预览不再落明文副本**：PDF 附件直接由内存中的密文字节渲染，不在输出目录生成可被别的程序读到的临时 PDF；另存、系统打开与打印都要先经风险确认，选定普通 PDF 保存位置后以 0600 原子写落盘。Word 里的 PDF 插图改用进程内光栅化，取消 Poppler 临时 PNG（支持 `#page=N`，限 200 DPI 与 2400 万像素）。
- **研究报告全程内存**：Markdown、插图、文献与 Mermaid 改为不可变内存快照，排版作业禁止回落同名磁盘文件，缺项直接失败而不是悄悄读旧文件。
- **智能写作的工作目录也加密**：Pi 的正文快照、要求、材料、技能副本、来源、运行记录、接口缓存与长会话改为受保护读写，数据密钥只经标准输入传递，不进命令行参数、环境变量与日志；长会话由 SQLite 改为加密 JSONL，追加走「解密 → 内存拼接 → 整份原子重写」。宿主版本升到 0.4.0、协议 4。
- **个人配置纳入保护**：个人词表、历史快照、自定义技能、使用统计与诊断日志随应用锁加密；详细诊断日志只在已解锁的提示框内查看，未解锁的早期启动只写最小诊断。
- **双槽备份按当前槽做**：只对当前槽的库做带密钥快照（此前有第二密码时备份会直接失败），恢复改为隔离暂存、校验锁封套与动态密文资源后再换入，失败自动回滚；非当前槽存在未检查点 WAL 时明确失败而不是只复制主库。备份导出与恢复共用同一套体积上限，恢复的文件与目录收紧为 0600 / 0700。
- **明文输出确认补齐 13 个漏网出口**：风格档案、标准词库 Excel、稿件包 `.gwx`、全量备份、四码词表与重码报告、自定义技能包、输入法词表与个人备份、校对词表、数据接口定义，现在都会先弹风险确认；判据由「失败时放行」改为「失败时拒绝」，加密工作区拿不到密钥就不导出。
- **密钥与槽位不再拿错**：诱饵密码解锁不再拿到真实槽的密钥句柄；停用解密补齐接口定义与配置副本，并在删除锁封套前断言当前槽没有密文残留；配置解密失败先留底原始密文再报错，不会用明文覆盖解不开的密文。

### 打印：加密工作区恢复打印，但每次先确认

- **加密工作区可以打印了**：上一版禁止在加密工作区直接打印，这一版改回**每次确认后放行**——中央打印入口、PDF 查看器打印、起草页「打印…」与内存附件「另存并打印」都先弹一次风险说明（打印队列、纸件与打印机缓存不在应用密码与本地加密的保护范围内），确认才送打，取消不打印。
- **打印队列去标识**：送打前先把 PDF 复制成中性随机名的 0600 副本，Windows 与 CUPS 的任务名、文档名统一固定为「公文助手打印任务」，公文标题不出现在系统打印队列里；打印结束即删除副本，启动时清理崩溃残留。
- **锁定不留明文**：解锁前与锁定、退出时清理 PDF 预览、打印与花脸稿预览的明文缓存，花脸稿打印预览改按槽位目录 0600 原子写。

### 导出：固定目录、同名直接替换、按当前内容另存

- **同一稿件固定一个导出目录**：不再按版本名或「待提交」分子目录，也不再生成「标题-2、标题-3」这类重复文件；导出总是覆盖同名文件，设置页里那条「覆盖同名文件」勾选项随之取消。
- **「另存」按当前正文重新生成**：另存不是复制上次导出的旧文件，而是按当前正文与要素表单重新排版生成到所选位置，勾选「另存并打印」时打印的是这份新成品。
- **文号口径统一**：要素表单里文号序号的说明由「正式版」改为「盖章版」。

### 印制追溯码：每份 PDF 带一个能查的编号

- **可开关的页脚标识**：设置页「导出格式 → 印制追溯码」默认关闭；开启后填一个「印制单位」（不超过 60 字的单行名称）。此后导出的每份 PDF 会在**每页右下角的底部页边距**叠一个 24 × 11 毫米的黑白 Data Matrix 点阵码，下方两行小字写单位名与编号。
- **编号可查**：每轮生成独立分配 16 位十进制编号（四位一组显示），码里只有编号，不含正文、单位名或网址；编号、单位、生成时间、题名与成品 PDF 的 SHA-256 记在稿件库里，设置页可按编号查询或看最近 20 条。登记随现有 SQLCipher、双槽隔离与全量备份一起走。
- **不占版心**：标识是矢量前景叠加层，不改正文的换行、分页、版记与既有页码，横向页也照原样定位。生成标识或写登记失败时直接报错并移除本轮 PDF，不会把没有标识的文件当成带码成品发出去。
- **覆盖范围**：起草页普通导出、PDF 快捷导出、另存为、起草页「打印」生成的 PDF，以及同轮生成的签收记录单与传发任务单；Markdown、Word 与 Typst 包不受影响。稿件库批量 PDF、送批材料合并、花脸稿与已有 PDF 的直接打印暂不覆盖，也不改已有附件，避免破坏扫描件或签名件的原貌。
- **它是什么、不是什么**：目标是识别生成副本时登记的印制单位，不是防复印、阻止流转或认定泄露责任；编号不是逐份纸件流水，同一份 PDF 打印多份仍是同一个码。

### 稳定性与兼容性

- **麒麟 V10 打开即崩已修**：启动前在子进程里按实际请求顺序探测图形能力（OpenGL 3.3 核心配置 → OpenGL ES 2.0 → 旧式上下文创建），建不出上下文就切软件渲染再探一次；X11 迟到的扩展类错误（GLX 等）被接住记进日志，不再让程序崩溃，启动失败时给中文提示与自救办法。探测结论写在配置目录的 `logs/gl-boot.log`。
- **智能写作的工具额度与程序侧对齐**：常规任务 60 次、分阶段绝对上限 84 次，宿主与 Rust 共用同一组常量；被拒绝的工具调用不再白扣额度。
- **写作模型不再回落旧起草备用通道**：选了智能写作模型就没有旧起草备用语义，旧配置未选时仍按原样兼容。
- **提问校验与数字解析下沉共享层**：旧会话与智能写作共用同一套出题校验规则，避免两处规则漂移。
- **删除已不再挂载的旧技能管理模块**，免得让人误以为还有第二套技能页。
- **CI 新增智能写作评测判据的离线回归**，防止判据脚本改坏后无人发现。
- **CI 的 macOS 作业改用 `macos-15` runner**：`macos-14` 的 arm64 配置已不被 GitHub 支持，作业会被直接取消。

### 质量检查

- 三平台 CI 门禁（格式、clippy、3004 余项自动化测试）全部通过。
- 本版新增的关键测试：受管资源密封后按当前密钥读回、图片目录按槽位隔离、图表缓存与提示文件密封往返、加密数据探测覆盖资源与接口定义、停用解密补齐接口与配置副本且停用标记须通过认证、诱饵槽与真实槽的密钥句柄互不串用、备份只保留当前槽的带密钥快照。

### 已知限制

- 应用锁、资源加密与双槽备份**仍待真机验收**：三平台上的锁屏、迁移耗时、断电恢复与备份往返都要在真机上过一遍。
- 智能写作的加密长会话在真实模型下的性能与稳定性未测；宿主 0.4.0 随包运行时已重建并通过校验。
- 打印路径只在本机做过校验，Windows 打印未在真机上跑过。
