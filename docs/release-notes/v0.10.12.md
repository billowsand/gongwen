## 公文助手 v0.10.12

本版本把送批材料并入与起草页相同的交付入口，并让单独发文的公函也能逐行登记多组承办信息。

### 送批材料：交付方式统一

- **「选择交付方式…」取代原来的保存框**。呈批件的「送批材料」确认后不再只能存成文件：加密工作区复用起草页的同一交付窗口，可选密码加密文件、空白实体光盘或已认证 IS903。刻录在内存里生成 ISO 9660 / Joliet 镜像并回读校验，不留明文刻录临时文件；没有配置独立导出密码也能走介质交付。
- **交付成功才记账**。逐件编译与合并全部成功后，才把完整 PDF 交给文件或刻录出口；任何一件失败都不生成缺件的半成品。文件成品仍在应用内 PDF 标签打开，刻录记录在导出历史里标为「外部介质刻录」，不再显示打不开的本地路径。
- 交付窗口的选文件与选介质动作从起草页抽成同一套入口，呈批件与起草页的行为保持一致。

### 公函：单独发文的多组承办信息

- **承办信息改为逐行登记**。单独发文的公函也支持多行「承办单位 + 联系人 + 电话」，三样一一对应；首行沿用原有承办单位 / 联系人 / 联系电话三个字段，续行单独保存，旧稿件和旧版本照常打开。
- **表单与候选单位**。表单里的「承办单位」换成「承办信息」逐行编辑；单独发文的候选单位优先列出发文单位及其下级（按词库树形顺序），其余单位照旧可检索、可从词库选人带出电话。
- **校验跟着每一行走**。每行都查承办单位是否填写、联系人与电话是否成对、号码是否与词库一致、联系人是否属于同行承办单位；单独发文还提示承办单位通常应为发文单位或其下级。
- **预览、Word、PDF 三端一致**。版记逐行排入承办信息，续行与首行的名称对齐；Typst 量版记高度时把续行和实际折行一起计入，版记不会压住印数行。「共印」份数、份号清单、稿件详情与写作提示词里的承办单位顺序，都按各行单位合计。
- 版本对照与稿件详情的承办信息同步显示续行，要素显示按词条身份解析。
