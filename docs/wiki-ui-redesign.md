# 公文助手知识库界面改版

原型里的分类树、阅读器和反向引用栏构成浏览页。框架管理、收件箱、审核台和版本历史各占一个完整工作区。当前实现把归纳、审核和版本历史放进浮窗，维基作业只显示最新一条进度。这两个地方需要一起改，用户才能在原界面核对资料、跟踪作业并处理结果。参见[可点原型](wiki-ui-prototype.html)、[当前界面入口](../src/wiki_ui.rs#L196)和[维基作业接线](../src/app/wiki.rs#L18)。

## 六个界面

| 界面 | 主区与操作 | 右侧栏 |
|---|---|---|
| [维基浏览](wiki-ui-redesign/01-browse.png) | 左侧采用紧凑大纲显示主题、分类和条目。中间可切换 Wiki 版式预览、Markdown 源码与双栏对照，正文中的链接和来源编号可直接点击。搜索、框架管理、缺口清单和待审收件箱放在同一行工具栏。 | 「被引用」展示来源页面和引用上下文，「依据」可打开原文。右栏可折叠。 |
| [框架整编](wiki-ui-redesign/02-framework.png) | 「从资料归纳」和「导入大纲」是同一工作区的两个入口。左侧编辑候选树，中间核对节点名称、归属和映射的原始资料。人工确认后应用框架。 | AI 工作状态跟随本轮归纳。提案通过校验后，状态卡提供查看提案入口。 |
| [原始资料整理](wiki-ui-redesign/03-sources.png) | 资料表保留搜索、文种、维基状态和关联条目。圈选后在表内确认目标分类与资料范围，再发起整编。原始资料可打开原文预览。 | 显示所选范围、已读材料和最近一次活动。交付后可从同一位置打开待审批次。 |
| [待审收件箱](wiki-ui-redesign/04-inbox.png) | 左侧选批次，中间按条目列出新建或更新、依据数和审核状态。选中条目先看变更摘要，再打开审核台。 | 显示对应作业的运行记录。「AI 已完成」和「条目待审核」各自表达真实状态。 |
| [人工审核确认](wiki-ui-redesign/05-review.png) | 整个中间工作区用于左右对照。左为可编辑 Markdown，右为实时版式预览。更新提案可切到「变更对比」。底栏固定显示「退回」和「采纳并入库」，可在同批条目间切换。 | 默认看依据。点击来源编号可在右栏阅读同一份原文，另可打开完整版式预览。可切换到「AI 工作状态」复看本批运行记录。 |
| [版本历史](wiki-ui-redesign/06-history.png) | 左侧选历史版本，中间对照两个版本。回滚前明确目标版本，确认后生成新版本。 | 查看所选版本的采纳方式、时间和对应依据。 |

## AI 工作状态

沿用智能写作的活动卡。运行时，右侧栏固定显示作业名称、状态、已用时间和停止入口。最近动作常显，历史活动按时间排列，工具结果按需展开。主区仍可阅读和核对资料。资料库和知识库之间切换时，可找回同一作业及其活动记录。

设计图中的阶段用于示意信息层级。界面以实际 Pi 事件为准。活动事件提供动作、耗时和结果，有阶段事件时才呈现阶段，有可靠总数时才显示篇数。无总数的检索显示当前动作和累计阅读量。停止、失败和交付各有明确终态，活动记录留在状态栏供查看。通过校验的框架和页面提案分别交给「确认框架」和逐条审核。AI 交付完成时，入库仍需人工操作。

同一位置在阅读时承载被引用和依据，在运行时优先展示工作状态。审核时默认展示依据，保留切回活动记录的入口。窄窗口里右栏可折叠，工具栏保留带状态的入口，展开后可以继续查看进度或停止。

| 作业状态 | 右栏动作与主区反馈 |
|---|---|
| 准备中 / 运行中 | 显示当前动作、耗时及「停止」。新提案生成期间，现有内容可继续阅读。 |
| 正在停止 / 已停止 | 请求发出后显示「正在停止」，后台退出后显示「已停止」及可用的重新发起入口。 |
| 失败 | 保留最后一条已完成活动和失败原因，提供重新发起入口。 |
| 已交付 | 框架作业显示「查看框架提案」，整编或更新显示「打开待审批次」。人工作业仍显示「待审核」，直到逐条处理。 |

## 视觉与交互约束

- 设计图采用暖灰浅色作为展示主题。落地使用应用已有的面板、纸面、强调和告警语义色，随主题切换。
- 分类树参照起草页大纲，使用整行选择、缩进和小箭头。阅读器与审核台使用 Wiki 专用版式，按链接、依据和引文各自的用途呈现。浏览、框架和审核工作区各自保留选择与滚动位置。
- 「待审核」「待复核」「已退回」同时使用文字和语义色。文档关联只代表可能相关，采纳后才显示已用于维基。
- 缺口清单可从浏览工具栏打开，按待建条目和失效依据查看。版本比较和审核差异都需能看到基线版本。
- 「校验依据」对应程序对引用编号和资料可用性的检查。正文与原文口径的一致性由审核人对照确认。若基线发生变化，审核台给出冲突提示并要求基于当前版本重新发起。

## 实现与验收

- 工作区导航、框架提案、收件箱、审核和版本历史见 [workspaces.rs](../src/wiki_ui/workspaces.rs)。框架提案可增删节点、改名、同级移动和调整分类归属。已处理批次和活动记录在本次会话内可回看。
- [作业状态栏](../src/wiki_ui/job.rs)接收 Pi 实际的进度和活动事件。同一工具的开始与结果合成一条记录。交付后仍由用户确认框架或逐条采纳。
- 阅读器和审核台共用 [Wiki 正文排版](../src/wiki_ui/body.rs)。段落、标题、引文和表格中的维基链接与依据编号可直接点击。当前依据记录只有资料编号和支撑说明，右栏可读原文开头并打开全文。
- 使用独立样本库绘制六个工作区和双栏阅读模式。执行 `GONGWEN_WIKI_SAMPLES=/tmp/gongwen-wiki-samples cargo test --locked wiki_workspaces_render` 可重新生成样张。
