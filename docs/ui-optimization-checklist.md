## 一、选中态反馈：点击后「只有文字变色、没有条目背景变化」

这是当前最突出的交互问题。egui 0.35 的 `Button::selected(true)` 只有在**绘制外框（frame）**时才会用 `selection.bg_fill`（本项目已设为 `accent_soft`）填充背景；一旦 `frame(false)`，选中态就只剩文字/图标颜色变化。

### 1.1 左上角应用菜单的选中项（P0，直接命中你描述的问题）

- **位置**：`src/app.rs:2778-2792`（`app_menu_button` 内）
- **现状**：菜单项用 `.selected(opened).frame(false)`，`frame(false)` 使按钮在未悬停时不画任何背景。菜单关闭后，当前所在页面那一项**只有文字变成强调色**，条目本身没有背景高亮——正是你感觉到的「点完菜单文字变色、背后的条目没反应」。
- **建议**：与顶部 `nav_button` 保持一致，把 `.frame(false)` 改为 `.frame_when_inactive(selected)`（选中项常显 `accent_soft` 淡底 + 圆角），或去掉 `frame(false)` 让 egui 默认选中背景生效。
- **顺带**：菜单项悬停时背景闪烁问题（`ui.rect_contains_pointer` 处理）无需改动。

### 1.2 功能区分区卡（开始/插入/格式/审校/视图/输出）的选中态（P0）

- **位置**：`src/theme.rs:1014-1038`（`ribbon_tab_button`）
- **现状**：注释明确「不用整块底色，怕六个分区卡全底色压掉第二行层次」，因此选中态 = 强调色文字 + 底部 2px 下划线。但实际观感下划线细、文字变色不明显，用户第一眼分不清当前在哪个分区。
- **建议**：折中方案——选中项用 `accent_soft` 淡底圆角（区别于第二行按钮的 `surface_sunk` 底），去掉或保留细下划线二选一；或选中项加浅色底 + 左/上边缘强调。参照 Word 分区卡：选中 tab 是白/淡底 + 顶部色条。
- **注意**：若改底色，需保证第二行按钮的 `surface_sunk` 底色与分区卡 `accent_soft` 区分开，避免「六个块」的层次问题反而变成「一块一块」。

### 1.3 其余选中态现状核对（基本合格，列出备查）

| 控件 | 位置 | 选中态表现 | 结论 |
|---|---|---|---|
| 顶部导航 `nav_button` | `theme.rs:1004` | `.selected + frame_when_inactive(selected)` → 常显 `accent_soft` 底 | ✅ 合格 |
| 视图图标 `view_icon_button` | `theme.rs:1041` | 同上 | ✅ 合格 |
| 标签页 `tab_button` | `app.rs:3023` | 自定义胶囊填充 + 白字动画 | ✅ 优秀 |
| 下拉菜单项 `selectable_label` | 各处 | egui 默认 `selection.bg_fill`=accent_soft 背景 | ✅ 合格 |
| 稿件表格行 | `app.rs:5649+` | 每格 `selectable_label(row_selected,…)` 淡底 | ✅ 合格，但见 2.6 |
| 词库树行 | `app.rs:3753` | `selectable_label(selected,…)` 淡底 | ✅ 合格 |
| 格式区「标题层级」按钮 | `draft_page.rs:2744-2769` | `.selected(…)` 默认背景 | ✅ 合格 |

## 二、入口可发现性：一些常用入口不够明显

### 2.1 应用菜单入口过隐蔽（P0）

- **位置**：`app.rs:2749-2757`（`app_menu_button`）、`app.rs:2741-2747`（`top_bar`）
- **现状**：左上角只有一枚 22px 汉堡图标，无「菜单」文字、无应用名。里面藏着五个常驻页面 + 新建公文等高频入口，第一次用基本靠猜。
- **建议**：
  1. 图标旁加「菜单」文字（或改为应用品牌 Logo + 名称，仿 Word 的「文件」）；
  2. 菜单项内为「新建空白公文 / 从文档新建公文」等高频项加**快捷键提示**（Ctrl+N 等），菜单右上角或行尾灰字显示；
  3. 五个导航页当前所在页在菜单里用 `frame_when_inactive(selected)` 高亮（见 1.1）。

### 2.2 导航页与文档标签混排（P1）

- **位置**：`app.rs:2905-2979`（`tab_strip`）
- **现状**：标准词库、AI 管理、知识库、设置等**导航页**与打开的**稿件文档**、**PDF** 挤在同一条标签栏里，标签溢出后收进 `»N` 下拉。多开稿件时导航页很难找，且文档标签和导航标签外观完全一样，缺少类别区分。
- **建议**：给导航页标签加小图标已有（`page.icon()`），可再给导航页标签用不同底色/圆角样式（如浅色描边、无关闭按钮）；或在左侧固定一条窄导航栏（仿 VS Code 活动栏）放五个常驻页面，标签栏只放文档/PDF。

### 2.3 标题栏快速访问只有图标（P1）

- **位置**：`app.rs:2568-2616`（`titlebar_quick_access`）
- **现状**：保存/提交版本/导出三枚纯图标按钮（`icon_button`），无文字；「保存」的脏标记是一个 3px 小圆点，`app.rs:2588-2591`。
- **建议**：
  1. 保存按钮的脏标记改为更醒目的方式（小圆点旁加数量/「未保存」角标，或按钮本身用 accent 描边）；
  2. 若空间允许，保存/导出带短文字（Word 快速访问也是图标+可选的文字）；
  3. 统一 icon-only 按钮的 `WidgetInfo` 无障碍名称（已有 `widget_info` 调用，保持）。

### 2.4 状态栏右侧抽屉入口只有图标（P2）

- **位置**：`app.rs:3248-3295`（`status_bar` 右侧）、`app.rs:8538`（`status_icon_button`）
- **现状**：审校提示、版本历史两枚 icon-only 按钮，与 ribbon 里带文字的「校验结果/版本历史」重复。
- **建议**：要么只留一处（ribbon 带文字更易发现），要么状态栏入口保持图标但加「小红点」角标提示有 N 条审校提示（目前只在悬停 tip 里写数字）。

### 2.5 破坏性操作缺少文字确认（P1）

- **位置**：`draft_page.rs:2342-2354`（「清空审校稿」用 `danger_icon_button`，仅图标）
- **现状**：`danger_icon_button` 只把图标染红、无文字（`theme.rs:988-1001` 注释也说明了设计意图）。「清空审校稿」是**不可逆破坏操作**，纯图标 + 悬停提示对用户的警示不够。
- **建议**：清空类操作改用 `warning_icon_button`（带「清空审校稿」红字文字，已有该组件 `theme.rs:956`），或保留图标并在点击后弹确认浮窗。

### 2.6 稿件表格列过多、行选中反馈弱（P1）

- **位置**：`app.rs:5540-5552`（非紧凑表格 11 列）、`app.rs:5649+`
- **现状**：非紧凑模式列有 勾选/状态/文种/密级/标题/文号/成文日期/更新/归档/知识库/操作 共 11 列，小窗口挤压严重；行选中只是每格淡底，整行没有统一高亮（标题列与其它列底色一致，看不出「选中了一行」）。列宽可拖拽但无任何提示。
- **建议**：
  1. 行选中时给整行画统一 `accent_soft` 底（在 `TableBuilder` 行内先占位再回填，参照词库树 `app.rs:3719-3802` 的 Noop-Shape 回填手法）；
  2. 表头加「拖拽调整列宽」的悬停提示；
  3. 考虑把「归档/知识库/更新」等低频列收进「更多」展开，或提供列显隐开关。

## 三、视觉层级与细节

### 3.1 功能区分组分隔不够清晰（P1）

- **位置**：`draft_page.rs:230-235`（`toolbar_separator`）
- **现状**：分组之间只有 8px 宽、向内缩 4px 的细竖线，二十来个按钮靠这条细线分组，扫一眼很难看出边界。
- **建议**：加粗/加长分隔线（Word 用的是 1.5px 实心竖条 + 更宽间距），或给每组包一层浅色 `surface_sunk` 底的分组框（注意保持功能区总高固定两行）。

### 3.2 功能区分区卡双击收起的可发现性（P2）

- **位置**：`draft_page.rs:2198-2200`
- **现状**：双击当前分区卡收起第二行（仿 Word），但悬停提示里没有写，用户几乎不可能发现；折叠箭头在行尾（`draft_page.rs:2216-2236`），与分区卡距离远。
- **建议**：把折叠箭头挪到分区卡行内右侧紧邻处，或给分区卡悬停提示补一句「双击收起功能区」。

### 3.3 表单区密度与分区（P2）

- **位置**：`draft_page.rs:3107+`（`form_ui`）、`draft_page.rs:3223`（Grid）
- **现状**：左侧「公文要素填报」是长条 Grid，从「1. 文种与基础信息」到后段几十个字段一路排下来，`ui.heading` 只有两处（3223、3830），长表单没有视觉分组卡片，密集感强。
- **建议**：按语义把字段包进若干 `theme::card()` 分组（如「文种与版本」「行文对象」「落款与成文」），卡片间留白；字段较多时保持 heading 小标题。

### 3.4 「已入库」标记只有文字（P2）

- **位置**：`app.rs:5733-5748`
- **现状**：知识库列显示「已入库」（accent 色文字）或「—」（弱化色），无图形辅助。
- **建议**：加一个小圆点/对勾图标（`theme::dot` 已有，`theme.rs:1083`），「已入库」= 成功色圆点 + 文字。

### 3.5 主题切换入口太深（P2）

- **位置**：`app.rs:7789`（`theme_settings_ui`，在设置页内）
- **现状**：四套主题只能进「设置」页找，且主题名是英文（Claude/Sky/Lilac/Green），中文用户不直观。
- **建议**：应用菜单底部加「外观」子菜单直接切换主题；主题名给中文标签（如「奶油」「天青」「淡紫」「青绿」）。

### 3.6 菜单里混用 egui 默认 Button 与自绘样式（P2）

- **位置**：`app.rs:2750-2841`（菜单项）、`draft_page.rs:2643-2727`（词库下拉）
- **现状**：菜单项用 `.frame(false)` 的裸按钮（悬停有底、常态无底），下拉（ComboBox）里是 egui 默认 selectable_label，两者圆角/内边距/字号不完全一致（菜单内手工改过字号 `app.rs:2763-2771`）。
- **建议**：统一菜单位（字号 12px、圆角、选中高亮方式），下拉与菜单共用一套视觉参数，避免两处手感不一致。

### 3.7 空状态与引导（核对结论）

- 稿件管理、词库、知识库、版本历史、附件等空状态均有文案引导（`app.rs:4388/6080/6145`、`draft_page.rs:2071`、`knowledge_ui.rs:149`），**基本合格**，无需大改。

### 3.8 一致性核对（无需改动，防止回归）

- 标题栏失焦弱化、窗口缩放边框、标签动画、行淡入、浮窗入场动画（`theme.rs:527`）等细节已相当成熟，改动 1.1/1.2 时注意不要破坏这套动效节奏（`theme::anim`）。

## 五、改动时务必守住的设计约束

- 所有颜色从 `theme.rs` 取（`theme::accent_soft()`、`theme::surface_sunk()` 等），禁止硬编码 RGB；
- 动效时长统一用 `theme::anim::{FAST,MEDIUM,SLOW}`；
- 功能区分区卡与第二行按钮的底色必须保持可区分（这是当初不做整块底色的原因，改用淡底时重新验证层次）；
- 状态栏行高钉死（`app.rs:3187-3207` 注释的「第二行爬升」约束），新控件不得引入第二行；
- 选中态改动后跑 `cargo clippy --all-targets -- -D warnings` 与 `cargo test --all-targets` 验证。
