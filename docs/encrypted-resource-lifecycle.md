# 加密资源全生命周期闭环

2026-11-06 用户确认：独立资源加密；把导入、稿件包往返、全量备份与恢复统一考虑；
加密模式导出 PDF / Word 必须每次明确确认信息泄露风险。本文是第三期的实施入口，
补充 `security-lock-design.md`，不代表下列全部能力已经实现。实际进度见末节。

## 1. 边界与不变量

- 开启加密时，应用管理的敏感持久数据只能以密文落盘，包括原图、PDF 插图、缩略图、
  Mermaid 图及源数据、研究报告中间文件、Pi 材料/接口结果/会话/交付快照。
- 解锁后按需在内存解密；不能在启动时把整个目录解密，也不能到退出时才补加密。
- 用户选择导出的成品是明确的保护边界出口。导出确认必须在首次写入明文（包括中间文件）
  之前完成；取消、Esc、关闭、锁屏均不能启动导出。不提供“不再提示”。
- 密文认证失败视为损坏/密钥不匹配，禁止回退为明文读取；没有当前槽位密钥时禁止读取。
- 主密码修改只重新包裹 DEK；资源不随密码变更重写。GWA2 使用当前槽位的同一 DEK，
  把槽位、资源用途与稳定逻辑路径放入 AAD 做用途和位置绑定；不是按用途派生多把资源密钥。
  新文件格式版本化，GWA1 只保留只读兼容与锁内部用途。
- 保留原来的安全边界：不防解锁后恶意软件读取内存、截屏；不承诺隐藏文件数量、大小、
  修改时间或抵抗完整磁盘取证。诱饵槽位须隔离，但不能宣称体积差异无从辨认。

## 2. 存储结构与兼容策略

采用 SQLCipher 元数据 + 不可变加密对象，不把大图片全部写进主库。

- 数据库保存资源 ID、类型、原文件名、明文长度和 SHA-256、对象定位信息。
- 对象使用随机 ID 命名，不含原标题、原文件名、时间或明文哈希；普通图片先整文件 AEAD，
  后续只有经真实负载证明有必要的大附件才引入成熟的分块认证加密格式。
- 逻辑引用与物理文件路径分离。新引用使用不含语义的资源 ID；旧 `images/原名.png`
  在加密库内映射到对象。**不修改任何已有不可变版本、正文或 payload_hash**。
- 同一个旧路径属于槽位内部命名空间；真实/第二密码、备份恢复、后台任务不得混用映射。
- 存储上下文在任务开始时捕获槽位与密钥句柄；后台线程不在每次读写时重新查询全局槽位。
  锁定先停止/排空写入任务并拒绝新任务，再释放句柄，避免切槽后串写。
- 资源层接口区分 `read_managed`、`import_external`、`write_managed`、
  `export_plaintext` 和 `copy_ciphertext_backup`。禁止依靠“文件头看起来像密文”判断
  外部文件是否要用本机密钥解密；外部资源与本机资源必须有明确来源类型。
- 统一处理路径规范化、目录穿越、符号链接、文件/解码像素上限、认证与校验。
  不对所有 `fs::read` 做盲目透明解密。

写入次序为：生成 ID → 同目录写密文临时文件 → sync/原子落位 → 验证 → 数据库事务提交
引用。事务失败清理本批对象；崩溃留下的无引用对象由延迟回收处理。回收同时扫描活稿、
全部历史版本、待合并分支、归档钉版；不得只看当前正文。并发回收与备份需有快照租约。

资源表与稿件库放在同一个 SQLCipher 数据库，避免跨库事务；建议最小结构如下。
此处是待实现的 schema，不是已有表：

```sql
CREATE TABLE resource_objects (
    object_id TEXT PRIMARY KEY,
    media_type TEXT NOT NULL,
    original_name TEXT NOT NULL,
    plain_size INTEGER NOT NULL,
    plain_sha256 TEXT NOT NULL,
    storage_version INTEGER NOT NULL
);
CREATE TABLE resource_aliases (
    logical_path TEXT PRIMARY KEY,
    object_id TEXT NOT NULL REFERENCES resource_objects(object_id)
);
```

对象位置从随机 `object_id` 推导为当前槽位 `objects/<分片>/<ID>.blob`；数据库只在
对应槽位解锁后打开，不把映射另存明文 JSON。别名统一用 `/`，拒绝绝对路径、父级
和跨槽位访问。按内容去重只在同一槽位、解密后的索引里比较，不跨密码系统去重。
对象 ID 不因引用文件名变化而改变。物理目录要登记到槽位清除与备份收集清单。

普通模式也走同一资源接口和引用表，内容可为明文对象；启用/停用仅迁移物理编码，
不改稿件正文。加密态对象读取必须由库记录声明格式；旧 GWA1 配置格式不直接冒充
新的资源封套。资源新格式需魔数、版本、nonce、认证标签，并将版本/对象 ID/用途
纳入认证，使用经过审查的库实现，禁止自创分块 nonce 或流密码格式。

## 3. 各入口如何闭环

| 流程 | 输入与处理 | 持久结果 / 失败语义 |
| --- | --- | --- |
| 插入图片、剪贴板图片 | 从文件或内存读取，校验类型/大小后直接加密 | 密文对象及引用；不得先复制明文到 images |
| Word 等文档导入 | anydoc 提取内嵌图片；EMF/WMF 转换在内存完成 | 统一交资源层加密，正文在资源成功后写库 |
| Markdown 导入 | 相对所选来源目录解析本地图片，不越界、不自动联网 | 复制入库即加密并重写本次新稿引用；不修改外部原件 |
| 富文本粘贴 | data URI/剪贴板/允许的本地图片统一解码 | 同图片导入，不设另一套明文缓存 |
| PDF 附件 | 当前已在 SQLCipher BLOB 中的盖章 PDF 保持原机制 | 插图 PDF 走对象层；不得因统一资源而重复保存明文 |
| 当前稿预览 | 按需解密到内存，位图/PDF 解码器消费字节 | 纹理仅内存缓存，锁定清空，并隔离后台回传的代际 |
| 版本回看/回退 | 旧逻辑路径通过映射读取同一不可变对象 | 不依赖当前正文，旧图继续可用 |
| 删除稿件/资源清理 | 全引用图检查，正在导入/备份的对象受租约保护 | 仅删除确认无引用的对象 |

导入事务先完整校验待接收稿件、图片、PDF、版本图和资源冲突，再写对象与数据库。
缺图沿用各入口现有策略：普通文档导入可报告跳过，严格稿件包缺资源则拒绝整批；
加密/落盘失败不可降级为“缺图继续”。原始外部文件仍由用户保管，应用不能代为删除。
检查范围包含第三方读取器的解压/转换临时目录；不能只验证调用资源层以后的文件。
用户取消导入时，撤销本次资源租约并清理未引用对象，不删除先前已存在且复用的对象。

## 4. 稿件包 `.gwx` / 历史 ZIP 往返

稿件包是传输格式，不能直接装本机 DEK 加密的对象，否则另一台机器无法打开。

1. 导出前保存工作稿并建立原有同步检查点；收集活稿和全部版本祖先引用的资源。
2. 资源层解密为字节，按**原逻辑引用**与明文 SHA-256 写入现有 AES 加密 ZIP 条目，
   不生成明文资源暂存目录。包密码仍独立于应用密码，不携带本机 DEK/锁封套。
3. 导入先用包密码在内存解密并检查 manifest、资源哈希、大小、版本图；
   同逻辑路径冲突比较明文内容摘要，不比较随机 nonce 导致必然不同的密文。
4. 目标机启用加密：用目标槽位资源密钥重新加密；未启用：按正常明文模式入库。
   A→B 的本机密码不同不影响往返。
5. 已有版本、引用和资源校验值保持不变，旧 ZIP 继续能读；同名不同内容仍拒绝覆盖。
6. 失败回滚数据库及本批资源，取消不留半份稿件；重复导入保持幂等。

ZIP 条目名可被观察，旧包资源名可能有语义；新建资源使用随机逻辑 ID，旧格式兼容
不等于文件名保密。若以后需要隐藏全部目录元数据，应另立外层容器格式并做版本迁移。

## 5. 全量备份与恢复

全量备份是本机数据的灾备，不走“解密后重打包”。

- 备份包含 SQLCipher 一致快照、密文对象、资源映射、配置密文以及 `vault` 锁封套。
  不含解锁口令、内存 DEK、明文缩略图/临时文件、诊断日志。
- 数据库和资源须属于同一快照：先冻结新写入或取得快照租约，生成库快照与资源清单，
  在备份完成前禁止回收清单中的对象。只冻结短期写入，实际复制在后台。
- 源对象不可变，备份可直接流式复制密文，不解密重加密；密文哈希用于发现损坏，
  恢复解锁后仍要做认证检查及引用完整性检查。
- 新增版本化备份清单：备份 ID、格式版本、创建时间、每个条目的相对路径/长度/
  密文 SHA-256、所需文件集合。清单不得含原文件名、稿件标题、内容摘要或明文哈希；
  含敏感信息的索引留在加密库中。裸校验值只用于损坏检测，不冒充来源真实性签名。
  老备份没有清单时沿用兼容检查并明确无法做新格式的逐条完整性校验。
- 真/第二密码各用各自 DEK。当前只持有一个 DEK，不能拿它去对另一个槽位做
  `sqlcipher_export`。全配置灾备需明确处理非活动库：暂停所有实例写入并确认其 WAL
  已检查点后原样复制，或以原库 + WAL 的一致冻结集保存。不得静默跳过或用错密钥。
  实施前需要修正现有备份对两个库共用当前句柄的假设。
- 必须带上**与备份数据同一代**的锁封套；改密后旧备份仍用备份时密码。UI 明确提示
  “恢复后使用备份时的应用密码”，恢复前展示备份日期、加密状态和范围。
- 恢复到隔离暂存目录，先校验条目名/重复条目/软链接/大小总额/清单及密文哈希；
  密文只按密文暂存，禁止把当前机器密钥用于解释备份数据。
- 通过后停任务/关库/释放当前密钥，原目录原子改名留底，再切入新目录并强制重新解锁。
  不把新机器现有配置、DEK 与旧备份混合。失败撤回，留底目录维持原有密文。
- 恢复旧明文备份：提醒它本身含明文；恢复后在进入工作区前按用户选择启用迁移。
  如果要求整个恢复过程也不出现明文磁盘，则需先取得目标密钥、逐条加密入库，
  不能先解压明文再声称全程受保护。

全量备份 ZIP 外层目录结构仍可见，并且某些未纳管配置可能含敏感数据。
只有配置目录逐项盘点与保护验证通过，才能宣称“加密备份不含敏感明文”。

## 6. PDF / Word 等明文输出确认

所有加密工作区的正文输出统一确认，包括正常导出、快捷按钮、打印前自动导出、
花脸稿/历史版本花脸稿、送批材料合并、PDF 附件另存，以及 Markdown/Typst 源码包。
独立附属单据包含在同一次任务的确认范围内，不对每个文件重复弹框。

确认标题：**导出文件可能泄露信息**。

正文至少明确：

> 当前工作区已启用加密。此次导出的 PDF、Word 或源码文件将以普通文件保存，
> 不再受应用密码和本地加密保护。文件可能包含正文、图片、附件及人员等敏感信息；
> 复制、同步、发送或由其他软件打开时，可能导致信息泄露。请确认保存位置和接收范围。

显示本次操作/范围、已知输出位置；按钮“取消”与“确认风险并继续”，取消在前，
无默认确认、无 Enter 快捷放行、无永久豁免。确认只对本次任务有效，关闭或锁屏即丢弃。
正文快捷导出要保留“完成后打开/打印”意图，不能在弹框前挂到其他后台任务上。

加密 ZIP 的 PDF 批量输出另行说明：外层由独立 ZIP 密码保护，解压后的 PDF 不受
应用加密保护；不能误说它是未加密 ZIP。已有普通文件另存也再次提示新副本的风险。
帮助页等不含用户数据的内置公开材料不触发。

应用内普通预览不属于用户授权的明文导出。尤其 PDF 附件预览应改为字节加载，
不能为了“预览”悄悄在 `output_dir/temp` 写一份原件。当前存在该路径，是必须消除的缺口。
阶段 A 过渡措施：加密模式下该预览也先确认，明确提示会产生明文副本；
阶段 C 完成内存加载后移除此过渡确认，普通预览不再释放明文。
直接打印在加密工作区中禁止；用户可显式确认风险后导出普通 PDF，再交给系统 PDF 阅读器打印。
导出后的文件及系统打印队列属于应用外边界。普通模式打印维持原实现，本轮不做打印内存化。

## 7. 中间文件、Pi 与日志

- Mermaid 缓存“可重建”不意味着“不敏感”，修正旧方案：加密缓存或只在内存保留；
  旧缓存启用加密时迁移/清除。警告 sidecar 也按内容检查，不留下节点原文。
- 研究报告现有 `ResearchSourceBundle` 会把正文、文献和图片写到系统临时目录。
  应改 mdx 的字节/虚拟资源读取接口，Typst World 和 Word 生成器接收内存资源。
  在此完成前不可把“图片密文落盘”宣称为导出链无明文中间文件。
- Pi 同时涉及 Rust 工作区、Node host 与会话 SQLite。不能只封 Rust 的 sources 文件，
  或在运行结束后压缩目录；运行期间也不得明文落盘。
- 优先把材料、交付、接口缓存的持久化留给 Rust 加密存储，Node 经协议按需读写；
  会话持久化需核对 Durable Harness 的可替换存储接口，选择宿主代理或受支持的加密
  存储适配。若协议/依赖不能满足，明确阻断加密模式下该功能，而不是明文降级。
- 不把完整 DEK 经命令行或环境变量传给 Node；协议能力按运行/用途绑定，锁定后撤销。
  并行调用、续读、恢复、停止和 host 崩溃均要测。涉及协议改动必须重建随包 runtime。
- 日志、错误栈、崩溃记录不写密钥；加密工作区中完整诊断使用 GWA2 保存，只在已解锁应用的
  崩溃提示框内解密查看，不提供直接打开日志目录。未解锁的早期启动只写最小诊断，不回退为
  包含程序路径、环境变量或错误详情的明文日志。公式 SVG、OCR 结果、其他缩略图按同样原则盘点。

## 8. 启用、迁移、停用与异常恢复

启用前停止资源写入、Pi、同步与备份任务。迁移在后台执行并显示进度；工作区只有
全部必需迁移通过才可进入。每个对象迁移可重入：读取旧文件 → 密文原子落位 →
校验认证与明文哈希 → 数据库事务写映射 → 删除旧明文。事务前崩溃只留孤儿密文，
事务后崩溃可据映射补删旧文件。不能用一个提前落盘的“完成”标记跳过剩余明文。

迁移须检查旧 `images/`、`alt-images/`、`mermaid-cache/`、`pi/`、研究报告临时目录及
旧损坏配置留底；应用外的输入原件、旧导出、旧备份只能提示用户处理，不能擅自删除。
磁盘剩余空间不足、损坏图、密钥错误、重启均不得丢源文件。迁移记录本身不得明文
保存敏感路径。SSD 删除不等于安全擦除，推荐全盘加密补足历史残留保护。

停用是一次明确的明文释放操作：再次认证 → 提示全部本机数据将失去加密保护 →
按可恢复状态机解密资源与数据库 → 校验完整性 → 最后移除锁封套。失败保留密钥
恢复能力，不能先删封套。更改密码不运行此迁移；清第二密码只清对应槽位对象。

## 9. 实施次序与验收门槛

| 阶段 | 交付 | 必须通过 |
| --- | --- | --- |
| A | 完整设计 + 统一输出风险确认 | 取消零写入；快捷导出/花脸稿/送批/PDF 附件/批量 PDF 都覆盖；普通模式不多弹框 |
| B | 资源层、元数据与导入/同步闭环 | 明文/加密双方交叉往返；历史路径/hash 不变；冲突/失败回滚；切槽隔离 |
| C | 预览、mdx/Typst/Word、Mermaid 全链 | 无明文暂存；认证失败不吞掉变成静默缺图；并发/锁定/坏图/大图验证 |
| D | 迁移、备份恢复、停用状态机 | 中断每一步后可恢复；备份含正确封套；双槽/WAL 一致性；旧备份兼容 |
| E | Pi 持久化与日志、帮助和发布验收 | host 协议/恢复/续读完整测试；重建 runtime；三平台真实数据目录扫描 |

B/C 应合并验收后才开放图片加密给正式用户，避免存成密文却导致研究报告或预览
损坏。D/E 全部通过后才能标记“第三期全部完成”。性能用真实 1MiB/10MiB/100MiB
图片/PDF、数千资源、百图报告测导入/预览/导出/备份时延及内存峰值；不凭经验写

   修改时间可见仍是已接受边界，历史 SSD 残留由全盘加密补足，不把删除等同安全擦除。

### 2026-11-06 第八轮：应用锁密码强度与「启用即加密」

针对威胁模型复核（拷走整个配置目录后离线翻看正文）的两项收口。

**一、密码强度改成硬要求（此前下限只有 4 字节且无强度约束）**

锁文件 `vault.dat` 里存着「用密码派生密钥加密的固定明文」，拷走目录的人可以直接拿它
离线穷举密码——Argon2id 的代价（实测本机约 0.07 秒/次，单核约 14 次/秒）是唯一防线。
下限 4 字节意味着 4 位纯数字在**单核上约 12 分钟**就能被试出来，等于没有加密。

- 新增 `src/password_policy.rs`：应用锁与稿件包导出密码**共用同一套判据**
  （长度按**字符数**计，不按字节数，免得一个汉字只算 3 个字符把中文用户挡在门外）：
  - 应用锁主/第二密码：**长度必须大于 10 个字符**（11 起步）；
  - 稿件包导出密码：维持不少于 10 个字符；
  - 两者都要求至少覆盖**三类**字符（大写 / 小写 / 数字 / 符号 / 中文）；
  - 拒绝常见口令、4 位及以上连续字母或数字、4 个及以上连续相同字符、首尾空格；
  - 错误文案逐条说明**是哪一条不满足**（「简单字符等于没加密」）。
- 出口只有两处：`Vault::create` / `Vault::set_password` 走 `check_password`，
  界面侧（锁屏首设、设置页启用/改主密/设第二密）先本地校验一遍，给出即时反馈。
  「暂不设置」不写任何密码，不受此约束。
- 已知弱口令的**既有**锁文件不受影响：校验只在**新设/改密**时执行，
  已设的旧密码仍能正常解锁（否则升级即等于把用户锁在门外）。
- 常见口令表**不收本程序自己的名字**（「公文助手」）：用户很可能把工作单位/产品名
  写进密码，那是他们的自由，不该因为我们猜得到就拒人。

**二、启用密码保护后当场加密，不再留「下次解锁前」的明文窗口**

此前设置页启用后，本会话继续按明文开库（磁盘数据还没迁），迁移安排在**下次解锁**。
这段窗口里磁盘上的 `manuscripts.db` 一直是明文——与威胁模型第一条直接冲突。

- 现在启用后立刻走「存盘 → 丢弃工作区 → 后台迁移 → 重建工作区」：
  迁移要**换掉**稿件库文件（SQLCipher 重新导出），工作区里的旧连接必须先关掉，
  否则它们会继续往已被替换的旧文件里写；顺序与首次启用的闸门迁移同一条。
- 迁移失败（存盘失败/磁盘写不动）时：状态栏说明「现有数据尚未加密」，且**下次解锁时
  闸门仍会补上迁移**（`slot_needs_encryption` 是磁盘实况判定，不依赖本次是否成功）。
- 顺带修掉三处测试脚手架缺口：
  - 测试构建里配置目录与密钥句柄都是**线程局部**的，后台搬运线程看不到
    （会退回**真实**配置目录）。搬运线程现在显式继承父线程的配置目录与密钥句柄，
    两种构建都成立；
  - `storage::WRITES_BLOCKED`（锁定流程的停写闸门）在测试构建里改成**线程局部**：
    它在生产里必须进程级（要挡住被丢弃工作区里跑在别的线程、收尾晚到的写操作），
    但测试并行跑时，一个测试走锁定流程会让同时在跑的别的测试存盘失败。生产语义不变。

**验证**：`cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings`
通过；`cargo test --locked --all-targets` 全量通过（`single_instance` / `pi_agent::process`
两例为**既有**并行时序抖动，基线代码同样复现，非本轮逻辑）。
新增测试覆盖：应用锁密码长度必须大于 10、单一类别字符/常见口令/连续序列/连续重复字符
一律拒收、导出密码维持 10 字符、启用密码后磁盘上的稿件库当场变成密文。
