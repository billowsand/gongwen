# 词表输入法改造与交接

2026-10-02，分支 `codex/table-ime`。取代旧「拼音引擎＋音形候选」混合流程。

## 定位与数据

输入法只接受编码、查询词表、选词上屏，不区分全拼、双拼或任何输入方案。
以本机 `assets/fuma/quan.txt` 为初始基础表，完整保留单字、词组与简码。
动态叠加稿件库中已接受的公文四码词、导入的四码表与个人词条。
词条可以自己指定编码；公文词表原有编码建议与读音维护仍保留在维护侧。

基础表与个人词条使用 1–4 个小写字母，公文表与导入的公文四码表使用四码。只做完整编码匹配，
一至三码不展开四码前缀。相同「编码＋文字」合并，保存所有来源；同词不同码保留。
默认基础表在前、公文表和新增词在后，使用者可显式排序，不自动调频。

## 已实现

- 进程内直接查表与上屏，保留 egui 焦点、光标、候选定位、横竖排、字号与翻页。
- 四码唯一候选自动上屏默认关，开启后单字与词组相同。
- 第五码顶屏默认开：有候选则先上屏高亮，再开始下一编码；无码保留原编码。
- 空格无码时不上屏字母；回车可明确原样上屏编码；Shift 切英文时也原样上屏。
- 基础表整体导入更新、上次基础表恢复；日常修改见下文第二轮（进个人层，基础表只读）。
- 公文四码表导入预览，统计新增、已有、重码、文件内重复与无效行。
- 导入表分来源启停与整批撤销；其他来源的同码同词不会随撤销消失。
- 查词查码、重码筛选、候选首选与上下移动、屏蔽与恢复、个人词条增删改。
- 正文右键「加入词表」，不改正文；新词立即可用（第二轮起自动出码）。
- 最终词表文本导出，个人词表 JSON 备份恢复，恢复前保留上次个人文件。
- 公文词表变化后延时同步，仅接受状态且最终编码为四码的词进入输入候选。
- 基础表和个人文件通过同目录临时文件替换，保存成功后才替换内存。
- 兼容旧用户音形表路径与配置中的有效短语，旧文件不主动删除。

## 第二轮：出码、提示与码表管理（2026-10-02）

五个部分，各自一次提交：

1. **自动出码**（`encoder.rs`）：从基础表反推字码（单字两码以上编码的前缀）与构词规则
   （Rime 写法，候选规则逐条在全码词组上验证，取命中最多的）。多音字按「字码在已有词组里
   被用的次数」排序。本机 `quan.txt` 推得二字 `AaAbBaBb`、三字 `AaBaCaCb`、四字及以上
   `AaBaCaZa`；留一法首选命中约 97.6%，前三命中约 99.9%。只用全码长度（表中最长码长）的
   词组推算，三简词组（三字三码）不参与，否则三字规则会被推成 `AaBaCa`。
   加词窗（`add_word.rs`）、造词（`Ctrl+Shift+A`，取选区或最近上屏的连续汉字，最多八个）、
   查码（`lookup.rs`，正文右键「查编码」）。`Ctrl+=` 已被字号放大占用，所以造词用 `Ctrl+Shift+A`。
2. **候选窗**：词后星标（沿用早先整句模型候选的四角星，表示不只在基础表里）、空码标记、
   简码提示（默认开）、词组提示（默认开，走状态栏）、逐码提示（默认关；空格只上屏精确候选，
   挪过高亮才上屏补出来的）、悬停来源、候选右键菜单（置顶 / 上移 / 下移 / 屏蔽 / 查编码）、
   `Ctrl+Delete` 屏蔽高亮候选（不组码时交给编辑器删词）。
3. **分层模型**（`ops.rs`、`history.rs`）：基础表只读，只能整体导入升级；改基础词 = 屏蔽原词
   ＋个人词条，个人词条直接替换。每次写 `tables.json` 前存一份到 `history/`（保留 20 次，
   可逐条回退，回退本身也记一笔；第一次写入前没有旧文件，不记）。升级基础表时预览差异
   （新增、删除、换位）与升级后个人层里的多余、失效记录；体检可一键清理。
4. **「输入法词表」页**（`page.rs`，`NavPage::ImeTable`）：查询与维护（编码框不走输入法、
   前缀与 `?` 通配；文字框走输入法；来源 / 码长 / 字数 / 重码 / 不符规则筛选；虚拟滚动、
   右侧详情）、查码、导入与来源（含构词规则改写）、体检、修改记录。设置页只留开关与入口。
5. **公文词表统一编码**：`LexiconTerm::code_with` 优先用输入法出码器的候选；人工标音只在候选里
   挑一个，标音算出的码不在候选里（基础表不是小鹤方案）就用首选。出不了码时退回拼音出码。

真机待验：加词窗与造词的实际手感、候选右键菜单弹出时焦点是否保住（代码里菜单打开期间每帧
把焦点还给编辑框）、词表页在小窗口下表格与详情的宽度分配。

## 文件与模块

| 文件 | 作用 |
|---|---|
| `src/ime/table.rs` | 格式解析、去重、来源合并、精确查询、导入比较与导出 |
| `src/ime/session.rs` | 焦点、按键接管、编码与上屏 |
| `src/ime/keys.rs` | 无状态按键分流 |
| `src/ime/manage.rs` | 导入与升级、导入表来源、个人层体检、修改记录、构词规则分区 |
| `src/ime/encoder.rs` | 字码与构词规则推算、自动出码 |
| `src/ime/add_word.rs` | 加词与造词窗 |
| `src/ime/lookup.rs` | 查码浮窗与查码视图 |
| `src/ime/ops.rs` | 个人层修改操作（加、改、屏蔽、调序、批次、清理、回退、规则） |
| `src/ime/history.rs` | 个人层修改记录 |
| `src/ime/page.rs` | 「输入法词表」页 |
| `src/ime/data.rs` | 基础表定位与原子保存 |
| `config_dir()/ime/base.txt` | 当前基础表 |
| `config_dir()/ime/base.previous.txt` | 上次基础表 |
| `config_dir()/ime/tables.json` | 导入表、个人词条、屏蔽、排序、手动构词规则与迁移标记 |
| `config_dir()/ime/history/` | 个人层最近 20 次修改前的文件与 `index.json` |

首次基础表查找顺序：用户 `base.txt` → 环境指定的 runtime → 可执行文件旁
`runtime/ime/base.txt` → 开发 `assets/fuma/quan.txt` → 旧用户音形表。
初始表只在用户没有当前基础表时复制，重新安装不会覆盖用户维护。

## 裁剪与打包

删除 qingjian 六个 vendor crate、四个直接依赖、旧拼音装配与附加词库模块、
音形叠加模块、学习逻辑和对应旧测试。删除辅码/音形编译 feature 与旧设置项。
保留项目 GPL-3.0-or-later 许可证；不变更其许可范围。

所有平台打包排除旧 runtime 的 `ime/` 数据，不再携带 `dict.qj`、`lm.qj`。
本机旧文件合计 47,943,072 字节（45.7 MiB）；初始 `quan.txt` 为 1,333,336 字节。
便携打包在本机存在 `quan.txt` 时独立复制成 `runtime/ime/base.txt`，无需编译 feature。
CI 中没有该本机资源时仍可构建和安装，使用者在设置中导入基础表。
发布工作流保留 PDF runtime 冒烟检查，删除已无意义的拼音数据冒烟步骤。

## 验收边界

自动化验证包括格式解析、同码来源合并、整批启停与隐藏、导出往返、四码与第五码、
候选选择、标点、焦点切换。`cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings` 与 release 构建通过。
全量测试 1,353 项通过，7 项失败均为沙箱文件权限问题，20 项忽略；真实基础表往返测试通过。
尚需真机交互验收：实际正文连续输入、右键加入、词表管理窗口布局、导入文件对话框、
安装后基础表首次复制及用户基础表跨安装保留。

## 注意

词表页结果不设上限，只在筛选条件或词表变化时重算（本机全表 6 万行加体检约 70 ms，开发构建）。
公文表扫描是收词流程，待确认词不会自动进候选。基础表更新独立于个人屏蔽与排序。
旧短语中超四码、带换行或停用的条目保留在旧配置中，不加入新词表。
本次不改离线 ZIP 同步；跨机携带输入法个人设置可导出备份或复制整个用户 `ime/` 目录。

本机最终 release 二进制由 114,757,632 字节降至 113,088,512 字节，约减少 1.6 MiB。
加上词库/模型换成基础表，输入法相关未压缩交付内容合计约减少 46.0 MiB；
压缩安装包的节省量以实际打包结果为准。便携包已检查只有 base.txt，无 .qj 文件。
