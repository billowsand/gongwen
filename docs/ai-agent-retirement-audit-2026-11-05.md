## 一、结论

新写作主链已完成 Pi 切换，不能再称“Pi 尚未接入”或“两条新写作路线并存”。仍未完成的是：5D 的业务效果和目标机验收、5E 的历史执行入口退出与旧编排删除，以及少量模型备用分支和共享依赖收尾。发现一个明确的工具预算不一致和一个新接口 AI 调用仍使用旧备用配置的问题。

“生产新任务只走 Pi”成立；“旧智能体已经完全退役 / 所有旧会话都只读”不成立。旧侧栏检查点仍可执行，属于设计明确允许的过渡兼容；应计入 5E 未完成项，不能当成新入口回流，也不能用“只读兼容”掩盖。

## 二、当前代码问题与清理遗漏

### F1 · P2 · 分阶段工具硬上限两端不一致（how）

- `pi-host/src/budget.mjs:174`：分阶段 `toolBudget=72`。
- `pi-host/src/agent.mjs:710`：`hardToolCap = toolBudget + 16`，结果为 **88**。
- `src/pi_agent/process.rs:38,1015`：Rust 硬上限 **84**，第 85 个领域工具请求直接终止。
- 触发：长分阶段任务按宿主阶段追加额度，累计领域工具调用超过 84 次。host 仍允许请求，Rust 提前停止，用户只能保留工作区再恢复。文件读写和阶段登记并非全部经过领域工具桥，不应把此数字描述成所有工具的总次数。
- 应处理：统一常规 60 / 分阶段硬上限 84 的来源；加 host 与 Rust 的边界对账测试，覆盖 84/85，而非只测默认 60。
- 本次实际执行 `decideStrategy`，输出 `mode=phased, toolBudget=72, hostHardCap=88, rustHardCap=84`；未用真实模型耗尽额度。

### F2 · P2 · 新数据接口 AI 调用仍可回落旧起草备用模型（how）

- 新接口 AI 试调、用例、问法生成通过 `LmBackend` 运行：`src/app/api_settings/detail.rs:467`、`detail/ai_try.rs:130,153,172`。
- `src/agent/apidef/ai_cases.rs:101,278` 使用 `ModelRole::Draft`。
- `src/ai_services/backend.rs:131,135`：主模型已是 `aux_chat()`（选了 Pi 时即 Pi），备用却仍读取 `draft_backup_chat()`。
- `src/models/config.rs:404`：这个备用来自旧 `draft_backup_model`；`backend.rs:209-227` 在连接/超时/服务端失败且未开始输出时执行备用。
- 影响：只改主模型解析，没有统一备用分支。升级用户残留的隐藏旧备用配置，仍会影响新接口 AI 任务；不能把它概括为“只供历史会话兼容”。切换有 backend notice，并非声称完全无日志。
- 应处理：新调用的主/备用绑定同一用途与配置版本；没有当前写作备用语义时，明确失败。旧备用字段仍可供明确的旧任务兼容使用。这里不要求删除所有备用模型机制。

### F3 · P3 · 旧技能管理器已退出编译，源码目录仍残留（how）

- `src/app.rs:30-59` 声明当前 `pi_skill_manager`，没有旧 `skill_manager`；全仓库搜索未找到挂载旧目录的引用。
- `src/app/skill_manager/` 仍有 `browser.rs`、`catalog.rs`、`detail.rs`、`markdown.rs`、`mod.rs`、`tests.rs`、`workflow.rs` 共 7 个文件，约 80 KB。
- 这部分没有历史会话解码职责，可先单独清理，不必等待模型质量或 5D。其中旧 tests 也已不随主 crate 编译，不能当作现有测试覆盖。

### F4 · P3 · 共享 API 仍反向依赖待退役工具模块（how）

- `src/agent/api.rs:781` 的数字参数解析调用 `crate::agent::tools::parse_number`；实现仍在 `src/agent/tools/mod.rs:518`。
- API 是当前 Pi 与数据接口工作台共同依赖，不是只供旧会话使用。删除旧 `tools` 前，应先把这段纯函数移入共享模块，再让旧工具单向转发。
- Pi 还使用 `agent::clarify::{Question, Reply}` / `agent_questions`（`src/pi_agent/process.rs:25,1073`）；应先提取通用问题协议，不能随旧澄清算子整体删除。
- `agent::{api,api_import,apidef}` 本身是现役业务服务，目录名陈旧不等于代码可退役。

### F5 · P3 · 当前状态入口混用历史口径（what，事实可确定）

- `docs/ai-model-unification-design.md:215,237` 写“旧会话只读兼容”，而 `src/ai_panel/ui.rs:1851-1890` 明确保留旧检查点“接着跑”和“从这里重跑”。应注明历史写作页只读与旧侧栏轮次可恢复的区别。
- `docs/pi-unified-writing-design.md` 前段仍写“设计，尚未实现”，末尾却记录 5A–5C 已落地；`docs/pi-implementation-plan.md` 的阶段表也落后于后续 API 与统一写作记录。
- `docs/pi-writing-eval.md:199` 写当前 9 例，实际 `tests/fixtures/pi-writing-eval/cases.json` 为 **11 例**；其中退役政策核查例已不在当前矩阵。
- `docs/pi-runtime.md:385` 的“AI 自动学风格并保存仍未实现”应明确指“模型自动直接入库不提供”；目前 Pi 学习 JSON → 用户编辑保存已实现。不能让读者误以为设置页仍走旧学习链。
- 早期阶段报告保留历史内容合理；需要的是一份权威现状索引和明确 superseded 标识，不是把历史成功/失败重新改写。
