## 一、产品目标与边界

用户始终从「智能写作」提交要求、材料和当前正文，不选择小模型版或大模型版。常规与分阶段是同一任务的内部策略，模型设置也归为一个写作模型选择。

- 常规策略：按需读材料，直接起草或修改，自查后交付。
- 分阶段策略：分批提炼、形成提纲、逐节写作、合稿检查；默认连续执行。
- 用户可在高级选项选择「自动 / 倾向分阶段」，无需配置输出长度或压缩阈值。
- 仅在缺少关键事实、存在无法自行取舍的内容分歧，或用户主动要求时提问。阶段转换不要求用户逐次点按钮。
- 短通知、局部修改可以直接完成；大窗口也可以分阶段写长报告。报告型任务仍可通过 `finish_report` 结束，不强制生成正文。

所有新任务共用 Pi 的交付权限：明确提交完整 Markdown，程序检查，界面线程保留精确撤销记录后写正文。事实疑点只提示；路径、体积、哈希、基线、选区、只读与授权要素保护继续拦截。中间成果不自动写正文，表单字段不因策略变化获得新权限。

## 三、策略选择：容量与能力分开判断

### 3.1 三类输入

1. 服务容量：实际部署窗口及来源、输出能力；服务端观察到的较低上限约束手动配置，不能被模型宣传窗口覆盖。
2. 执行能力：工具参数遵循、单任务完成与分步遵循的实测记录。未知模型不按名称猜测能力，不静默发送联网探测任务。
3. 任务规模：材料估算 token、当前正文、文种、目标篇幅、任务类型、是否要求逐步讨论。

统一用 token 估算预算；中文字符数只用于界面解释。256K token 不等同于 20 万汉字。首次复用现有保守估算，展示估算属性，通过请求实际 usage 校准，不增加在线分词依赖。

### 3.2 有效预算

真实服务窗口与建议工作预算是两个字段，不伪造较小的 `contextWindow` 来驱动切换。

```text
总工作预算 = min(实际服务窗口, 经验证的模型工作预算)
可放材料预算 = 总工作预算 - 固定指令与技能 - 输出预留 - 工具返回预留 - 安全余量
```

工作预算尚无实测值时使用保守默认，并记录「未验证」。预算不足以放下最小指令、一次工具结果和有效输出时，在请求前说明原因；不断压缩无法解决这种情况。

256K 仅作为首版可调、可评测的参考点：低于它时倾向分阶段，但任务很小可常规完成；高于它也要核算本次需求。暂不为某个 Qwen 9B 名称预填可靠窗口或执行能力。

路由顺序：

1. 报告、提取、局部修改按任务类型缩小范围，不套完整长稿阶段。
2. 用户倾向分阶段、材料超出预算、长稿需要多次输出，或模型实测需短步骤时，使用分阶段。
3. 其余采用常规策略；未知能力且任务复杂时保守采用明确的小步骤。
4. 运行中材料增长、反复压缩或超长错误可使常规转分阶段；保留已验证成果并记录原因。
5. 同一轮不自动反复切回常规，避免震荡。无效工具参数不直接判为窗口不足。

窗口限制和执行能力分别记录。工具协议始终不兼容的模型明确提示无法完成本任务；分阶段不能保证任意聊天模型都能成为可靠工具智能体。

## 四、分阶段写作契约

以下是公文成果约定，按任务跳过不适用阶段，不开发通用流程 DSL、分支图或第二个推理循环。

| 阶段 | 输入范围 | 必要成果 | 完成条件 |
| --- | --- | --- | --- |
| 材料提炼 | 材料索引、当前批原文、任务约束 | 带来源定位的事实摘录，风格/结构摘要分开保存 | 本阶段选入的材料分块均有处理记录，未读部分明确列出 |
| 提纲 | 任务约束、材料摘要、当前正文结构 | 章节标识、写作目标、事实依据映射 | 章节能对应任务，缺失依据明确，不默认问用户确认 |
| 分节写作 | 全稿简要提纲、本节证据、必要的相邻段落 | 独立章节稿及所用证据 | 成果存在、依赖版本匹配，未超授权范围 |
| 合稿检查 | 各节稿、约束、关键事实原文 | 完整候选稿与待提示疑点 | 检查重复、矛盾、遗漏和引用；必要时回改章节 |
| 交付 | 完整候选稿 | 现有提交回执 | 通过现有程序检查及正文写入入口 |

建议文件为 `work/task.md`、`work/notes/`、`work/outline.md`、`work/sections/`、`work/final.md`。实际路径由 Pi 报告并经程序验证，不根据文件名猜终稿，不扫描目录自动拼稿。合稿由 Pi 完成。

材料摘要须保留源文件标识、版本哈希和可回查位置；数字、日期、单位名称、直接引文保留原文摘录。压缩摘要不是新的事实来源。知识库依据绑定实际工具返回的证据快照，不能凭标题或检索计划声称已阅读。

逐篇材料标记「事实 / 风格样稿 / 结构范文 / 来函」。风格和结构文件只影响表达与组织，不能成为事件事实；角色是结构化元数据，不能仅靠文件正文自述。

## 五、薄宿主控制与标准技能

### 5.1 责任划分

- Pi Durable：模型调用、工具执行、会话持久化、压缩与任务恢复。
- 标准技能：公文写作步骤、事实忠实规则、各阶段的输入输出要求；公共分阶段说明按需加载，避免在八份技能中复制。
- 宿主：计算预算、限制读取、核验与登记阶段成果、选择下一次短任务、最终交付权限。

常规策略沿用现有执行。分阶段时宿主通过同一 Harness 发出当前阶段的明确短任务；不调用旧 `agent::engine`，不在 Rust 中另写模型循环。具体依 Pi 1.4.0 的 settled/submit 契约实现，不把「模型本轮结束」自动当作「业务任务完成」。

设计一个宿主验证的中间成果登记入口（名称暂定 `record_progress`）：模型提交阶段、成果路径、章节或材料块标识及依据标识；宿主验证后保存记录。它不能写正文、伪造来源或代替 `submit_document`。模型填写的「全部完成」不能绕过宿主的覆盖范围检查。

未提交成品的合法中间阶段不触发当前 `not_submitted` 兜底；只有登记了有效成果才能接续下一阶段。最终阶段仍必须明确交付。无成果空转、工具失败和压缩失败分别处理，不能无限自动续写。

### 5.2 进度与依赖

宿主保存小型结构化状态：运行标识、设计/技能版本、策略与原因、当前阶段、基线哈希、材料与角色哈希、已登记成果路径和哈希、成果依赖、重试次数。状态是内部记录，不向模型开放任意编辑，不信任模型写入的 JSON。

阶段转移只允许：待执行 → 执行中 → 成果已验证 → 下一阶段；异常进入暂停/失败；正文交付另走现有状态机。登记与继续之间崩溃时，重开先对账已有成果再调度；登记请求要可幂等重放。

成果复用按依赖失效：

- 材料改动只失效其摘录和依赖它的章节；未关联章节继续保留。
- 用途从风格改为事实等角色变化也会触发失效。
- 篇幅变化通常重算提纲/章节，不重新提炼未变材料。
- 风格变化保留事实摘录，重写相关章节。
- 用户运行中改正文，沿用现有基线冲突保护，不自动覆盖；不把旧选区迁到新正文。

用户新一轮要求是新的输入版本；旧运行按原快照恢复，新要求不偷偷混进旧阶段。

## 六、上下文、读取与错误恢复

材料放文件仍可能一次读爆窗口，因此阶段策略必须配合工具边界：

- 原文按稳定段落/行范围读取，返回来源定位和明确的未读范围；不静默截断后假装全文。
- 知识库全文和稿件库全文工具同样受单次结果预算约束。超限提供继续读取方式，不能只限制文件工具。
- 工具返回上限由宿主执行；模型读取过多时拒绝或返回可继续的有界结果，不依赖技能自觉。
- 最终交付读取完整候选文件、哈希与校验仍按现有独立体积上限执行，不用分块结果替代全文。

压缩前后保留任务约束、进度摘要与工作文件路径；下一阶段必须回读必要成果与关键证据。支持自定义压缩保留要求，但不承诺摘要能无损保存全部事实。

继续使用 Pi 自动压缩；`reserveTokens`、`keepRecentTokens` 与实际输出需求协调，避免只剩很小历史或输出挤占输入。阶段切换需要新上下文时，先验证 Pi 1.4.0 的 reset 行为再使用，不将上游 main 的 handoff 语义当作锁定版本能力。

区分并设有界恢复：

| 情况 | 处理 |
| --- | --- |
| 服务返回真实窗口更小 | 更新本次观察上限、重算预算并分批；保留已完成文件 |
| 压缩失败 | 有界重试后暂停；展示原因，保留工作区 |
| 中间阶段无成果 | 在本阶段纠正一次；仍失败则暂停，不冒充完成 |
| 输出被截断 | 检查候选文件完整性，缩小章节继续；不得提交半稿 |
| 工具参数反复无效 | 有界纠正，标记能力问题；不靠无限循环兜底 |
| 用户停止/崩溃 | 先核验已登记成果，再从未完成单元接续 |

总体时间、工具次数与单步重试均有上限；阶段数增加后重新评估现有 60 次领域工具额度，不直接取消额度。业务已读范围与预算摘要可展示，不暴露隐藏推理。

## 七、界面与历史迁移

统一输入框继续提供 `/` 技能、`@` 文章、粘贴与导入；材料卡各自选用途。状态显示「正在提炼第 2/5 份材料」「正在写第 3/6 节」，可展开已读依据与阶段成果；普通用户无需管理工作目录。

高级信息展示策略原因及窗口来源，例如「材料超过本次可用预算，已分批处理」。不把「小模型模式」当作面向用户的能力标签。

迁移顺序：

1. 新能力先在 Pi 现有入口完成并验证；旧入口在过渡期仍可使用，界面注明历史流程。
2. 新任务切换为统一入口；提供从旧任务复制材料、用途、要求与可验证阶段成果的显式动作。
3. 旧检查点不能直接解释为 Pi 检查点；原任务保留只读与原有恢复能力，迁移建立新运行，不覆盖旧历史。
4. 达到退役条件后停止旧任务续跑入口，历史成果仍可读/导出。无有效证据映射的旧摘录只能作待回查材料，不伪造为已验证依据。
5. 核对共享引用后移除旧写作调度；材料分块、缓存思路、词库与确定性检查按需提取复用，数据接口工作台不随之删除。

文种支持按统一 Pi 已有技能和导出能力逐项验收，不从旧流程的支持表直接推断新覆盖范围。新统一流程采用 Pi 直接写入权限；旧任务仍按其原有提案权限执行，历史兼容不授权旁路写正文。

## 八、实施分期与验收门槛

| 分期 | 交付 | 主要验收 |
| --- | --- | --- |
| 5A 预算与策略基础 | 窗口来源、任务估算、策略原因、独立工作预算；先不删除旧入口 | 同模型不同任务可选不同策略；同任务不同部署窗口正确变化；未知窗口保守回退；不新增输出长度设置 |
| 5B 分阶段最小闭环 | 公共技能、阶段成果登记、有界读取、提炼→提纲→分节→合稿→交付 | 中间阶段不报未交付；最终必须显式提交；证据可回查；只交付完整单稿；选区修改无外溢 |
| 5C 恢复与材料体验 | 依赖失效、逐篇用途、阶段状态、停止恢复、已读依据 | 中断后不重做已验证单元；角色变化正确失效；风格样稿事实不进入正文；运行中编辑不被覆盖 |
| 5D 模型效果与离线验收 | 同题对照、打包、断网安装升级、GUI 真机 | 自动化与真实模型分开报告；无在线安装依赖；写入/撤销/恢复走完整链 |
| 5E 入口收敛与旧编排退役 | 统一设置与入口、历史迁移、删除旧调度 | 达到下述退役条件；数据接口、知识库与历史读取不受影响 |

5A 仅验证路由不代表分阶段完成；5B 是首个必须跑通的垂直闭环。各阶段实现前按真实基线写独立 TASK，继续由 Pi 实现、主代理审查实际差异和修正；不把本设计当作已执行任务，不自动提交或发布。

最低评测矩阵：短通知、多材料长稿、仿写、来函复函、局部修改、事实冲突、研究报告；组合短/长窗口、少/多材料。真实模型至少包含用户目标本地模型和一个可用的较强模型；具体模型 ID、实际窗口、推理设置、skill 版本与数据哈希随结果登记，不能以名称替代测量。

记录完成率、无据新增事实、关键事实保留、引用格式、选区保护、调用量/耗时、恢复重复工作量及人工改稿量；同题常规与分阶段对照，不拼接多轮最好结果。模拟模型验证状态机，不能替代真实小模型工具能力验收。真实模型无法访问时列为未验收，保留旧入口。

退役最低条件：目标本地模型在明确部署窗口下完成通知、材料长稿和修改三类任务；较强模型同题回归无明显退化；停止/崩溃恢复、正文冲突、撤销、旧任务只读迁移通过；离线安装包包含相同 host 和技能版本。效果未达标时保留旧兼容，不以时间到期强删。

## 九、本轮决定与待实测项
