# 公文引用：方案与交接

## 需求与契约

起草页「插入 → 公文引用」在光标处插入稳定标记，预览、PDF、Word 展开成
《公文名称》（完整发文字号）。确实无文号的文件须明确登记，展开成《公文名称》。
引用支持稿件库与手工登记来文；默认读取来源最新提交版，没有提交版时明确提示工作稿。
来源后来变化只提示，用户确认才更新本篇；历史稿、归档稿保持自己的快照。

正文中的 `{{公文:UUID}}` 对应独占一行的 `<!-- gongwen-reference JSON -->` 定义。
定义包含引用 UUID、名称、完整文号、无文号标记、可选来源稿件 UUID 与来源版本 UUID。
JSON 注释内尖括号转义，名称与文号按普通文字处理；解析在切行后展开，源码字节范围
保持不变。来源关联用于核对，不是渲染依赖；没有来源原稿时仍能完整导出。

定义作为正文元数据随保存、版本、另存、同步 ZIP 自然携带，参加已有正文内容校验，
不增加 DraftInput 字段，不重算旧不可变版本校验值。不同稿件的引用 ID 不按标题或文号
自动关联。无定义、重复定义、定义损坏、标记破损阻断正式导出，预览显示待修复提示。

普通 Markdown 与对外复制展开引用；可编辑源码保留标记和定义。同步包无需默认携带
来源全文；同时选中来源稿件导出后，目标电脑可以按稿件 UUID（含身份别名）恢复追溯。

AI 不生成、删除或改写引用定义；引用名称和文号不由模型维护。确定性规则校验引用结构。

## 分期与验收

1. 插入、手工登记、无文号、复用与定位；源码范围保持；预览 / Word / PDF 一致；错误阻断。
2. 历史 / 花脸稿 / ZIP 往返与分叉合并；Markdown 源码交换；跨稿复制及 AI 保护。
3. 实时排版编辑交互、来源查看与变化提示、更新与转普通文字；帮助和最终回归。

## 当前进度

第一阶段已提交 `35a1e48`，5 项引用测试、fmt、clippy 与 release 构建通过。代码在 `src/document_reference.rs`、
`src/draft_page/references.rs`，公文解析入口在 `export::parse::prepared_lines`。
研究报告在交给 mdx 前展开；公文 Word 与 PDF 各自底层写出入口也检查引用，
避免批量导出与送批材料绕过校验。弹窗冻结正文及插入点，确认插入一次性支持 Ctrl+Z。

第二阶段实现：两套独立数据库只同步引用者（含历史版本），没有来源原稿仍还原完整快照；
随后补导入来源按 UUID 可追溯，引用者不变，B→A 往返识别同版。花脸稿比较展开文字，
过滤定义元数据，来源身份变化不产生纸面标注。分叉按引用 ID 整条选择，新增不同条目独立合并。
源码包主 `.md` 展开为通用文字，另带 `-可编辑.md` 保存标记与定义。
源码、实时排版、版本对照编辑器共用临时富剪贴板：对外复制展开，应用内粘贴带定义；
同 ID 不同快照生成新 ID，不覆盖目标篇。富数据只在本次应用进程中保留，重启后粘贴为普通文字。
修订采纳与 AI 整篇提案接受前检查引用定义和出现次数，拒绝改变引用；AI 事实清单同时保护
引用身份、展开后的名称与文号。引用需要调整时由用户通过按钮操作。

真机最终验收：从库引用带文号函件、手工来文、无文号白头呈批件；选区替换与撤销；
跨行断行及表格；PDF / Word；另一套数据库只导入本篇；历史版本；来源更名后显式更新。
