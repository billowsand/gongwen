## AI 侧栏

功能区点「AI 助手」，右侧滑出 AI 侧栏；再点一下收起。先在正文里选中一段再点，
这段会锁进输入区，只改它，其余逐字不动。

侧栏下面是输入框，上面是任务流。写好要求后按 **Ctrl+Enter** 发送（Enter 是换行，也留给
输入法上屏）。

### 技能条：这一轮怎么做

输入框上方的技能条决定这一轮按哪个**技能**做。内置两个：「研究式起草」按材料写新稿，
「润色」改现有正文（全文或选区）。默认是「自动」：

- 正文为空时只会选起草；
- 边输入边按关键词判断，例如写了「压缩」「改一下」就是润色，写了「起草」「写一份」就是起草，
  技能条上显示「自动 · 润色」这样的结果；
- 分不出时，发送后由模型从候选技能里选一个，过程里会留一行「按「润色」处理（模型判断）」。

想自己定，点技能条选一个；或者在输入框开头敲「/」，从列出的技能里点一个，例如
「/润色 只改错别字」。指定的技能当前用不了（比如正文为空时指定润色）会直接说明原因。
鼠标停在技能条上，能看到这个技能做什么、能用哪些工具。

### 起草：先查后写

起草不是检索一次就动笔，而是像有经验的人那样「写到拿不准就去翻资料，翻不到就问人」：

1. **动笔前确认**：要求里写的文种和当前文种对不上、受文对象或目的不明确时，先出几道选择题，
   最多 3 道。推荐项已经替你选好，点「确认，开始起草」即可；
2. **预研**：列出要到知识库里查清的问题，逐个检索，形成带编号的证据；
3. **带证据起草**：用到证据的地方，模型会标出处；不知道的写「【待核实：缺什么】」；
4. **围绕缺口反复补全**：程序找出稿里的待核实和来源不明的数字、日期、文件名，能从知识库查到的
   去查、补上；本次的时限、地点、人员这类只有你知道的，不去查；最多 3 轮，一轮没进展就停；
5. **核验**：带出处的句子逐句对照原文，对不上的去掉出处；
6. **出题**：还要你确认的，一批出成选择题，最多 4 道。

卡片上能看到「过程（N 步）」：每次检索、补全、核验都有一行；「核实清单」里列出每处缺口
怎么处理的、证据出自哪里。

题目答完点「按回答修订」：你填的值原样写进稿子，选「保留待核实」的保持占位，**程序不会替你猜**。
修订后的稿子是新的一轮提案。

> **提示** 没启用知识库时也能起草，只是所有缺口都会出题问你。

### 结果都是提案

无论润色还是起草，生成完都是一张结果卡，正文不会被直接改动：

- 空稿点「采用为正文」，已有正文点「接受提案」，或「查看对照」逐处看改动；
- 有关键事实变化（单位、人员、日期、数字、文件依据）时，必须先勾选核对，才能接受；
- 不满意就「放弃」，正文不变。

> **提示** 生成中随时可以点「停止」。半截输出不能采用，可以「重新生成」。

### 调整技能的做法

每个技能是一个 `SKILL.md` 文件：开头写流程（先做什么、后做什么）、参数（迭代几轮、出几道题、
证据取多少字）和能用的工具，正文是每一步的提示词。想改内置技能，把 `research-draft/SKILL.md`
或 `polish/SKILL.md` 复制到配置目录的 `skills/<同名文件夹>/SKILL.md` 再改；只写想改的那一步
也行，其余沿用内置写法。也可以新建一个文件夹写自己的技能，它会出现在技能条里。

文件写坏了不会影响使用：改内置的那份会退回内置版本，新建的会被停用，原因都会提示在侧栏里。

仿照起草与大纲起草暂时仍在原来的工作台里，从侧栏右上角「•••」打开。

## 工作台的五种工作流

侧栏右上角「•••」→「仿照起草 / 知识起草 / 大纲…」打开工作台：

![AI 事实单确认流程](images/diag-ai-workbench.png)

| 工作流 | 干什么 | 何时用 |
|---|---|---|
| **仿照起草** | 载入基准稿做仿写 | 有同类旧稿，要出新稿 |
| **知识起草** | 依据主题和知识库起草 | 有历史成稿积累 |
| **材料成文** | 从材料形成事实单，确认后成文 | 手里有原始材料 |
| **大纲起草** | 先列大纲、人确认后再逐节填 | 长文、结构优先 |
| **受控润色** | 只生成修改提案 | 已有稿子要润 |

五个工作流共用一件事：**AI 只出建议，正文由你采纳。**

## 仿照起草

载入一篇基准稿（从稿件库选或当前稿），四种仿写策略：

| 策略 | 用途 | 例 |
|---|---|---|
| 结构仿写 | 抄结构不抄内容 | 按商洽函框架写新商洽事项 |
| 同类改稿 | 同文种换事实 | 去年的通知换今年的时间地点 |
| 局部更新 | 只改指定部分 | 换掉其中一段事项 |
| 续期换届 | 机构换届、任期续期 | 委员会换届通知 |

四种策略的差别在**约束强度**：结构仿写最松（可改写每一段），续期换届最紧（时间、届次这类要素严格替换，其余照搬）。

> **红线** 无论哪种策略，公文要素（单位、人员、文号、密级、日期）都不在模型的改动范围内。仿的是正文写法，不是要素。

## 知识起草

「依据主题和知识库起草」：

1. 填主题（写什么）与文种；
2. 程序**先出事实单**（时间、单位、事项等要你定的点）；
3. 你逐项确认；
4. 程序拿你写的材料原话到知识库**检索片段**（RAG），与知识库页的检索、问答是同一套；
   默认不限文种，工作台里可以改成「跟随当前文种」或指定某个文种；
5. 模型结合检索片段与确认后的事实起草。

知识库要先建好，见 [知识库与问答](chapter:18-knowledge)。命中了哪几篇、或者为什么没命中，
都会留在 AI 侧栏这一轮的卡片上；检索不到就退回纯主题起草。

## 材料成文

「先从材料形成可编辑事实单，确认后再按当前文种和版式生成 Markdown」：

1. 粘贴或导入材料原文（可以是会议纪要、来函、口头要点）；
2. 点「提取事实单」——**程序按材料原文拆分，不调用模型**；
3. 事实单逐项可改：改文字、删条目、加条目；
4. 确认后按当前文种与版式起草。

> **提示** 「提取不调模型」这点很关键：事实单是**确定性拆分**的结果，模型没机会在拆分阶段就把事实改错。模型只在你确认之后、按你确认的事实写正文。

事实单里典型字段：事项、时间、地点、单位、人员、数字、依据文件。缺的项自己补，多的项删掉。

## 大纲起草

「先列大纲、人确认后再逐节填」：

1. 给主题与要点；
2. 模型出**大纲**（节标题 + 每节要点）；
3. 你在大纲窗里调整：改标题、换顺序、加节删节；
4. 确认后**逐节**填内容，每节填完可单独看、单独改。

适合长文（工作报告、调研报告）。逐节填的好处是：一节写砸了只重写那节，不用整篇重来。

## 受控润色

「AI 只生成修改提案；单位、人名、日期、数字和文件依据发生变化时必须另行确认」：

| 选项 | 说明 |
|---|---|
| 润色范围 | 全文 / 当前选区 |
| 提示词 | 从提示词库选，或写临时提示词 |
| 临时素材 | 用完即弃的补充上下文 |

流程：

1. 选范围与提示词；
2. 模型出**修改提案**（不是直接改）；
3. 提案审阅窗左右对照；
4. 涉关键事实的改动**单列清单逐项确认**；
5. 接受后自检，有问题自动回滚。

提示词库管理见 [AI 优化、提示词与文字复核](chapter:14-ai-polish)。

## 提案审阅窗

所有工作流的产出都进同一个「审阅 AI 修改提案」窗：

| 区域 | 内容 |
|---|---|
| 左 | 当前审校稿 |
| 右 | AI 提案 |
| 中 | 增删对照，逐处可跳 |
| 下 | 事实变化清单（若有）、接受 / 忽略按钮 |

> **提示** 「接受前不会覆盖正文或自动导出」——这是硬约定。你关掉窗、程序崩了，正文都是原来的样子。

接受后：

- 提案写入正文；
- **重新执行审校**（要素 + 词表 + 规则）；
- 新问题自动回滚那次采纳。

忽略后提案作废，可在会话里重新生成。

## 事实单：三步走

材料成文、知识起草、大纲起草共用事实单流程：

1. **提取**（不调模型）：程序从材料原文确定性拆分；
2. **确认**（人）：逐项改定，这是唯一能定事实的地方；
3. **起草**（调模型）：按确认后的事实单写正文，提示词里附「不得改动」清单。

模型从头到尾没机会自己定事实。这是红线二（不碰要素）在起草侧的落地方式。

## 用起来的几个建议

- **仿照起草**选基准稿要选**同文种**，跨文种仿写效果差；
- **材料成文**的材料越原始越好——会议纪要比整理好的摘要强，因为事实更全；
- **大纲起草**别偷懒跳过大纲确认，逐节填之前结构定了，后面很少返工；
- **受控润色**先用全文跑一遍看整体，再用选区精修局部；
- 任何工作流出来的提案，**先看事实变化清单再看文字**——事实对了，文字好改。
