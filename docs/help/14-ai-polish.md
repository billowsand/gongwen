## AI 管理页

AI 相关的设置都在「AI 管理」页，布局和设置页一样：左栏分区，右栏内容，底部一个「保存」。

| 组 | 分区 | 管什么 |
| --- | --- | --- |
| 模型 | 模型服务 | 起草与各技能用的对话模型：接口地址、模型、生成参数 |
| | 文字复核 | 逐句查语病的小模型、检查器开关、采纳统计 |
| | 知识库检索 | Embedding 与 Rerank 模型、检索方式 |
| 智能体 | 技能 | SKILL.md 的启用停用、复制改写、新建、导入导出 |
| | 数据接口 | 技能能调的内网查询接口与密钥 |
| | 工具调试台 | 写技能时试工具 |
| 写法 | 风格 | 从指定稿件学写法风格，起草、改写时按内容自动选用 |
| | 润色预设 | 侧栏技能的 `{preset}` 预设库 |
| | 输出标准 | 程序内置的输出格式契约（只读） |

各分区改完点页底「保存」才写入配置；润色预设编辑区里没「应用」的内容、数据接口没保存的修改也一并保存。
技能文件在技能分区里单独保存（带校验）。侧栏「•••」里的「管理技能…」直接打开技能分区。

> **提示** 网络代理是全局的，仍在「设置 → 网络代理」。

## 模型服务

| 配置 | 说明 |
| --- | --- |
| 对话接口地址 | AI 侧栏的技能都用它，内网 vLLM 或本机 LM Studio `http://127.0.0.1:1234/v1`、Ollama `http://127.0.0.1:11434/v1` |
| 对话模型 | 点「测试连接 / 刷新模型」后从下拉选，**中文指令模型** |
| 生成参数 | 温度、最大输出 Token、超时 |
| 上下文窗口 | 一次请求里输入加输出最多多少 token。默认「自动」：先问服务（点「测试连接」时读到），问不到按模型名估（DeepSeek 系 128k、MiniMax 系 192k、Qwen3 系 32k），再不行按 32k，下拉框里写明来源；也可以选档位或直接填。服务端报过超长时以它说的为准 |
| 文字起草 · 备用模型（可不选） | 主模型这次调不通时改用它；不选就是不用备用。选择器占位「不配置备用」，只列对话类模型 |
| 文字复核 · 备用模型（可不选） | 复核模型在吐出第一个字之前不可用时，本次改用它。不选时：若复核沿用起草模型，就沿用起草的备用模型 |

备用模型切换后会立刻在卡片说明区出现一行提示：`主模型 <主模型> 不可用（<原因>），本次改用 <备用模型>`；备用也失败，报 `备用模型 <模型> 也失败：…`。

> **提示** 模型**已经开始吐字**之后出错、用户点「停止」、上下文超长、客户端错误、只拿到部分正文，这些情况都**不切换**备用模型（已经开始输出时提示 `模型已开始输出，不能切换备用模型`）。澄清、核对、自主步骤这些辅助角色没有自己的备用时，就沿用起草模型的备用。

最大输出 Token 是上限：每次请求还会按上下文窗口的剩余空间自动收紧，接 32k 窗口的服务也不会因为「输入 + 输出」超限被拒。
「文字复核」分区里也有一项上下文窗口，管复核模型。

对话、Embedding、Rerank 三个接口地址**相互独立**（后两个在「知识库检索」里配），不用的可以留空。Ollama 的接法见 [知识库与问答](chapter:18-knowledge)。

## 技能

AI 侧栏按**技能**做事，每个技能是一个 `SKILL.md`：开头写流程、参数和能用的工具，正文是各步
提示词。这一页列出全部技能：

- 前面的勾选框是启用 / 停用，停用的不出现在输入框的 `/` 列表与技能标签里，也不会被自动选到；
- 点技能看详情：做什么、触发词、能用的工具及权限、还没配置的数据接口、校验发现的问题；
- 详情页的「工作流程」把技能里实际写的步骤画成一张横向流程图（节点与配色跟随界面主题），子流程点开单独一张，图太宽时按可用宽度等比缩小——图上看到什么，跑起来就是什么；
- 内置技能点「复制为我的技能」得到一份可改的副本（同 id 覆盖内置），改完「保存」——保存前会
  校验，解析不过不让存；有问题也能存，但加载时会退回内置版本并提示；
- 「恢复内置」删掉你的副本；自己新建的技能用「删除我的技能」；
- 输入一个英文 id 点「新建技能」，按模板起一个新的；
- 写技能时可以用 `references:` 声明输入框里 `@` 引用的文章怎么用：`evidence`（默认，进证据包）、
  `baseline`（当基准稿）、`material`（并进材料）、`letter`（当来函），见 [AI 侧栏与技能](chapter:13-ai-workbench)；
- 「导出…」打成 `.skill` 包分享，「导入技能包…」「导入文件夹…」装别人的。技能文件里没有接口
  地址和密钥，分享不会带走它们。

## 数据接口

这一页管的是**让技能调内网系统取数据**：统计系统、政策库、各类业务系统、算法服务，都配到这儿，技能里引用一下就能查。

### 中心格式：一个服务一份 OpenAPI

接口配置的真身是 **OpenAPI 文件**：一个服务一份，存放在配置目录的 `apis/` 下。界面上改完（名称、说明、只查询勾、字段映射、用例）保存时写回同一个文件。导出的文件能在 Postman、Apifox 里直接打开。

老的单文件配置在**第一次打开这一页时自动**转成按服务器分组的 `apis/` 下的文件，原文件改名留成 `.bak`。**迁移没有任何提示**。迁移后接口状态会变成「配置改过，需重测」，因为配置指纹变了；接口本身的名称、说明、条件、映射、样例都不变。

### 导入与导出

页面上方「导入 / 导出接口配置」按钮里两项：

- **导入接口文件…**：可一次多选。支持 OpenAPI 3.0 / 3.1（JSON、YAML）、Swagger 2.0、Postman 集合（可同时选环境文件）、cURL、以前导出的接口配置。
- **导出为 OpenAPI…**：一个服务时弹保存框（按扩展名决定写 JSON 还是 YAML），多个服务时选文件夹。成功提示 `已导出到 <路径>（不含密钥）`。

导入完左栏顶部有一条结果消息，第一行 `导入了 N 个接口，记得保存。`，下面是报告（界面没有单独的「导入报告」页，失败时整块转红）。代表性的几行：

| 报告 | 什么意思 |
| --- | --- |
| `文件名：「标题」N 个接口` | 认出来了 |
| `；M 个按会改数据处理，不给 AI 调、不自动试调（其中 K 个 POST，确认只是查询的，在「技术配置」里勾上「只查询」）` | 有会改数据的接口要你人工定性 |
| `；M 个暂时发不了：接口名（原因）、…` | 程序组不出请求，最多列 4 个；原文保留但发不出去 |
| `「标题」没有服务器地址：保存后在接口地址里补上 http://主机:端口` | 得自己补 |
| `文件名：认不出格式。支持 OpenAPI / Swagger（JSON、YAML）、Postman 集合与环境、cURL；Word、PDF 这类文档请用「从文档识别」` | 选错文件类型了 |
| `文件名：读不了（原因）` | 文件有问题 |

导出的文件里带用例、期望、AI 用例、只读标记和字段映射这些扩展字段，所以「证明」随文件走；**不带密钥，也不带本机的环境地址**。测试记录不导出。

### 页面结构

左栏按**服务器分组**，组标题是主机名（地址为空显示「未填地址」），搜索框提示「搜索接口」。「添加」菜单两项：从文档识别…、手动填写。

组标题右侧一枚**密钥状态片**：`无需鉴权` / `缺 Key` / `Key 被拒` / `已配置`，悬停写「这台服务器上的接口共用的密钥：点开填写、更换、全部重测」。

点组标题进**服务与密钥**页：同一个服务通常共用一把 Key，在这儿填一次，下面的接口都用它。「接口」区有按钮「全部重测」（每个接口用样例值各调一次）。**密钥不是单独列在页面底部的**——它就在这台服务自己的页里，改名、重测也在那儿做。区底说明：粘贴后点别处，用到它的接口自动重测；Key 只存在本机，导出配置、同步稿件时都不带，也不发给模型；记得保存。

详情页三个页签：**接口说明** / **试一下** / **技术配置**（配置有问题时这个页签上挂一枚 `配置有 N 个问题`）。顶部「管理」菜单：`鉴权与密钥…` / `复制技能引用` / `复制地址` / `删除接口…`。页底是保存条，有未保存的修改时出现「保存」，存成功提示 `已保存，下次发送时生效。`

### 接口用例

「试一下」页顶部两个切换：`手填参数` 与 `说一句话让 AI 调`。

手填这一路：请求区顶部一排标签，标题字「用例」，跑过的标签前带对勾或叉。选中一条后出现「编辑当前用例与期望」，可以改名称、删掉这条。

期望区的标题原文是 `期望（先要调通且业务成功，再逐条检查）`。每条期望读起来是一句人话，比如 `/data/items 至少 1 条`、`有字段 /data/total`、`/data/items/0/title 包含 防火`。加期望的下拉五种：**不为空 / 至少几条 / 等于 / 包含 / 有字段**，位置写 JSON 指针（提示 `/data/items（空 = 整个返回）`），要值的种类再给一个值框。

没写期望的用例按**默认期望**判定：调通且业务成功（发得出去、HTTP 2xx、配了成功判据时成立、返回不是登录页这类网页）。

- **存为用例**：把现在填的值存成一条用例；调通过的会按这次的返回建议期望；
- **全部 N 条用例跑一遍**：逐条实测并检查期望，结果记下来，作为这个接口可用的证明；跑完一行 `N 条用例，通过 M 条。`；
- **AI 编几条用例**：按接口说明编几条典型用法（内容取材于公文），只编参数不写期望。

单条结论写在响应区顶上：`用例「X」通过（只要求调通且业务成功）`、`用例「X」通过：满足全部 N 条期望`，或红条 `用例「X」没通过：期望…，实际…`。

### 运行记录

接口列表右侧的状态片就是运行记录的入口：`用例 5/6 通过 · 10-06 21:30`、`测试通过 · 时间`、`测试失败 · 时间`、`配置改过，需重测`、`未测试`、`缺密钥`、`鉴权没过 · 时间`、`配置有 N 个问题`。

「接口说明」页里能看到每组用例的结论（`5/6 通过 · 时间`）和每组 AI 用例的结论（`5/6 调对 · 时间`）。

记录**只存结论与一句原因，不存返回内容，也不存参数值**。改了配置（指纹变了）之后整组结论不再算数，状态退回「配置改过，需重测」。

### 会改数据的接口

默认所有接口都按「会改数据」处理，要开放的得自己在「技术配置 → 性质」里勾两个勾：`只查询，不改数据`、`给 AI 用`（后者必须先勾前者才勾得上）。

只勾了「只查询」的接口才给 AI 调、才自动试调；会改数据的接口只能人在调试台发：请求区底部常驻黄条 `这个接口会改数据：发送前要确认，不参加「全部跑一遍」，也不给 AI 调。`，点发送先弹确认框，标题 `发送会改数据的请求？`，下面把实际要发出的请求列出来（密钥打码），再点「确认发送」才真发。

> **提示** 「只查询」这个勾程序和模型只能往严的一边改：能把只查询改成会改数据，不能反过来。POST 的查询接口得你本人在界面上勾。

### 说一句话让 AI 调

「试一下 → 说一句话让 AI 调」：像用户那样问一句（例如「2025 年全省森林火灾多少起？」），点「让 AI 调」，看模型挑哪个接口、填什么参数。

右栏依次给你看：问题回显 `问：…`；选对了 `模型调了这个接口「接口名」`；选错了会告诉你多半是两个接口的用途写得不够分明；没调接口出红条 `模型没有调接口。`。

选对且参数校验过了，才出现 `选得对就存成 AI 用例。勾上要锁定的参数（不勾的模型可以自由发挥，比如页码）：`，下面是每个参数一个勾选框（默认全勾）和按钮「存为 AI 用例」。**AI 用例**的判定口径是三件事都成立：接口选对 + 写明的参数对 + 调用成功；不勾的参数不锁。

同一条接口还能「全部 N 条 AI 用例跑一遍」，逐条让模型调，记下正确率；也有「AI 出几个问法」，让模型按接口说明出几句不同问法与它认为的参数，你逐条确认后才加进 AI 用例。

### 两级访问

一个服务里给 AI 用的接口超过 12 个时，模型不会把清单全拿在手上，而是**先按关键词搜再调**：提问框下那句说明会写成 `模型能挑这个服务里给 AI 用的 N 个接口；接口多，模型要先搜再调。`，结果栏也会多一行 `先搜了：…`。参数在真正发请求前照样校验，不合格不发。

### 响应区

右侧响应区三个分段：**整理后的条目 N**（按返回映射整理好的条目）、**原始返回**、**实际请求**（密钥打码）。最上面一行是状态：`HTTP 200` / `没发出去`，带 `· N ms`，取到条目时带 `· 取到 N 条`；重测时写 `重测中…`。

> **提示** 调通了但没整理出条目、没发出去、请求没组出来，响应区都会给一句对应的话（`返回里没有条目。` / `请求没发出去，没有返回。` / `请求没组出来，看上面的出错原因。`），照着去原始返回里看就行。

## 工具调试台

写技能时用来试工具：选一个工具、按说明填参数（JSON）、点「运行」，看输出、会并入证据包的资料、
改动后的工作稿。对象是当前稿件的**副本**，写工作稿的工具改不到正文；问用户和调模型的工具不在
这里，到技能里试。

## 风格

风格档案记下一种写法：总体基调、开头怎么起、主体怎么组织、常用表达、结尾怎么收、用词偏好与忌用、数字与时间的写法，
加上程序算的统计特征（句长、段长、编号样式、常用开头语与结尾语、常用说法）和 3–5 段原文范例。

- **新建风格**：从稿件库、知识库里勾 2–10 篇同类稿子，点「开始学习」。样稿多、放不进模型上下文时会分批先小结再合成。
  学完先给你看：名称、适用文种、适用场合（关键词，如「讲话、对下部署」）、写法描述都能改，范例可以删改，点「保存」才生效；
- **只学写法，不学事实**：写法描述里出现样稿里的单位、人名、日期、数字时，会标出来提示你删掉；
- **怎么被用上**：起草、改写前按文种（必须对得上，不勾表示不限）和适用场合关键词打分，只有一份最高就用它，几份分不出交模型挑，
  都对不上就不用；「设为默认」的文种分不出时用它。侧栏框底的「风格」标签可以指定或不用；
- **管理**：停用、删除、重新学习（照原来的样稿再学一次，名称、文种、场合保留）；样稿学过之后改了，列表上会提示「样稿有更新」；
- **导出 / 导入**：风格档案只存在本机（配置目录 `styles.json`），可以导出成 `.json` 发给同事导入。

风格与润色预设分工：预设是一句指令（「精简篇幅」），风格是学出来的一整套写法。

## 润色预设

润色、语气调整这类技能提示词里的 `{preset}` 就是这里的预设：在侧栏输入框底栏的预设标签里选一条，它的指令就拼进提示词。每条预设五项：

| 字段 | 说明 |
|---|---|
| 名称 | 列表里显示的名字 |
| 指令 | 给模型的自然语言要求 |
| 适用文种 | 限定哪些文种可用；**留空 = 全部文种** |
| 内置标识 | 内置项不可删，可另存为自定义后改 |
| 创建时间 | 自动记 |

### 内置预设

| 名称 | 用途 | 适用 |
|---|---|---|
| 格式规整 | 保底项：规范标点、空行、引号、编号 | 全部文种 |
| 充实论述 | 扩写论据、充实段落 | **限白头件、普通公文**等；会议议程、电话通知**不给** |

「格式规整」是保底：任何文种都能用，改的只是格式不动事实。「充实论述」刻意不给会议议程和电话通知——那两种文种短而实，扩写只会灌水。

适用文种限制是硬的：侧栏输入框的预设标签只列当前文种可用的项。

### 一次性的要求

不想存进预设库的要求，直接写在 AI 侧栏的输入框里：选了预设又写了要求时，两者一起交给模型；
只写要求不选预设也行。常用的要求再存进预设库。

## 输出标准：用户改不了

> **注意** 输出形态由程序**内置约束**，用户不可改、不可关。这是 AI 优化不会破坏导出结构的保证。

「内置输出标准」定义了模型输出的**格式契约**：必须保留哪些标记、标题层级怎么给、表格与图片引用怎么带、区段注释不得删。「输出标准」分区可按文种切换查看（只读）。

为什么这么死：模型输出一旦破坏了 Markdown 结构，导出链路就崩。把契约焊死在程序里，模型只负责文字，结构永远是对的。

这是红线三的一部分——确定性闸门之一。

## 文字复核做什么

「表达复核」用**小模型**逐句查：

| 查什么 | 例 |
|---|---|
| 语病 | 搭配不当、成分残缺、语序别扭 |
| 称谓 | 单位与人名称谓是否规范、前后一致 |
| 标点 | 公文标点用法（顿号与逗号、书名号） |

配置在「AI 管理 → 文字复核」，与起草模型**独立**：

- 可以指到不同的模型端点（比如起草用 14B，复核用 7B）；
- 不配置就都走起草模型；
- **温度锁 0**：同输入同输出，便于回归；
- 输出是**待确认的修订建议**，一条条采纳，正文不变。

小模型的输出形态同样由程序内置约束，不可改。

## 采纳与自检

所有 AI 产物（侧栏技能的提案、文字复核的建议）采纳路径一致：

1. 提案审阅窗左右对照；
2. 事实变化**逐项确认**（若有）；
3. 接受 → 写入正文；
4. **重新执行审校**；
5. 引入新问题 → **自动回滚**那次采纳。

见 [AI 的边界与保障](chapter:12-ai-guard)。

## 使用建议

- **预设与要求写得越具体越好**：「把第二段改成请示语气，保留事项与时间」远胜「润色一下」；
- **适用文种别乱放宽**：给电话通知用「充实论述」只会让它变长变空；
- **临时要求先试**：好用了再存成预设，库里堆一堆一次性预设反而难找；
- **复核模型选小的**：查语病称谓不需要大模型，小模型快且稳定（温度 0）；
- **事实变化清单永远先看**：文字对不对可以慢慢改，事实错了是事故。
