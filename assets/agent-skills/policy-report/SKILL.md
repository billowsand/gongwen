# 政策研究报告

流程：澄清 → 确定报告题名 → 列大纲（你确认，可直接改）→ 逐章「检索 → 带出处写这一章」→ 补摘要 → 缺口循环
→ 核验引用 → 引用落到报告（文献库里有的写成 `[@key]`，没有的写成脚注）→ 出题。

要让某一步也查内网数据接口，在 `retrieve` 与 `gap_loop` 下写 `apis: [接口 id]`，并在 `tools`
里声明 `http.call:接口 id`。

## 动笔前澄清

下面是一份研究报告的写作要求。判断在动笔之前，有没有**会让整篇写偏**的事情必须先问清楚。

只考虑这几类：研究的问题与范围、给谁看（决策参考 / 内部研究 / 公开发布）、篇幅、重点要回答什么。
要求里已经写明或能直接推断的不要问；具体的数据、案例、文件不要问（稍后检索）。
信息已经足够动笔时，只输出「无」。

需要问时，每行一题，最多 {max} 题，格式严格如下（用全角竖线分隔，2 到 4 个选项）：
问题｜选项1｜选项2｜选项3

【标题提示】{title}
【写作要求】
{request}

## 报告题名

根据下面的写作要求拟定这份报告的具体题名，概括研究对象与核心问题。
要求中明确指定了报告名称时原样使用；否则根据研究主题拟题，不编造单位、日期或数据。
只输出一行题名文字，不加 Markdown 标记、书名号、说明或编号。
不得只写“研究报告”“调研报告”“政策研究报告”“咨询报告”“决策参考”或“报告题名”。

【写作要求】
{request}

不写编号，不写节，不写摘要、参考文献。第一章一般是背景或现状，最后一章一般是对策建议。

## 写一章

你在写研究报告《{report_title}》里的一章：{section}

【整篇要求】
{request}

【已经写好的部分——只为衔接，不要重复】
{workspace}

【这一章查到的证据】
{evidence}

要求：
1. 只写这一章：第一行是「## 章标题」（标题不写编号），下面可以分「### 节」；
2. 用到证据里的具体事实、数据、文件名称或原文表述时，在该句标点之前标注证据编号，例如
   「……已覆盖全部试点地区[K3]。」；只借鉴思路时不标；
3. 证据和要求里都没有的具体事实不得编造，写「【待核实：缺什么】」，缺什么要写具体；
4. 证据里属于其他事项的时间、单位、数字不得挪用；
5. 不写摘要、全文总结和参考文献。

## 摘要

下面是一份研究报告的正文。写一段摘要（200～400 字）：研究什么问题、主要发现、主要建议。
只输出摘要正文，不加标题，不标证据编号，不写正文里没有的内容。
