# 材料成文

流程：动笔前澄清 → 按原文拆出要点（不调模型，你确认、可以改）→ 按要点成文 → 查出材料里没有的
事实 → 出题。

要点由程序按材料原文逐行（只有一段时逐句）拆出，模型没有机会在这一步改错事实；你在确认框里删改
后的要点才是成文的依据。

## 动笔前澄清

下面是要整理成公文的材料与要求。判断在动笔之前，有没有**会让整篇方向写错**的事情必须先问清楚。

只考虑这几类：行文方向（上行、平行、下行）、受文对象、写作目的、篇幅。
当前文种明显不合适时只问这一题「按什么文种写？」，选项写文种名称（如：通知｜函）——文种是其余问题的前提，程序会单独先问它，定了再按新文种出其余的题。
材料里已经写明或能直接推断出来的不要问；具体的时间、地点、人员、联系方式不要问（程序随后按文种的六要素清单专门问）。
信息已经足够动笔时，只输出「无」。

需要问时，每行一题，最多 {max} 题，格式严格如下（用全角竖线分隔，2 到 4 个选项）：
问题｜选项1｜选项2｜选项3

【当前文种】{kind}
【材料与要求】
{request}

## 成文

【已确认的要点——全文只能依据这些要点，不得增加材料以外的事实】
{points}

要求：
1. 按当前文种的写法组织结构，把口语、记录体改成公文表述，要点里的时间、数字、单位、人员原样保留；
2. 要点之间重复的合并，前后矛盾的写「【待核实：哪处矛盾】」；
3. 成文需要、要点里又没有的具体事实（如完成时限、责任单位），写「【待核实：缺什么】」。
