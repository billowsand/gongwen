# 归纳维基框架

## 先分清

- 本作业只产出框架提案 JSON（主题 → 分类 → 依据文档），**不改框架、不写正文、不写数据库**，
  也不要在交付说明里声称框架已经建好。
- 只读：用 `kb_search` / `kb_read` 浏览资料库；只写 `work/` 下的文件，最后只交 `work/frame.json`。

## 步骤

1. 读 `input/request.md`，弄清本次归纳的范围要求与今天日期。若附有现有分类口径，按相关业务范围读取；能覆盖的资料优先归入原节点，沿用其名称与层级。
2. 用 `kb_search` 多轮检索资料库：先按业务领域宽查，摸清有哪些条线；再对每条线细查，
   `kb_read` 读关键文档全文。资料多时宁可多查几轮，不要凭一轮印象定框架。
3. 按 `references/frame-granularity.md` 的粒度口径归纳两级框架：主题（一级）→ 分类（二级），
   分类下不再分层。
4. 每个主题和分类都写 `guidance`（最多 600 字）。给出可判断的收录范围、排除条件和容易混淆时的归属规则。沿用已有节点时遵循用户确认的口径，为相关的空白节点拟定口径。
5. 每个分类填 `doc_ids`：只写本次 `kb_search` / `kb_read` 真实返回、且确实支撑该分类的
   文档编号；一篇文档可支撑多个分类。**每个分类至少挂靠一篇依据**，归不进任何分类的
   资料不要硬凑分类，更不要交「（待定）」之类的空壳分类。
6. 写 `work/frame.json`，用 `submit_task` 交付，交付说明里概括归纳思路。

## frame.json 格式

```json
{
  "themes": [
    {
      "name": "安全生产",
      "guidance": "收录生产经营单位安全监管、风险预防和事故应急。排除消防宣传等通用宣传资料。",
      "categories": [
        { "name": "监督检查", "guidance": "收录日常检查、隐患台账和整改复查；以事故处置为主的归入应急管理。", "doc_ids": [3, 7] },
        { "name": "应急管理", "guidance": "收录应急预案、演练和事故处置；日常隐患整改归入监督检查。", "doc_ids": [12] }
      ]
    }
  ]
}
```

## 红线

- 主题与分类的名称用资料里出现的业务术语，不编造资料里没有的条线。
- `doc_ids` 只写工具真实返回的编号，不凭记忆、不猜编号。
- 主题控制在 2–12 个，每个主题 1–8 个分类；资料覆盖不了的领域不要硬凑。
- 拿不准归属的分类放进最接近的主题；确实两条线都涉及的，按资料里主要的表述归一处。
