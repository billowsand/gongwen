# 风格档案的交付格式

风格文件是 UTF-8 JSON，对象只允许以下五个字段：

| 字段 | 内容 |
| --- | --- |
| name | 可辨认的写法名称，1–40字 |
| note | 一句话说明，至多500字，可省略 |
| occasions | 适用场合关键词数组，至多8项，每项1–60字，可省略 |
| description | 1–12000字的完整写法描述，可用换行组织 |
| example_numbers | 从程序候选范例中选择的编号，1开始，最多5项，不重复，可留空 |

`input/style-guide.json` 保存本轮程序统计及候选范例。候选列表第一个编号为1，第二个为2，以此类推。
只能选择该列表中实际存在的编号。范例原文由应用提取，不在JSON里重写原句。

`description` 应总结样稿中反复出现的写法倾向，并区分共性与个例。样稿未出现某种标题长度或开头，不代表今后禁止；不要据此编造固定字数、唯一开头或绝对禁令。新任务中的事实由新材料和用户要求决定，风格档案不能删改或补造日期、数量、人员、单位、事项与结论。

示例：

```json
{
  "name": "简洁部署式通知",
  "note": "目的清楚、安排具体、结尾简短",
  "occasions": ["部署", "对下通知"],
  "description": "总体基调：庄重直接。\n开头：先交代目的，迅速进入安排。\n主体：按工作环节分层，明确动作及牵头、配合关系。\n结尾：简短提出落实要求。",
  "example_numbers": []
}
```

不输出id、来源、样稿哈希、统计值、启用、默认文种等字段；这些由程序与用户维护。
写好`work/style.json`后必须调用`submit_style`，不能用聊天答复、`submit_document`或`finish_report`代替。
模型不会直接修改`styles.json`，只有用户在风格编辑器点保存后，档案才进入可供起草使用的风格库。
