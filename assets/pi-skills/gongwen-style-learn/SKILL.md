# 从样稿学习写法风格

1. 交付格式需要时读 `references/style-profile.md`。读取 `input/request.md` 的要求、程序统计和候选范例，再读材料索引与全部样稿。
   优先整篇理解，观察它们共有的表达习惯及差异，不把个别事项当成风格。
2. 概括总体基调、开头、主体组织、句段长短、常用表达、结尾、用词偏好与忌用、数字和时间的表达方式。
   只学写法，不把样稿里的具体单位、人名、日期、数字、事项或结论写进描述；必要时用“××”示意。
   原文范例由程序按编号取回，不能改造或伪造引文。
3. 输出 `work/style.json`，格式严格为：
   `{"name":"风格名称","note":"一句话说明","occasions":["适用场合"],"description":"完整写法描述","example_numbers":[1,2,3]}`。
   name 非空且不超过40字；note 不超过500字；场合不超过8项且每项不超过60字；description 非空且不超过12000字；
   example_numbers 从用户消息中的候选范例编号选，最多5项、不重复；没有合适范例可留空。
   不填写身份、文种、统计值、来源、启用或默认状态，这些由应用和用户管理。
4. 调用 `submit_style({path:"work/style.json",summary:"总结了哪些写法"})` 明确交付。
   不调用 submit_document 或 finish_report，不把聊天文字当成交付，不声称已保存风格库。

分阶段时只完成宿主指定的样稿分析并用 `record_progress` 登记；最后阶段才生成并提交完整风格文件。
程序会把结果送回设置页供用户编辑、保存。风格学习不改任何稿件正文，也不调用第二个辅助模型。
