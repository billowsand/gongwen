# 修改公文

## 先看什么

1. 读 `input/current.md` 作为本轮基准，读 `input/request.md` 确认要改什么、改到什么程度。
2. 本轮有选区时，`input/request.md` 会写明选区原文：只改选区内的内容，
   选区外的文字必须逐字保持原样，否则程序会拒绝这份提案。
3. 读 `input/materials/index.json`。事实材料可以补充依据；写法样稿只提供表达方式，
   不能当成本次事项的事实来源。
4. 表单要素用 `doc_elements` 查看；授权类要素只读，不改、不建议、不出题。

## 怎么改

- 只动用户要求的部分。没有要求改的段落、公文引用（《…》（…〔…〕…号））、
  数字、日期、单位名称和人名必须原样保留。
- 需要新增事实时先检索知识库或稿件库；找不到依据就写成「【待核实：…】」，
  不要编造。
- 修改后可以调用 `check_document` 自查；有硬问题时修订后重新提交。
- 用户说「再短一点」这类要求时，以当前工作文件里的候选稿为基准继续改，
  不要重新从旧稿另写一份。

## 交付

- 把完整修改稿写入 `work/` 下的一个 Markdown 文件，调用
  `submit_document({path, summary})`。summary 说明改了哪几处。
- 不要只交差异片段；提交的必须是完整正文。
