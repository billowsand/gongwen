# 整编维基页面

## 先分清

- 本作业只产出**页面提案 JSON**，不写维基库、不改公文正文、不写数据库；
  交付说明里不要声称页面已经建好。
- 只读：用 `kb_search` / `kb_read` 读资料库，用 `wiki_search` / `wiki_read` /
  `wiki_links` 查已有维基页（便于互相链接）；只写 `work/` 下的文件，
  最后只交 `work/pages.json`。

## 步骤

1. 读 `input/request.md`：本次要整编的分类、所属主题与今天日期。
   从资料库圈选发起的作业，request 里会给出优先资料编号（E 开头）——
   先用 `kb_read` 读这些，再按第 2 步补充检索。
2. 备料：用 `kb_search` 围绕该分类的业务词检索资料库，`kb_read` 读关键文档全文；
   资料与分类不贴切的不要硬用。
3. 看已有页面：`wiki_search` 查与分类相关的已有页，`wiki_links` 看出链候选——
   新页面要链向已有页，也在相关处预留指向新页的链接（见下）。
4. 拆题成页：一页一个主题（细则见 `references/page-rules.md`）。该分类还应有一篇
   导览页（`kind: "guide"`），综述全分类并链向本分类各页。
5. 逐页撰写正文并附依据清单，写 `work/pages.json`，用 `submit_task` 交付。

## pages.json 格式

```json
{
  "pages": [
    {
      "title": "监督检查",
      "category": "监督检查",
      "kind": "normal",
      "body": "# 监督检查\n\n……见 [[责任体系]]……",
      "doc_refs": [{ "doc_id": 3, "note": "闭环整改要求出自本文" }]
    }
  ]
}
```

- `category` 必须是 request.md 里给定的分类名；`kind` 只取 `normal` 或 `guide`。
- `body` 是公文助手 Markdown：标题用 `#` / `##`，列表用 `-`，**不手写章节编号**
  （「一、」「（一）」由导出程序生成）；正文里用 `[[页面名]]` 互链，
  `[[目标|显示文字]]` 可换显示。
- `doc_refs` 只填本次 `kb_search` / `kb_read` 真实读过、且支撑该页要点的文档；
  `note` 一句话说明支撑了什么。

## 红线

- 正文只写资料里有的内容；推断和概括要站得住，拿不准的写成「待核实」提示，
  不要编造数字、日期、单位与结论。
- 链接目标写成资料里确实存在的概念：已有页直接链（先用 wiki_search 查名字）；
  资料里有、维基还没有的概念写成 `[[待建页]]` 红链，不要为它现编内容。
- 一次交付的页面数量控制在 10 页以内，单页正文一般不超过 5000 字。
