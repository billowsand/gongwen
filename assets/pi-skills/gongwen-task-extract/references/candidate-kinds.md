# 候选类型与摘录规则

## 候选类型

| kind | 什么时候用 | 必须带的字段 |
| --- | --- | --- |
| `new_task` | 原文讲了一项工作，已有任务里没有对应项 | `name`（不超过 30 字）、`progress`（原文已完成的情况） |
| `progress` | 已有任务的当前进展 | `task_id`、`progress` |
| `decision` | 拟议、建议、等待批准的事项 | `note`（原意）；**不得**写成正式字段调整 |
| `opinion` | 某人对某项工作的意见 | `speaker`（提出主体）、`about`（针对的任务或事项）、`note`（原意） |
| `owner` | 负责人或牵头人 | `owner`（**只写原文出现的人名**） |
| `deadline` | 原文给出的期限或完成时间 | `deadline`（`YYYY-MM-DD`） |
| `risk` | 风险问题及应对措施 | `risks` |
| `scope` | 责任范围或工作边界（多为旧材料说法） | `name` 或 `note` |
| `completion_evidence` | 原文称某项工作已完成、已验收 | `note` 或 `progress`；程序不会自动闭合任务 |

- 一段话讲几项相对独立的工作可以拆成几条；同一项工作的多个成果合成一条。
- 材料与任何工作事项都无关（停水停电、放假安排之类）时输出空 `items`，不硬凑。
- 原文没有的字段一律 `null`，不补「待开始」「尽快」「按计划推进」这类原文没有的说法。
- 不虚构人员、日期、数字、结论；原文前后矛盾的，两条都留下并如实摘录，不替原文选一个。

## 摘录（evidence）

- 必须是原文里**连续的一段**，能支持这一条候选；不拼接两句、不改写、不编造。
- 程序逐字核对，只忽略空白与全半角标点差异；对不上就丢弃这条候选。
- 摘录不要超过 500 字；长段落只摘支持这条候选的那一句或几句。

## 日期（deadline）

- 只写原文能推出的 `YYYY-MM-DD`。
- 只写月日、能按今天推出最近的将来日期时，可以补年份。
- 「下周」「月底」「尽快」或原文没给日期，一律 `null`。
