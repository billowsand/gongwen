# 事实核对

用户说「核一下文中的数字和文件依据」「这些日期对不对」时按这里做。**只出清单，不改稿。**

## 核什么

- 正文里的时间、日期、期限：年月日是否写反、是否与材料一致、是否已经过期。
- 数字：金额、比例、数量、序号；同一件事在文内多处出现时是否一致。
- 文件依据：书名号里的文件名称、文号（年份要用六角括号〔〕）、引文。
- 单位、人员：是否与材料、标准词库的规范名称一致。

## 怎么核

1. 同一处只核最长的那个事实，避免把「2026年11月8日」拆成三个问题。
2. `input/current.md` 是待核对象，也可用于比较修改前后是否一致，不能证明自身事实真实。
   先查 `input/materials/` 中标为事实或来函的材料、用户实际回答；写法样稿与风格范例不是事实出处。
   材料有对应记载时注明材料标题，只能说「与材料一致」，不能据此扩大为已独立核实。
3. 材料里没有的，用 `kb_search` / `kb_read`、`ms_search` / `ms_read` 找原文；
   证据原文里字面撞上就算有出处，说法不同要说明差别。
4. 找不到出处的，写「未找到出处」，**不要**写成「已核实」。找不到不等于错，也不等于对。

## 结论怎么写

每条写：位置（原文片段）、核的是什么、结论（有出处 / 与资料矛盾 / 未找到出处）、
依据（文档标题或材料标题）、建议怎么处理（改为原文说法 / 补依据 / 删去 / 保留待核）。

## 交付

只核对时用 `finish_report` 交清单，不提交正文，也不在清单里顺便重写全文。
用户同时要求按核对结果改稿时，在工作区内部核对，再按修改技能改稿，最终只用
`submit_document` 交完整正文；不要先调用会结束本轮的 `finish_report`。
