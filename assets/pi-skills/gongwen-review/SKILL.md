# 审核公文

## 按需读什么

1. 读 `input/current.md` 与 `input/request.md`，确认审核范围（全文还是选区）。
2. 读 `skills/gongwen-markdown/` 里当前文种的规则，作为结构与格式的判据。
3. 用户要核时间、数字、文件依据有没有出处时，读 `references/fact-check.md`。
4. 表单要素用 `doc_elements` 看；授权类要素只读，可以指出与程序表单不一致，
   但不能建议或改写它们的值。

## 怎么审

- 按顺序看：文种与结构、标题层级、序号层级、附件说明、公文引用、关键事实与日期、
  称谓与用字、语气与篇幅。
- 每条问题写清位置、问题、依据、建议改法；没有依据的猜测不要列。
- 词表、文档规则与程序闸门的结论优先于你的主观判断：先跑
  `check_document({path:"input/current.md"})`，再补充它查不出的表述与逻辑问题。
- 找不到出处的数字和日期标成「需核对」，不要替用户改成你猜的值。

## 交付

- 只审不改：调用 `finish_report({summary, items:[{title, detail, severity}]})`，
  结果只进侧栏，**不生成新正文**，也不要为了显得完整而重写一篇。
- 用户明确要求「直接改」「改完给我」：按修改技能写出完整修改稿并 `submit_document`；
  summary 说明修了哪些问题。
- 只做事实核对、政策依据核对时只出清单；用户同时要求核对并改稿时，内部完成核对再走修改，
  最终只提交完整正文，不先调用 `finish_report`。
