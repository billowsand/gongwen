# 起草公文

## 按需读什么

1. 先读 `input/current.md`、`input/request.md`，再读 `input/materials/index.json`，
   分清每条材料是**事实材料**、**来函**、**写法样稿**还是**结构范文**。
2. 读 `skills/gongwen-markdown/SKILL.md` 里当前文种的正文规则、标题层级和附件写法；
   需要时再读 `references/` 下的语法与文种文件。不要一次把所有语法文件读完。
3. 本轮有事实材料或来函（尤其是多份材料）时，先读
   `references/material-drafting.md`，按那里的判据成文。
4. 宿主说「分阶段」时，先读 `references/phased-writing.md`：每一步只做宿主指定的那一小步，
   写完用 `record_progress` 登记；中间阶段不要提交半稿。
4. 要求按本单位写法写时，用 `style_list` 看当前文种可用的风格档案，再按 id
   用 `style_read` 取回。风格档案与范例是**写法样稿**，不是本次事项的事实来源。
5. 表单里已经填好的要素用 `doc_elements` 看：已填的描述类值可以直接用，空着的
   描述类要素不要编；授权类要素（密级与保密期限、文号、份号、签发人、成文日期、
   版记印发机关与印发日期）只读，不能写、不能建议、也不能出题。

## 怎么起草

- 事项内容忠实于材料；单位规范名与职能分工可以参考本轮标准组织背景，涉及时间以当前日期为基准理解。缺事实就写「【待核实：…】」，缺什么写清楚，不要用猜测填空。
- 材料之间前后矛盾时，把两处原话都写进「【待核实：哪处矛盾】」，不要悄悄选一个。
  有冲突的时限或数值，不要在其余正文里先选一个作为确定要求，再仅用一句「以哪份为准」提示。
  冲突位置只写含两处具体原文及来源的占位，未冲突的事项可继续成文；交付说明不能代替正文保留冲突信息。
- 需要补充政策依据、历史做法时先走维基：`wiki_search` 找已整编的知识页，`wiki_read` 读全文，
  按其依据清单用 `wiki_doc_read` 溯源原文；`wiki_links` 只给出链候选、由你判断要不要下钻，
  不是必读清单。维基没有命中再回落 `kb_search` / `kb_read`、`ms_search` / `ms_read`；
  工具返回的证据编号只用于自查，**不要写进正文**。
- 需要查内网数据（统计口径、政策库、业务系统数据）时，先用 `api_search` 搜只读接口，
  再用 `api_call` 调用；参数按返回的参数签名填，接口报参数错就照错误改。
  接口返回是**资料**，不是结论；没有匹配接口就明说没查到，不要猜数据。
- 用户把某份 `@` 文章当事实材料时可以当依据；当写法样稿时只学结构、语气和句式，
  不能把样稿里的单位、人员、日期、数字、结论搬进正文。
- 按技能文件规定的标题层级、序号层级、附件说明和表格语法写 Markdown；
  不要用代码块或引用块模拟版式。
- 主送单位只出现在表单与要求里，正文**不要再写一遍主送行**。章节序号由公文语法与
  导出程序生成，正文标题不要手写「一、」「（一）」「1.」这类编号。
- 用户给了字数上限就是硬约束；写完先数一遍，超了就删到限内再交，不要交完再说。
- 材料多时可以拆提纲、分节稿再合并；中间文件都放 `work/`。

## 问什么，不问什么

- 只有**会让整篇方向写错**的事才用 `ask_user`：行文方向（上行 / 平行 / 下行）、受文对象、
  写作目的、篇幅，或者当前文种明显不合适。要求里已经写明或能直接推断的不要问。
- 不要先交一份「要点清单 / 大纲 / 事实勾选」让用户确认再动笔；用户要改，会在拿到成稿后说。
- 具体的时间、地点、人员、联系方式能写成「【待核实：…】」就不问；授权类要素不出题。

## 交付

- 生成或修改正文：把完整 Markdown 写入 `work/` 下的一个文件，调用
  `submit_document({path, summary})`。summary 一句话说明依据了哪些材料。
- 只查资料、只回答「能不能这样写」而不产生正文：调用 `finish_report`，不要交半成品。
- 提交前用 `check_document({path:"work/文件名.md"})` 自查：优先传文件路径，
  不要把整篇正文再输出一遍到 `text` 参数。只检查格式、文字规则与引用保护，不执行事实核查，不生成审校清单。
- 提交之后不要再改这个文件，也不要把正文贴在聊天里充当交付。

## 日期与组织背景

- 每轮以程序给出的当前日期、星期和时区为基准理解相对时间；跨日或不确定时调用 `current_date`。
  材料中的明确日期和已约定期限不自动改动；成文日期等表单授权要素仍由用户填写。
  当前日期只帮助解释相对时间，不是事项发生日期。没有材料或用户依据时，不得把今天写成会议、决定、启动、发布等事项的日期。
- 涉及单位、人员或责任分工时先用本轮组织背景，再按需 `vocab_search`：可按名称、职能、简介检索，
  按 `unit` 查所属人员/下属单位。结合职能任务和组织关系安排牵头与配合，不凭名称猜职责。
  人员优先查标准词库，同名按所属单位区分；未命中保留用户材料中的明确人名。
- 优先完整理解材料，容量不足时按大章节处理，保留全稿目的和结构。
- 本技能不做额外 AI 全面审校或事实核查。程序检查只负责格式、文字规则及技术和权限保护。
