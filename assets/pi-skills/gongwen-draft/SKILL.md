# 起草公文

## 先看什么

1. 读 `input/current.md`、`input/request.md`，再读 `input/materials/index.json`，
   分清每条材料是**事实材料**还是**写法样稿 / 结构范文 / 来函**。
2. 读 `skills/gongwen-markdown/SKILL.md` 中当前文种的正文规则、标题层级和附件写法；
   需要时再读 `references/` 下的语法与文种文件。
3. 用户把某份 `@` 文章当事实材料时，可以把它当成本次事项的依据；当写法样稿时，
   只学它的结构、语气和句式，**不能把样稿里的单位、人员、日期、数字、结论搬进正文**。
4. 表单里已经填好的要素（`doc_elements` 工具）可以直接用；空着的描述类要素不要编，
   授权类要素（密级、文号、份号、签发人、成文日期、版记印发机关与印发日期）
   只读，不能写、不能建议、也不能出题。

## 怎么写

- 只写材料里有依据的内容。缺事实就写「【待核实：…】」，不要用猜测填空。
- 按技能文件规定的标题层级、序号层级、附件说明和表格语法写 Markdown；
  不要用代码块或引用块模拟版式。
- 材料多时可以拆提纲、分节稿再合并；中间文件都放在 `work/`。
- 需要知识库、稿件库、词库或确定性检查时，调用对应工具；工具结果里的编号
  可以用于自查，但不要把工具编号写进正文。

## 交付

- 完成后把最终全文放在一个 `work/` 下的 Markdown 文件里，调用
  `submit_document({path, summary})`。summary 一句话说明依据了哪些材料。
- 不要提交半成品，也不要把正文贴在聊天里充当交付。提交之后不要再改这个文件。
