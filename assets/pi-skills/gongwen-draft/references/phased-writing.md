# 分阶段写作（公共参考）

本轮如果宿主说「分阶段」，说明按本次实际窗口和工作预算，一次写完一份长稿风险太高。
阶段由程序安排，不需要你规划流程；你只要把当前这一步做扎实。

## 每一步只做一件事

| 宿主这一步 | 你要做的 | 写完登记 |
| --- | --- | --- |
| 提炼材料 | 只读指定的一块材料，抄下与要求有关的事实（数字、日期、单位、责任、期限照原文），风格 / 结构材料只写写法要点 | `record_progress`：`phase:"distill"`、提示里的单元编号、`work/notes/…` 文件、至少一条能在原文定位的 `sources` |
| 写提纲 | 读已登记的摘记，写 `work/outline.md`，用 Markdown 标题表达章节 | `phase:"outline"`、`work/outline.md`、`uses` 列全部材料单元、`sections` 列章节标题 |
| 写第 n 节 | 读提纲与摘记，只写本节到 `work/sections/nn.md` | `phase:"sections"`、提示里的 `section:n`、`uses:["outline", …材料单元]` |
| 合稿检查 | 读各节稿，合成 `work/final.md`，自查重复、矛盾、遗漏 | `phase:"review"`、`unit:"final"`、`uses` 含 `outline` 与全部 `section:n` |
| 交付 | 读完整 `work/final.md`，确认是成品 | 调用 `submit_document`（正文）或 `finish_report`（只交清单） |

## 硬规则

- 中间阶段**不要**调用 `submit_document` / `finish_report`。宿主会拒绝提前提交，半稿不能算成品。
- 宿主只认文件真实存在、哈希对得上、引文能在原文里找到的登记。说「已经全部读完」没有用：
  没登记的单元就是没做。
- 只登记提示里列出的单元编号，不要自己发明编号、不要跳步、不要把多步合成一次。
- 读长文件用 `read` 的 `offset` / `limit` 分页，按返回里的「未读」范围继续；不要把一页当全文。
- 摘要与摘记不是新的事实来源。回写正文时以原文和已登记摘记为准；样稿里的单位、人员、
  日期、数字与结论不能搬进正文。
- 前面步骤已经登记的成果不要重写。重新登记同一单元会替换旧版本，依赖它的章节与合稿会
  失效并被要求重做，白白多跑几步。

## 与本机小模型打交道的经验

- 每次只回答一步，不要在同一轮里顺手把后面几步也做掉。
- 主送单位在表单与要求里已经有了，正文里**不要再写一遍**主送行；这是模型最容易重复的地方。
- 章节序号（一、／（一）／1.）由公文语法与导出程序生成，正文标题不要手写编号。
- 用户给了字数上限（如「不超过 80 字」）就是硬约束；写完数一遍，超了就删到限内再登记。
