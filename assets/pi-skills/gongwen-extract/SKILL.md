# 要点提炼

## 先分清

- **提炼要点 / 列清单 / 做摘要**：结果是一份清单或一段摘要，**不改正文**。
- 用户既要提炼又要改稿时，在工作区内部提炼，再按修改技能改稿，最终只提交一份完整正文。
  不要先调用 `finish_report`；两种终结工具互斥，交清单后不能在同一轮再提交正文。

## 怎么提炼

1. 先读 `input/current.md` 与 `input/request.md`。有选区时**只提炼选区**，
   没有选区才提炼全文。
2. 需要拿准取舍时读 `references/extraction-checklist.md`。
3. 用户给了条数（「五条以内」「三条」）就按条数；没给时按内容定，
   一般不超过 10 条，同类合并。
4. 每条一句话，说清「做了什么 / 要求什么 / 什么时候」，保留原文里的时间、数字、
   单位、人员与文件名，不改口径。
5. 按原文顺序列，不重排因果，不加评论、不加评价、不写「重要意义」这类总结词。
6. 原文有矛盾的，两条都留下并注明「原文前后不一致」；不要替原文选一个。
7. 摘要类要求（「用 200 字概括」）按字数写，只写原文有的内容。

## 交付

- 仅提炼、不改稿时，用 `finish_report({summary, items:[{title, detail, severity}]})` 交清单，
  `items` 一条一个要点；摘要类把摘要放在 `summary`，或作为一条 `detail` 较长的条目。
- 仅提炼时**不要**调用 `submit_document`，不要交改写后的正文，也不要在清单里顺手润色原文。
- 明确要求提炼并改稿时，按修改技能检查成稿，再调用 `submit_document`；不调用 `finish_report`。
- 用户看完清单要求改稿，再按修改技能走。

## 分阶段时

本轮若分阶段，先按宿主提示逐块提炼材料并用 `record_progress` 登记；最后一步用 `finish_report` 交清单，不要提交正文。不要声称已读完全部材料，以宿主核对的登记覆盖为准。
