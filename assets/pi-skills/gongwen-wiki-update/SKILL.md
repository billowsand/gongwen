# 维基页面更新（gongwen-wiki-update）

用户指定一篇或多篇已有维基页面发起：按资料库里的内容（尤其是新入库、
上次整编后变化的文档）更新这些页面，交回整页新正文提案。**只交提案**：
写库由用户在审核台点「采纳」后程序完成（采纳产生一个新版本，历史全量保留）。

## 工作循环

1. 用户请求里给出目标页（标题 + 正文以材料形式附上），读 `references/update-rules.md` 的规则。
2. 用 `kb_search` / `kb_read` 找与这些页面主题相关的文档，重点看上次整编
   之后新入库或内容变化的文档；维基内现状用 `wiki_search` / `wiki_read` /
   `wiki_links` 自查（互链是否新增可链的页面）。
3. 逐页改写：保持页面主题与写法不变，把新资料里的口径、数据、表述并进来；
   正文写法与普通公文一致，页间引用用 `[[页面名]]`（同整编规则）。
4. 每页附 `change_note`（一两句话说清这版改了什么、依据哪些文档）与
   `doc_refs`（依据清单：doc_id + 支撑要点）。
5. 用 `submit_task` 交 `work/pages.json`（形状见下）。

## 交付形状（work/pages.json）

```json
{
  "pages": [
    {
      "uuid": "目标页 UUID（用户请求里给出，原样带回）",
      "title": "目标页原标题（一字不改；更新不改名）",
      "body": "整页新正文（完整替换，不是片段）",
      "change_note": "这版改了什么、依据哪些新资料",
      "doc_refs": [{ "doc_id": 12, "note": "支撑要点" }]
    }
  ]
}
```

## 红线

- **更新不建页、不改名、不改页面类型**（normal / guide 保持原样）；
  缺的内容写成 `[[待建页]]` 红链，由缺口清单将来整编。
- 正文**必须真的有变化**：与现有正文逐字相同会被复核退回。
- 依据文档必须真实存在（`kb_search` 查得到的 doc_id）；
- 每页至多 20000 字，一次作业最多交 5 页更新。
- 不要写文件、不要调数据接口；只读资料库与维基，只交 `submit_task` 回执。
