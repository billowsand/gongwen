# 政策依据核对

## 先认引用

读 `input/current.md`，找出正文里引用的政策文件。判据：

- 书名号里、以「法」「条例」「规定」「办法」「意见」「通知」「方案」「决定」「细则」
  等结尾的名称；
- 带文号的表述：机关代字 +〔年份〕+ 序号 + 号；
- 引号里的话如果标注了出自某份文件，也一并核。

一份文件多处出现时合成一条核对，不要重复列。拿不准名称、文号、引文怎么比时，
读 `references/citation-check.md`。

## 怎么核

1. 用文件名称到知识库找原文：`kb_search` 按标题检索，`kb_read` 读全文。
   稿件库里的旧稿只能参考，**不能当政策原文**。
2. 比对三件事：
   - **名称**：与原文标题逐字比（「××市森林防火若干规定」不能写成「××市森林防火规定」）；
   - **文号**：机关代字、年份（六角括号〔〕）、序号是否一致；
   - **引文**：引号里的话是否在原文里找得到；找不到就说明"原文最接近的表述是什么"，
     由用户判断，你不替他改。
3. **知识库里没有原文时**，结论写「未找到原文，需人工核对」，并写清你检索了什么词。
   **不可以**写成「已核实」「经核对无误」，也不可以凭印象或旧稿说原文是什么。
4. 名称与文号有明确改法（与原文逐字对得上）的，在清单里给出改法；
   表述不一致、但拿不准的只提示，不改。

## 交付

- 用 `finish_report` 交清单，每条写：引用位置（原文片段）、核的文件、结论
  （一致 / 名称差字 / 文号不符 / 引文与原文不一致 / 未找到原文）、依据、建议。
- **只核对时不改稿**：不要在清单里附一份重写后的正文，也不要调用 `submit_document`。
- 用户同时要求按核对结果改稿时，内部核对后按修改技能改稿，最终只用 `submit_document`
  交完整正文，不先调用 `finish_report`。
- 本稿表单的授权类要素（本稿文号、成文日期等）只读，只指出不一致、不建议新值；
  正文引用的外部政策文号可依据政策原文在清单里给出更正建议与出处。

## 分阶段时

本轮若分阶段，先按宿主提示逐块提炼材料并用 `record_progress` 登记；最后一步用 `finish_report` 交清单，不要提交正文。不要声称已读完全部材料，以宿主核对的登记覆盖为准。
