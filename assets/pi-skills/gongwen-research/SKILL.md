# 写研究报告

## 按需读什么

1. 读 `input/request.md` 确定研究问题、范围、篇幅与交付形态。
2. 读 `skills/gongwen-markdown/references/research-report.md`，按研究报告的
   题名、摘要、章节、图表、公式、交叉引用与文献规则写 Markdown。
3. 读 `references/argumentation-and-sources.md`，按那里的论证与出处判据组织全文。
4. 先检索：用 `kb_search` / `ms_search` 找本机知识库与稿件库里的材料；
   `kb_read` / `ms_read` 读全文。证据编号用于内部追溯，正文用资料标题与章节说明出处。
5. 需要按本单位写法写时，用 `style_list` / `style_read` 取回风格；风格是写法，不是资料。

## 怎么写

- 先列提纲，再逐节写，最后整合；中间文件放 `work/`。
- 起草前在工作区留一份简短的出处笔记：关键判断、来源完整标题、对应原文。
  没有对应原文的本地现状判断不写成结论；资料未记载的问题放「待调查事项」，
  用「是否……尚需调查」表达，不先断言问题存在，再靠文末局限性说明撤回。
- **每个关键判断都要有出处。** 引用只使用工具实际返回过的资料和用户提供的文献库，
  不要自己编文献名、作者、年份、卷期、页码或链接；找不到出处的表述宁可不写。
- 写现状和问题前，区分「资料明确记载」「基于资料的推断」「尚无资料」。资料少时可以写短，
  明说资料不足与调研边界，不能为了凑齐问题章节或篇幅写出本市已经存在的通病。
  例如只有监控点数量和发现时间的数据，不能据此断言本市已有数据孤岛、基层人才不足、
  经费紧张或落后于先进地区。此类只能标为待调查问题或条件性风险，不能在摘要和结论中当成事实。
- 事实材料里的数字、日期、单位名称照原文使用；推算得到的数字要写明算法，
  不要伪装成原文数据。
- 图表用技能文件规定的 Markdown 表格或 Mermaid；公式用 `$…$` / `$$…$$`。
- 工具返回的证据编号只用于自查；正文引用按应用支持的语法写（见参考文件）。

## 交付

- 完整报告写入 `work/` 下的一个 Markdown 文件，调用
  `submit_document({path, summary})`。summary 说明研究问题与主要依据。
- 只做资料调研、不写正文时，用 `finish_report` 交一份资料清单到侧栏。
- 提交前用 `check_document({path:"work/文件名.md"})` 自查，优先传路径。
