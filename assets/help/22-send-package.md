## 送批材料是什么

一份呈批件送领导审批，后面往往跟着几份**独立的件**：要发的函稿、相关的普通公文、支撑用的研究报告。「送批材料」就是给呈批件挂上这些随行件，在一个面板里看清各件用的是哪一版，最后**一键合并成一个 PDF** 打印装订。某一件改了，不用重新整理，重新导出即可。

| 概念 | 说明 |
|---|---|
| 主件 | 白头件或红头呈批件本身，合并时排第一 |
| 随行件 | 稿件库里的其他稿件，任意文种都行 |
| 正文附件 | 呈批件正文里 `<!-- [附件] -->` 标出的附件，是主件的一部分，**不是**随行件 |

随行件不加「附件N」标识、不在呈批件正文里列名，版式与它单独导出时完全一样。

> **提示** 同一篇稿件可以同时挂在几件呈批件下，比如一份研究报告支撑两件请示。送批材料只有一层：挂着随行件的稿件不能再被当作随行件，反之亦然。

## 打开面板

两个入口：

| 入口 | 位置 |
|---|---|
| 起草页 | 「开始」分区第一组，「提交版本」旁的「送批材料」，**只在白头件、红头呈批件下出现** |
| 稿件管理 | 呈批件的资料卡里「送批材料 → 管理…」 |

稿件还没存进稿件库时按钮是灰的：先「保存」，再挂送批材料。

## 添加、排序与移出

- 「添加稿件…」展开候选区，按标题、文号、备注搜索，可按文种筛选；
- 不能加的稿件置灰，鼠标停上去看原因（已在清单里、挂着自己的送批材料等）；
- 鼠标移到某一行上，右侧才显示：打开、移出清单；
- 两件及以上随行件时，按住行左侧的拖动手柄调整顺序，松手后自动保存；拖到列表上下边缘可自动滚动，按 `Esc` 或在列表外松手取消。已归档清单不能排序；
- **移出清单不删除稿件本身**。
- 排序后可点「撤销排序」恢复上一次顺序；清单发生其他变化后，这个撤销入口会消失。

主件固定在第一行，不能移动。

## 各件的状态怎么看

每行第一行是序号和**标题**，下面一行小字是文种、状态和**最新提交版**（版本号、名称、时间、说明）。需要处理的情况用一枚徽标标出来：

| 徽标 | 意思 |
|---|---|
| 有未提交修改 | 起草页或稿件库里有没提交的改动，这些改动**不会进包**；点旁边的「提交新版本」 |
| 未提交 · 不能进包 | 从未提交过版本；点旁边的「提交版本」 |
| 有待处理同步分支 | 离线同步时暂存了对方的版本，导出用本机这一支 |
| 导出后有新版本 | 点「对照 vM → vN」看这期间改了什么（花脸稿） |
| 本机未找到该稿件 | 清单里有、本机没有（多见于同步包只带了清单），导入该稿件后自动恢复 |

清单上方有一行汇总，如「共 3 件 · 2 件待提交」；有件不能进包时「导出合并 PDF…」置灰。

### 在这里直接提交版本

不用打开稿件：点「提交版本」，卡片里展开一行表单，版本名预填「初稿」（首次）或「修订稿」（之后），备注可选，回车即提交。稿件已在某个标签里打开时，提交的是编辑器里的当前内容（含未保存的修改）；没打开则提交稿件库里存的内容。有两件以上待提交时，底部还有「全部提交」，各提交一版。已归档的送批材料只读，不提供提交。

面板每隔几秒自动刷新，别的标签里提交了版本，这里跟着变。

> **注意** 进包的永远是**提交版本**，不是正在编辑的内容。改完要送的稿子，先提交版本。

## 导出合并 PDF

点面板底部「导出合并 PDF…」：

1. 先出一张**确认清单**：每件用哪一版、有什么要注意、哪件不能进包；
2. 可勾选「前面加一页送批材料目录」；
3. 处理完不能进包的件后点「重新检查」，确认无误点「选择位置并导出」；
4. 后台逐件排版，面板底部显示进度；
5. 成功后在应用内的 PDF 标签打开成品，那里可以直接**打印**、用系统程序打开或定位文件。

| 规则 | 说明 |
|---|---|
| 顺序 | 目录页（可选）→ 主件 → 随行件按清单顺序 |
| 每件从奇数页开始 | 页数为奇数的件后面自动补一张同尺寸空白页，双面打印后各件能拆开分别装订；最后一件不补 |
| 页码 | 各件保持自己原来的页码，不连续编 |
| 目录页 | 一张「序号 / 名称 / 文种 / 密级 / 版本 / 页数」表（密级列写各件自己的「密级★保密期限」，无密级为「—」），页眉密级沿用主件 |
| 整体成败 | 任何一件排版失败，整个导出失败，**不生成半成品、不覆盖已有同名文件**，原因显示在面板里 |
| 版本冻结 | 点「选择位置并导出」时各件的版本就定了，排版途中别人再提交也不会混进来 |

> **提示** 合并导出与单篇导出一样在程序里直接排版。研究报告自带的目录超链接和 PDF 书签在合并后的文件里不可点，打印不受影响。盖章扫描件不参与合并。

## 导出记录

每导出一次记一条：时间、总页数、是否含目录、文件位置，以及当时**每一件用的版本**。面板底部「导出记录」里展开查看，文件还在就能直接打开。

「上次导出后有新版本」的提示和归档时的钉版，都以最近一次导出记录为准。

## 归档：钉住送出去的那一套

呈批件归档时，送批材料里的各件（连同主件自己）会**固定在某一版**，以后再导出都用这一套，随行件后来怎么改都不影响：

| 情况 | 钉在哪一版 |
|---|---|
| 默认 | 最近一次导出时用的版本，也就是实际送出去的那一套 |
| 从没导出过、或导出后才加入的件 | 归档时的最新提交版 |
| 送出之后有件又提交了新版本 | 归档确认框里二选一：「送出时的版本」或「当前最新版本」 |

有件既没导出过、也没有提交版本时，不能归档：先提交版本或把它移出清单。

归档后面板只读，每行显示「钉住 vN」。

## 删除保护

- 删除一篇被呈批件用作送批材料的稿件，确认气泡会列出是哪几件呈批件，删除后从它们的清单里移除；
- 被**已归档**呈批件用作送批材料的稿件**不能删除**，免得归档材料缺件；批量删除时这类稿件像归档稿一样跳过。

## 换机器：随同步 ZIP 带走

导出稿件 ZIP 时，密码框里「连同呈批件的送批材料一起导出」默认勾选：只勾呈批件，它的随行件也会进包。不勾时只带清单。

导入时：

| 处理方式 | 送批材料清单 |
|---|---|
| 作为新稿导入 | 原样带过来；归档的呈批件连同钉版一起带 |
| 另存副本 | 带清单，不带钉版 |
| 采用导入版 / 生成合并版本 | 两边清单不同时多一个勾选「送批材料清单也采用导入版」 |
| 跳过、暂存分支、本机已归档 | 不动本机清单 |

> **注意** 增删随行件不会产生新版本，程序分不出两边的清单哪个新。所以默认只在「导入版较新」或「本机清单为空」时采用导入的清单；其他情况看清楚本机与导入各几件，再决定勾不勾。

旧版程序导出的稿件包不带清单，导入时不动本机清单。
