## 标准词库是什么

「标准词库」是**单位与人员的唯一权威来源**。一次维护，多处一致：

| 谁在用 | 用它干什么 |
|---|---|
| 要素表单 | 候选项、自动补全 |
| 校对词表 | 检查称谓写法、抓错别名 |
| AI 事实闸门 | 抽取与比对单位/人员全称 |
| 公文词表 | 合并写法，收进输入法词库 |
| 导出 | 落款、主送、抄送、承办的规范写法 |

写错单位名、人名前后不一致，根子都在这里。把它维护好，别的地方自动对。

## 单位树

单位是**树形**的，带层级编码：

| 字段 | 说明 | 例 |
|---|---|---|
| 全称 | 正式全称 | 市财政局 |
| 对外名称 | 对外行文用名 | 市财政局 |
| 简称 | 内部简称 | 财政局 |
| 别名 | 历史名、俗称 | 财政口 |
| 发函代字 | 公函文号前缀 | 财函 |
| 呈批代字 | 红头呈批件文号前缀 | 财呈 |
| 层级编码 | 树形排序 | 0102 |
| 排序 | 同级顺序 | 2 |
| 上级 | 父节点 | 市政府 |

树形的好处：

- 主送「市政府」时，候选自动按层级排；
- 简称与别名进了校对词表，写错能抓；
- 发函代字与呈批代字分别进入对应文种的文号候选；下级单位未填写时沿上级单位继承。旧配置中的单个机关代字保留为发函代字，呈批代字需单独补充。

## 人员

人员挂在**承办单位**下：

| 字段 | 说明 |
|---|---|
| 姓名 | 全名 |
| 电话 | 联系电话 |
| 所属承办单位 | 哪个部门的人 |

要素表单选联系人时按承办单位筛人，电话跟着人走。换人只改这一处，所有稿子的联系人候选跟着走。

> **提示** 联合承办的联系人是**单位 ↔ 人 ↔ 电话成对**的，配对错了导出会串。要素表单里的联合承办编辑器就是按对编辑。

## Excel 导入导出

三个按钮：

| 按钮 | 用途 |
|---|---|
| 下载空白模板 | 拿到 `.xlsx` 空白模板（只有表头 + 数据验证） |
| 导入 Excel | 按**层级编码/姓名优先**合并 |
| 导出 Excel | 备份当前词库 |

合并策略：

- **按编码优先**：层级编码/姓名相同的条目，Excel 里的更新本机的；
- **不覆盖**：本机有而 Excel 没有的条目**保留**，不删；
- **增量合并**：新条目加进来，不推倒重建。

所以导入是**安全**的：误导入不会清空词库，最多是更新了几条。真要清空得在页面上点「清空整库」并二次确认。

导入冲突（同编码不同内容）会列出来让你逐条定，不会闷头覆盖。

## 首次建库引导

第一次用「标准词库」页会进入**建库引导**：先帮你完成一个**可工作的最小词库**（一个顶级单位 + 一个联系人），再进完整编辑器。

不要求一次填全。先录最常用的三五个单位和两三个联系人，够出稿就行；后面边用边补。

## 全称与简称的用法

| 场合 | 用什么 |
|---|---|
| 红头发文单位 | 全称 |
| 主送 / 抄送 | 全称（正式行文） |
| 落款 | 看「落款用简称」开关 |
| 正文内提及 | 首次全称、后文可用简称（自己掌握） |
| 校对 | 全称/简称/别名都算合法写法，错字才拦 |

要素表单有「落款用简称」开关：开了落款处用简称，关了用全称。正式公文一般用全称。

## 与校对词表的关系

标准词库里的简称、别名会**自动进校对词表**的合法写法集合——写对了不拦。

反过来，校对词表里的「错误写法」会进公文词表的黑名单，既不入库也不导出。两套词表是**互相喂养**的，但职责分开：

- **标准词库**管「正确写法有哪些」；
- **校对词表**管「哪些写法是错的、哪种对」。

## 与公文词表的关系

公文词表扫描稿件收词时，会**合并**标准词库里的单位全称、对外名称、简称、别名与两类代字，并自动置为**已接受**——这些都是你亲手维护的，不用再确认一遍。

见 [公文词表与输入法](chapter:17-lexicon)。

## 备份建议

- 定期「导出 Excel」存一份，放网盘或版本库；
- 稿件 ZIP 导出时会**随附完整标准词库**（`vocabulary.json`），换机器时自动合并；
- 配置文件里也有词库（`config.json`），备份配置即备份词库。

迁移细节见 [数据、备份与迁移](chapter:21-data)。
