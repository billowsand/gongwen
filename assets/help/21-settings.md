## 设置全解 {#chap:settings}

### 十三个分区

「设置」页左栏十三项，按「配什么」分成五摞：

| 组 | 分区 |
| --- | --- |
| 外观 | 界面主题、字体、输入法 |
| 公文排版 | 标题与列表编号、加密传输单 |
| 安全 | 应用锁、密级规则 |
| 文件与现场 | 输出与录入、导出格式、保存与现场、数据备份 |
| 网络与帮助 | 网络代理、上手指引 |

主题、界面缩放、纸面、图表样式与字体改完**立即生效**；其余各项要**保存**后才写入配置文件。

> [!提示]
>
> 模型服务、文字复核、知识库检索、技能、数据接口、风格都搬到了 **AI 管理**页（见第{@chap:ai-polish}章「AI 管理：模型、技能与风格」）。设置页左栏顶上留了一条「AI 设置在『AI 管理』」，点一下直达。网络代理是全局的，起草、复核、知识库、数据接口都走它，所以留在这里。

### 网络代理

起草、文字复核、知识库的 embedding / rerank 请求，以及技能调用的数据接口，都走这里设的通道。

| 连接方式 | 说明 |
| --- | --- |
| 直连 | 不走任何代理，环境变量里设的也不认 |
| 跟随系统 | **默认**。先看 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` 环境变量，没设再读 Windows「设置 → 网络和 Internet → 代理」里的手动代理；不支持 PAC 脚本 |
| 自定义代理 | 填代理地址，如 `http://127.0.0.1:7890`、`socks5h://127.0.0.1:1080` |

- 协议支持 `http`、`https`、`socks4`、`socks4a`、`socks5`、`socks5h`，没写协议按 `http`
- 需要认证时写成 `socks5://用户名:密码@主机:端口`
- `socks5h` 由代理端解析域名，本机 DNS 不可靠时用它
- 「不走代理」填逗号分隔的域名、IP 或网段，如 `intranet.gov.cn, 10.0.0.0/8`

> [!注意]
>
> 本机地址（`localhost`、`127.0.0.1`）**始终直连**，本地 LM Studio / Ollama 不受代理影响。

代理改完**立即生效**，可以直接点「测试连接」验证，再保存写入配置文件。

同一分区的「更新检查地址」决定关于窗「检查更新」访问哪里：默认是项目在 GitHub 上的最新发布接口，内网可改成镜像地址。检查只在点击时请求一次，不会轮询。

> [!提示]
>
> 设了代理又要调内网的数据接口时，把内网地址段填进「不走代理」，例如 `10.0.0.0/8`。

### 界面主题

六套主题即点即换（明色三、深色三），菜单底部也有入口。在 Omarchy 桌面上会多出一组「Omarchy 桌面」，其中只有一张「跟随 Omarchy」：程序找到 Omarchy 当前主题目录里的 `colors.toml` 就换算出一套界面配色，找不到就不出现这张卡。它**只读**用户的 Omarchy 配置，不写钩子、不改模板；Omarchy 那边换了主题后，回到这里再点一次卡片即重新读取。**默认跟随系统明暗**：系统是浅色就用「Claude 奶油」，系统是深色就用「复古暗」，桌面在深浅模式之间切换时界面跟着换。设置页的「明暗跟随系统」勾选框控制这个行为；手动点下面任一套配色就改为手动选择，想再跟随就勾回去。

另有**纸面明暗**三档：

| 档 | 效果 |
| --- | --- |
| 跟随主题 | 纸面明暗跟界面主题走 |
| 白纸黑字 | 强制白纸 |
| 深色纸面 | 屏幕上省眼 |

「跟随主题」下，MDEX 夜墨使用灰绿墨纸，纸边、悬停底色与投影也随纸面搭配。MDEX 夜墨选择「深色纸面」时仍使用灰绿墨纸；选择「白纸黑字」则回到纯白纸、纯黑正文。

「界面缩放」把整个界面按比例放大或缩小，点选常用档位（80%、90%、100%、110%、120%、150%、175%）立即生效，不影响导出的公文版式。旧配置里手填的 85%、125% 之类仍会显示成选中档位。高分屏字太小或窗口装不下两栏时先调这里。

> [!注意]
>
> 纸面明暗**只影响屏幕预览**，导出一律白纸黑字红头。

### 字体

字体分四层：

#### 编译字体（公文五处）

| 位置 | 默认 | 用途 |
| --- | --- | --- |
| 标题 | 方正小标宋 | 文件标题 |
| 一级标题 | 方正黑体 | `#` |
| 二级标题 | 方正楷体 | `##`，兼主送机关、正文括号与斜体；西文、数字与符号取楷体_GB2312 字面 |
| 正文 | 方正仿宋 | 正文；西文、数字与符号取仿宋_GB2312 字面 |
| 页码 | 方正书宋 | 页码；数字保持宋体字面 |
| 粗体 | 专用粗体 | `**粗体**`，内置为方正黑体 |
| 兜底 | 方正书宋 | 缺字时替补 |

内置中文一律是覆盖 GBK 的方正系列。仿宋、楷体是随包的合成字体（公文仿宋、公文楷体）：汉字取方正仿宋 / 方正楷体，西文、数字、带圈数字「①②」、弯引号、破折号等非汉字取仿宋_GB2312 / 楷体_GB2312，所以正文、表格、各级仿宋与楷体标题、主送机关、括号楷体、列表编号的西文数字都是国标字面。页码数字另用一支取自宋体的随包拉丁子集，黑体与小标宋用自带字面。某处另选了本机字体，那一处就用本机字体自己的西文数字。

勾「**使用本机字体编译**」后给五处分别选本机字体，留「内置」就继续用内置。屏幕预览同步切换，所见即所得。

> [!注意]
>
> 排版 PDF 时**按文件加载**所选字体；字体文件后来被删/卸载会自动退回内置，并在导出结果里提示。Word 里写的是字体名，在别的机器上打开要装了同名字体才一致。研究报告的字体固定，不受这一组设置影响。

**字体集合（`.ttc`）不可选**：`.ttc` 一个文件装多字面，按文件加载须指定是哪一个。请找单字面的 `.ttf`。列表只收 `.ttf` 与 `.otf`。

二级标题字体**同时充当正文斜体**，改它一并影响正文里的斜体。

#### 兜底字体

内置字体（方正系列）全部覆盖 GBK，「喆」「赟」「堃」这类字直接就能排。兜底字体是给**另选了本机字体**的位置准备的：那支字体排不出的字自动换用兜底字体，**预览、Word、PDF 三端一致**，不必配置。

内置兜底是方正书宋，覆盖 GBK 两万余汉字，日常够用。要排 GBK 以外的字（如「𠮟」），在「兜底字体」另选字库更大的本机字体——这一项**不受**「使用本机字体编译」开关约束（它决定的是排不排得出来，不是版式）。所选字体也漏的字，仍由内置兜底接着兜。

#### 界面字体

界面字体不随包：Windows 微软雅黑、Linux Noto Sans SC、macOS 苹方，可另选本机字体。与公文字体互不干扰。

下一行是「**输入法字体**」：应用内输入法的候选窗（候选字词、编码与提示）用它，默认「跟随界面字体」，也可另选本机 `.ttf` / `.otf`；所选文件失效时自动回退界面字体，不会出现方框。

#### 源码编辑器 Markdown 字面

三套模板（编辑器字体 / 标题随公文 / 与公文一致）或六处自定义。只改屏幕字面，不影响导出。见第{@chap:editor}章「拟稿：源码编辑与四种视图」。

### 导出格式

| 配置 | 说明 |
| --- | --- |
| 默认勾选 | 新建稿子时 Markdown / PDF / Typst 包哪些默认勾上 |
| 输出目录 | 同一稿件使用固定目录，同名文件直接替换 |

PDF 一律由内置 Typst 引擎在程序里直接排版（公文几十毫秒一份，研究报告同样），完全离线，不依赖本机装任何排版软件。

启用「起草页导出 PDF 时添加印制追溯码」并填写印制单位后，每页右下角底部会叠加长方形 Data Matrix 码、印制单位和编号，不改变正文分页。普通导出、单格式快捷导出、另存为与起草页「打印」都继承设置；随本次导出的 PDF 随行单据也会带码。

码里仅含编号，登记记录保存在本机稿件库，可在同一设置区按完整编号查询。这里记录的是生成 PDF 时登记的印制单位，不是主送、抄送或接收单位，也不能验证文件转交后的实际打印单位。当前首版不覆盖稿件库批量 PDF、送批材料合并与花脸稿入口；不会修改已有 PDF 附件。

### 数据备份

把配置、稿件库与资料库、知识库（`manuscripts.db`）、图片、Pi 运行数据、数据接口配置、输入法词表与技能文件
一键打成一个加密 7z；恢复前自动把当前数据留底到同级目录。崩溃日志等诊断文件不进备份。
加密工作区的备份保留密文与同一代锁封套，恢复时需要使用**备份当时的应用密码**。
备份与恢复的边界、手工备份清单见第{@chap:data}章「数据、备份与迁移」。

本分区底部的「清空数据」会永久删除标准词库、全部文稿（含归档）、资料库和维基库，
包括版本、附件、插图与索引；应用设置、公文词库、校对词表、输入法词表和任务助手数据保留。
操作需要二次确认，执行前应先导出全量备份。

### 应用锁

给整个程序加一把锁：启动要输密码，闲置一段时间自己退回锁屏，磁盘上的稿件库与敏感配置全库加密。没启用时这一分区显示「本机未启用应用锁」。

#### 启用

填**主密码**与**确认主密码**，点「启用密码保护」。密码**忘记无法恢复**——程序不保存任何可找回的凭据。

密码必须**足够强**：长度**大于 10 个字符**，并且至少用到**大写字母、小写字母、数字、符号、中文里的三类**；
常见口令（如 `password`、`123456`）、4 位以上连续字母或数字、4 个以上连续相同字符一律拒收。
这是硬要求而不是建议：应用锁的密码是整个加密体系的根，锁文件里存着「用密码派生的密钥加密的
固定明文」，拷走配置目录的人就能拿它离线反复试——**弱密码等于没有加密**。不够强时程序会直接
拒绝并说明是哪一条不满足。

| 表单项 | 说明 |
| --- | --- |
| 主密码 / 确认主密码 | 启用后进入程序要输的密码（同样按上面的强度规则） |
| 同时设置第二密码 | 可选。输第二密码进入的是**空白系统**（诱饵系统） |

第二密码（诱饵系统）是一个完整的独立环境：两套密码都能正常进入，界面上看不出区别，两套数据完全独立、互不越界。在设置页里**看不出当前是否已设置**第二密码——这里只能提供「设置（覆盖）」与「清除」两个盲操作。

启用后现有数据**当场加密**：稿件库整体迁移为密文（SQLCipher），盖章扫描 PDF
附件本来就在库里随之加密；`config.json`、记住的稿件包密码、接口密钥、风格档案、个人词表、
自定义技能与使用统计整份加密；图片目录、PDF 插图和图表缓存也逐文件加密，正文引用不变。
Pi 的材料、工作文件、会话、接口缓存、进度与交付快照同样加密保存，模型只在内存中读取解密后的
内容。迁移在后台跑，锁屏显示进度。

诊断日志也按当前密码系统加密，详细内容只在已解锁应用的崩溃提示框里查看，不直接打开密文日志
目录。加密工作区**允许打印**，打印内容从内存交给系统打印队列，不生成应用自己的明文送打缓存；
队列副本、打印机缓存与纸件不受应用锁保护，打印前仍逐次确认风险。

在「导出格式」中可选**加密导出文档**（默认开启），并另设与登录密码不同的**导出加密密码**。
开启时直接导出加密成果，不弹风险提示；关闭时每次明文导出前明确确认风险。PDF、Word 用打开密码加密，
源码包和份号清单用加密 7z；详见第{@chap:export}章。密码单独以密文保存，不进入配置历史，
修改后只影响新导出；停用应用锁时清除本机保存的导出密码。收到导出密码的人不能用它登录应用，
但能解锁本机数据的人仍可能读取本机保存的导出密码。已有输入原件、历史导出和旧备份不会自动加密。

应用锁不防解锁后的恶意软件、内存读取或截屏，也不隐藏文件名、文件大小和修改时间；删除旧明文
不等于对 SSD 做安全擦除。需要防历史磁盘残留时，还应启用操作系统全盘加密。

#### 启用之后

| 项 | 说明 |
| --- | --- |
| 闲置自动锁定 | 没有任何键盘 / 鼠标输入超过这个时长就退回锁屏。可选「永不 / 5 分钟 / 15 分钟 / 30 分钟 / 1 小时」 |
| 修改主密码 | 立即生效，数据不动；旧密码随即失效 |
| 设置第二密码 | 设置或覆盖；与主密码不能相同。**会重置第二密码系统的数据** |
| 清除第二密码 | 无论之前是否设置过，都把第二密码槽位置空；该密码立即失效，其数据一并删除 |
| 停用密码保护 | 锁定后输入一次密码，把数据解密回明文，回到无密码状态 |

菜单里有「**锁定窗口**」可随时手动退回锁屏（启用密码保护后才出现）；闲置超时也会自动锁定。锁定前程序会**保存所有已修改或新建的稿件与配置**（不受自动保存开关影响）；有任务在跑或保存失败时**不丢弃工作区**，状态栏说明原因。

锁屏时窗口收成约 380 × 250 的小窗，只留密码框与「解锁」按钮；运行中锁定则用当前主题的抽象底图遮住工作区，看不到原文内容。解锁后恢复上次的工作区窗口大小、位置与最大化状态。

### 加密传输单

公函导出时随附的电子《传发任务单》上，有几处是要人每次都手写的：题名（传输任务）、
传字、签批人、时效要求、发后处理、备注、保密负责单位。这里把它们做成默认配置，
导出时照填，不用每回再抄一遍。

| 项 | 说明 |
| --- | --- |
| 传输任务 | 单子的题名，从下面的传输任务类型字典里挑；留空则**按密级自动带**（有密级为涉密信息加密、无密级为公开信息明文） |
| 传输任务类型 | 题名备选的字典，可增删改，默认三项：涉密信息加密 / 公开信息明文 / 公开信息密文传发任务单 |
| 传字 | 印在右上角「传　　号」里，**只填「传」这样的一个字，号码留白**手写；不加方括号与横线 |
| 签批人 | 默认签批人姓名；旁边有「留空手签」开关，勾上时这一栏只留空白、不画横线，由人在单子上签名 |
| 时效要求 | 如「急」；留空则这一栏留白手写 |
| 发后处理 | 「传输后销毁原件」或「传输后退回原件」，单子上勾选其中一项 |
| 备注 | 可粘多行，印在单子的备注栏 |
| 保密单位 | 保密负责单位，整体替换末行的「【保密单位】」占位，不保留方括号；留空则保留占位 |

备注按模板上的事例排：**仿宋小四、固定行距**，一行一条，序号「1.」「2.」……
自己已经带序号的行原样保留。留空不填时，备注栏照模板留出一大块空白手写区。

这些内容对**所有公函**的传发任务单生效；单据本身在设置页「导出格式」里勾选导出。

### 输入法

词表输入法按编码精确查表。设置包括启用、全角标点、四码唯一候选自动上屏、
第五码顶屏，候选数量、翻页键、横竖排和字号，以及简码提示、词组提示、逐码提示三项编码提示。

词表维护在主菜单「输入法词表」页：基础表升级、公文四码表导入、快速增删改、查码、检查与修改记录。
设置里的「打开输入法词表」直达；维护后立即生效，公文词表仅同步已接受且编码为四码的词。
具体操作见第{@chap:lexicon}章「公文词表与输入法」。

#### AI 技能包

「上手指引」底部可以导出 **AI 技能包**（Agent Skill，名为 `gongwen-markdown`）。它把本程序的 Markdown 公文子集、九种文种的正文规则、行文规范、各文种模板和一个自检脚本打成一套说明书，装进外部 AI 工具后，它们写出的 `.md` 可以**直接粘贴到起草页**，预览、导出与手写稿件完全一样。

| 按钮 | 产物 | 适合 |
| --- | --- | --- |
| 导出 .skill 技能包 | 单个 `gongwen-markdown.skill` 文件（zip 格式） | 需要上传技能包的工具；也可自己解压 |
| 导出为技能文件夹 | 在选定目录下生成 `gongwen-markdown/` 文件夹 | 直接读技能目录的命令行工具 |

安装包里也带了一份现成的技能包：安装目录下的 `skills/gongwen-markdown.skill`（macOS 在应用包的 `Contents/Resources/skills/`）。

常见工具的放置位置（以各工具当前文档为准）：

| 工具 | 放在哪里 |
| --- | --- |
| Claude Code | `~/.claude/skills/`（个人）或项目里的 `.claude/skills/` |
| Claude 桌面版 / 网页版 | 设置 → 技能（Skills）里上传 `.skill` 文件 |
| Codex | `~/.agents/skills/`（个人）或项目里的 `.agents/skills/`；老版本用 `~/.codex/skills/` |
| OpenCode | `~/.config/opencode/skills/` 或项目里的 `.opencode/skills/`，也认 `~/.claude/skills/` |
| pi | `~/.pi/agent/skills/` 或 `~/.agents/skills/` |
| DeerFlow | 在应用的技能面板安装 `.skill`，或把文件夹放进 `skills/custom/` |

「导出为技能文件夹」时选的是**上面这一级 skills 目录**，程序在里面建 `gongwen-markdown/`；再导一次会覆盖成新版本，目录里别的技能不动。

用法：在工具里说「用公文助手格式写一份关于××的函」，或直接点名 `gongwen-markdown` 技能。拿到结果后：

1. 新建对应文种的稿子，先在「文档要素」里填好单位、文号、主送、落款等——技能包刻意让模型**不写**这些，写了会印两遍；
2. 把 Markdown 粘进起草页（或用「从文件导入」打开 `.md`），切到版式预览验收；
3. 研究报告分章写成多个 `.md` 时，连同 `images/` 放进一个文件夹，用「从文件夹新建研究报告」一次合成；`.bib` 只有排序第一份 `.md` 的 frontmatter 里写了 `bibliography: 相对路径` 才会一并读入，单独放在旁边的不会被读。

> [!提示]
>
> 技能包里的 `scripts/check_gongwen_md.py` 可以让工具在交付前自检（手写编号、要素混入正文、附件标记、表格列数等）。它只是提前拦错，最终仍以本程序的审校面板为准。升级程序后建议重新导出一次，规则与新版保持一致。
