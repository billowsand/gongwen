## 知识库是什么

「知识库」把**历史成稿与参考资料**变成可检索、可问答的素材库，供 [知识起草](chapter:13-ai-workbench) 与问答用。

存储在稿件库同一个 SQLite 文件里（`manuscripts.db`），用 FTS5 虚表做全文索引 + 向量检索。

## 两种来源

| 来源 | 说明 |
|---|---|
| **Markdown 导入** | 从文件导入 `.md`，归到某个文种 |
| **稿件库收录** | 把已有稿件收进知识库 |

导入 Markdown 时：

1. 选文件（可多选）；
2. 为每个文件**选文种**（决定它在哪个文种下被检索到）；
3. 建索引。

> **提示** 归对文种很关键：知识起草按**同文种**检索片段。通知归到会议议程下，起草通知时就检索不到。

## 索引

导入后要**建索引**才能检索：

| 操作 | 说明 |
|---|---|
| 重建索引 | 全量重扫，切分块、算向量 |
| 索引进度 | 显示 `(已完成, 总数, 当前文档名)` |

切分规则按段落与节，块带文种与文档来源标注。重建索引是幂等的，随时可重来。

> **注意** **换 embedding 模型后必须重建索引**——不同模型的向量空间不同，旧向量在新模型下没意义。程序会在换模型后提示重建。

## 检索测试

「检索测试」输入查询词，看返回哪些片段：

| 显示 | 用途 |
|---|---|
| 片段正文 | 看检索到什么 |
| 相关度 | 打分排序 |
| 来源文档 | 哪篇稿子/文件 |
| 文种 | 筛选用 |

检索用 **RAG 管线**：

1. **Embedding 向量检索**取候选；
2. **Rerank 重排**精调顺序；
3. **FTS 全文**兜底——服务不可达时自动退化到全文检索，**不报错只降级**。

> **提示** 检索测试是调知识库的抓手：起草效果差先来这里查，看是不是检索本身没召回到对的片段。检索不对，模型再好也白搭。

## 知识库问答

「知识库问答」模式是**对话式检索**：

| 能力 | 说明 |
|---|---|
| 多轮对话 | 上下文带进下一轮 |
| 引用标注 | 回答里标出依据片段来源 |
| 降级 | 服务不可达退到全文检索 |

> **红线** 问答是**检索增强**，回答里若含单位、人名、日期、数字、文号，仍要你**人工核实**。问答不能替代事实核对——它是找材料的助手，不是定事实的权威。

问答历史留在当次会话，不进稿件库。

## RAG 配置

「设置 → 知识库」配三项：

| 项 | 说明 |
|---|---|
| Embedding | 向量化模型与接口地址 |
| Rerank | 重排方式：None / 专用端点 / 用对话大模型 |
| 启用 RAG | 总开关 |

### 用 Ollama

Ollama 走 OpenAI 兼容协议，三个接口地址**相互独立**：

| 配置 | 地址 | 模型名例 |
|---|---|---|
| 对话 | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |
| Embedding | `http://127.0.0.1:11434/v1` | `bge-m3` 或 `nomic-embed-text` |
| Rerank | `http://127.0.0.1:11434/v1` | — |

> **注意** Ollama **不提供 rerank 专用端点**，所以重排方式选「**用对话大模型重排**」。「专用端点」模式在 Ollama 上用不了。用对话模型打分同样可用。

LM Studio 的接法见 [五分钟出第一份稿子](chapter:03-quickstart)。

## 文档预览

文档列表里点条目可**预览**原文（弹窗），看清楚收进来的是什么再决定删不删。按文种筛选列表，删除有二次确认。

## 建库建议

1. **先收定稿**：已发布/已归档的稿子才是好素材，草稿收进去会污染检索；
2. **归对文种**：宁可多归两处，别归错（错了检索不到）；
3. **定期重建索引**：大改动后重建一次，增量容易留脏块；
4. **检索测试先行**：起草效果差先查检索，别急着换模型；
5. **换模型就重建**：embedding 换了向量空间就变了，别偷懒；
6. **问答答案要核实**：它给的是片段拼的答案，要素还是你定。

## 与 AI 起草的关系

知识起草工作流依赖知识库：

1. 你给主题与文种；
2. 程序按主题 + 文种**检索同文种片段**；
3. 模型结合片段与**你确认的事实单**起草。

检索不到就退回纯主题起草并提示。所以知识库的质量直接决定知识起草的质量。见 [AI 起草工作台](chapter:13-ai-workbench)。
