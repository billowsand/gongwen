## 资料库与问答 {#chap:knowledge}

### 资料库是什么

「资料库」把**历史成稿与参考资料**变成可检索、可问答的素材库，供第{@chap:ai-workbench}章「AI 侧栏的技能」与问答用。这一页原先叫「知识库」，现在它只管原材料；把材料整编成有框架、能互链的条目页是另一页「知识库」，见第{@chap:wiki}章「知识库（维基）」。

存储在稿件库同一个 SQLite 文件里（`manuscripts.db`）。本地全文索引与向量索引分开维护。

### 两种来源

| 来源 | 说明 |
|---|---|
| **文档导入** | 从本机导入 Markdown、Word、PDF（电子版）等文档，归到某个文种 |
| **稿件库收录** | 把已有稿件收进资料库 |

点「导入文档」时：

1. 选文件（可多选）；
2. 为这批文件**选文种**（决定它在哪个文种下被检索到）；
3. 开始导入。导入完成即可全文检索；列表的块数和待索引状态仅指向量索引。

导入时自动在后台建立本地全文索引，不需要 embedding 服务。首次打开资料库页面时，旧数据也会在后台补建。另可建立向量索引，供语义检索和问答使用。

可导入的格式与起草页「导入文档」相同——Word（docx / doc）、Excel、PowerPoint、OpenDocument、RTF、EPUB、CSV、纯文本、Markdown，以及 **PDF（电子版）**：

| 情况 | 结果 |
|---|---|
| 电子版 PDF（能在阅读器里选中文字） | 正常导入。版式不保留，检索只用文字 |
| 扫描版 PDF（页面是图片），哪怕只有个别页 | **整份拒收**，提示哪几页是扫描件。缺页的内容进了库，检索时会被当成原文没有 |
| 字体没内嵌文字映射、提取出来是乱码的 PDF | 拒收，请改用原始 Word 文件 |
| 设了密码的文件 | 拒收，先去掉密码 |

Word 公文里「一、总体要求」这类一级标题常常只是加粗、没套标题样式，导入时程序会把它认成章节，按章节切块；Markdown 原文按作者写的结构来，不做改动。文档没有大标题时，以文件名作标题。

> [!提示]
>
> AI 侧栏的技能检索时不限文种，与问答一致。文种仍用于这里的筛选和问答的范围，导入时归对文种，日后找起来才方便。

### 索引

全文索引与向量索引用途不同：

| 操作 | 说明 |
|---|---|
| 本地全文索引 | 导入自动建立；首次打开资料库页时补建旧数据。后台显示进度 |
| 建立向量索引（N） | 为 N 篇文档切分块、计算向量，用于语义检索和问答；需要配置 embedding 模型 |
| 重建向量索引 | 重新切分全部文档并计算向量，不会替换本地全文索引 |

本地全文检索使用 SQLite FTS5、jieba 分词与 BM25，无需配置模型服务。搜索结果按篇展示原文命中片段，可复制、查看并定位原文，或打开版式预览；空格分隔多个关键词表示同时包含，双引号包裹查询可查连续原文短语。输入普通关键词不会作为 FTS 语法执行。向量索引按段落与节切块，供语义检索及问答引用。重建向量索引是幂等的，随时可重来。

页面上方工具栏的一行统计会写成「N 篇 · N 块 · 最近一次检索 3.6 秒」。检索失败也照样计时、照样显示。**这个耗时只在本次运行里保留，重启不落盘。**

> [!注意]
>
> **换 embedding 模型后必须重建索引**——不同模型的向量空间不同，旧向量在新模型下没意义。程序会在换模型后提示重建。

### 检索测试

「检索 / 问答」输入查询词，默认使用「全文检索」，在本机查找原文，不访问模型服务；也可点「语义检索（需模型）」使用原有向量与 RAG 检索：

| 显示 | 用途 |
|---|---|
| 本地全文 | 按篇显示原文上下文、字面命中高亮，可复制片段或打开全文 |
| 语义检索 | 返回相关片段及排序分数，走 embedding / rerank 服务 |
| 来源文档 | 查看命中来自哪篇稿子或文件 |
| 文种 | 限定检索范围 |

仅「语义检索」使用 **RAG 管线**：

1. **Embedding 向量检索**取候选；
2. **Rerank 重排**精调顺序；
3. **FTS 全文**兜底——服务不可达时自动退化到全文检索，**不报错只降级**。

> [!提示]
>
> 检索测试是调资料库的抓手：起草效果差先来这里查，看是不是检索本身没召回到对的片段。检索不对，模型再好也白搭。

### 问答

输入区的「问答」模式是**对话式检索**，在资料库原文之上先垫一层知识库条目页：

| 能力 | 说明 |
|---|---|
| 多轮对话 | 上下文带进下一轮 |
| 维基优先 | 先按提问检索至多 3 篇已审核的条目页（每篇取前 3000 字），资料库原文片段兜底补细节；两类资料口径冲突时分别标出处、说明差异，不合并成一个结论 |
| 引用标注 | 回答里标出依据来源：条目页标（维基《标题》），原文片段标（文种《标题》· 章节）；答案卡片下方列出**维基依据**，点一下跳到知识库并打开该页 |
| 降级 | 知识库不可用或没命中时不报错，照常用资料库回答；服务不可达退到全文检索 |

> [!红线]
>
> 问答是**检索增强**，回答里若含单位、人名、日期、数字、文号，仍要你**人工核实**。问答不能替代事实核对——它是找材料的助手，不是定事实的权威。

问答历史留在当次会话，不进稿件库。

### RAG 配置

「AI 管理 → 知识库检索」配三项：

| 项 | 说明 |
|---|---|
| Embedding | 向量化模型与接口地址 |
| Rerank | 重排方式：None / 专用端点 / 用对话大模型 |
| 启用 RAG | 总开关 |

#### 用 Ollama

Ollama 走 OpenAI 兼容协议，三个接口地址**相互独立**：

| 配置 | 地址 | 模型名例 |
|---|---|---|
| 对话 | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |
| Embedding | `http://127.0.0.1:11434/v1` | `bge-m3` 或 `nomic-embed-text` |
| Rerank | `http://127.0.0.1:11434/v1` | — |

> [!注意]
>
> Ollama **不提供 rerank 专用端点**，所以重排方式选「**用对话大模型重排**」。「专用端点」模式在 Ollama 上用不了。用对话模型打分同样可用。

LM Studio 的接法见第{@chap:quickstart}章「五分钟出第一份稿子」。

### 文档预览

文档列表里点条目可**预览**原文（弹窗），看清楚收进来的是什么再决定删不删。按文种筛选列表，删除有二次确认。

### 建库建议

1. **先收定稿**：已发布/已归档的稿子才是好素材，草稿收进去会污染检索；
2. **归对文种**：宁可多归两处，别归错（错了检索不到）；
3. **定期重建索引**：大改动后重建一次，增量容易留脏块；
4. **检索测试先行**：起草效果差先查检索，别急着换模型；
5. **换模型就重建**：embedding 换了向量空间就变了，别偷懒；
6. **问答答案要核实**：它给的是片段拼的答案，要素还是你定。

### 与 AI 起草的关系

智能写作中的 Pi 按任务需要检索资料库，沿用本章的索引与模型配置（先查知识库条目页，查不到再回落资料库，见第{@chap:wiki}章「知识库（维基）」）：

1. Pi 根据写作要求调用检索工具，返回带出处的片段；
2. 需要原文时继续分段读取，返回会注明还有多少未读内容；
3. 也可通过 `@` 明确指定一篇资料库文章，发送时保存本轮全文快照。

未找到依据时应说明缺失，必要时问用户；结果里的来源仍需结合原文判断。资料库未启用时，也可使用用户提供的材料起草。见第{@chap:ai-workbench}章「智能写作与技能」。
