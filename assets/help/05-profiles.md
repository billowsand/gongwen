# 写一篇公文

## 立稿与要素填报 {#chap:profiles}

### 九种文种

新建稿件先选文种。文种决定版式要素、文号规则、页码位置和导出形态，选错了后面都是白填。

| 文种 | 适用 | 特性 |
|---|---|---|
| 公函 | 商洽、征求意见、告知、答复等平行行文 | 有文号、有份号位、函稿版式 |
| 电话记录单 | 记录收到的电话通知 | 来电信息、首长批示空栏、人工拟办建议及承办栏 |
| 电话通知 | 沿用函稿版式的简式通知 | **无文号**，底部无版记 |
| 普通公文 | 无红头无版记的纯正文公文 | 最简：无红头、无发文单位、无主送、无落款、无版记 |
| 会议议程 | 会议时间地点、参会人员、议程安排 | 多会议时间、会议地点、参会人员字段 |
| 会议纪要 | 记载会议情况和议定事项 | 红色纪要标志与编号，正文后列出席名单，底部分送、抄送、印发版记 |
| 白头件（呈批件） | 内部情况报告、请示、领导呈批 | 呈批件版式，无红头 |
| 红头呈批件 | 带红头、文号、首页批示栏的内部呈批件 | 有文号，**承办条目上限 4 条** |
| 研究报告 | 按研究报告规范出 PDF 与 Word | 封面分项目类、研究类两种样式，另有文献系统 |

> [!提示]
>
> 切换文种**保正文、只换版式**。已经写好的内容不会丢，但要素表单的字段集会跟着变——原来填的电话通知没有文号栏，换成公函就多出文号栏，需要补填。

研究报告的用法单独成章，见第{@chap:research}章「研究报告专章」。

### 会议纪要

会议纪要的版头、名单和版记都由表单填、程序排，正文只写会议情况与议定事项。纸面从上到下是这样：

```mermaid
flowchart TD
  A[份号、密级] --> B[红色纪要标志：××局会议纪要]
  B --> C[编号：〔2026〕3号，其下红色反线]
  C --> D[可选标题：只有专题纪要才写]
  D --> E[正文：首段概述，其后会议认为、会议要求、会议明确]
  E --> F[出席、列席、请假名单]
  F --> G[末页底部版记：分送、抄送、印发机关与印发日期]
```
图：会议纪要的纸面结构

表单三段对应的字段：

| 分段 | 字段 | 说明 |
|---|---|---|
| 版头 | 发文单位 | 纪要标志与印发机关默认随它带出 |
| 版头 | 纪要标志 | 红头文字，留空为「发文单位＋会议纪要」，可改成「××局局长办公会议纪要」 |
| 版头 | 编号 | 只有年份与序号，印成「〔2026〕3号」，不带机关代字；预览版序号留空 |
| 主体 | 会议时间、会议地点 | 供 AI 写首段概述，不单独印出 |
| 主体 | 出席、列席、请假 | 顿号分隔；空着的那项不印 |
| 版记 | 分送、抄送单位 | 空着的那行不印 |
| 版记 | 印发机关、印发日期 | 印发机关留空取发文单位；预览版印发日期的「日」留空 |

几条排版规则：

- **标题可选**。纪要名称已经印成红头，正文一般不写 `# 标题`；写了就在红线下排一个小标宋二号标题，适合专题纪要。
- **「一是」楷体**。正文段里「一是……」「二是……」从序号到第一个句号（或分号）自动排楷体，不用加任何标记。序号要在段首或句号、分号、冒号之后才算；这一截超过 40 字时只有「一是」两字排楷体，所以概括句写短些。
- **名单排法**。都是三字以内的姓名时每行 6 人对齐排，两字名中间空一字；有一个名字放不进一格（带单位、四字以上），这一项就改成连排，回行与冒号后首字对齐。
- **印数**。版记里的「共印 N 份」按出席、列席、分送人数和抄送单位数自动算，请假的人不计；勾选逐份编号时份号也按这个顺序编（PDF 才有逐份编号，Word 只出一份）。
- **AI 起草**。AI 只写正文，名单和版记不会写进正文；照抄出来的「出席：」「分送：」「……印发」行在落地前会被剔掉。

#### 版头

| 字段 | 说明 |
|---|---|
| 密级 | 不标注 / 内部 / 秘密 / 机密 / 绝密，默认「机密」 |
| 保密期限 | 默认「20 年」，受密级规则约束（见下） |
| 发文单位 | 红头上的单位名称 |
| 联合发文 | 单独发文 / 联合发文；联合时填联合发文单位与主办单位 |
| 机关代字 | 如「办函」，是函号的前半截 |
| 发文年份 | 如「2026」 |
| 发文序号 | 如「12」 |
| 特殊处理 | 指人专办等标注 |
| 函稿版本 | 预览版 / 正式版 |
| 逐份编号 | 份号是否逐份编号 |

#### 主体

| 字段 | 说明 |
|---|---|
| 主送单位 | 主送对象 |
| 标题 | 文件标题；留空时用「标题提示」回退 |
| 标题提示 | 起个头，供模型与文件名回退用 |
| 正文体例 | 正文的编号与段落风格 |
| 标题与列表编号 | 节内/全局编号规则，见第{@chap:settings}章「设置全解」 |
| 紧缩样式 | 正常 / 全局紧缩 / 节内紧缩 |

#### 版记

| 字段 | 说明 |
|---|---|
| 抄送单位 | 抄送对象 |
| 承办单位 | 承办部门 |
| 联合承办 | 联合承办单位与各自联系人（单位 ↔ 人 ↔ 电话成对） |
| 联系人 / 电话 | 从标准词库带出 |
| 呈报领导 | 白头件、呈批件用 |
| 落款单位 | 署名单位 |
| 落款用简称 | 落款处是否用简称 |
| 成文日期 | 可手动填，也可「自动」跟当天 |
| 会议时间 / 地点 | 会议议程、会议纪要显示 |
| 双面页码 | 双面打印时页码位置 |
| 份数 | 印发份数 |

> [!提示]
>
> 承办联系人在标准词库里维护一次，要素表单里直接选。换了人只改词库一处，所有稿子跟着走。见第{@chap:vocabulary}章「标准词库」。

> [!提示]
>
> AI 起草时，主送、承办单位、联系人这些要素会按材料和词库出选择题、进要素建议卡，点采纳才写进这里。见第{@chap:ai-workbench}章「AI 侧栏与技能」的「表单要素：选择题与要素建议卡」。

### 密级与保密期限规则

密级不是随便写的，程序按规则卡：

| 密级 | 保密期限上限 | 允许「长期」 |
|---|---|---|
| 秘密 | 10 年 | 否 |
| 机密 | 20 年 | 否 |
| 绝密 | 30 年 | 是 |

填了超上限的期限，校验会拦下提示。不标注密级与「内部」不走这套期限规则。

密级也决定导出成品里密级标注的位置与字色。这些都由程序算，模型碰不到——见第{@chap:ai-guard}章「AI 的边界与保障」。

### 行文方式

**内部 / 外部**切换的是语气与行文方向：内部行文可用「请示」「报告」这类上行语气，外部平行行文用「商洽」「告知」。程序会按方向切换文号与行文语气规则。

**单独发文 / 联合发文**：联合发文时要填主办单位、联合发文单位、联合承办单位与各自的联系人。落款与版记按联合规则排。红头呈批件的承办条目有上限（4 条），超出请改用普通呈批件或拆件。

> [!提示]
>
> 红头呈批件导出的 Word 与 PDF 里，联系人姓名一栏留空、电话之前空出一段，供经办人手写签字；编辑区预览仍显示所选联系人，电话照常印出。

### 版面缩略导航图

表单顶部那张小纸是**版面缩略导航图**：

- 三色块对应版头（红）、主体（白）、版记（灰）；
- 点色块跳到对应表单段；
- **缺项会在图上标出来**——哪块发虚说明那段还有必填项没填。

填长表单时不用来回滚，抬头看一眼缩略图就知道还差哪块。

### 按文种保存默认要素

每个文种都有一份「默认配置」（`TemplateProfile`）。发文单位、机关代字、承办联系人、呈报领导这些**每次都一样**的字段，填一次保存，下次新建同文种稿子自动带出。

- 在要素表单里改完点保存，即更新该文种的默认配置；
- 切换文种时，原配置按旧文种存回，新文种取自己的配置，**正文不动**；
- 想基于已有稿子另起一篇，用稿件管理的「基于此公文新建」——要素连同版式一起带过去。

### 版式细节开关

| 开关 | 作用 |
|---|---|
| 函稿版本 | 预览版留改稿痕迹，正式版清稿 |
| 紧缩样式 | 正常行距；全局紧缩整篇压行距；节内紧缩只在节内压 |
| 双面页码 | 双面打印时奇偶页码分置外侧 |
| 逐份编号 | 份号是否逐份递增 |
| 横页排版 | 仅普通公文：整份文件（含附件）排成横向 A4、左侧装订，PDF、Word 与预览一致；双面打印时选「短边翻转」 |
| 领导阅件 | 仅普通公文：呈阅领导的大字版，正文、层级标题、附件说明与附件正文改小二宋体、行距 31.85 磅；主标题仍是二号方正小标宋，表格、密级不变。再勾「加粗」则正文整体加粗（层级标题不加粗，行内加粗不再另行区分）。PDF、Word 与预览一致 |

这些开关只影响版式，不影响正文文字。
