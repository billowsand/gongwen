# 公文助手 Markdown 语法完整参考

公文助手认的是一个「公文子集」，不是网页 Markdown。下面每条都对应程序解析器的
实际行为；没列出来的语法一律不要用。

## 1. 文档标题与区段标记

| 写法 | 含义 |
|---|---|
| `# 标题` | 文档主标题（小标宋居中）。全文第一行，只写一次。 |
| `<!-- [正文] -->` | 正文区段起点，写在主标题下一段。 |
| `<!-- [附件] -->` | 一份附件的起点。**每份附件前各写一个**，程序另起一页并自动加“附件”或“附件1、附件2……”标识。 |

- 标记必须**独占一行**，前后建议各空一行。
- 标记可以写成 `<!-- [附件] -->`、`<!-- 【附件】 -->`，也认英文 `body` / `attachment`。
  统一用中文方括号以外的 `[正文]` `[附件]` 写法即可。
- 附件标记之后紧跟的 `# 标题` 是这份附件的正式标题，附件内部再用 `##`、`###` 表示
  第一、二层标题，编号从“一、”重新开始。
- 旧写法 `# 附件1` + `## 附件标题` 程序也能识别，但新稿一律用上面的写法。
- 标题要长也不要手工换行，程序按公文标题回行规则自动断行（词边界、标点不落行首等）。

## 2. 标题层级与自动编号

| Markdown | 默认编号 | 字体 |
|---|---|---|
| `## 标题` | 一、 | 黑体 |
| `### 标题` | （一） | 楷体 |
| `#### 标题` | 1. | 仿宋 |
| `##### 标题` | (1) | 仿宋加粗 |

- 编号由程序按「设置 → 标题与列表编号」生成，用户可能把它改成“第一章”“第一部分”
  等，所以**永远不要手写编号**。下面这些前缀会被程序识别为手写编号并剥掉：
  `一、` `（一）` `(一)` `1.` `1、` `(1)` `（1）` `1.1` `第一章` `第二节` `第三部分`。
  标题正文本身恰好以这类字样开头时（如“一是……”不受影响），换个说法避开。
- 不要跳级：`##` 下面接 `####` 会出现“一、”下面直接“1.”。
- `######` 及更深层级不编号，不要用。
- 标题独占一行，末尾一般不加句号。
- 公文里三、四级标题有时习惯与正文同段（“1.要素核对。本单位……”）。需要这样排时
  不要用 `####`，直接写成一个正文段落、把小标题**加粗**即可：`**要素核对。**本单位……`，
  但此时编号要手写，且不会被程序统一管理，只在确有必要时用。

## 3. 段落

- 段与段之间**空一行**。
- 连续的非空行会被接成同一个自然段（中文之间不插空格），所以一段话折成几行写也行。
- 每段自动首行缩进两字、两端对齐，不要在行首打空格或全角空格。
- 不要用空行做“视觉间隔”，程序的段距是固定的；连续多个空行等同于一个。

## 4. 行内格式

| 写法 | 效果 |
|---|---|
| `**文字**` 或 `__文字__` | 着重（按用户设置排黑体或加粗）。 |
| `（说明）` `(API)` `【注】` | 成对括号内的文字**自动排楷体**，无需任何标记。 |
| `\*` `\_` `\|` 等 | 反斜杠转义，输出字面字符。 |

- 加粗要成对，且不要跨段。一段里加粗不宜超过一两处，公文讲究克制。
- 括号必须配对才切楷体；不配对的孤立括号照普通文字排。
- 不支持斜体、删除线、下划线、行内代码的特殊排版（反引号内的文字按正文排，但没必要用）。
- 引号用中文全角“”‘’，书名号《》，省略号……，破折号——，数字与单位用阿拉伯数字。

## 5. 列表

- `1. 内容` 与 `- 内容`（或 `* 内容`）**效果相同**：公文不区分有序无序，一律编号。
  源码里可以全写 `1.`，程序按组内位次重排；首项写几就从几开始。
- 列表前**空一行**：每项独立成段，默认编“1. 2. 3.”。
- 列表**紧跟在正文行后面不空行**：各项并入上一段，编成“①②③”接排。
  适合“主要有以下几项：”之类的段内枚举。
- 末尾标点自动归一：任一非末项以分号结尾，则中间项全部改分号、末项改句号；
  否则全部改句号。按这个规律写即可，不必逐项纠结。
- **不支持嵌套列表**，缩进的子项会被当成普通行。需要层级就用标题。
- 白头件、红头呈批件**不得使用列表**，段内枚举写成“一是……；二是……；三是……。”。

## 6. 表格

标准 GFM 管道表：表头行 + 分隔行 + 数据行，每行用 `|` 开头和结尾。

```markdown
| 序号 | 单位名称 | 事项总数 | 完成率 |
| --- | --- | ---: | :---: |
| 1 | 示例单位一 | 126 | 93.7% |
```

- 分隔行的冒号决定列对齐：`---` 自动，`:---` 左，`---:` 右，`:---:` 居中。
  数字列建议右对齐。
- 列宽由程序按内容自动计算，不要为对齐源码而补空格（补了也无妨）。
- 表格前后空一行；表格中间不能有空行，遇到空行或非 `|` 开头的行即视为表格结束。
- 单元格内不能换行，也不支持在格内写列表；长文字直接写，程序自动折行。
- 表格跨页自动续表，不要手工拆表。
- 公文表格没有自动表题。需要表题时在表格上方单独写一行，并用居中标记（见第 7 节）。

### 合并单元格

| 写法 | 含义 |
|---|---|
| `\| 甲 \|\| 乙 \|` | 两根竖线之间为空 = 与**左边**单元格横向合并（甲占两列）。 |
| `\| ^^ \|` | 单元格只写 `^^` = 与**上方**单元格纵向合并。 |

```markdown
| 类别 | 项目 | 金额 |
| --- | --- | ---: |
| 办公费 | 纸张 | 1200 |
| ^^ | 耗材 | 800 |
| 合计 || 2000 |
```

- `^^` 纵向合并时，其宽度（含右侧的 `||`）要与上方单元格一致。
- 普通空单元格请写成 `|  |`（竖线之间留空格），**紧挨着的 `||` 会被当成合并**。

### 序号表

常见的“序号 + 标题 + 内容 + 备注”分组表，在表格**正上方**加一行标记，程序自动编号、
自动合并分组行：

```markdown
<!-- [序号表] -->
| 序号 | 事项 | 责任单位 | 完成时限 |
| --- | --- | --- | --- |
| 重点工作 |||
|  | 完成年度计划编制 | 办公室 | 2026年3月底 |
|  | 组织专题培训 | 人事处 | 2026年5月底 |
| 常规工作 |||
|  | 做好日常督办 | 督查室 | 全年 |
```

- **分组行**：首格写组名、其余格留空（写成 `| 组名 |||` 或 `| 组名 |  |  |  |`）。
  程序整行合并、靠左，并补“（一）”之类的组编号。
- **数据行**：首列留空，程序按组编号 1、2、3……；文字写在第二列起。
- 表头首格留空会自动填“序号”。
- 标记只管紧挨着的下一张表，中间只能隔空行。

## 7. 居中与居右

```markdown
<!-- [居中] -->
居中的第一行
居中的第二行

<!-- [居右] -->
——摘自《××讲话》

空行之后恢复正常排版。
```

- 标记下方**直到空行**为止，每行单独成行，整行居中或贴右，不缩进。
- 区内只认加粗和括号楷体，`#`、`1.`、表格竖线都按普通文字。
- 也认 `<!-- [右对齐] -->`、`<!-- [center] -->`、`<!-- [right] -->`。
- 用途：表题、题词、引文出处、特殊落款。**正常的落款和日期由程序生成，不要用居右手写。**

## 8. 图片

```markdown
![图注](images/chart.png)
```

- 必须**独占一行**，前后空行。
- 路径相对于稿件，公文助手把图片存在 `images/` 下。支持 PNG / JPG / WebP / BMP / GIF / PDF。
- 只有用户确实提供了图片文件时才写；没有图片时不要编造图片引用，改用文字描述或
  `【待核实：此处插入××示意图】`。

## 9. 占位与其他字符

- `【待核实：具体事项】`：事实不确定时的占位。程序在审校面板逐条列出，必须落实后才能签发。
- 需要示意数字时写 `【待核实：示意约××，须核实替换】`，不要写看似真实的数字。
- 中文日期：正文中写“2026年8月20日（星期四）”；成文日期在要素表单里，不写进正文。

## 10. 不支持 / 不要用的写法

| 写法 | 原因 |
|---|---|
| YAML frontmatter（`---` 包的元数据） | 要素在程序表单里填，写了会印到纸上。 |
| `---` / `***` 分隔线 | 公文没有分隔线，版记横线由程序画。 |
| 代码块 ```` ``` ```` | 按正文排版，没有意义；交付文件里更不能有外层围栏。 |
| `> ` 引用块 | 不识别，`>` 会原样印出。 |
| HTML 标签 | 不识别或被跳过。 |
| 链接 `[文字](url)` | 原样印出方括号，公文不放超链接。 |
| 嵌套列表、任务列表 | 不识别。 |
| `$公式$`（公文文种） | 公文里 `$` 是普通字符；公式只在研究报告里可用。 |
| 行首空格缩进 | 程序自动缩进，手打的空格会被吃掉或造成错位。 |
| emoji、特殊符号装饰 | 不符合公文规范。 |
