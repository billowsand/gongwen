# 研究报告 Markdown 规则

研究报告在公文助手里按研究报告规范输出 PDF 与 Word：有封面、可选目录、分章正文、
附录、交叉引用、文献引用、脚注、表题和 LaTeX 数学公式。

预览（起草页纸面）、Word、PDF 三条链多数写法一致，不同的只有三处，正文里分别注明：
**普通代码围栏**（Word 不排代码块，见「代码」一节）、**行内代码**（预览与 Word 不换等宽字）
和 **Word 版的软换行与列表合段**（见「段落与列表」）。版式以 PDF 为准。

## 封面信息不写进正文

密级、保密期限、文件类型、文件编号、版本稿次、标识行、署名行、外文原题、撰写单位、
撰写时间、参考文献库（BibTeX），都在程序的“文档要素”里填，**正文不要重复**，也不要写
YAML frontmatter。

## 整体结构

```markdown
# 报告题名

<!-- [目录] -->

<!-- [摘要] -->

摘要正文，一至三段。

<!-- [正文] -->

## 研究背景

### 问题的提出

#### 政策依据

##### 上级文件要求

<!-- [附录] -->

## 附录一的标题

<!-- [附录] -->

## 附录二的标题

<!-- [版本变更记录] -->

## 版本变更记录

| 版本 | 日期 | 说明 |
| --- | --- | --- |
| V1.0 | 2026年3月 | 初稿 |

<!-- [参考文献] -->

## 参考文献
```

- `# 报告题名`：**正文区段里的第一个 `#`**（正文区段＝文首到第一个区段标记之间，或
  `<!-- [正文] -->` 之后）。它只供封面取用——「文档要素」的“文件名称”留空时才拿它当
  封面题名——正文版面不再排。已提供具体报告名称时原样使用；未提供名称或只有“研究报告”
  “调研报告”等文种名称时，根据写作要求中的研究对象与核心问题拟出具体题名，不得照抄
  文种名或“报告题名”占位文字。
  **全文只写一个**：再写第二个 `#` 且其后没有区段标记，导出时它会被当成一个普通章
  （“第N章”），预览里则两个都不排，版面对不上。
- 层级：`##` 章、`###` 节、`####` 小节、`#####` 四级小节。**最多用到 `#####`**——
  正文里六级及以下标题不排，附录里会压成同一级节。**标题不手写编号**（不写“第一章”
  “1.1”），程序按层级自动编号。
- 区段标记（独占一行）：

  | 标记 | 区段 | 也认的写法 |
  |---|---|---|
  | `<!-- [目录] -->` | 在此处排目录（可选；不写就没有目录；只认第一处） | `toc`、`contents`、`tableofcontents` |
  | `<!-- [摘要] -->` | 摘要 | `abstract` |
  | `<!-- [正文] -->` | 正文起始 | 无（只认中文“正文”） |
  | `<!-- [附录] -->` | 一份附录的起点，每份附录前各写一个，其后 `## 附录标题`，附录编号由程序生成 | `appendix`、`附件` |
  | `<!-- [版本变更记录] -->` | 其后写 `## 版本变更记录` 作为该节标题 | `changelog` |
  | `<!-- [参考文献] -->` | 其后写 `## 参考文献`，文献表由 BibTeX 自动生成，**不要手写文献条目** | `references`、`reference` |
  | `<!-- [部分] -->` | 其后每个 `#` 开一个部分（见下节） | `part` |
  | `<!-- [不编号] -->` | 管紧随标题连同其下级（见下节） | `unnumbered`、`nonumber`、`no-number`、`no_number` |
  | `<!-- [序号表] -->` | 紧随的那张表按序号表排（同公文） | `numbered-table`、`numbered_table`、`numberedtable`、`序号表格` |
  | `<!-- [居中] -->` / `<!-- [居右] -->` | 其下到空行为止逐行居中 / 居右 | `center` / `right`、`右对齐` |

- 方括号可以省略、也可以写成全角 `【】`，标签大小写不敏感（`<!--abstract-->`、
  `<!-- 【摘要】 -->` 都认）。
- **英文标签只用上表列出的**。“正文”只认中文：`body` 预览认、导出不认；
  `version`、`bibliography`、`attachment` 只有预览认，`reference` 只有导出认——写了
  就会出现“预览与 PDF 不一致”的毛病。**统一写中文最稳。** 自检脚本对
  `contents`、`tableofcontents`、`reference` 会提醒“不认识的标记”，目录一律写
  `<!-- [目录] -->`。
- 标记行不落版面。目录常见位置是封面之后、摘要之前，也可放在摘要与正文之间；目录页
  用大写罗马页码 I、II、III，摘要插在目录之后时用小写罗马页码 i、ii。
- 研究报告里 `<!-- [附件] -->` 与 `<!-- [附录] -->` 同义，统一用 `<!-- [附录] -->`。

## 题名、部分、附录的 `#`

`#` 的身份由它所在的区段决定，三个区段三种含义，别混：

| 位置 | `#` 是什么 | 编号 |
|---|---|---|
| 正文区段（文首，或 `<!-- [正文] -->` 之后） | 报告题名，归封面，正文版面不排 | 无 |
| `<!-- [部分] -->` 之后 | 一个部分 | “第一部分”“第二部分”由程序生成 |
| `<!-- [附录] -->` 之后 | 该附录的章标题（与 `##` 同等，写 `## 附录标题` 也行） | “附录A”“附录B” |
| 摘要、版本变更记录、参考文献区段 | 不是题名也不是章：该节的首个标题被当成节标题（摘要的首个标题由程序自己印“摘要”，写了会被吞掉） | 无 |

- 报告题名必须写在 `<!-- [部分] -->` **之前**；`<!-- [部分] -->` 之后的 `#` 一律是部分，
  不是题名。
- `<!-- [附录] -->`、`<!-- [参考文献] -->`、`<!-- [正文] -->` 等区段标记都会结束部分段。
- 摘要区段不写标题行（程序自己印“摘要”）；版本变更记录、参考文献区段只写
  `## 版本变更记录`、`## 参考文献` 这样的二级标题，**三个区段里都不要用 `#`**。

## 部分与不编号标题

篇幅长、要分成几大部分时，写一个 `<!-- [部分] -->`，其后**每个 `#` 开一个部分**，
`##` 起照常是章、节：

```markdown
# 报告题名

<!-- [不编号] -->
## 前言

<!-- [部分] -->

# 现状分析

## 研究背景

# 对策建议

## 总体思路

<!-- [不编号] -->
## 结束语

<!-- [附录] -->

## 附录标题
```

- 部分标题独占一页，编号“第一部分”“第二部分”由程序生成，**标题不写“第一部分”**。
- 章号跨部分连续：上例是“第1章 研究背景”“第2章 总体思路”。
- `<!-- [不编号] -->` 写在标题**上一行**（中间只许隔空行，隔了别的行就不生效），管这个
  标题连同它的全部下级标题；遇到同级或更高一级的标题自动恢复编号，不用收尾。不编号标题
  不占章节号，照样进目录。
- 图、表题注**全文连续编号**（表 1、表 2……图 1、图 2……），不按章节，也不分编号章
  与不编号章。文框仍按章编号；不编号章里的文框不带章号，全篇不编号章共用一套流水号
  （每种文框名称各一套）。
- 部分标题可挂锚点 `{#part:xz}`，`{@part:xz}` 引出的是“一”，“第…部分”自己写。
- **不编号标题不要挂锚点**：挂上去也引不出号（预览印 `??`）。锚点只挂在引得出号的块上：
  编号的部分、章、节，有图注的图片、有图题的 Mermaid 图、有表题的表、文框首行。

## 锚点与交叉引用

| 写法 | 含义 |
|---|---|
| `{#id}` | 锚点，写在标题、表题或图片行的**行尾** |
| `{@id}` | 引用该锚点的编号 |

```markdown
## 研究背景 {#sec:bg}

如 {@sec:bg} 所述……，详见表 {@tbl:plan}，见图 {@fig:flow}。
```

- `{@id}` 只印**号**，不印“第…章”“图”“表”“案例”这些字：写“见第{@chap:bg}章”
  “详见图{@fig:flow}”“如案例{@case:city}所示”。引出的是：部分“一”、章“1”（附录里
  是“A”）、节“1.1”、图/表“1”（全文流水号）、文框“2.1”。
- id 以英文字母开头，其后可含字母、数字、`_` `:` `.` `-`（汉字也收，但不要用）。起名
  习惯是前缀按对象取：部分 `part:`、章 `chap:`、节 `sec:`、图 `fig:`、表 `tbl:`、文框按
  名称（专栏 `box:`、案例 `case:`、例子 `ex:`，其他名称取名称拼音），冒号后写标题的拼音，
  如 `chap:yanjiu-beijing`、`fig:zongti-jiagou`。公文助手「研报 › 锚点」按钮起的 id
  就是这个样子；id 本身随意，只要全文唯一、定义与引用一致。**用户或任务已经指定了 id
  就照原样用。**
- **全文每个 id 只能定义一次**，同名时加 `-2`、`-3` 区分。
- 下面四种写法会让导出**直接中止**（交叉引用检查不通过）：
  同一个 id 定义两次；`{@id}` 引用了不存在的锚点；锚点没挂到标题、表题、图片行或文框
  首行上（挂在普通段落、引文上不行）；锚点在图上但图片没有图注、或图片没有独占一行。
- 已定义但没人引用的锚点只提示，不影响导出。

## 文献引用

- 写法 `[@key]`，多篇 `[@key1; @key2]`，key 对应 BibTeX 条目的键。导出后序号印成**上标**，
  紧贴前一个字，所以写在句号、逗号等标点**前面**：`……研究表明[@key]。`，不要写成 `。[@key]`。
  同一组序号从小到大排，三个及以上连号压成区间（`[1–3]`）。
- 序号作句子成分时（“见文献[1]”“王某等[1]认为”）写成不带方括号的 `@key`：
  `见文献@key`、`王某等@key认为`，序号与正文平排。这种写法的 key 须以英文字母或下划线开头；
  key 不在文献库里时 `@key` 会原样印出，不算引用（正文里的账号、邮箱因此不受影响）。
  确实要印一个与 key 同名的 `@…` 时写 `\@…`。
- **`[@key]` 里的每个 key 都必须在文献库里**：key 不在库里、或整篇没有文献库时写 `[@key]`，
  导出会中止（提示“Bib 文件缺少引用键…”）。**只能引用用户提供的 BibTeX 里确实存在的 key，
  绝不编造。**
- 没有文献库时不要写任何引用（包括 `@key`）。
- 如果任务要求你同时整理文献库，可另外输出一份 `references.bib`（标准 BibTeX），由用户
  粘贴到程序的“文献内容”里。用「从文件夹新建研究报告」导入时，只有**排序第一份** `.md`
  的 YAML frontmatter 里写了 `bibliography: references.bib` 才会读入这份 `.bib`（frontmatter
  是那个入口的机制，普通起草稿仍不要写）；否则单独放在旁边的 `.bib` 不会被读。

## 脚注

行内脚注：`[^id]:(脚注内容)`，全角写法 `[^id]：（脚注内容）` 也可。

```markdown
样本来自三省六市[^s1]:(样本采集时间为2025年6月至8月。)，共计……
```

- 脚注内容里不能再出现同种右括号（不支持嵌套），也不要把脚注写在 `**加粗**` 里面。
- 只写 `[^id]` 不带内容的写法不生效，会原样印出。
- 脚注是页下注；文框与表格单元格里的脚注印成全角括注。

## 表格与表题

表题写在表格**正上方**一行，以 `表：` 开头，可带锚点：

```markdown
表：三省样本分布 {#tbl:sample}

| 省份 | 样本数 | 占比 |
| --- | ---: | ---: |
| 甲省 | 320 | 40.0% |
```

- 表号由程序生成，全文连续流水（表 1、表 2……），不按章节；表题里不写“表1”
  （写了也会被剥掉，但别写）。半角冒号 `表:`、`Table:` 也认，统一用全角即可；
  表题与表格之间只许隔空行和 `<!-- [序号表] -->` 标记行。
- 表格合并（`||`、`^^`）、格内换行（`<br>`）与序号表（`<!-- [序号表] -->`）写法同公文，见
  [markdown-syntax.md](markdown-syntax.md)；有表题时表题写在序号表标记行上方。
- 没有表题的表格不编号，也不能引用。

## 图片

```markdown
![图题](images/flow.png){#fig:flow}
```

图片独占一行，alt 文字即图题，图号由程序生成（排成“图 1　图题”，与表号各自
全文连续流水，不按章节）。行尾只挂
`{#id}` 锚点，**不要写宽度、尺寸之类属性**。只在用户提供了图片时使用；没有图注的图片
不编号，也不能挂锚点。图宽、缩放由程序按图的比例统一决定。

## Mermaid 图表

图表可直接写在 Markdown 正文，预览与导出均由本机 Rust 引擎生成。图题紧跟结束围栏，
图号由程序生成；有交叉引用时在图题末尾挂锚点。

````markdown
```mermaid
flowchart LR
  A[资料收集] --> B[分析研判] --> C[形成建议]
```
图：研究工作流程 {#fig:process}

详见图 {@fig:process}。
````

支持流程（泳道用 `subgraph` 分组）、序列、甘特、饼、时间线五种，写法见
[markdown-syntax.md](markdown-syntax.md) 第 9 节；饼图中文扇区名加英文引号。围栏必须写成
```` ```mermaid ````，结束围栏是单独一行 ```` ``` ````。图内不写配置指令（`%%{init}%%`）、
HTML 和点击链接（`click`），配色、线宽、字号一律由“图表样式”统一控制；其余图种
（含桑基图、雷达图）暂不支持。不写图题时图不编号。图中文字使用黑体五号（10.5 pt），
刻度和标签同号，节点文字尽量简短，多环节流程优先纵向 `flowchart TD`；超出版心会缩小后
继续显示，预览和导出均提示实际字号低于要求，建议调整或拆图。

## 引文与文框

大段照录政策原文、讲话、法规条文、访谈原话时写成**引文**：每行以 `> ` 开头，
出处另起一行、以 `——` 开头。排成楷体、左右各缩进两字的独立引文，出处靠右，
不自动加引号。

```markdown
> 坚持统筹发展和安全，……推动公共数据有条件无偿使用。
>
> ——《××关于加快公共数据资源开发利用的意见》
```

案例、国外经验、典型做法、名词解释、例子这类与主线论证分开的材料写成**文框**：
首行 `> [!名称] 标题`，方括号里的名称写什么印什么（专栏、案例、例子、做法……），
行尾可挂锚点，其后每行以 `> ` 开头。排成带细框、浅灰底的方框，标题行印
“案例 2.1　标题”。**每种名称各编各的号**，按章编号（章号.序号，不编号章里
是流水号，附录里是 A.1；图表题注不同，是全文连续流水号），文框不占表号。

```markdown
> [!案例] 某市“场景牵引”授权运营做法 {#case:city}
>
> 一是先定场景、后给数据。……
>
> 二是运营机构分场景准入。……

> [!专栏] 新加坡的数据治理经验 {#box:sg}
>
> ……
```

- 上例两个框分别印“案例 2.1”“专栏 2.1”。同一篇里名称要写得一致，“案例”和
  “典型案例”会被当成两种，各编各的号。
- 正文里写“见案例{@case:city}”引用，印成“见案例2.1”；名称自己写，程序只填号。
- 标题可以不写（`> [!例子]`），这时标题行只印“例子 2.1”。
- 块内一行一段，空的 `>` 行只起分隔作用；空行（不带 `>`）结束整块。块内可写列表
  （`> - 内容`，编号 ⑴ ⑵ 由程序生成）、加粗、脚注、文献引用和行内公式；
  **不写标题和表格**，引用块也不进章节编号。`> >` 嵌套引用不排，压成一层。
- 行首 `>` 后要有空格才算引用，`>5%` 仍是正文；行首要写字面的 `>` 时写成 `\>`。
- 文框首行是唯一能挂锚点的引用块；**引文不编号，不能挂锚点**。
- 只有资料里确有原文时才写引文，引文内容必须与原文一致；拿不准写
  `【待核实：核对原文】`。

## 数学公式

- 行内：`$E=mc^2$`。正文、标题（含封面题名）、引文、文框、表格单元格里都能写。
- 独立公式：`$$...$$` **单独成一段**（前后空行）：

  ```text
  $$\int_0^1 x^2\,dx = \frac{1}{3}$$
  ```

- 居中 / 居右区、引文、文框里整行写 `$$...$$` 也是独立公式（对齐区跟着该行对齐，
  引文、文框里居中）；行中间的 `$$` 不算公式。

- 支持 amsmath / mathtools / amssymb 常见构造：分数、上下标、根式、求和、积分、矩阵
  （`matrix`/`pmatrix`/`bmatrix`/`vmatrix`/`Bmatrix`/`Vmatrix`）、`cases`、`array`、
  `aligned`、`align`、`gather`、`split`、`\substack`、`\mathbb{...}` 黑板粗体、
  `\mathcal{...}` 花体、`\mathfrak{...}` 哥特体、`\boldsymbol{...}`、`\textcolor{...}`、
  `\operatorname{...}`、`\varnothing`、`\leqslant`、`\therefore` 等符号。
- `\mathscr{...}` 也能排，但与 `\mathcal{...}` 是同一套花体字形，直接用 `\mathcal` 即可。
- 不要用库外命令：`\bm`、`\mathrsfs` 之类要额外宏包的命令排不出来，导出时**整条公式按
  源码原样印出**，并在提示里指出是哪一条。
- 字面美元符写成 `\$`。公式里尽量不夹中文；确需时用 `\text{中文}`（预览与导出都能渲染，
  中文走随包字体的回退字形）。
- 公式由本机排版器排成矢量图形，放大不失真，但不能像正文那样选中复制；预览与 PDF 用
  同一个排版器，预览里看到的就是 PDF 上的那一行。

## 代码

- **普通代码围栏（```` ```text ````、```` ```python ```` 之类）三条链结果不同，正文里不要写。**
  - PDF：排成代码块——JetBrains Mono 五号、浅灰底、细框、左侧灰色行号，不排编程连字。
  - 预览：与 PDF 同样排成代码块，围栏里的内容原样显示（`## 标题`、`{@id}` 都不生效）。
  - Word：每一行按正文段落排（方正书宋四号、整体左缩进），没有等宽字体、框线和行号。
  - 技能包自检脚本（`scripts/check_gongwen_md.py`）只放行 ```` ```mermaid ````，其余围栏
    一律报错。
  研究报告的正文以段落为主，要分点就用列表或“一是……二是……”。
- 唯一该用的是 ```` ```mermaid ```` 围栏（见上节）。
- 行内代码 `` `x` ``：PDF 排等宽字，Word 与预览按正文字面排（反引号不显示）。三处都把
  反引号里的内容当字面：`` `{@id}` ``、`` `$x$` `` 不会被当成引用或公式。技术名词、文件名
  可以这样写，正式表述仍建议直接用文字。

## 段落与列表

- 普通正文只换行、不空行时仍是同一自然段：预览与 PDF 接成一段，**Word 版按行成段**。
  想让 Word 也成一段，就别在句中换行。
- 列表紧接正文、不空行时合入段内（预览与 PDF；Word 仍各自成段）；列表前空一行时
  三处都独立成段。预览与 PDF 使用同一套编号设置、起始序号和末尾标点规则。
- 研究报告可以用列表，但正式文本仍建议以段落为主；“一是……二是……”这类段内枚举
  比项目符号更像成稿。
- 段落、加粗、居中居右的写法与公文相同，见 [markdown-syntax.md](markdown-syntax.md)。
- 不得输出原始 LaTeX 命令（公式除外）和 HTML，也不写 `---` 分隔线、页码或版式符号。

## 多文件分章导入

分章写作时，可以输出多个 `.md` 文件（按**文件名升序**合并，如 `01-摘要.md`、
`02-背景.md`，只取文件夹**第一层**，子目录不进），连同 `images/` 一起放在一个文件夹里，
用户在公文助手里用「从文件夹新建研究报告」一次合成：

- 合并后**全文第一个 `#` 标题**被当作报告名并从正文删去（通常是第一篇的顶层 `#`），
  其余内容照搬；
- 只有排序第一份可以写 YAML frontmatter（`密级`、`文件类型`、`文件编号`、`文件版本号`、
  `撰写单位`、`撰写时间`、`文件名称` 等封面字段，以及 `bibliography: references.bib`）；
  第二份起再写 frontmatter 会直接报错中止导入；
- 正文里引用的本地图片按相对路径复制进稿件，缺图只提示、不阻断导入；
- 各篇里都可以继续用区段标记、章节层级、锚点、表题、文框、公式等全部写法；分篇不影响
  编号，编号按合并后的全文统一算。
