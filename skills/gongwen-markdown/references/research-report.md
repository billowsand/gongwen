# 研究报告 Markdown 规则

研究报告在公文助手里按研究报告规范输出 TeX / PDF 与 Word：有封面、可选目录、分章正文、
附录、交叉引用、文献引用、脚注、表题和 LaTeX 数学公式。

## 封面信息不写进正文

密级、保密期限、文件类型、文件编号、版本稿次、标识行、署名行、外文原题、撰写单位、
撰写时间、参考文献库（BibTeX），都在程序的“文档要素”里填，**正文不要重复**，也不要写
YAML frontmatter。

## 整体结构

```markdown
# 报告题名

<!-- [目录] -->

<!-- [摘要] -->

摘要正文，一至三段。

<!-- [正文] -->

## 第一章标题

### 第一节标题

#### 小节标题

##### 四级小节标题

<!-- [附录] -->

## 附录一的标题

<!-- [附录] -->

## 附录二的标题

<!-- [版本变更记录] -->

## 版本变更记录

| 版本 | 日期 | 说明 |
| --- | --- | --- |
| V1.0 | 2026年3月 | 初稿 |

<!-- [参考文献] -->

## 参考文献
```

- `# 报告题名`：文首至多一个，文字与文件名称一致；它只供封面取用，正文版面不再排。
- 层级：`##` 章、`###` 节、`####` 小节、`#####` 四级小节。**标题不手写编号**（不写“第一章”“1.1”）。
- 区段标记（独占一行）：

  | 标记 | 区段 |
  |---|---|
  | `<!-- [目录] -->` | 在此处排目录（可选；不写就没有目录；只认第一处） |
  | `<!-- [摘要] -->` | 摘要 |
  | `<!-- [正文] -->` | 正文起始 |
  | `<!-- [附录] -->` | 一份附录的起点，每份附录前各写一个，其后 `## 附录标题`，附录编号由程序生成 |
  | `<!-- [版本变更记录] -->` | 其后写 `## 版本变更记录` 作为该节标题 |
  | `<!-- [参考文献] -->` | 其后写 `## 参考文献`，文献表由 BibTeX 自动生成，**不要手写文献条目** |

- 目录常见位置是封面之后、摘要之前；也可放在摘要与正文之间。

## 部分与不编号标题

篇幅长、要分成几大部分时，写一个 `<!-- [部分] -->`，其后**每个 `#` 开一个部分**，
`##` 起照常是章、节：

```markdown
# 报告题名

<!-- [不编号] -->
## 前言

<!-- [部分] -->

# 现状分析

## 研究背景

# 对策建议

## 总体思路

<!-- [不编号] -->
## 结束语

<!-- [附录] -->

## 附录标题
```

- 部分标题独占一页，编号“第一部分”“第二部分”由程序生成，**标题不写“第一部分”**。
- 章号跨部分连续：上例是“第1章 研究背景”“第2章 总体思路”。
- 附录、参考文献等区段标记结束部分段；报告题名 `#` 写在 `<!-- [部分] -->` 之前。
- `<!-- [不编号] -->` 写在标题**上一行**，管这个标题连同它的全部下级标题；遇到同级或
  更高一级的标题自动恢复编号，不用收尾。不编号标题不占章节号，照样进目录。
- 不编号章里的图表题注不带章号，全篇不编号章共用一套流水号（前言“表1”、结束语“表2”）。
- 部分标题可挂锚点 `{#part:xz}`，`{@part:xz}` 引出的是“一”，“第…部分”自己写；
  不编号标题没有编号，**不要挂锚点**。

## 锚点与交叉引用

| 写法 | 含义 |
|---|---|
| `{#id}` | 锚点，写在标题、表题或图片行的**行尾** |
| `{@id}` | 引用该锚点的编号 |

```markdown
## 研究背景 {#sec:bg}

如 {@sec:bg} 所述……，详见表 {@tbl:plan}，见图 {@fig:flow}。
```

- id 以字母开头，可含字母、数字、`_` `:` `.` `-`。前缀按对象取：部分 `part:`、章
  `chap:`、节 `sec:`、图 `fig:`、表 `tbl:`、文框按名称（专栏 `box:`、案例 `case:`、
  例子 `ex:`），冒号后写标题的拼音，如 `chap:yanjiu-beijing`、`fig:zongti-jiagou`。
  公文助手「研报 › 锚点」按钮起的 id 也是这个样子。
- **全文每个 id 只能定义一次**：重复定义会让导出 PDF 中止。同名时加 `-2`、`-3` 区分。
- 引用的 id 必须真实存在，否则编译报错。

## 文献引用

- 写法 `[@key]`，多篇 `[@key1; @key2]`，key 对应 BibTeX 条目的键。
- **只能引用用户提供的 BibTeX 里确实存在的 key，绝不编造。** 没有文献库时不要写引用。
- 如果任务要求你同时整理文献库，可另外输出一份 `references.bib`（标准 BibTeX），
  由用户粘贴到程序的“文献内容”里，或与 .md 放在同一文件夹用「从文件夹新建研究报告」导入。

## 脚注

行内脚注：`[^id]:(脚注内容)`，全角写法 `[^id]：（脚注内容）` 也可。

```markdown
样本来自三省六市[^s1]:(样本采集时间为2025年6月至8月。)，共计……
```

- 脚注内容里不能再出现同种右括号（不支持嵌套）。
- 只写 `[^id]` 不带内容的写法不生效，会原样印出。

## 表格与表题

表题写在表格**正上方**一行，以 `表：` 开头，可带锚点：

```markdown
表：三省样本分布 {#tbl:sample}

| 省份 | 样本数 | 占比 |
| --- | ---: | ---: |
| 甲省 | 320 | 40.0% |
```

- 表号由程序生成，表题里不写“表1”。
- 表格合并（`||`、`^^`）与序号表（`<!-- [序号表] -->`）写法同公文，
  见 [markdown-syntax.md](markdown-syntax.md)；有表题时表题写在序号表标记行上方。

## 图片

```markdown
![图题](images/flow.png){#fig:flow}
```

图片独占一行，alt 文字即图题，图号由程序生成。只在用户提供了图片时使用。

## Mermaid 图表

图表可直接写在 Markdown 正文，预览与导出均由本机 Rust 引擎生成。图题紧跟结束围栏，
图号由程序生成；有交叉引用时在图题末尾挂锚点。

````markdown
```mermaid
flowchart LR
  A[资料收集] --> B[分析研判] --> C[形成建议]
```
图：研究工作流程 {#fig:process}

详见图 {@fig:process}。
````

支持流程（泳道用 `subgraph` 分组）、序列、甘特、饼、时间线五种，写法见
[markdown-syntax.md](markdown-syntax.md) 第 9 节；饼图中文扇区名加英文引号。图内不写
配置指令、HTML、点击链接和自定义样式，其余图种（含桑基图、雷达图）暂不支持。
配色按研究报告主题由程序统一控制。图中文字使用黑体五号（10.5 pt），刻度和标签同号。
节点文字尽量简短，多环节流程优先纵向 `flowchart TD`；超出版心会缩小后继续显示，预览和导出均提示实际字号低于要求，建议调整或拆图。

## 引文与文框

大段照录政策原文、讲话、法规条文、访谈原话时写成**引文**：每行以 `> ` 开头，
出处另起一行、以 `——` 开头。排成楷体、左右各缩进两字的独立引文，出处靠右，
不自动加引号。

```markdown
> 坚持统筹发展和安全，……推动公共数据有条件无偿使用。
>
> ——《××关于加快公共数据资源开发利用的意见》
```

案例、国外经验、典型做法、名词解释、例子这类与主线论证分开的材料写成**文框**：
首行 `> [!名称] 标题`，方括号里的名称写什么印什么（专栏、案例、例子、做法……），
行尾可挂锚点，其后每行以 `> ` 开头。排成带细框、浅灰底的方框，标题行印
“案例 2.1　标题”。**每种名称各编各的号**，口径与图表相同（章号.序号，不编号章里
是流水号，附录里是 A.1），文框不占表号。

```markdown
> [!案例] 某市“场景牵引”授权运营做法 {#case:city}
>
> 一是先定场景、后给数据。……
>
> 二是运营机构分场景准入。……

> [!专栏] 新加坡的数据治理经验 {#box:sg}
>
> ……
```

- 上例两个框分别印“案例 2.1”“专栏 2.1”。同一篇里名称要写得一致，“案例”和
  “典型案例”会被当成两种，各编各的号。
- 正文里写“见案例{@case:city}”引用，印成“见案例2.1”；名称自己写，程序只填号。
- 标题可以不写（`> [!例子]`），这时标题行只印“例子 2.1”。
- 块内一行一段，空的 `>` 行只起分隔作用；空行（不带 `>`）结束整块。
- 块内可写列表（`> - 内容`，编号 ⑴ ⑵ 由程序生成）、加粗、脚注、文献引用；
  不写标题和表格。文框里的脚注印成括注，行内公式照常排成公式。
- 行首 `>` 后要有空格才算引用，`>5%` 仍是正文；行首要写字面的 `>` 时写成 `\>`。
- 只有资料里确有原文时才写引文，引文内容必须与原文一致；拿不准写
  `【待核实：核对原文】`。

## 数学公式

- 行内：`$E=mc^2$`。正文、标题（含封面题名）、引文、文框、表格单元格里都能写。
- 独立公式：`$$...$$` **单独成一段**（前后空行）：

  ```text
  $$\int_0^1 x^2\,dx = \frac{1}{3}$$
  ```

- 居中 / 居右区、引文、文框里整行写 `$$...$$` 也是独立公式（对齐区跟着该行对齐，
  引文、文框里居中）；行中间的 `$$` 不算公式。

- 支持 amsmath / mathtools / amssymb 常见构造：分数、上下标、求和、积分、矩阵、
  `cases`、`\mathbb{...}` 黑板粗体、`\mathfrak{...}` 哥特体、`\varnothing`、
  `\leqslant`、`\therefore` 等符号。
- 不得使用未随包内置的宏包命令：`\mathscr`（mathrsfs）、`\bm`（bm）等会导致
  导出编译失败；花体字母一律用 `\mathcal` 代替。
- 字面美元符写成 `\$`。
- 公式里尽量不夹中文；确需时用 `\text{中文}`：顶层的 `\text`（含 `\mbox`、
  `\textbf` 等）预览用随包仿宋渲染，导出用正文字体；嵌在分数、上下标里的
  中文预览仍显示占位框，导出正常。

## 其他

- 不得输出原始 LaTeX 命令（公式除外）和 HTML。
- 段落、加粗、列表、居中居右的写法与公文相同。
- 研究报告可以用列表，但正式文本仍建议以段落为主。
- 分章写作时，可以输出多个 `.md` 文件（按文件名排序，如 `01-摘要.md`、`02-背景.md`），
  连同 `images/` 与 `references.bib` 放在一个文件夹里，用户在公文助手里用
  「从文件夹新建研究报告」一次合成：第一篇的顶层 `#` 标题被当作报告名，其余照搬。
