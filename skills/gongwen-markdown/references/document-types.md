# 九种文种的正文规则

公文助手每篇稿子先选一个文种。文种决定版式、要素表和正文能写什么。**要素（版头、文号、主送、落款、成文日期、版记、承办与联系人等）由用户在程序的“文档要素”表单里填，程序负责排版；模型只写正文 Markdown。**

本文逐文种给出：正文结构、结语、行文方向与力度词、能不能带附件、**绝对不能写进 Markdown 的要素**，以及模型最容易写错的地方。每条结论都对应程序里的提示词、校验器或审校规则，照抄即可。

---

## 通用规则（九种文种都适用）

- **第一行只有一个 `# 正式标题`**。附件标题也用 `#`，但必须写在 `<!-- [附件] -->` 之后；研究报告按“部分”分篇时，`<!-- [部分] -->` 之后的 `#` 是部分标题（见第 9 节）。**会议纪要例外**：纪要名称在表单里、印成红头，正文一般不写 `#` 标题，直接从 `<!-- [正文] -->` 开始（见第 6 节）。
- **标题不手写编号**：不写“一、”“（一）”“1.”“第一章”“1.1”。要层级就用 `#` 的数量。
- **标题不用标点**：书名号、引号除外；尤其不加句号、逗号、问号。标题末尾不自称别的文种（公函以“函”结尾、电话通知以“通知”结尾）。
- **正文标题层级**：`##` → 一、，`###` →（一），`####` → 1.，`#####` → (1)（第四级默认用半角括号，可在设置里改）。程序自动编号，标题文字里不写编号，标题末尾不加句号。
- **正文区段标记** `<!-- [正文] -->` 独占一行，写在主标题之后的正文开始处。白头件的输出范围只含标题和正文，可省略这个标记。
- **段落靠空行分隔**。连续几行会接成同一段；不要用空行把一句话切碎，也不要在行首打空格。
- **不写任何版头版记要素**：红头、密级和保密期限、份号、签发人、文号、主送抬头、落款单位、成文日期、抄送、承办单位、联系人、联系电话、页码、分隔线、版记横线。写了会在成品里重复出现或被程序当正文原样印出。
- **不编造**：文件号、领导批示、机构名称、人名、日期、数据和联系方式。缺依据的原位写 `【待核实：缺什么】`；送审前程序会把这些占位列为待办。
- **日期与时间**：相对日期（今天、明天、下周）换算成“YYYY年M月D日（星期X）”；时间用 24 小时制“14:30”，不写“下午14:30”；日期与星期必须对得上。
- **表格**用标准 GFM 管道表（表头行 + `| --- |` 分隔行 + 数据行），每行列数一致；单元格内要分行写 `<br>`，不要真的回车换行。“序号 + 事项 + 单位 + 时限”的分组表，在表格正上方加一行 `<!-- [序号表] -->`。
- **输出只有 Markdown 正文**：不要代码围栏、YAML frontmatter、解释、修改清单或思考过程。

### 表单要素：只填在表单里，不写进正文

| 类别 | 要素 | 说明 |
|---|---|---|
| 版头版记 | 密级与保密期限、份号（公函、会议纪要有位置）、发文字号、签发人、成文日期、印发机关与印发日期 | 任何文种都不写 |
| 单位与人员 | 发文单位、主送单位、抄送单位、呈报领导、落款单位、承办单位、联系人、联系电话 | 任何文种都不写；AI 可以给建议，但值由用户在表单里确认 |
| 会议 | 会议时间、会议地点、参加人员 | 会议议程从素材提取后写进骨架，不另起“会议时间：”行 |
| 会议纪要 | 纪要名称（红头）、编号、出席、列席、请假、分送、印发机关与印发日期 | 名单与版记由程序排在正文之后，正文不写；会议时间、地点、主持人和出席范围只在首段概述里提 |
| 电话记录 | 本单位、来电单位、来电电话、谈话人及职务、通话时间、拟办建议、承办联系信息 | 电话记录单只写来电内容正文 |
| 研究报告 | 封面用的密级、文件类型、文件编号、版本稿次、撰写单位、撰写时间、参考文献库 | 正文不重复，也不写 YAML |

### 附件区段：只有五种文种可以带

**公函、电话通知、普通公文、会议纪要、红头呈批件**可以带附件区段。**白头件（呈批件）、会议议程、电话记录单**不带附件区段。研究报告不用附件，用“附录”（见第 9 节）。

写法固定：

```markdown
<!-- [附件] -->

# 附件正式标题

附件正文。附件内 `##`、`###` 与正文一样依次是两层标题。

<!-- [附件] -->

# 第二份附件的正式标题

附件正文。
```

- 每份附件前各写一个**独占一行**的 `<!-- [附件] -->`，紧接着写 `# 附件正式标题`（中间可以空一行）。
- 附件编号（“附件”“附件1、附件2……”）和附件内标题编号都由程序生成。**不写“附件1”，也不在标题里写“一、”“（一）”。**
- 附件里可以用标准 Markdown 表格；附件内标题编号从“一、”重新开始。
- **只有素材明确给出了附件全文时才写附件区段。** 素材里只是提到“另附表格”“随文报送××表”，不要凭名称臆造附件内容；这时最多在结语后手写一行附件说明（“附件：××表”）。
- 已经写了附件区段，**不要再手写“附件：1.…… 2.……”说明**，程序会按附件标题自动生成。
- 正文里引用“见附件2”时，实际内嵌附件不能少于 2 份；“附件3份”说的是印制份数，不是附件种类数，程序不会拿它核对。

## 1. 公函

**定位**：适用于商洽、征求意见、告知、答复等平行行文。**平行文。**

**版式**：函稿版式。有发文机关标识（红头）和版头，按表单填写的机关代字、年份、发文序号生成文号；只有公函的版头有份号位。可以走“联合发文模式1”（多家发文单位并列落款），由表单设置，正文不用写任何联合发文标记。

- 标题：`关于……的函`；答复来函时用 `关于……的复函`。标题不写标点（书名号、引号除外），末尾不加“请示”“通知”等别的文种词。
- 正文：`# 标题` → `<!-- [正文] -->` → 开头交代依据和事由（第一句进入正题）→ `## 事项`（可分 `###`）→ 明确请求 → 结语。
- 结语按语义选一个，单独成段：“特此函告。”“特此函复。”“特此函商，请予支持为荷。”“请予研究函复。”
- 语气：对方不是下属，用“请贵单位”“希望”“请予支持”；不用“要求”“责成”“务必”“严禁”去命令对方。
- 附件：素材给了附件全文才写。写法见上文“附件区段”；附件说明由程序生成，不手写。
- 不得出现：**密级和保密期限、发文机关标识（红头）、发文字号、主送单位抬头、落款单位、成文日期、抄送单位、承办单位、联系人、联系电话**。

**模型最容易写错的地方**

- 抬头：✗ 正文第一行写“市数据局：” → ✓ 主送单位在表单里选，正文直接从“为……”或“根据……”开始。
- 落款和日期：✗ 文末写“市数据局”“2026年10月18日” → ✓ 这两项由程序按表单排版，正文不写。
- 手写编号：✗ `## 一、共建事项` → ✓ `## 共建事项`；编号由程序生成。
- 把函写成命令：✗ “要求贵局务必于10月31日前反馈。” → ✓ “请贵单位于2026年10月31日前将意见函复我办。”
- 附件：✗ `# 附件1：共建方案` / 正文写“附件1、附件2” → ✓ `<!-- [附件] -->` 后写 `# 共建方案`，编号由程序加。
- 臆造附件：素材只说“另附共建方案”却没给内容 → ✓ 结语后写一行“附件：共建方案”，不编造方案全文。
- 引用别的公文时，文号写成《关于开展检查的函》（某办函〔2026〕12号）：年份用六角括号〔〕，外层用全角括号。这不是本稿的发文字号，不违反“不得出现文号”。

## 2. 电话通知

**定位**：沿用函稿版式，但不编机关代字、发文字号和底部版记。**下行文。**

**版式**：标题、正文、可选附件；主送单位和发文单位在表单里填。

- 标题：`关于……的通知`。标题不要写成“函”“请示”等其他文种。
- 正文：`# 标题` → `<!-- [正文] -->` → 通知事项 → 执行要求 → 时间节点 → 结语“特此通知。”。
- 语气：对下级用“要”“切实”“确保”部署工作；结尾交代谁督促落实、有问题向谁反映。对象不隶属于本单位时改用“希望”“请”，不用命令式。
- 附件：与公函写法相同，素材给了附件全文才写。
- 不得出现：**密级和保密期限、发文机关标识（红头）、机关代字、发文字号、主送单位抬头、落款单位、成文日期、抄送单位、承办单位、联系人、联系电话**。

**模型最容易写错的地方**

- 把通知写成商洽函：✗ “请贵单位研究后函复。” → ✓ 对下级写“请各单位于2026年10月20日（星期二）17:00前将名单报市局办公室。”
- 抬头和版记：✗ 正文写“主送：各县区林业局”或文末写联系人电话 → ✓ 主送和联系方式都在表单里，正文只写事项。
- 自己编文号：✗ 正文写“某林函〔2026〕12号” → ✓ 电话通知没有文号，正文不写。
- 时间：✗ “下周三下午3点” → ✓ “2026年10月21日（星期三）15:00”。
- 附件：✗ 在正文里写“附件：参会名单”又加附件区段 → ✓ 有附件全文就只写附件区段，附件说明由程序生成。

## 3. 电话记录单

**定位**：如实记录收到的电话通知，版式是来电记录表，不设红头、文号、主送或发文落款。

**版式**：**只写三样东西**：

```markdown
# 电话记录单

<!-- [正文] -->

来电内容正文。
```

- 本单位名称、来电单位、来电电话、谈话人及职务、通话时间、密级、保密期限、拟办建议、承办与联系信息，全部由界面表单填写并排版。正文不重复。
- 首长批示栏留空供人工填写：不写首长意见，也不编造领导决定。
- 如实保留来电通知的事项、要求和时间；通话内容里的相对日期按原话保留，不按导出当天换算（程序对电话记录单单独放行）。
- 不要改写成本单位下发的通知，不要虚构执行要求、承办意见或办理结果。
- 不带附件区段，不写落款、成文日期和结语式表态。
- 不得出现：**密级和保密期限、文号、红头、主送抬头、落款单位、成文日期、抄送单位、承办单位、联系人、联系电话、来电单位/电话/谈话人/通话时间/拟办建议、首长批示、附件区段**。

**模型最容易写错的地方**

- 改文种：✗ “现将有关事项通知如下” → ✓ “来电通知：……（照录原话）”。
- 把表单信息写进正文：✗ “来电单位：市应急局；谈话人：张三；通话时间：……” → ✓ 这些在表单里，正文只写来电内容。
- 编造批示或拟办意见：✗ “拟请领导批示后转办公室办理。” → ✓ 不写；首长批示栏由人工填。
- 改日期：✗ 把原话“明天上午9点”改成“2026年10月19日9:00” → ✓ 照录“明天上午9点”，记录单保留原话。
- 加附件：✗ 正文后写 `<!-- [附件] -->` → ✓ 电话记录单没有附件区段。

## 4. 普通公文

**定位**：无红头、无发文单位、无主送、无落款、无版记，只排标题、正文和可选附件。适合方案、办法、要点、总结、讲话稿、情况说明等。

**版式**：纯正文。整份可以横排（表单里的横页选项），正文不需要写任何横排标记。

- 标题按内容写，如“2026年度××工作方案”“关于××情况的说明”。标题末尾不加句号，标题里不用逗号、问号等标点（书名号、引号除外）。
- 正文：`# 标题` → `<!-- [正文] -->` → 开头段（依据、目的，第一句进入事由）→ `##` 大节 → `###` 小节。
- 行文方向由内容决定：写给下级的用“要”“切实”“确保”，写给上级的用“建议”“请”“恳请”，对象不明时力度词宁弱勿强。
- 可以用 `1.` 列表和序号表：列表前空一行时每项独立成段、编“1. 2. 3.”；列表紧接正文不空行时并入上一段、编“①②③”。“序号 + 事项 + 单位 + 时限”的分组表在表格正上方加 `<!-- [序号表] -->`，分组行首格写组名、其余留空，数据行首列留空。
- 附件：可以有，写法见上文“附件区段”。
- 不得出现：**密级和保密期限、发文机关标识（红头）、机关代字、发文字号、发文单位、主送单位、落款单位、成文日期、抄送单位、承办单位、联系人、联系电话**。

**模型最容易写错的地方**

- 按“通知”写：✗ 写主送抬头“各有关单位：” → ✓ 普通公文没有主送，正文直接进入事由。
- 加落款：✗ 文末写单位名称和日期 → ✓ 全部由表单控制，正文不写。
- 序号表标记和表格中间插了字：✗ `<!-- [序号表] -->` 与表格之间写一行说明 → ✓ 标记和表格之间只能有空行，否则不按序号表编号。
- 表格列数不齐：✗ 表头 4 列、某行 3 格 → ✓ 每行列数一致；空单元格写成 `|  |`。
- 把“序号表”当普通表：✗ 首列手写 1、2、3 或写“一、二、三” → ✓ 首列留空，程序编号。
- 标题手写编号：✗ `# 一、2026年度××工作方案` → ✓ `# 2026年度××工作方案`。

## 5. 会议议程

**定位**：固定骨架，用于会议时间地点、参加人员和议程安排。**只替换【】里的内容，不得改动字段名、字段顺序、编号体系或空行结构。**

```markdown
# 【会议标题】

一、时间地点：【YYYY年M月D日（星期X）HH:MM，会议地点。】

二、参加人员：【参加人员。】

三、研讨内容：

1. 【第一项议程；】
2. 【第二项议程；】
3. 【最后一项议程。】
```

- 第一行只能是一个 `# ` 标题，不加副标题；除第一行外不再用任何 `#` 标题。
- “一、时间地点”“二、参加人员”“三、研讨内容”各占一行、顺序不变；**不能改成 `##` 标题、表格或项目符号**。这是整个技能包里唯一允许手写“一、二、三”的地方。
- 时间地点写在同一行；日期具体到年月日和星期，时间用 24 小时制。
- 议程只用从 `1.` 开始的连续阿拉伯数字，每项一行，可增减项数；不得用“（一）”、项目符号或多级编号。
- 每项写清责任主体和动作；除最后一项以句号结尾外，其余各项以分号结尾。
- 不得增加会议目的、背景、工作要求、联系人、落款、日期、附件或说明等骨架外段落。
- 会议时间、地点、参加人员在表单里空着时，从用户素材里提取并做有限归纳（可把“明天下午2点30分”和“3C会议室”合并成标准时间地点，可把明确出现的主持人、汇报人、参会单位归入参加人员）；不得添加素材里没有的人名、单位、职务或参会范围。素材只能支持部分信息时，保留能确认的部分，其余原位写“【待核实：会议时间/会议地点/参加人员】”，不写“无”“未提供”。
- 不得出现：**密级和保密期限、文号、红头、主送抬头、落款单位、成文日期、抄送单位、承办单位、联系人、联系电话、附件区段**。

**模型最容易写错的地方**

- 字段改成标题：✗ `## 一、时间地点：……` → ✓ `一、时间地点：……`（普通文本行）。
- 议程用列表符号：✗ `- 汇报工作进展` → ✓ `1. 汇报工作进展；`（连续编号、分号结尾）。
- 加骨架外内容：✗ 在“三、研讨内容”后加“四、会议要求：……” → ✓ 只有三项议程，会议目的、背景、要求都不写。
- 时间写法：✗ “2026年8月20日下午2:30” → ✓ “2026年8月20日（星期四）14:30”。
- 缺信息写“无”：✗ “会议时间：待定” → ✓ “【待核实：会议时间】”。
- 加附件或落款：✗ 文末写单位、日期或 `<!-- [附件] -->` → ✓ 会议议程没有附件、落款和日期。

## 6. 会议纪要

**定位**：记载会议主要情况和议定事项。版头是红色纪要标志（如“××局会议纪要”）和编号“〔2026〕3号”，正文后列出席、列席、请假名单，末页底部是分送、抄送、印发版记——**这些全部由表单填写、程序排版**，正文只写会议情况与议定事项。

```markdown
<!-- [正文] -->

2026年10月20日上午，××主持召开××会议，听取××关于××的汇报，研究部署××工作。

会议认为，××。一是××。展开说明。二是××。展开说明。

会议要求，××。一是××。二是××。

会议明确，由××牵头××，××前报××审定。
```

- **一般不写 `# 标题`**：纪要名称在表单里，印成红头。只有专题纪要要在红线下单列标题时，才在第一行写 `# 关于××的专题会议纪要`（以“纪要”结尾，不要照抄红头上的纪要名称）。
- 首段概述会议六要素：时间、地点、主持人、出席范围、议题。只写素材和表单能确认的部分，其余写 `【待核实：……】`。
- 其后按“会议听取了……”“会议认为，……”“会议指出，……”“会议要求，……”“会议明确，……”“会议决定，……”分段，按素材实际取用，不必每样都写。
- 段内枚举写成“一是××。二是××。”：**每项先用一句话概括、以句号收住，再展开**。程序把“一是”到第一个句号（或分号）这一截自动排成楷体，所以概括句不要写得太长（超过 40 字就只有“一是”两字排楷体）。“一是”前面要是句号、分号、冒号或段首，写成“会议要求，一是……”不会排楷体。
- 不用 `- `、`* `、`1. ` 列表；议题多时可以用 `## 议题名称` 分节，程序编“一、二、三”，标题不手写编号。
- 附件：可以带，写法见上文“附件区段”；附件说明排在正文之后、名单之前。
- 行文方向由内容决定：“会议要求”部署下级用“要”“切实”，涉及不隶属单位用“请”。
- 不得出现：**纪要标志（红头）、编号、密级和保密期限、出席 / 列席 / 请假名单、分送、抄送、印发机关、印发日期、落款单位、成文日期**。

**模型最容易写错的地方**

- 写红头：✗ 第一行写 `# ××局会议纪要` → ✓ 纪要名称在表单里，正文从 `<!-- [正文] -->` 开始。
- 抄名单：✗ 文末写“出席：王局长、李副局长” → ✓ 名单在表单里填，程序按网格排。
- 写版记：✗ 文末写“分送：局领导”“××办公室　2026年10月20日印发” → ✓ 都在表单里。
- 用列表：✗ `1. 压实责任` → ✓ “一是压实责任。区民政局主要负责同志要亲自抓。”
- 概括句太长：✗ “一是要进一步加强组织领导、压实各级责任、强化统筹协调和督促检查确保各项任务落到实处。” → ✓ “一是压实责任。”后面再展开。

## 7. 白头件（呈批件）

**定位**：适用于内部情况报告、请示和领导呈批。无红头。**上行文。**

**版式**：只写标题和正文，不带附件区段。呈报领导、落款单位、密级等由表单填写并排版。

- 标题：`关于……的请示` 或 `关于……的报告`。呈批件只是版式，不等于请示；实际文种看标题。
- 正文结构：依据与概述 → `## 前期工作情况` → `## 下步工作建议` → 结语。大节用 `## 标题`，程序自动编“一、二、三”，标题文字不写编号。
- 段内枚举写成“一是……；二是……；三是……。”**不得使用 `- `、`* ` 或 `1. ` 列表。**
- 结语：标题自称“请示”的，用请求性结语“妥否，请批示。”“妥否，请指示。”或“特此请示。”；实为报告的，按报告写法收束，**不附加请示结语**。
- 语气：向上级提事项用“建议”“请”“恳请”，不用“要求”“务必”“责成”；谦辞在开头一次说完。
- 不得出现：**密级和保密期限、发文机关标识（红头）、发文字号、主送单位或呈报领导抬头、落款单位、成文日期、抄送单位、承办单位、联系人、联系电话**。白头件没有首页批示栏，也不要画批示框或写批示文字。

**模型最容易写错的地方**

- 用列表：✗ `- 完成前期调研` → ✓ “一是完成前期调研；二是形成工作方案；三是征求相关单位意见。”
- 加附件：✗ 正文后写 `<!-- [附件] -->` → ✓ 白头件只写标题和正文，没有附件区段。
- 抬头：✗ 第一行写“××领导：” → ✓ 呈报领导在表单里选，正文从依据写起。
- 落款和日期：✗ 文末写单位、日期 → ✓ 由程序按表单排版。
- 文种与结语对不上：✗ 标题“关于××情况的报告”，结尾却写“妥否，请批示。” → ✓ 报告按报告收束，不加请示结语；请示才必须有请求性结语。
- 手写编号：✗ `## 一、前期工作情况` → ✓ `## 前期工作情况`。
- 对上级用命令式：✗ “要求市政府予以支持。” → ✓ “建议市政府予以支持。”或“请市政府予以支持。”

## 8. 红头呈批件

**定位**：带发文单位红头、文号和首页批示栏的内部呈批件。**上行文。**正文业务结构与白头件一致。

**版式**：发文单位、呈批代字、文号、呈报领导、落款单位、承办单位、联系人、联系电话由表单填写；首页批示栏由程序排。承办信息最多 4 条，超过会挤占批示框和正文，正文里不写承办条目。

- 标题：`关于……的请示` 或 `关于……的报告`，规则同白头件。
- 正文结构：依据与概述 → `## 前期工作情况` → `## 下步工作建议` → 结语；标题文字不写编号。
- 段内枚举用“一是、二是、三是”，**不得使用 Markdown 列表**。
- 结语按实际文种区分请示与报告：请示用“妥否，请批示。”“妥否，请指示。”；报告不加请示结语。
- 附件：**可以带**，写法见上文“附件区段”；素材没给附件全文就不写附件区段。
- 不得出现：**密级和保密期限、发文机关标识（红头）、发文字号、呈报领导抬头、批示文字、落款单位、成文日期、承办单位、联系人、联系电话**；也不要画批示框。

**模型最容易写错的地方**

- 画批示框：✗ 在标题下画表格或方框写“领导批示：” → ✓ 批示栏由程序排，正文一个字都不写。
- 写文号：✗ 正文写“某呈〔2026〕5号” → ✓ 文号在表单里填，正文不写。
- 用列表：✗ `1. 完成前期调研` → ✓ “一是完成前期调研；二是……”。
- 附件没有标记：✗ 直接写 `# ××表` → ✓ 每份附件前先写独占一行的 `<!-- [附件] -->`。
- 承办信息写进正文：✗ 文末写“承办单位：办公室　联系人：张三　电话：……” → ✓ 最多 4 条承办信息都在表单里。
- 抬头：✗ 第一行写“××领导：” → ✓ 呈报领导在表单里，正文不写。

## 9. 研究报告

**定位**：按研究报告规范排封面、目录、章节、文献，与上面八种差别很大。完整规则见
[research-report.md](research-report.md)，模板见 [research-report.md 模板](../templates/research-report.md)。

- 文首至多一个 `# 报告题名`，文字与文件名称一致，只供封面取用，正文版面不再排。已给具体名称时原样使用；只给“研究报告”“调研报告”等文种名时，按研究对象和核心问题拟一个具体题名。
- 章从 `##` 开始：`##` 章、`###` 节、`####` 小节、`#####` 四级小节，标题不手写编号。
- 区段标记独占一行：`<!-- [目录] -->`（可选）、`<!-- [摘要] -->`、`<!-- [正文] -->`、`<!-- [附录] -->`（每份附录前各写一个，其后跟 `## 附录标题`）、`<!-- [版本变更记录] -->` 与 `<!-- [参考文献] -->`（其后各写一个同名的 `## 标题`）。
- 需要分部分时，在报告题名后写一个 `<!-- [部分] -->`，其后每个 `#` 开一个部分（“第一部分”由程序编号，标题不写）；前言、结束语等不编号的标题，在标题上一行写 `<!-- [不编号] -->`。
- 文献引用只使用资料中已经提供的 BibTeX 键：一般写成 `[@key]`（序号印在上标，写在句号、逗号等标点之前），作句子成分时写 `@key`；文献表由 BibTeX 自动生成，不手写文献条目，也不编造引用键。
- 图表：图片用标准 Markdown 图片语法，图题写在图片替代文本里；表题写在表格上一行的“表：题名”。数学公式可用 `$...$` / `$$...$$`。
- 不得出现：**YAML/frontmatter、密级、文件编号、版本号、撰写单位、撰写时间、封面要素、手写文献条目、编造的引用键、原始 LaTeX 或 HTML**。
- 研究报告不用附件区段：附录每份前写 `<!-- [附录] -->`，不是 `<!-- [附件] -->`。

**模型最容易写错的地方**

- 标题写成文种名：✗ `# 研究报告` → ✓ `# 公共数据授权运营机制研究`（或素材给出的具体名称）。
- 用 `#` 开章：✗ `# 研究背景` → ✓ `## 研究背景`（只有 `<!-- [部分] -->` 之后的 `#` 才是部分标题）。
- 手写编号：✗ `## 第一章 研究背景` / `## 1.1 研究背景` → ✓ `## 研究背景`。
- 封面信息写进正文：✗ 正文开头写“密级：秘密”“撰写单位：××研究室” → ✓ 这些在“文档要素”里填。
- 编文献：✗ 自己写参考文献列表或编一个 `[@zhang2024]` → ✓ 只见已给 BibTeX 里的键，文献表由程序生成。
- 附录写法错：✗ `<!-- [附件] -->` 或一个 `<!-- [附录] -->` 下挂多份附录 → ✓ 每份附录前各写一个 `<!-- [附录] -->`，后面跟 `## 附录标题`。
- 用 YAML 写元数据：✗ 文件开头 `---` → ✓ 不写 frontmatter，元数据在表单里。

## 文种选择参考

| 用户说的 | 选 |
|---|---|
| 给平级或不相隶属单位发的函、商洽、征求意见、复函 | 公函 |
| 通知下级开会、报材料、执行事项 | 电话通知（或普通公文） |
| 记录收到的电话通知 | 电话记录单 |
| 方案、办法、总结、讲话稿、情况说明、工作要点 | 普通公文 |
| 开会议程、会议安排 | 会议议程 |
| 会议纪要、办公会纪要、专题会纪要，整理会议议定事项 | 会议纪要 |
| 向本单位领导请示、报告、呈批 | 白头件（呈批件）；需要红头文号批示栏的用红头呈批件 |
| 调研报告、课题报告、咨询报告、方案论证、外文翻译 | 研究报告 |

用户若只想“写个通知”又没指定，普通公文最通用；拿不准就问。
