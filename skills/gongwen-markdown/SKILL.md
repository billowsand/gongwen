# 公文助手 Markdown 起草规范

公文助手是一个离线公文排版程序：**模型只写正文 Markdown，版头、文号、主送、落款、
成文日期、版记、页码、标题编号、字体字号全部由程序按国家公文格式自动生成**。你的
产物是一份 `.md` 文件（或一段 Markdown 文本），用户把它粘贴进起草页、或用「从文件
导入」打开，就能直接预览并导出 Word / PDF。

写错格式的代价是：编号重复（手写了“一、”又被程序编一次）、版头要素印两遍、附件
不分页、表格散架。所以**格式规则比文采优先**。

## 工作流程

1. **确定文种**。用户没说就按内容判断，拿不准时问一句。七种文种的差异见
   [references/document-types.md](references/document-types.md)，这是必读的。
2. **打开对应模板**，在骨架上写：
   | 文种 | 模板 |
   |---|---|
   | 公函 | [templates/official-letter.md](templates/official-letter.md) |
   | 电话通知 | [templates/phone-notice.md](templates/phone-notice.md) |
   | 普通公文 | [templates/plain-document.md](templates/plain-document.md) |
   | 会议议程 | [templates/meeting-agenda.md](templates/meeting-agenda.md) |
   | 白头件（呈批件） | [templates/white-paper.md](templates/white-paper.md) |
   | 红头呈批件 | [templates/red-head-approval.md](templates/red-head-approval.md) |
   | 研究报告 | [templates/research-report.md](templates/research-report.md) |
3. **按语法规则写正文**。速查见下文；完整规则（表格合并、序号表、居中居右、图片、
   列表标点归一等）见 [references/markdown-syntax.md](references/markdown-syntax.md)。
   研究报告另读 [references/research-report.md](references/research-report.md)。
4. **按行文规范润色**：[references/writing-style.md](references/writing-style.md)。
5. **自检**：跑一遍文末清单；环境里有 Python 时可再运行
   `python scripts/check_gongwen_md.py <文件.md> --kind <文种>` 做机器检查。
6. **交付**：输出纯 Markdown。写文件时用 UTF-8 编码、`.md` 扩展名；在对话里给出时，
   整篇放进一个 ```` ```markdown ```` 代码块便于复制，但**文件内容本身不能带代码围栏**。

## 语法速查（公文六种文种）

```markdown
# 关于××××的函                ← 文档主标题，全文只有一个，放第一行

<!-- [正文] -->                 ← 正文区段起点

开头段落，交代依据和目的。连续的几行会接成同一个自然段，段与段之间空一行。

## 一级标题                     ← 程序编成“一、”黑体，不要手写编号

### 二级标题                    ← 编成“（一）”楷体

#### 三级标题                   ← 编成“1.”仿宋

##### 四级标题                  ← 编成“(1)”仿宋

正文里要强调的话用 **加粗**，括号（全角、半角、【】）里的补充说明自动排楷体。

1. 独立列表项；               ← 列表前空一行：逐项成段，编“1.”
2. 独立列表项。

正文紧接着列表不空行，
1. 第一项；                   ← 列表前不空行：并入上一段，编成①②
2. 第二项。

特此函告。

<!-- [附件] -->                 ← 每份附件前各写一个，程序自动编“附件1”、另起一页，
                                   并在正文后自动列出“附件：1.……”说明

# 附件正式标题

附件内容，标题层级与正文相同。
```

要点：

- **标题不手写编号**。“一、”“（一）”“1.”“第一章”之类会被程序剥掉重编；想要什么层级
  就用几个 `#`。`##` 是正文第一层，`#` 只给文档标题和附件标题用。
- **段落靠空行分隔**。同一段不要硬折行也不要紧（程序会接回去），但不要用空行切碎一句话。
- **不要写版头版记**：密级、文号、红头、主送抬头、落款单位、成文日期、抄送、承办、
  联系人电话、页码、分隔线 `---`，这些都在程序的“文档要素”表单里填，写进正文会印两遍。
  “主送单位：”抬头这一行也不要写。
- **不用的语法**：代码块、HTML、YAML frontmatter、`---` 分隔线、`> ` 引用、脚注、
  链接、删除线、`- [ ]` 任务框。公文文种里 `$` 是普通字符，不支持公式。
- **拿不准的事实写占位**：`【待核实：具体事项】`。程序会把它列入待办，不得编造人名、
  单位、数字、文号、日期、领导批示。
- **表格**用标准 GFM 管道表，可用 `||` 横向合并、`^^` 纵向合并；表前加一行
  `<!-- [序号表] -->` 可自动编号、分组。见 [references/markdown-syntax.md](references/markdown-syntax.md)。

## 研究报告速查

研究报告走另一套排版（封面 + 章节 + 目录 + 文献），语法差异较大：

```markdown
# 报告题名                       ← 只供封面取用，正文不再排

<!-- [目录] -->                  ← 可选：写了才排目录

<!-- [摘要] -->

摘要正文……

<!-- [正文] -->

<!-- [不编号] -->                ← 可选：紧跟的标题及其下级标题不编号（前言、结束语）
## 前言

<!-- [部分] -->                  ← 可选：其后每个 # 开一个部分（第一部分……）

# 现状分析

## 研究背景 {#sec:bg}            ← ## 是章，### 节，#### 小节，##### 四级小节

如 {@sec:bg} 所述，已有研究指出……[@zhang2024]。样本来自三省[^s1]:(样本说明)。
行内公式 $E=mc^2$；独立公式单独成段：

$$\int_0^1 x^2\,dx = \frac{1}{3}$$

<!-- [附录] -->

## 附录标题

<!-- [参考文献] -->

## 参考文献
```

完整规则见 [references/research-report.md](references/research-report.md)。

## 交付前自检清单

- [ ] 第一行是唯一的 `# 标题`（会议议程、研究报告同样如此）；没有副标题行。
- [ ] 所有 `##`～`#####` 标题都**没有手写编号**，层级没有跳级（`##` 下直接 `####` 属于跳级）。
- [ ] 没有密级、文号、主送抬头、落款、成文日期、抄送、联系人电话、页码、分隔线。
- [ ] 附件每份前都有独占一行的 `<!-- [附件] -->`，其后一行是 `# 附件标题`；没有手写“附件1”。
      写了附件区段时，**不要在正文末尾手写“附件：1.……”说明**，程序按附件标题自动生成。
      用户没提供全文的附件不要臆造，这时才在结语后手写一行附件说明。
- [ ] 正文里“见附件2”“附件3份”之类的说法与实际附件份数一致（程序会核对）。
- [ ] 表格每行列数一致，有分隔行 `| --- |`；图片独占一行。
- [ ] 白头件 / 红头呈批件没有 `- ` 项目符号，结尾有“妥否，请指示。”。
- [ ] 会议议程严格照骨架，没有多出的段落。
- [ ] 所有日期写成“2026年8月20日（星期四）”，时间用 24 小时制“14:30”。
- [ ] 不确定的内容都已写成 `【待核实：……】`，没有编造。
- [ ] 输出里没有解释、思考过程、审校清单——只有 Markdown 正文。

## 关于程序

公文助手（gongwen-assistant）是开源的离线公文写作桌面程序，Rust 编写。编号样式
（例如把一级标题改成“第一章”）是用户在「设置 → 标题与列表编号」里配的，你只管用
对 `#` 的层级。本技能包由公文助手在「设置 → 上手指引 → AI 技能包」中导出。
